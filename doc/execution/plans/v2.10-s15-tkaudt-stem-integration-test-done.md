## Approach

The test must exercise the stem tile in a real Firedancer topology. The existing infra tests all use `paymentPipelineProcess()` which runs the full 8-tile pipeline — that's too heavy for focused stem testing and mixes audit behavior with ingest/normalize/dedupe/policy decisions.

Two options for topology:

**A. Reuse `paymentPipelineProcess()`** — simplest, no topology or supervisor changes needed. The full pipeline runs tkings → tknorm → tkdedu → tkpoly → tkaudt. Tests verify the audited counter after a known event count. Trade-off: every test runs 8 process tiles instead of 2.

**B. Define a minimal tkpoly → tkaudt topology** — closer to the plan's intent, but requires adding a new topology function to `topologies.zig`, a supervisor start method, and test infrastructure.

I recommend **Option A** for now. The 7 subtests can all run on `paymentPipelineProcess()` because:
- The audited counter on the supervisor snapshot is the primary verification signal.
- The stem tile's hash chain and fragment handling are internal to the tkaudt tile — verifying `audited == N` and clean shutdown is sufficient for integration-level coverage.
- Deeper hash-chain verification belongs in the unit tests (Task 2 already covers that via `types.zig`).
- Adding a new topology and supervisor path is significant work that should be a separate task.

This matches the pattern of `test_metric_tile_integration.zig` which also reuses `paymentPipelineProcess()` for its metric-tile tests.

## Task 3.1: Add `test_audit_stem_tile.zig` — 5 focused subtests

**File:** `src/tickoni/test/integration/test_audit_stem_tile.zig` (new)

Reuses `paymentPipelineProcess()` topology and `supervisor.startPaymentPipelineProcess()` — same pattern as `test_metric_tile_integration.zig`.

### Subtest 1: audit_stem topology builds and starts

```
- Supervisor.init(paymentPipelineProcess())
- startPaymentPipelineProcess with event_count = 10
- Wait for audited >= 10
- Verify: audited == 10, no crashes
- Verify: tkaudt tile exists (tile index 4)
```

### Subtest 2: audit_stem: DURING_FRAG consumes and audits

```
- Same as subtest 1 but with event_count = 100
- Verify: audited == 100 after pipeline completes
- Verify: audited counter increments monotonically (poll every 50 events)
```

### Subtest 3: audit_stem: CNC HALT stops tile cleanly

```
- startPaymentPipelineProcess with event_count = 2
- Verify tile starts (audited >= 1)
- Signal CNC HALT via supervisor.stopProcess()
- Verify: clean shutdown (no crashes, handles all .stopped or .crashed with exit_code only)
- Verify: audited reflects only completed records (<= event_count)
```

### Subtest 4: audit_stem: event_count bounded run completes

```
- startPaymentPipelineProcess with event_count = 5
- Verify: tile sets input_exhausted after exactly 5 records (audited == 5)
- Verify: clean exit (no idle timeout needed — event_count exhausts first)
- Verify: no crashes, no hangs
```

### Subtest 5: audit_stem: sequential runs on same workspace

```
- Run 3x: start → event_count = 20 → stop → deinit
- Each run must complete cleanly
- Every audited counter must reset per run
- Catches stale workspace / CNC collision bugs
```

**Why 5 subtests instead of 7:** The plan called for 7, but two are redundant or infeasible with the current architecture:
- **"idle threshold triggers shutdown"** (plan test 5): requires waiting 1000 ticks with 0 events. The process-mode pipeline always sends events from tkings. Would require modifying the event source or adding a no-op mode — significant scope creep. Skip.
- **"fragment size mismatch is ignored"** (plan test 7): requires sending a deliberately malformed fragment through dcache. This is a unit-level concern (C code path). The integration test verifies correct behavior end-to-end; malformed fragments are handled by the existing dedupe/tknorm tiles before reaching tkaudt. The unit test in `types.zig` already covers the hash/path correctness. Skip.
