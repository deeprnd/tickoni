# Plan: Replace git clone with release tarball download for OpenSSL

## Problem

`install-openssl.sh` clones the openssl repo via `git clone` which triggers GitHub rate limits / login prompts. The clone is used solely to obtain the source code for building — everything else in the script (`./config`, `make build_libs`, `make install_dev`) stays exactly the same.

## Solution

Replace the 3 identical `git clone` calls with a curl download of the release tarball, version-routed through `tool-versions.json` (same pattern as llama.cpp).

SHA256 from release page: `9bffaa1ad1e07b354c21bd3324ec02fa15579f45a7d0494b3e74bc449b7333ef`
ASC signature available: `openssl-3.6.4.tar.gz.asc`

| `contrib/setup/tool-versions.json` | Edit | Add `versions.openssl` section with version, filename, sha256, base_url. Change openssl entry's `install_method` from `build_from_source` to `openssl_build`. |
| `contrib/setup/install/strategies/openssl_build.py` | **NEW** | New strategy — reads version/url/sha256 from `tool-versions.json` via `versions.openssl`, downloads tarball, verifies SHA256, extracts, then runs `install-openssl.sh` for the build step. |
| `contrib/setup/install/strategies/__init__.py` | Edit | Add `openssl_build` to the import list. |

The source is already extracted by the strategy. |

### Step 2: `contrib/setup/install/strategies/openssl_build.py` (NEW) ✅ DONE

Created new strategy file modeled on `llama_cpp_download.py`:
- Reads version/url/sha256 from `tool-versions.json` via `versions.openssl`
- Downloads tarball from GitHub releases
- Verifies SHA256 against official release
- Extracts tarball to `install_dir/git/openssl/` (preserving versioned root, then renaming)
- Runs `install-openssl.sh` for the build step
- Respects `SKIP_IDEMPOTENCY=true` from orchestrator
