# Plan: Move Qt6 graphics dependencies to JSON-driven apt category

**Status:** Done
**Created:** 2026-09-04
**Scope:** `contrib/setup/tool-versions.json`, `contrib/setup/install/strategies/qt_installer.py`
**Depends on:** None

---

## Problem Statement

`contrib/setup/install/strategies/qt_installer.py` hardcodes Linux OpenGL/X11 dev packages (`libgl1-mesa-dev`, `libx11-dev`, `libxext-dev`, `libxcb1-dev`) and prints a manual `apt-get` message when they're missing, then exits with code 1.

This violates the established setup-model principle: package installation must go through the JSON-driven orchestrator (`just setup-*` / `orchestrator.py`), not direct `apt-get` calls in strategy code.

The hardcoding is also **incorrect** for macOS and Windows:

| Platform | Qt6 default RHI backend | OpenGL/X11 dev packages needed? |
|----------|----------------------|-------------------------------|
| **Linux** | OpenGL | **Yes** — `libgl1-mesa-dev`, `libx11-dev`, `libxext-dev`, `libxcb1-dev` |
| **macOS** | Metal | **No** — Metal is built into macOS; no equivalent Mesa/X11 packages exist |
| **Windows** | Direct3D 11 | **No** — D3D11 is built into Windows; Qt6 dynamic OpenGL builds ship a Mesa llvmpipe software rasterizer |

Qt6 uses the Qt Rendering Hardware Interface (QRhi) which abstracts graphics APIs. The default RHI backend is platform-specific: D3D11 on Windows, Metal on macOS, OpenGL on Linux. Neither macOS nor Windows needs Mesa dev packages — they get native backends built into the OS.

---

## Target State

### Principle

System packages are declared in `tool-versions.json` as a category with `install_method: "apt"`. The orchestrator resolves the category dependency graph and installs them before the tool's strategy runs. Strategy code (e.g., `qt_installer.py`) must **never** call `apt-get` directly.

### Changes

#### 1. Add `graphics-libs` category and tool in `tool-versions.json`

New category for Linux graphics development libraries, installed via apt:

```json
"graphics-libs": {
  "description": "Linux graphics dev libraries (OpenGL, X11) needed by Qt6",
  "tools": [
    "graphics-libs"
  ],
  "platforms": ["linux"]
}
```

New tool entry:

```json
"graphics-libs": {
  "category": "graphics-libs",
  "platform": "linux",
  "install_method": "apt",
  "parameters": {
    "packages": [
      "libgl1-mesa-dev",
      "libx11-dev",
      "libxext-dev",
      "libxcb1-dev"
    ]
  },
  "idempotent_check": "pkg-config --libs gl x11"
}
```

`platform: "linux"` means the orchestrator only installs this on Linux runners (macOS/Windows CI lanes skip it entirely).

#### 2. Add `graphics-libs` to the `qt` category dependency graph

```json
"qt": [
  "core",
  "build",
  "toolchain",
  "graphics-libs"
]
```

The orchestrator resolves `qt` → `[core, build, toolchain, graphics-libs]`, installs `graphics-libs` via apt before `qt-installer`, then installs Qt.

#### 3. Remove hardcoded `apt-get` call from `qt_installer.py`

Refactor `QtInstallerStrategy._install_system_dependencies()`:

- **Linux path**: remove the package-check + `apt-get` install block entirely. The orchestrator already installed `graphics-libs` before invoking this strategy. If any package is genuinely missing (e.g., user skipped the setup step), print a diagnostic message but do not call `apt-get` — exit with a clear error like "Qt6 requires graphics-libs category: run `just setup-linux-x86-qt`".
- **macOS path**: keep as-is (no-op, Metal is built-in).
- **Windows path**: keep as-is (no-op, D3D11 is built-in).

#### 4. Add `graphics-libs` to the `dev` category

Ensure `just setup-dev` (full developer environment) installs graphics libraries:

```json
"dev": [
  "build",
  "toolchain",
  "zig",
  "ssl",
  "ops",
  "quality",
  "secrets",
  "coverage",
  "security",
  "fd",
  "qt",
  "graphics-libs"
]
```

Note: since `qt` now depends on `graphics-libs`, adding `graphics-libs` to `dev` is technically redundant but makes the dependency explicit and avoids the orchestrator from installing Qt without graphics libs if `qt` is listed directly in a CI lane that doesn't transitively pull `graphics-libs` through `dev`.
