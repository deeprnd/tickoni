# Plan: Migrate tkpoly tile to fd_stem

**Status:** Proposed; implementation has not started.

**Goal:** Move the Phase 0 payment pipeline's `tkpoly` from the generic
process callback to its own Firedancer `fd_stem` specialization. Preserve
policy precedence, signed amount comparisons, decision attribution, message
layout, counters, and one forwarded message per consumed event.

Execute tasks in dependency order: establish requirements and tests before
switching dispatch. Tests written for the new path may fail until that path
is implemented; this plan does not promise that every intermediate task passes.
Unit contracts run in `test-unit-tk`; real-process proofs run in
`test-integration-tk-infra`.

## References And Scope

The implementation standard is
[`tile-orchestration.md`](../../knowledge/tile-orchestration.md#fd_stem-tile-implementation-standard),
especially its callback, scratch, accessor, registration, and test sections.
The callback contract also lives in
[`contribution/tickoni.md`](../contribution/tickoni.md#fd_stem-callback-contract)
and `src/tickoni/c_abi/shim/stem_helpers.h`.

Use the completed
[`tkdedu` plan](v2.NN-sXX-tkdedu-fd-stem-migration-done.md) for task structure,
not as current implementation instructions. This plan was checked against
`story/tkdedu-fd-stem` through `815883342`, including the later callback,
counter, accessor, and scratch-alignment refactors and the working-tree
orchestration standard.

This is a lifecycle/transport migration of the existing payment spike.
Finance-native capability expansion, new outcomes, approval rules, policy
limits, public request schemas, audit schemas, and storage roles remain
separate work. The Zig in-process `policy.zig` path remains the behavioral
reference for its existing dev/test lane. Tickoni-owned C stays inside
`src/tickoni/c_abi/shim/` as the existing stem bridge pattern requires.

## Preserved Policy Contract

Apply these branches in order to each copied `PaymentMessage`:

| Condition | Outgoing decision | `decided_by` | Counter change |
| --- | --- | --- | --- |
| Incoming decision is `malformed_drop` | Preserve it | Preserve incoming producer, normally `tknorm` | Neither allowed nor denied |
| Otherwise `duplicate` is true | `duplicate_drop` | `tkpoly` | Neither allowed nor denied |
| Otherwise `raw.amount_cents > policy_limit_cents` | `deny` | `tkpoly` | Denied +1 |
| Otherwise | `allow` | `tkpoly` | Allowed +1 |

Equality to the limit is allowed. Compare `int64_t` values without unsigned
casts or narrowing. Preserve the existing handling of configured signed
limits; this migration does not add a new financial validation rule.

Increment `pipeline_hops` exactly once. Preserve the raw payment,
`source_offset`, `event_hash`, and duplicate flag. A financial rejection is
still a valid transport message and must reach `tkaudt`; do not filter it
with `BEFORE_FRAG` or silently discard it.

Track a separate `processed` count for **all** committed messages. Gate
exhaustion on `processed`, never `allowed + denied`: duplicate and malformed
events count toward completion too. Keep the existing CNC schema:
`app[0] = allowed`, `app[1] = denied`. Expose processed state through a C
accessor for tests rather than adding a new supervisor metric field.

## Topology, State, And Lifecycle Contract

The full payment process topology keeps tile id `tkpoly`, descriptor index 3,
one input, and one output. Find tiles by id in tests; subset topologies can
assign a different descriptor index, and Firedancer moves `metric` last.

| Property | Input | Output |
| --- | --- | --- |
| Link / ownership | `tkdedu -> tkpoly`; `tkdedu` writes payload/metadata | `tkpoly -> tkaudt`; `tkpoly` writes payload/metadata |
| Backing | Existing application Tango workspace selected by run config | Same existing application workspace |
| Mapping | Producer writes link objects; consumer reads payload/metadata and advances its own fseq | Same producer/consumer discipline; retain metric observer mappings |
| Depth / MTU / payload | Existing depth 64, MTU 128, `PAYMENT_MSG_SIZE` (currently 56 bytes) | Same |
| Reliability | Reliable, polled; credit backpressure | Reliable; stem reserves one publication per iteration |
| Overrun | Stem abandons a speculative read; policy commits nothing for that read | Publish only after the input re-check; do not bypass stem credits |
| Restart | Rebuild topology and replay/regenerate the run inputs; no independent in-place resume is added | No new persistence or recovery guarantee |
| Shutdown | Positive event count self-exits after the Nth committed message; zero disables the gate; CNC HALT remains available | Publish the Nth message before exiting; administrative HALT retains current semantics |
| Health | Process exit/crash and existing link diagnostics | Allowed/denied CNC progress and downstream committed audit records |

Owned state is bounded tile scratch: allowed, denied, processed, staging
validity, one staged `PaymentMessage`, CNC/input/output addresses, output
chunk bounds/cursor, configured event count, signed policy limit, and the
exhaustion flag. Embed the staged message in the context to avoid a second
allocation or a second layout formula. No dedupe arrays, unused tile pointer,
idle counter, heap allocation, network, filesystem work, or blocking operation
belongs in the per-fragment path.

The per-event budget is O(1): one input copy, a bounded branch chain and
fixed-size attribution copy, one output copy/publication, and two CNC counter
stores. Scratch does not grow with traffic. Keep `STEM_BURST = 1UL` and
explicit `STEM_LAZY = ((long)10e6)` to match the existing pipeline peers.

Stem CNC `BOOT -> RUN` transitions/heartbeats and the pre-satisfied
`allow_shutdown` guard are existing orchestration gaps. Preserve the current
launch convention and describe health as process liveness. Do not add a
tile-specific heartbeat policy or claim stale-loop detection is solved here.

## Task 5: Implement The Stage/Commit Callbacks

### Initialization And Run Entry

Resolve scratch with `STK_GET_CTX`. Initialize all owned fields, copy the
explicit configuration, and validate exactly one input and one output before
indexing link arrays. Resolve the input workspace with `stk_derive_wksp`,
not `fd_wksp_containing`. Validate input/output mcache and dcache objects,
MTUs, and workspace joins; fail startup on an incompatible shape. Resolve CNC with
the shared helpers and require it before entering the loop.

Precompute output workspace, compact chunk bounds, and initial chunk once
in unprivileged initialization. Use the registered run entry to call only
the generated `tkpoly_run`. Retain the existing intentional-return convention
without claiming the current `allow_shutdown` guard detects unexpected exits.

### DURING_FRAG

1. Clear `stage_valid` as the first executable statement.
2. Validate transport size with `stk_validate_frag` and validate the chunk
   against the joined input dcache bounds before converting/dereferencing
   its address. Keep malformed transport separate from a valid message
   carrying the financial `malformed_drop` outcome.
3. Copy the whole `PaymentMessage` into the context's staging message.
4. Set staging validity. Any calculations here operate only on that copy.

No counters, output dcache writes, policy-state commits, CNC stores, event
gate, or publication belong here. Invalid transport never becomes a
financial outcome or advances the processed gate. Do not re-read the input
dcache from `AFTER_FRAG`.

### AFTER_FRAG

1. Return if staging is invalid; otherwise clear validity immediately.
2. Increment the staged hop count once and apply the policy contract above.
   Preserve malformed attribution; copy all six tile-id bytes for decisions
   owned by `tkpoly`, without a terminator overflowing the field.
3. Copy the staged result to the precomputed output dcache slot. Call
   `fd_stem_publish(stem, 0UL, 0UL, out_chunk, PAYMENT_MSG_SIZE, 0UL, 0UL, 0UL)`
   exactly once, then advance with `fd_dcache_compact_next`.
4. Advance processed and the appropriate allowed/denied counter once;
   publish both assigned CNC slots with `stk_publish_counter`.
5. Apply `STK_EVENT_EXHAUSTED(ctx, ctx->event_count, ctx->processed)` after
   the publication and count increment.

Use only `DURING_FRAG`, `AFTER_FRAG`, and `SHOULD_SHUTDOWN`. The shutdown
predicate reads exhaustion or CNC HALT. No idle timeout, `AFTER_CREDIT`
publication, or extra credit/poll callbacks are needed.

**Verify:** A single input reaches the audit sink before self-exit, rejected
events still flow, and all observable per-fragment work follows the stem
sequence re-check.
