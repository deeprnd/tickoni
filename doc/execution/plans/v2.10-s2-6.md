# Plan: Move Fixture Path Resolution from Runtime to build.zig

## Problem

Source files contain runtime filesystem path resolution (`std.Io.Dir.cwd().readFileAlloc`) that fails when the test binary runs from `.zig-cache/o/...` (not the repo root). This causes `FileNotFound` errors and requires workarounds like `@src().dir` which breaks in Zig 0.17 (field removed from `SourceLocation`).

The `io` parameter is passed to fixture-loading functions but ignored — `cwd()` bypasses it and uses the OS working directory.

## Plan

### Phase 1: Create `fixture_paths` build_options module in build.zig

Add a build_options module (same pattern as existing `version` module) that exports comptime string constants for all fixture directories:

```zig
const fixture_opts = b.addOptions();
fixture_opts.addOption([]const u8, "FIXTURE_INVESTMENT_SCENARIOS", "src/tickoni/test/fixtures/investment/scenarios");
fixture_opts.addOption([]const u8, "FIXTURE_AUDIT", "src/tickoni/test/fixtures/audit");
// ... etc for every fixture directory used by production code
```

Every test target and production module that loads fixtures imports this module via `.imports` in their `b.addModule`/`b.createModule` call.

### Phase 2: Remove `resolvePath()` from capsule.zig

Delete the entire `resolvePath()` function (lines 88-100) and replace all 3 `cwd().readFileAlloc()` calls in `loadReplayCapsule()`, `loadModelFixtureContent()`, and `loadPaperFixture()` with resolved paths from `build_options`.

Two approaches:
- **Option A (preferred for tests):** Remove the `io` parameter entirely. Functions take comptime path constants from `build_options` — zero runtime path manipulation.
- **Option B (for production runtime):** Caller receives fixture paths from `build_options` and passes resolved absolute paths to functions. Functions become pure file readers.

Option A is cleaner for test fixtures. Option B is needed if production code loads capsules from arbitrary user-provided paths at runtime (unlikely for replay).

### Phase 3: Apply same fix to model/backend.zig and adapter/backend.zig

Both have identical pattern: `resolvePath()` (injected previously) → `cwd().readFileAlloc()`. Replace with comptime path resolution from `build_options`.

### Phase 4: Move CWD-relative test paths into test-specific build targets

For test blocks in `basket.zig`, `thesis.zig`, `classification.zig`:

Replace each `cwd().readFileAlloc("src/tickoni/test/fixtures/...")` with either:
- A comptime string constant defined in the test file
- Or import from a shared test-options module added in Phase 1

### Phase 5: Verify build.zig has all C source files and link flags

Current state: 45 link/Library calls already centralized. No C source files in `src/`. No changes needed.

### Phase 6: Add `zig build verify-fixture-paths` step

Add a build step that verifies all fixture paths referenced by `fixture_opts` actually exist on disk at build time. Catches missing fixtures before running tests.

```zig
const verify_step = b.step("verify-fixture-paths", "Verify all fixture paths exist");
// Iterate fixture_opts options, check each exists at build.zig scope
```

## What This Solves

1. `FileNotFound` errors when test binary runs from `.zig-cache/o/...` — paths resolved at compile time, not runtime CWD
2. Zig 0.17 `@src()` compatibility — eliminates `@src().dir` usage entirely
3. CWD-dependent behavior — deterministic paths known at build time
4. `io` parameter being passed but ignored — can be removed from fixture loaders if paths are comptime
5. Missing fixtures caught early via `verify-fixture-paths` build step

## Risks & Mitigations

- **Risk:** Production code loads capsules from arbitrary user paths at runtime.
  **Mitigation:** Only apply comptime resolution to test fixtures. Production capsule loading keeps dynamic path support.

- **Risk:** Fixture directory changes break comptime constants.
  **Mitigation:** `verify-fixture-paths` step fails fast at build time.

- **Risk:** Build.zig grows with many fixture path options.
  **Mitigation:** Group related fixtures into logical constants. Use relative paths from repo root consistently.
