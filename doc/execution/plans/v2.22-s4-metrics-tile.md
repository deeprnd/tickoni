# Plan: Port fd_metric_tile Pattern to Tickoni's Process Mode

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Close the architectural gap between Tickoni's process-mode pipeline and Firedancer's native metrics by wiring real-time `/metrics` HTTP serving, replacing the console-only sampling from Plan 1 with proper per-tile metric counters in shared memory.

**Architecture:** Fire up a `tickoni-metric` tile as a separate process in the Tango shared workspace. This tile joins the workspace, reads per-tile counters from the shared memory layout (same pattern as Firedancer's `fd_metric_tile`), and serves Prometheus-format output over HTTP. Tiles write metrics via the `appCounterWrite` C ABI path that already exists in `cnc_counters.zig` — we add a metrics area to the workspace layout and wire the tile to serve it.

**Tech Stack:** Zig, Firedancer `fd_http_server`, Tango shared memory, Prometheus text format, `tickoni-supervisor` process-mode.

## Task 1: Define the Tickoni metrics layout

**Objective:** Add a metrics area to the workspace that mirrors Firedancer's layout but uses Tickoni's existing counter schema.

**Files:**
- Create: `src/app/tickoni/metrics_area.zig`

**Step 1: Define the metrics area struct**

```zig
/// v2.22.S4.T2: Tickoni-specific metrics layout for process-mode.
///
/// Laid out in shared workspace memory, one region per tile. The supervisor
/// allocates this area via wkspAlloc_at_least during topology build.
///
/// Layout (all values are u64, aligned to 128 bytes):
///   [0]     in_link_cnt          — count of inbound links (always 0 for Tickoni tiles)
///   [1..]   tile_metrics[N]     — per-tile counter values, offset from tile base
///
/// Each tile's counters map 1:1 to tile_registry.CounterField:
///   tkings[0]: produced
///   tkrnorm[0]: normalized, [1]: invalid
///   tkdedu[0]: duplicates
///   tkpoly[0]: allowed, [1]: denied
///   tkaudt[0]: audited

pub const MetricsAlign = 128;

pub const TileMetricField = enum {
    produced,
    normalized,
    invalid,
    duplicates,
    allowed,
    denied,
    audited,
};

pub const TileMetricSchema = struct {
    field: TileMetricField,
    offset: u8, // offset from tile's base pointer within the metrics area
};

/// Counter schema for each tile in the Phase 0 pipeline.
pub const metric_schemas: [8][]const TileMetricSchema = .{
    // tkings (idx 0)
    &.{.{ .field = .produced, .offset = 0 }},
    // tkrnorm (idx 1)
    &.{.{ .field = .normalized, .offset = 0 }, .{ .field = .invalid, .offset = 1 }},
    // tkdedu (idx 2)
    &.{.{ .field = .duplicates, .offset = 0 }},
    // tkpoly (idx 3)
    &.{.{ .field = .allowed, .offset = 0 }, .{ .field = .denied, .offset = 1 }},
    // tkaudt (idx 4)
    &.{.{ .field = .audited, .offset = 0 }},
    // tkrepl, tkmetr, tkdiag — no counters, no metrics area
    &.{},
    &.{},
    &.{},
};

/// Total metric slots across all tiles. Used to size the shared memory area.
pub fn totalMetricSlots() u8 {
    var n: u8 = 0;
    inline for (metric_schemas) |schema| n += @as(u8, @intCast(schema.len));
    return n;
}

/// Footprint in bytes for the metrics area, aligned to MetricsAlign.
pub fn footprint(in_link_cnt: u8) usize {
    // in_link_cnt * 8 bytes (reserved for link counters, kept 0) +
    // tile_metrics * 8 bytes + alignment padding
    const tile_bytes: usize = totalMetricSlots() * @as(u8, 8);
    const link_bytes: usize = in_link_cnt * @as(u8, 8);
    const raw = link_bytes + tile_bytes;
    return (raw + MetricsAlign - 1) & ~(MetricsAlign - 1);
}
```

    const metrics_tag = c_abi.wksp.wkspAllocAtLeast(wksp, metrics_area.MetricsAlign, metrics_footprint, 0);

**Files:**

**Step 1: Add shared memory metric writes alongside existing cnc counter writes**

In each tile's process function, after the existing `appCounterWrite` calls, add a metrics-area write. For example, in `runIngestProcess`:

Current code (existing):
```zig

```

After the existing write, add:
```zig
// v2.22.S4.T2: also write to shared metrics area for the metric tile.
// The metrics area is a contiguous buffer in the workspace; tile N's
// counters start at offset N * total_slots. For tkings (idx 0), offset 0.
var metrics_ptr = c_abi.wksp.wkspLaddr(wksp, state.metrics_area_tag.?);
const tile_base: usize = 0; // tkings is tile index 0
// produced is at offset 0 within tkings' counters
metrics_ptr[tile_base + 0] = 8; // u64 byte offset from start
metrics_ptr[tile_base + 0] |= @as(u64, 1) << 8; // value
// (simplified — actual code uses ptrCast and @as(u64*) for proper alignment)
```

The real implementation uses:
```zig
var metrics_buf = state.metrics_area.?;
const metrics_u64 = @as(*[totalMetricSlots()]u64, @ptrCast(@alignCast(metrics_buf.ptr)));
// For tkings (tile 0), produced is at offset 0:
metrics_u64[0] += 1;
```

Do this for all 5 pipeline-stage tiles:
- `runIngestProcess`: write to `metrics_u64[0]` (produced, tile 0 offset)
- `runNormalizeProcess`: write to `metrics_u64[8]` (normalized) and `metrics_u64[9]` (invalid)
- `runDedupeProcess`: write to `metrics_u64[16]` (duplicates)
- `runPolicyProcess`: write to `metrics_u64[24]` (allowed) and `metrics_u64[25]` (denied)
- `runAuditProcess`: write to `metrics_u64[32]` (audited)

```zig
fn cmdMetrics(init: std.process.Init) !void {
    const log = logger.get();
    try log.enter("cmdMetrics", "init");
    defer log.exit("cmdMetrics", "done") catch {};
    
    const stdout = std.Io.File.stdout();
    const host = if (arg_count > 1) args[1] else "localhost:9090";
    
    var client = try std.net.connect(.{ .address = .{ .ip4 = try std.net.Address.parseIp4("127.0.0.1", 9090), .in_port = 0 } });
    defer client.stream.close();
    
    try client.stream.writeAll("GET /metrics HTTP/1.1\r\nHost: localhost\r\n\r\n");
    
    var buf: [8192]u8 = undefined;
    const n = try client.stream.read(&buf);
    const response = buf[0..n];
    
    // Parse response body (skip headers)
    if (std.mem.indexOf(u8, response, "\r\n\r\n")) |idx| {
        const body = response[idx + 4 ..];
        try stdout.writeAll(body);
    }
}
```

## Risk Assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| HTTP server adds complexity to tile lifecycle | Low | Use std.net.Server (Zig standard library, no deps). Tile exits cleanly on HALT signal. |
| Shared memory race between metric tile and writing tiles | None | Tiles write atomically (u64 stores), metric tile reads atomically (u64 loads). No lock needed. |
| Port binding conflicts if multiple runs start | Medium | Use configurable port per run, or bind to 127.0.0.1 only. |
| Metrics area allocation fails on workspace | Low | Workspace has sufficient space; allocation checked before spawning tiles. |
| Thread-mode tile doesn't serve metrics | None | Thread-mode uses console sampling (Plan 1). Metric tile only active in process-mode. |

---

## What This Does NOT Change

- Thread-mode pipeline (dev/test) — continues using console sampling from Plan 1.
- Tile financial logic — counters are metadata, not business state.
- Firedancer `fd_shmem` or `fd_topo` — this plan works within the existing Tango shared memory.
- Linux-only constraint — uses Firedancer's existing shmem infrastructure.
- No changes to Firedancer's `fd_metric_tile` C code — this is a Tickoni-native Zig implementation.
