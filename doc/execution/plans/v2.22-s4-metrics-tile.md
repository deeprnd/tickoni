Plan: Integrate tkmetr as a Firedancer C tile — not as a Tickoni base tile

**Goal:** Make tkmetr run its real Firedancer C tile logic (`fd_metric_tile.c`) in process mode, instead of just heartbeating as a no-op. On macOS/thread-mode, tkmetr already works via `tiles.runMetric()` polling. On Linux/process-mode, tkmetr currently goes through the base tile infrastructure (`TK_TILE_RUN`), which skips the C tile entirely.

**Architecture:** tkmetr is a 0-input/0-output tile. It runs as a standalone Firedancer C tile (`fd_topo_run_tile_t fd_tile_metric`) with its own scratch allocation, HTTP server, seccomp, and fd_stem. No Tickoni base tile infrastructure, no Zig callbacks, no C bridge.

**Why Firedancer C tile, not base tile:** `fd_metric_tile.c` is already architecturally complete: `scratch_footprint`, `scratch_align`, `privileged_init`, `unprivileged_init`, seccomp, fd_stem callbacks, HTTP server on scratch, Prometheus. The base tile path (`TK_TILE_RUN` → `tk_tile_run` → heartbeats) is designed for pipeline tiles with dcache/mcache coordination. tkmetr has 0 inputs, 0 outputs — forcing it into the base tile would duplicate what `fd_metric_tile.c` already does.

**Tech Stack:** C (`tile_run.c` shim), `tile_main.zig`, `topo_run.zig`.

  supervisor.startPaymentPipeline()

    → polls metrics from shared state (existing)

Process mode (Linux):
  supervisor.startPaymentPipelineProcess()
    → spawns tickoni-supervisor __tile-run for tkmetr
    → tile_main.zig detects tkmetr, calls fd_metric tile entry
    → tk_topo_run_tile(topo, tile, ..., &fd_tile_metric)
    → Firedancer runtime: scratch + HTTP server + fd_stem + Prometheus

## Task 3: Add tkmetr dispatch in tile_main.zig

**File:** `src/app/tickoni/tile_main.zig`

**Objective:** Detect tkmetr in the launch spec and use the C tile entry point instead of the base tile path.

### Step 1: Add tkmetr detection in run()

In `tile_main.zig`'s `run()` function, after reading the launch spec and before calling `tile_process.run()`, check if this tile is tkmetr and use the C tile path:

```zig
pub fn run(io: std.Io, allocator: std.mem.Allocator, spec_path: []const u8) u8 {
    const spec = rt.tile_process.LaunchSpec.readFromFile(io, std.Io.Dir.cwd(), spec_path) catch |err| {
        std.debug.print("tile_main: failed to read launch spec {s}: {t}\n", .{ spec_path, err });
        return 1;
    };

    // tkmetr runs as a Firedancer C tile, not through the base tile infrastructure.
    // It uses fd_metric_tile.c's fd_topo_run_tile_t directly.
    if (std.mem.eql(u8, spec.tile_id.slice(), "tkmetr")) {
        return runFdMetricTile(io, allocator, spec_path);
    }

    // ... existing code for base tile path ...
}
```

### Step 2: Add runFdMetricTile() function

Add a new function that handles the tkmetr-specific process-mode path:

```zig
fn runFdMetricTile(io: std.Io, allocator: std.mem.Allocator, spec_path: []const u8) u8 {
    const log = logger.get();
    log.enter("tile_main", "runFdMetricTile") catch {};

    // Boot with shmem path from spec
    rt.boot.bootWithSyntheticArgv(spec_path) catch |err| {
        std.debug.print("tile_main: bootWithSyntheticArgv failed for tkmetr: {t}\n", .{err});
        return 1;
    };

    // Rebuild topology (same as base tile path)
    var built = rebuildTopology(allocator, spec.shmemPath(), spec.workspace_name.slice()) catch |err| {
        std.debug.print("tile_main: failed to rebuild topology for tkmetr: {t}\n", .{err});
        c_abi.boot.haltForTileProcess();
        return 1;
    };
    defer {
        c_abi.boot.haltForTileProcess();
        built.deinit(allocator);
    }

    // Find tkmetr tile in rebuilt topology
    var tile_id_buf: [7]u8 = undefined;
    @memcpy(tile_id_buf[0..4], "tkmetr");
    tile_id_buf[4] = 0;
    // ... actually TileId.slice() returns the string representation
    const tile_idx = c_abi.topob.topoFindTile(built.topo, "tkmetr", 0);
    if (tile_idx == c_abi.topob.not_found) {
        std.debug.print("tile_main: tkmetr not found in rebuilt topology\n", .{});
        return 1;
    }

    // Launch as Firedancer C tile
    const tile = c_abi.topob.topoTilePtr(built.topo, tile_idx);
    c_abi.topo_run.runTileSimpleFdMetric(built.topo, tile);

    return 0;
}
```

The function needs access to the topology rebuild logic that `tile_process.zig::run()` already does. The cleanest approach: extract the topology rebuild + find tile logic into a shared helper, or simply inline the essential parts.

**Simpler approach:** Instead of duplicating the rebuild logic, add a special case in `tile_process.zig::run()` itself. When the spec's tile_id is "tkmetr", skip the base tile path and call `runTileSimpleFdMetric()` instead of `runTileSimple()`. This avoids duplication in `tile_main.zig`.

**Best approach:** Add the tkmetr check in `tile_main.zig`'s `run()` function, but delegate the actual work to a new `rt.tile_process.runFdMetricTile()` function in `tile_process.zig` that mirrors `run()` but calls `runTileSimpleFdMetric()` instead of `runTileSimple()`.
