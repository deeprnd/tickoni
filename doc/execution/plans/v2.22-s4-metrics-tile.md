# Plan: Integrate fd_metric_tile into Tickoni Process-Mode Pipeline

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Close the architectural gap between Tickoni's process-mode pipeline and Firedancer's native metrics by wiring a real-time `/metrics` HTTP endpoint. This plan **reuses `src/disco/metrics/fd_metric_tile.c` as-is** (via a Tickoni process-mode shim) rather than inventing a custom metric infrastructure.

**Architecture:** The existing Firedancer `fd_metric_tile.c` uses `fd_stem` as its run loop with `BEFORE_CREDIT` callback for HTTP polling and `METRICS_WRITE` callback for gauge reporting. We create a thin C shim (`tk_metric_tile.c`) that wraps the `fd_tile_metric` entry point to work within Tickoni's process-per-tile model, then spawn it alongside the pipeline tiles.

**Tech Stack:** Zig, Firedancer `fd_stem`, `fd_http_server`, `fd_prometheus`, Tango shared memory, `tickoni-supervisor` process-mode.

**What this plan does NOT do:**
- No custom `metrics_area.zig` — Firedancer's `fd_metrics.h` already provides the shared memory metrics infrastructure (`fd_metrics_register`, `FD_MCNT_SET`, `FD_MGAUGE_SET`). The existing `topob.c` `tk_obj_cb_metrics` already allocates a metrics area per tile.
- No manual metric writes per tile — tiles call `FD_MCNT_SET` which writes to the tile's registered metrics base pointer. The existing tile `appCounterWrite` path stays unchanged.
- No fd_stem migration of existing tiles — only the metric tile uses `fd_stem`. All other tiles keep their existing polling loops.
- No custom HTTP server — reuses `fd_http_server` (same as Firedancer's metric tile).

## Task 1: Create `tk_metric_tile.c` — C shim around Firedancer's `fd_metric_tile`

**Objective:** A C file that provides a `fd_topo_run_tile_t` compatible with Tickoni's process-mode launch pipeline, wrapping Firedancer's `fd_tile_metric`.

**File:** `src/tickoni/c_abi/shim/tk_metric_tile.c` (new)

**Key design decisions:**

1. **Use `fd_tile_metric`'s callbacks** — `fd_tile_metric.privileged_init` (scratch alloc + HTTP server start), `fd_tile_metric.unprivileged_init` (ctx setup), `fd_tile_metric.run` (stem_run).

2. **Prevent double-init** — `fd_stem.c` calls `unprivileged_init` internally before `stem_run`. If Tickoni's `tk_topo_run_tile` also calls `unprivileged_init`, the HTTP server gets double-initialized (crash). So we set `unprivileged_init = NULL` in our wrapper and let `stem_run` handle it.

3. **Custom `privileged_init`** — Must join Tickoni's cnc (for heartbeat/halt), call Firedancer's `fd_tile_metric.privileged_init` for scratch/HTTP setup, then signal RUN.

4. **Reuse `fd_tile_metric`'s seccomp/FD callbacks** — `fd_metric_tile_seccomp.h` and `populate_allowed_fds` are needed for sandboxed execution (log file + HTTP listen socket).

**Implementation:**

```c
// tk_metric_tile.c — shim that wires Firedancer's fd_tile_metric into
// Tickoni's process-mode launch pipeline.
//
// Unlike other Tickoni tiles that use tk_tile_privileged_init / tk_tile_run,
// the metric tile needs Firedancer's fd_stem-based run loop with
// fd_http_server. This file provides a custom fd_topo_run_tile_t
// (TK_METRIC_RUN) that:
//   1. Joins Tickoni cnc + signals RUN (tk_metric_privileged_init)
//   2. Calls fd_tile_metric.privileged_init for scratch/HTTP server
//   3. Runs fd_stem via stem_run (tk_metric_run)
//   4. Returns after stem_run exits (on SHUTDOWN or HALT)
//   5. Tickoni's tk_topo_run_tile then does heartbeat/halt loop

#if FD_HAS_LINUX
#define _GNU_SOURCE
#endif

#include "../../../util/fd_util.h"
#include "../../../disco/metrics/fd_metric_tile.c"  // includes fd_stem.c, defines stem_run
#include "../../../disco/metrics/fd_metric_tile_seccomp.h"
#include "../../../tango/cnc/fd_cnc.h"
#include "../../topo_run_platform.h"

/* ---------------------------------------------------------------------
   tk_metric_privileged_init — joins Tickoni cnc, then calls
   Firedancer's fd_tile_metric.privileged_init for scratch + HTTP setup.
   --------------------------------------------------------------------- */

static void
tk_metric_privileged_init( fd_topo_t const *      topo,
                           fd_topo_tile_t const * tile ) {
  // Join Tickoni cnc (same pattern as tk_tile_privileged_init)
  // Find the cnc object for this tile — it was registered in topob via
  // topobObj("cnc", wksp_name) + topobTileUses(tile_id, cnc_obj_id, true)
  ulong cnc_obj_id = ULONG_MAX;
  for( ulong j=0UL; j<tile->uses_obj_cnt; j++ ) {
    if( FD_LIKELY( strcmp( topo->objs[ tile->uses_obj_id[ j ] ].name, "cnc" ) == 0 ) ) {
      cnc_obj_id = tile->uses_obj_id[ j ];
      break;
    }
  }
  FD_TEST( cnc_obj_id != ULONG_MAX );

  void * cnc_laddr = fd_topo_obj_laddr( topo, cnc_obj_id );
  fd_cnc_t * cnc = fd_cnc_join( cnc_laddr );
  FD_TEST( cnc );

  fd_cnc_heartbeat( cnc, fd_log_wallclock() );

  // BOOT->RUN transition (same pattern as tk_tile_privileged_init):
  if( fd_cnc_signal_query( cnc ) != FD_CNC_SIGNAL_HALT ) {
    fd_cnc_signal( cnc, FD_CNC_SIGNAL_RUN );
  }

  // Now call Firedancer's privileged_init for scratch + HTTP server setup
  // fd_tile_metric.privileged_init expects scratch space at tile->tile_obj_id
  void * scratch = fd_topo_obj_laddr( topo, tile->tile_obj_id );
  FD_SCRATCH_ALLOC_INIT( l, scratch );
  fd_metric_ctx_t * ctx = FD_SCRATCH_ALLOC_APPEND( l, alignof( fd_metric_ctx_t ), sizeof( fd_metric_ctx_t ) );

  fd_http_server_t * _metrics = FD_SCRATCH_ALLOC_APPEND( l, fd_http_server_align(),
                                                        fd_http_server_footprint( METRICS_PARAMS ) );

  fd_http_server_callbacks_t metrics_callbacks = {
    .request = metrics_http_request,  // from fd_metric_tile.c
  };
  ctx->metrics_server = fd_http_server_join(
    fd_http_server_new( _metrics, METRICS_PARAMS, metrics_callbacks, ctx )
  );
  fd_http_server_listen( ctx->metrics_server, tile->metric.prometheus_listen_addr,
                        tile->metric.prometheus_listen_port );
}

/* ---------------------------------------------------------------------
   tk_metric_run — wrapper around stem_run that returns cleanly so
   Tickoni's tk_topo_run_tile can continue to the heartbeat/halt loop.
   --------------------------------------------------------------------- */

static void
tk_metric_run( fd_topo_t *      topo,
               fd_topo_tile_t * tile ) {
  // stem_run is defined by the #include "fd_stem.c" in fd_metric_tile.c
  // It expects STEM_BURST, STEM_LAZY, STEM_CALLBACK_* to be defined.
  // fd_metric_tile.c defines exactly:
  //   STEM_CALLBACK_CONTEXT_TYPE = fd_metric_ctx_t
  //   STEM_CALLBACK_CONTEXT_ALIGN = alignof(fd_metric_ctx_t)
  //   STEM_BURST = 1
  //   STEM_LAZY = 10e6 (10ms)
  //   STEM_CALLBACK_BEFORE_CREDIT = before_credit
  //   STEM_CALLBACK_METRICS_WRITE = metrics_write
  // stem_run will call before_credit for HTTP polling, and
  // should_shutdown (not defined → defaults to false) for halt.
  stem_run( topo, tile );
}

/* ---------------------------------------------------------------------
   TK_METRIC_RUN — the fd_topo_run_tile_t passed to fd_topo_run_tile
   --------------------------------------------------------------------- */

static ulong
tk_metric_scratch_align( void ) {
  return FD_LAYOUT_INIT;  // just return the base alignment (128 from fd_metric_ctx_t)
}

static ulong
tk_metric_scratch_footprint( fd_topo_tile_t const * tile ) {
  // Reuse fd_tile_metric's scratch_footprint
  (void)tile;
  ulong l = FD_LAYOUT_INIT;
  l = FD_LAYOUT_APPEND( l, alignof( fd_metric_ctx_t ), sizeof( fd_metric_ctx_t ) );
  l = FD_LAYOUT_APPEND( l, fd_http_server_align(), fd_http_server_footprint( METRICS_PARAMS ) );
  return FD_LAYOUT_FINI( l, alignof( fd_metric_ctx_t ) );
}

/* tk_metric_tile uses the same seccomp and FD callbacks as fd_tile_metric */

static fd_topo_run_tile_t TK_METRIC_RUN = {
  .name                     = "tickoni-metric",
  .keep_host_networking     = 0,
  .allow_connect            = 0,
  .allow_renameat           = 0,
  .rlimit_file_cnt          = FD_HTTP_SERVER_METRICS_MAX_CONNS + 5UL,
  .populate_allowed_seccomp = populate_allowed_seccomp,  // from fd_metric_tile.c
  .populate_allowed_fds     = populate_allowed_fds,      // from fd_metric_tile.c
  .scratch_align            = tk_metric_scratch_align,
  .scratch_footprint        = tk_metric_scratch_footprint,
  .privileged_init          = tk_metric_privileged_init,
  .unprivileged_init        = NULL,  // stem_run handles it; double-init = crash
  .run                      = tk_metric_run,
  .rlimit_file_cnt_fn       = NULL,
};

/* ---------------------------------------------------------------------
   Export for tile_run.c to find and use
   --------------------------------------------------------------------- */

fd_topo_run_tile_t const *
tk_metric_get_run_tile( void ) {
  return &TK_METRIC_RUN;
}
```

**Key difference from `fd_tile_metric.c`:**
- `fd_tile_metric.c` is included by Firedancer's main binary which calls `fd_topo_run_tile` directly with `&fd_tile_metric`.
- `tk_metric_tile.c` is included by Tickoni's shim and provides a custom `TK_METRIC_RUN` that joins Tickoni's cnc before calling Firedancer's init.
- `fd_tile_metric.unprivileged_init` is intentionally not used — `stem_run` (the `run` callback) calls it internally, so Tickoni's `tk_topo_run_tile` would double-call it.

## Task 2: Wire metric tile into `tile_run.c`

**Objective:** When the tile being launched is `tkmetr`, use `TK_METRIC_RUN` instead of `TK_TILE_RUN`.

**File:** `src/tickoni/c_abi/shim/tile_run.c`

**Changes:**

1. **Include `tk_metric_tile.c`:**
```c
#include "tk_metric_tile.c"
```

2. **Add extern declaration:**
```c
extern fd_topo_run_tile_t const * tk_metric_get_run_tile( void );
```

3. **Modify `tk_topo_run_tile_simple` to select the right tile run:**
```c
void
tk_topo_run_tile_simple( void * topo, void * tile ) {
#if FD_HAS_LINUX
  fd_topo_run_tile_t const * run_tile = &TK_TILE_RUN;
#else
  tk_topo_run_tile_t const * run_tile = &TK_TILE_RUN;
#endif

  // Check if this is the metric tile — it needs special handling
  fd_topo_t * t = (fd_topo_t *)topo;
  fd_topo_tile_t * tc = (fd_topo_tile_t *)tile;
  if( FD_LIKELY( strcmp( tc->name, "tkmetr" ) == 0 ) ) {
    run_tile = tk_metric_get_run_tile();
  }

#if FD_HAS_LINUX
  fd_topo_run_tile( t, tc,
                    TK_PROCESS_MODE_SANDBOX_NONE, TK_KEEP_CONTROLLING_TERMINAL,
                    FD_TOPO_CORE_DUMP_LEVEL_REGULAR,
                    (uint)getuid(), (uint)getgid(), -1,
                    run_tile );
```

**Why this works:** `tk_topo_run_tile` in `topo_run.c` takes a `fd_topo_run_tile_t*` as the last argument. For `tkmetr`, we pass `&TK_METRIC_RUN` instead of `&TK_TILE_RUN`. The rest of `tk_topo_run_tile` (sandbox, fill_tile, metrics_register, etc.) handles it generically.

// scratch_footprint computes the size from METRICS_PARAMS.

## Task 7: Wire per-tile metric writes via `FD_MCNT_SET`

**Objective:** Each tile's `appCounterWrite` already increments counters in the app-region. We need the same counters to appear in the Firedancer metrics area (for the metric tile to read via `fd_prometheus_render_all`).

**File:** `src/tickoni/tiles/payment_pipeline/process.zig` (and other tile files)

**Current state:** Tiles call `cnc.appCounterWrite(tile_idx, field_idx, value)` which writes to the cnc app-region (64 bytes). This is the existing path.

**What's needed:** After each `appCounterWrite`, also call the appropriate `FD_MCNT_SET` macro. But these are C macros, not Zig functions. The existing `c_abi/cnc/appCounterWrite` is a Zig wrapper.

**Approach:** The metric tile reads metrics from each tile's `fd_metrics_tl` pointer (set by `fd_metrics_register` in `tk_topo_run_tile`). For this to work, each tile needs to call `FD_MCNT_SET` at some point. However, `FD_MCNT_SET` operates on `fd_metrics_tl` which is a thread-local pointer set by `fd_metrics_register(tile->metrics)` — and this is called inside `tk_topo_run_tile` BEFORE the tile's work function runs.

**Two options:**

A. **Add C-level metric writes in a tile-level shim** — create `cnc_metric_shim.zig` that calls `FD_MCNT_SET` for each counter write, wrapping `appCounterWrite`.

B. **Keep existing `appCounterWrite` path as-is** — the supervisor already snapshots per-tile metrics from the cnc app-region. The metric tile's Prometheus output shows Firedancer's tile-level metrics (status, heartbeat, regime ticks) but NOT the Tickoni financial counters. For full financial metrics in Prometheus, we'd need option A.

**For Task 7 (minimal viable):** Keep `appCounterWrite` as-is. The metric tile will serve Firedancer's tile metrics (PID, TID, heartbeat, regime ticks, backpressure) via Prometheus. Financial counter metrics remain visible via the supervisor's console snapshot (already working).

**For Task 7b (full metrics in Prometheus):** Create a C-level `cnc_metric_write` function that calls `FD_MCNT_SET` alongside `appCounterWrite`. Each tile calls this new function instead of (or in addition to) `appCounterWrite`.
