## Gap Analysis — What's Missing

The justfile currently has **bare dispatchers with monolithic case statements**, not the thin-dispatcher-to-qualified-form pattern the story requires. Here's the exact state:

### 1. Bare dispatchers are case-fat, not thin wrappers

**Current `build-fd`** (justfile:177-202): monolithic `case "os"` with explicit per-platform logic.
**Required**: bare `build-fd` computes `{os}-{arch}[-{compiler}]` and execs `just build-fd-{os}-{arch}[-{compiler}]`.

**Current `test-unit-fd`** (justfile:272-310): same pattern — case statement + Linux-specific content (`-Wl,-z,shstk`, `nproc`).
**Current `test-unit-tk`** (justfile:314-327): case statement routing only to Windows.
**Current `test-integration-tk`** (justfile:351-364): case statement routing only to Windows.

None of them delegate to a fully-qualified recipe. They inline platform logic.

### 2. test-unit-fd macOS/Windows variants do not exist

The story requires:
- `test-unit-fd-macos-x86_64` — but macOS x86_64 has a known `blst`/`zstd`/`lz4` build blocker
- `test-unit-fd-macos-arm`
- `test-unit-fd-windows-x86`
- `test-unit-fd-windows-arm`

None of these exist. The current `test-unit-fd` only handles Linux and falls back to `test-unit-tk` for macOS/Windows.

### 3. `-Wl,-z,shstk` CET linker flag is hardcoded in Linux-only `test-unit-fd`

**Location**: justfile:309, inside the bare `test-unit-fd` recipe.
**Problem**: This flag only works on Linux. It's inside the Linux `case` branch so it doesn't leak, but the new design must ensure non-Linux `test-unit-fd-*` recipes never include it. Currently no non-Linux `test-unit-fd-*` recipes exist at all.

### 4. `nproc` is hardcoded, not portable

**Locations**: justfile:243 (`build-fd-dev`), justfile:308 (`test-unit-fd`), justfile:339 (`test-e2e-fd`).
**Existing helper**: `contrib/fd-tk-libs.sh` already has `fd_nproc()` (line 239-247) that falls back to `sysctl -n hw.ncpu` on macOS. The justfile recipes don't use it.

### 5. `build-tkni` and `test-tkni` recipes do not exist

The story (S4 scope, cross-ref S3) requires:
- `build-tkni` — Qt terminal build via CMake
- `test-tkni` — placeholder for Qt tests (future V3.19)

Neither exists in the justfile.

### 6. No qualified aliases for quality-*/security-*

The story requires: `quality-lint-check-fd-linux-x86` → `quality-lint-check-fd` for consistency.
Currently, quality and security recipes have no qualified variants.

### 7. Aggregate recipes (`test-unit-all`, `test-integration-all`, `build-all`) route directly to sub-recipes, not through bare dispatchers

**Current `test-unit-all`** (justfile:335): calls `just test-unit-tk && just test-unit-fd` — this is correct (bare dispatchers), but the bare dispatchers themselves are not thin wrappers yet.

**Current `build-all`** (justfile:245): runs `run-badged-command.py` which runs `just build-fd && just build-tk` — correct pattern but build-fd needs to be a thin wrapper first.

### Batch 1 — Add fd_nproc helper to justfile + use it everywhere

Replace all hardcoded `$(nproc)` in justfile with `$(fd_nproc)` call.

**1a.** Add `fd_nproc` variable to justfile (after platform detection, before recipes):

```
# Portable core-count — falls back to sysctl on macOS, echo 1 as last resort.
fd_nproc := `bash -c 'command -v nproc >/dev/null 2>&1 && nproc || (command -v sysctl >/dev/null 2>&1 && sysctl -n hw.ncpu) || echo 1'`
```

**1b.** Update justfile:243 (`build-fd-dev`): replace `$(nproc)` with `$(fd_nproc)`.

### Batch 2 — Rewrite bare dispatchers as thin wrappers

**2a.** `build-fd` (justfile:177-202): Replace monolithic case with:

```
build-fd:
    @case "$(os)" in \
      linux) \
        case "$(arch)" in \
          x86) exec just build-fd-linux-x86-gcc ;; \
          arm) exec just build-fd-linux-arm-gcc ;; \
        esac ;; \
      macos) \
        case "$(arch)" in \
          x86) exec just build-fd-macos-x86_64 ;; \
          arm) exec just build-fd-macos-arm ;; \
        esac ;; \
      windows) \
        case "$(arch)" in \
          x86) exec just build-fd-windows-x86 ;; \
          arm) exec just build-fd-windows-arm ;; \
        esac ;; \
      *) echo "unsupported host OS for build-fd: $(os)" >&2; exit 1 ;; \
    esac
```

## Risks / Notes

- **S3 must ship first** for `build-tkni` to be real. Until then it's a placeholder that calls CMake.
- **macOS x86_64 test-unit-fd blocker**: the recipe should still be added (per the story's acceptance criteria) but must explicitly document the vendor-source blocker rather than silently failing.
- **`test-unit-fd-windows-*`**: the story says "validate the native run-unit-test make invocation actually builds and links on Windows." Currently Windows has no `run-unit-test` target in the Firedancer make system — this needs investigation before committing. The story calls this a spike.
- **`build-fd-dev`** (justfile:242-243) uses bare `make` without MACHINE/BUILDDIR. This is a Firedancer-level dev target, not Tickoni. Keep it as-is; it's not part of the grid.
- **`build-fd-gcc`, `build-fd-clang`, `build-fd-arm`** are CI-only names referencing BUILDDIR variants for test/quality/security compatibility. The new qualified names (`build-fd-linux-x86-gcc`, `build-fd-linux-clang`, `build-fd-linux-arm-gcc`) should be aliases to these existing recipes to avoid breaking CI (S6 handles CI cutover).
