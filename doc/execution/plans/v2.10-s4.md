## Architecture: Domain-First, Tile-Composition

### Core Concept (CORRECTED)

**Build.zig compiles Tickoni shim code, NOT Firedancer C.** Firedancer C is built by Firedancer's CMake/make into `.a` archives (`libfd_ballet.a`, `libfd_tango.a`, etc.). Build.zig compiles Tickoni's `tk_*` shim code (in `src/tickoni/c_abi/shim/`) into domain archives, then links against the appropriate Firedancer `.a` for `fd_*` symbols.

**Domains = Tickoni shim C + Firedancer `.a` linkage. Domains are classified into three types:**

1. **Firedancer shim domains** (Tickoni shim C + Firedancer `.a`): `ballet`, `flamenco`, `disco`
   - `ballet` = `ballet.c` → `libtickoni_ballet.a` + links `libfd_ballet.a`
   - `flamenco` = `tango.c` + `util.c` + `wksp.c` + `sandbox.c` + `os.c` → `libtickoni_flamenco.a` + links `libfd_tango.a` + `libfd_util.a`
   - `disco` = `topo_run.c` + `topob.c` + `tile_run.c` + platform variants → `libtickoni_disco.a` + links `libfd_disco.a`
2. **Common domains** (pure Zig, no C shims): `c_abi`, `util`, `logger`, `schema/*`, `test_utils/*`
3. **Tile domains** (composite domains referencing common + Firedancer shim domains): `audit`, `payment`, `policy`, `model`, `adapter`, `topology`, etc.

### Key Principles

1. **Build.zig does NOT compile Firedancer C** — Firedancer C is built by Firedancer's CMake/make into `.a` archives. `just build-fd` handles that.
2. **Build.zig compiles Tickoni shim C** (in `src/tickoni/c_abi/shim/`) into domain archives, linking against pre-built Firedancer `.a` for `fd_*` symbols.
3. **Tiles declare domain dependencies** (e.g., `[ballet]`, `[flamenco]`) — not C shim files.
4. **Tiles only link the domains they request** — if a tile needs `[ballet]`, only `libtickoni_ballet.a` is linked, NOT `libtickoni_flamenco.a` or `libtickoni_disco.a`.
5. **Zig's linker deduplicates archives** — each archive appears once per binary.
6. **Removing a tile = one entry removed** — from `domains/tiles.zig`.
7. **Adding a tile = one entry added** — to `domains/tiles.zig` with its domain deps.

### Domain Builder (`build/domain/builder.zig`)

```zig
/// Builds all domains in dependency order.
/// Returns a struct with all domain modules and Firedancer archives.
pub fn buildDomains(
    b: *std.Build,
    target: std.Build.ResolvedTarget,
    optimize: std.builtin.OptimizeMode,
    fd_lib_dir: []const u8,
) struct {
    modules: struct {
        c_abi: *std.Build.Module,
        util: *std.Build.Module,
        logger: *std.Build.Module,
        // ... all common domain modules
        // ... all Firedancer shim domain modules (link to archives)
        // ... all tile domain modules (compose common + Firedancer)
    },
    archives: struct {
        ballet: ?*std.Build.Step.Compile,  // libtickoni_ballet.a
        flamenco: ?*std.Build.Step.Compile, // libtickoni_flamenco.a
        disco: ?*std.Build.Step.Compile,    // libtickoni_disco.a
    },
} {
    // 1. Build Firedancer shim domains first (compile Tickoni shims, link Firedancer .a)
    // 2. Build common domains (pure Zig)
    // 3. Build tile domains (compose common + Firedancer shim)
}

/// Creates a Firedancer shim domain archive from Tickoni shim C files.
/// This compiles Tickoni shim C code, NOT Firedancer C code.
/// Firedancer C is already built by Firedancer's CMake into .a archives.
pub fn createFiredancerShimArchive(
    b: *std.Build,
    domain_name: []const u8,
    shim_c_files: []const []const u8,   // Tickoni shim files from src/tickoni/c_abi/shim/
    fd_lib_names: []const []const u8,    // e.g., "ballet", "tango", "util" — Firedancer lib names
    fd_lib_dir: []const u8,              // path to pre-built Firedancer .a archives
    target: std.Build.ResolvedTarget,
    optimize: std.builtin.OptimizeMode,
) *std.Build.Step.Compile {
    const mod = b.createModule(.{
        .target = target,
        .optimize = optimize,
        .link_libc = true,
    });
    mod.addIncludePath(b.path("src"));
    mod.addCSourceFiles(.{
        .files = shim_c_files,
        .flags = shim.shimCFlagsFor(target.result),
    });
    const archive = b.addLibrary(.{
        .name = "libtickoni_" ++ domain_name,
        .linkage = .static,
        .root_module = mod,
    });
    // Link pre-built Firedancer archives for fd_* symbols
    for (fd_lib_names) |fd_lib_name| {
        archive.root_module.addObjectFile(.{
            .cwd_relative = b.fmt("{s}/libfd_{s}.a", .{ fd_lib_dir, fd_lib_name }),
        });
    }
    return archive;
}
```

## Build.zig After Refactor (~60 lines)

```zig
const std = @import("std");
const domain = @import("build/domain.zig");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});
    const fd_lib_dir = b.option([]const u8, "fd-lib-dir", "...") orelse "build/native/gcc/lib";
    const build_tests = b.option(bool, "test", "...") orelse false;

    // 1. Build all domains (Firedancer shim → common → tile)
    const all = domain.buildDomains(b, target, optimize, fd_lib_dir);

    // 2. Supervisor executable (uses tile domains)
    const exe = domain.supervisorExe(b, all, target, optimize, fd_lib_dir);
    b.installArtifact(exe);

    // 3. Check step
    domain.checkStep(b, target);

    // 4. Test execution
    if (build_tests) {
        const test_step = b.step("test", "Run all Tickoni tests");
        const specs = domain.testSpecs(b, all);

        for (specs) |spec| {
            const root_mod = b.createModule(.{
                .root_source_file = b.path(spec.source_file),
                .target = target,
                .optimize = optimize,
                .imports = spec.imports,
            });
            const test_bin = b.addTest(.{ .name = spec.name, .root_module = root_mod });

            // Apply Firedancer shim archive linkage (Zig deduplicates across binaries)
            if (spec.linkage.needs_ballet) test_bin.root_module.addObjectFile(.{
                .cwd_relative = b.fmt("{s}/libtickoni_ballet.a", .{fd_lib_dir}),
            });
            if (spec.linkage.needs_flamenco) test_bin.root_module.addObjectFile(.{
                .cwd_relative = b.fmt("{s}/libtickoni_flamenco.a", .{fd_lib_dir}),
            });
            if (spec.linkage.needs_disco) test_bin.root_module.addObjectFile(.{
                .cwd_relative = b.fmt("{s}/libtickoni_disco.a", .{fd_lib_dir}),
            });

            const run = b.addRunArtifact(test_bin);
            test_step.dependOn(&run.step);
        }
    }
}
```

## Migration Strategy

This is a phased migration. **Never delete old files until the phase after the one that uses them.** This ensures every phase is a net-add, never a net-delete.

### Phase-by-phase strategy

1. **Add phase (Phases 1-3):** Add new `build/domain/` files alongside existing `build/lib/`, `build/mod/`, `build/test/` files. Old code remains untouched. Test command: `just build-tk` — the old `build.zig` path still works, but we're writing new code to coexist.

2. **Replace phase (Phase 4):** Rewrite `build.zig` to import from `build/domain/` instead of inline code. **This is the most dangerous step.** We test with `just build-tk` (supervisor only, no tests yet). If the supervisor builds, the domain system works.

3. **Test phase (Phases 5-6):** Update `build/test/helpers.zig` to link domain archives. Test with `just test-unit-tk`. This is where we verify the duplicate-symbol fix. If tests compile, link, and pass, the core problem is solved.

4. **Expand phase (Phases 7-9):** Test integration, then full lanes. Each step is a single `just` command that adds test coverage.

5. **Cleanup phase (Phase 10):** Full build pass. Remove old code, clean up.

### Rollback plan

If a phase fails and we can't fix it within 3 attempts:
1. `git checkout -- build/domain/` (if files were tracked) or `rm -rf build/domain/`
2. Revert `build.zig` to previous version
3. Assess what went wrong, fix the root cause, restart the phase

Since we never delete old code until Phase 5+, the old system always remains as a fallback.

### Key safety rules

- **Never delete** `build/lib/*.zig`, `build/mod/*.zig`, `build/test/*_specs.zig` until Phase 5+
- **Never modify** Firedancer C shims or `contrib/*.sh` scripts
- **Never compile Firedancer C from build.zig** — Firedancer C is built by Firedancer's CMake/make. Build.zig only compiles Tickoni shim C (in `src/tickoni/c_abi/shim/`)
- **Always test** with the `just` command listed above — never assume it works
- **Commit after each passing phase** — `git commit -m "Phase N: <description>"`
- **Never proceed** when the verification command fails — fix it first

## Risks / Notes

- **Firedancer archive paths**: The `.a` files are in `build/native/gcc/lib/`. On Windows, use `build/native/msvc/lib/` or the path from `fd_lib_dir`. The `fd_lib_dir` option must be passed to domain builder.
- **Platform-specific shims**: `topo_run_platform_*.c` files are per-platform. The `disco.zig` domain must select the correct file based on target OS.
- **Stub files**: `libuuid_stub.c`, `tile_run_test_stubs.c`, `windows_crt.c` are per-platform or per-test. They must be conditionally included.
- **Dependency cycle detection**: The domain builder must detect cycles in the dependency graph and fail early.
- **Incremental migration**: The plan above marks old files as OBSOLETE rather than deleting them. This allows gradual migration — each phase can run alongside the old system.
- **No sh/mk file changes**: This is a pure Zig refactor. `contrib/run-test-series.sh` is unaffected — it still receives the same `zig-out/bin/*_test` arguments.
- **Duplicate symbol guarantee**: By compiling Tickoni shim C once into archives and linking archives into each test binary, Zig's static linker deduplicates at link time. No `tk_*` symbols will appear in multiple object files within the same binary.
- **Tile modularity guarantee**: Each tile domain is a single entry in `build/domain/tiles.zig` with its source files and domain dependencies. Removing a tile = removing one entry. Its tests are automatically excluded from `build/domain/test_specs.zig`.
