# workspace names: Central workspace name constants

**Goal:** Eliminate scattered `"metric"` / `"metric_in"` string literals in Tickoni source code. One canonical source in `src/tickoni/c_abi/wksp.zig`, consumed by topology builder, supervisor, and C shim.

## Design

### 1. Add workspace name constants to `src/tickoni/c_abi/wksp.zig`

Mirror the tile ID pattern: define named constants with `.slice()` method for Zig callers.

```zig
/// Canonical workspace names for Tickoni topology.
/// These mirror Firedancer's workspace name conventions used by
/// the metric tile (fd_tile_metric.name = "metric") and the
/// metric_in workspace that collects metric tile outputs.
///
/// Tickoni's topo_build.zig and supervisor.zig must use these
/// constants instead of raw string literals to keep the topology
/// declaration centralized and consistent with Firedancer.

pub const wksp_name: struct {
    /// The main metrics workspace where the metric tile allocates
    /// its mcache/dcache/fseq objects. Mirrors Firedancer's
    /// `fd_tile_metric.name = "metric"`.
    pub const metric: []const u8 = "metric";
    /// The input workspace for the metric tile's metric outputs.
    /// Mirrors Firedancer's "metric_in" workspace used by
    /// fd_topo_find_wksp(topo, "metric_in") in fd_startup.c.
    pub const metric_in: []const u8 = "metric_in";
} = .{};
```

Zig callers use `wksp.wksp_name.metric` or `wksp.wksp_name.metric_in` (these are `[]const u8` directly, no `.slice()` needed since they're already slices).

### 2. Add C macros to `src/tickoni/c_abi/shim/audit_schema.h`

Same pattern as tile IDs — C-side callers use preprocessor macros:

```c
/* ─── Workspace Names ─── */

#define WKSP_NAME_METRIC    "metric"
#define WKSP_NAME_METRIC_IN "metric_in"
```

## Risks

- **Firedancer parity**: The constants must match Firedancer's exact strings (`"metric"`, `"metric_in"`). These are verified by the existing `test_metric_tile_integration.zig` which already asserts `"metric"` is the tile name. The Firedancer `fd_startup.c` uses `"metric_in"` — these are not arbitrary choices, they're Firedancer conventions.
- **C shim callers**: The C shim (`topob.c`, `ballet.c`) doesn't have hardcoded workspace names — it takes `wksp_name` as a parameter. No C changes needed beyond the header macros for completeness.
- **Comment references**: `topo_build.zig` has comments mentioning `"metric"` and `"metric_in"` (lines 231, 340). Update to reference the constants in comments.

## Relationship to tile IDs centralization

This follows the exact same pattern as `v2.22-sXX-tile-ids-central.md` and `v2.22-s22-tile-ids-centralize-rest.md`:

1. Create constants in a canonical module (`wksp.zig` vs `tile_ids.zig`)
2. Add C macros in the shared header (`audit_schema.h`)
3. Replace all callers in Tickoni source
4. Leave Firedancer upstream code untouched (it defines the canonical strings; Tickoni mirrors them)

The key difference: workspace names are **Firedancer conventions**, not Tickoni inventions. `"metric"` is set in `fd_tile_metric.name` in Firedancer's C code. Tickoni must match these names exactly (not rename them) because the Firedancer tile runtime uses the workspace name to look up shared memory. Tile IDs, by contrast, are Tickoni-owned identifiers.
