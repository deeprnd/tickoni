# Plan: Migrate tkmodl to an fd_stem tile

**Status:** Closed with an owner-approved carve-out (see "Closure and carve-out").
The fixture/replay-only `tkmodl` stem tile, its wire/audit/config contracts,
and the `tkagnt` result sink are implemented and proven in the minimal
topology. Three items were **not** done here and moved to follow-up plans; they
remain unchecked below and are not claimed.

**Goal:** Give the governed model gateway a dedicated `fd_stem` lifecycle in a
runnable Tickoni topology, while preserving the existing Zig request validation,
model allowlist, configured limits, result token fields, request/response hashes, and replay
substitution behavior. A migration is complete only when real tile processes
exchange bounded messages, audit the model boundary, and replay without a
provider call.

Execute in dependency order: decide the contracts, write tests, implement the
tile, then switch the caller. A file or a passing in-process fixture test is
not evidence that the process tile works.

The older `v2.10-s14-fd-stem-migration.md` table proposes backend dispatch in

callback layout: `DURING_FRAG` can see an overrun fragment and cannot commit,
and `AFTER_CREDIT` may lose the final event when shutdown is checked first.

## HTTP test placement and changes

The test lane is determined by its registered root, not simply by whether a
socket is used. `testing-tickoni.md` allows a localhost mock of an outside
system in the integration lane. The system lane starts a real `llama.cpp`
server and downloaded model. Keep deterministic protocol assertions in
integration so they run without that service; put actual provider
compatibility in system. Add a separate process integration root for the
`fd_stem` tile, because `test_model_tile_http.zig` never launches one.

| Existing case in `test_model_tile_http.zig` | Planned treatment | Reason / required assertion |
| --- | --- | --- |
| `hello round-trip via mock server` | Replace with a small live-server smoke in `src/tickoni/test/system/` after the approved live I/O path exists; remove the redundant mock-only case. | The current mock returns its canned thesis regardless of the prompt, so this case does not prove a model answered “hello.” The live case should check a nonempty response, model attribution, and valid usage without requiring exact model wording. |
| `thesis returns valid structured content from mock server` | Keep in integration as a backend protocol contract, preferably under a name such as `test_model_http_backend.zig`. | Assert POST path, serialized model/messages/sampling, response parsing, finish reason, and usage mapping. The restricted-ticker check only inspects canned JSON; financial recommendation policy belongs in the domain fixture tests, and any live semantic check belongs in system. |
| `two sequential calls both succeed against mock server` | Keep in integration. | Assert two HTTP requests, two separately owned responses, and no stale state or connection failure. This is deterministic backend behavior, not a multi-system deployment proof. |
| `wrong endpoint fails closed with HttpStatusError` | Keep in integration, but name the case for the actual condition. | It uses the right host/port with the `/v1` prefix omitted, so the mock returns HTTP 404. First remove the unconditional `shouldSkip = true` guards. The mock-server
bind probe may only skip for an explicitly unsupported host with a recorded
reason; an unexpected bind or HTTP failure on a supported host must fail the
test. Keep the mock-server self-tests in their existing root. After moving or
renaming a root, update `build-lib/lanes/integration.zig` and the registered
run count so the intended cases execute; moving a file without build-lane
registration does not move its evidence.

The current `test_investment_fixture_live.zig` system root also needs a
separate correction before it can count as live evidence: `use_fixture = true`
selects `runFixtureModel`, even though the orchestrator starts `llama.cpp`.
For the live gate, set up a case that selects `runLiveModel` or the approved
tile path, proves a request reached the server, and records the endpoint and
model used. A direct `runLiveModel` case proves backend compatibility only;
the live tile still needs its own process-system case. Keep the deterministic
fixture scenario as a separate, honestly named proof if it remains useful.
Do not turn the whole system suite into a live semantic test by changing one
flag without checking which assertions depend on canned ticker content.

## Decision gate: approve the runtime contract before implementation

These choices change link semantics, public model messages, audit/replay
behavior, or service authority. The framework owner must decide and record
them in the owning architecture/topology/capability documents before code is
changed. This plan deliberately does not choose values for them.

1. **Response route and ordering.** Define how `tkmodl` returns a result or
   denial to `tkagnt`, how request IDs correlate across fan-in, and how
   results and audit events are ordered. State whether a new result link is
   required, its producer/consumer, and its failure behavior.
2. **Wire contracts and link bounds.** Define bounded request, response,
   failure, and audit payloads; versioning; oversized prompt/response
   handling; content-addressed evidence references; and exact depth/MTU.
   `TkModlRequest` and `ModelResponse` contain Zig slices and cannot be copied
   into Tango as pointer-bearing structs. An MTU of 1024 or 256 does not by
   itself prove the payload fits.
3. **Provider I/O boundary.** Choose the approved non-blocking transport or
   governed I/O proxy, its tile/process ownership, allowlisted endpoints,
   sandbox/network permissions, timeout/cancellation behavior, bounded
   in-flight work, and behavior under backpressure and provider failure.
   `tkmodl` must remain the authority for provider access; agents do not get
   direct network access. Do not introduce a daemon or proxy silently.
4. **Governance and replay authority.** Specify where `tkpoly`'s capability
   decision is bound to each model request, how per-run budgets are reserved
   and charged across concurrent calls, how retries and token usage are
   audited, and how captured substitutions are supplied during replay.
   Replay must have no reachable live-provider path.
5. **Lifecycle and scope.** Decide whether the first runnable topology is a
   focused `tkmodl` fixture topology or the complete investment workflow;
   specify restart, in-flight request recovery, cancellation, and shutdown
   drain rules. Neither exists as a runnable product path today.

For each approved link, the decision record must answer owner tile, workspace,
mapping mode, producer/consumer, depth/MTU, reliability, overrun behavior,
restart behavior, shutdown behavior, and health metrics. If only fixture/replay
operation is approved initially, label the implementation fixture/replay only;
do not present synchronous HTTP as stem-compatible live mode.

### Open contract finding: role length vs the audit wire

The wire request carries `actor_role` in a 16-byte field because the existing
audit `ModelCallPayload.actor_role` (Zig schema, `WireModelCallPayload`, SipHash
layout) is 16 bytes. The role used by the current in-process agent,
`trading_ops_reviewer`, is 20 bytes, and `workflow` values near the limit
(`trading_control`, 15) only just fit. Widening the audit field changes the
audit schema and every recorded hash, so it was **not** done here. The owner must
decide: shorten role identifiers to 15 bytes, or widen `actor_role` in the audit
schema (a versioned audit-schema change). Until then the tkmodl tile rejects an
over-long role as a malformed wire request instead of truncating it.

## Preserved model contract

- Every request carries actor/role, workflow, run or case identity,
  capability envelope, policy version, budget, model ID, and replay mode.
  The approved wire contract must say which fields are mandatory; missing or
  malformed required scope fails closed before any provider call. The current
  Zig validator does not enforce every numeric identity field.
- Preserve the current `TkModlDecision` outcomes and `validator.zig` branch
  precedence unless a separately approved policy change says otherwise.
  Confirm the configured limits and defaults against the approved contract;
  migration must not silently redefine what zero or an empty allowlist means.
- Preserve provider-request and response hashing, request ID correlation,
  model attribution, retry count, latency, and token usage. Model payloads
  and outcomes must be captured for audit/replay without treating CNC
  counters as evidence.
- Replay substitutes captured model output by the approved identifier,
  validates the captured request/result relationship, and never calls HTTP,
  a local LLM server, or another provider.
- Keep model work outside the deterministic financial event path. No agent,
  UI, or ordinary API handler gains direct provider credentials or access.

### Audit hash correction (owner-approved)

Re-hashing C-committed records with the Zig codec showed a divergence that
pre-dates this migration: `tk_audit_stem.c` hashed `capability_envelope_id` as
a 16-byte zero-extended value, but the header field is a `u64` and
`codec/audit/hash.zig` hashes 8 bytes, so **every** C-chained record (including
existing policy decisions) differed from the Zig hash. Hashing 8 bytes in C
(owner's decision) makes them agree. `test_minimal_setup`:

## Risks and completion gate

- **The declared topology is one-way for model results.** No migration can
  claim a working agent/model round trip until the response contract is
  approved and tested.
- **Synchronous HTTP blocks stem progress.** A timeout bounds total waiting
  time but does not make the callback non-blocking; asynchronous transport
  and a bounded in-flight policy are required for live mode.
- **A model response may exceed the current link MTUs.** Decide the bounded
  inline/evidence-reference format before allocating scratch or adding links.
- **An audit link alone is not an audit guarantee.** Prove committed evidence,
  request/result attribution, and replay substitution through `tkaudt` and
  `tkrepl`; CNC counters are operational hints only.

Completion means an approved topology contract, passing registered unit and
real-process tests, no model-provider bypass, zero external effects in replay,
and a clearly stated live-provider status. Do not close this plan based on a
compiled shim or fixture-only tests.
