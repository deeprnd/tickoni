# Plan: Migrate tkmodl to an fd_stem tile

**Status:** Proposed; no `tkmodl` process tile or stem specialization exists yet.

**Goal:** Give the governed model gateway a dedicated `fd_stem` lifecycle in a
runnable Tickoni topology, while preserving the existing Zig request validation,
model allowlist, configured limits, result token fields, request/response hashes, and replay
substitution behavior. A migration is complete only when real tile processes
exchange bounded messages, audit the model boundary, and replay without a
provider call.

Execute in dependency order: decide the contracts, write tests, implement the
tile, then switch the caller. A file or a passing in-process fixture test is
not evidence that the process tile works.

## Current-state gap

| Surface | Observed state | Migration consequence |
| --- | --- | --- |
| Model logic | `runTkModlRequest` validates in Zig and calls a `Backend`; fixture, replay, and HTTP backends exist. | Keep one owner for each rule and preserve parity; do not duplicate policy in C. |
| Budget and scope | `validator.zig` checks required string fields and compares one request's maximum output tokens with the configured per-run budget; it does not track cumulative spend or require nonzero numeric identities. | Decide cumulative accounting and identity requirements explicitly; do not claim the current helper already enforces them. |
| Provider I/O | `HttpBackend.call` uses synchronous `std.http.Client.fetch`; connection retry sleeps. | It cannot run inside a stem fragment callback or its polling loop. A bounded asynchronous I/O boundary is a prerequisite for live mode. |
| Product topology | `investmentWorkflow()` declares `tkagnt -> tkmodl` (depth 32, MTU 1024) and `tkmodl -> tkaudt` (depth 32, MTU 256). It has no `tkmodl -> tkagnt` result link. | The declared graph does not yet deliver a response to the requesting agent. Its audit link alone is insufficient for a full request/response proof. |
| Runtime | The supervisor runs the eight-tile payment topology. `tile_registry.zig`, `tile_run.c`, and `topob.c` have no `tkmodl` process registration. | Do not claim a cutover from an existing `tkmodl` process callback. First establish a runnable, isolated test topology and its launch contract. |
| Tests | Model unit and fixture tests exercise Zig calls. All four `test_model_tile_http.zig` cases have unconditional `SkipZigTest` guards and call `HttpBackend` directly; the system root named `test_investment_fixture_live.zig` sets `use_fixture = true`. | Separate deterministic backend transport, real tile/process wiring, and actual provider compatibility evidence. None of these current roots proves live `tkmodl` HTTP. |

The older `v2.10-s14-fd-stem-migration.md` table proposes backend dispatch in
`DURING_FRAG` and audit publication in `AFTER_CREDIT`. Do **not** use that
callback layout: `DURING_FRAG` can see an overrun fragment and cannot commit,
and `AFTER_CREDIT` may lose the final event when shutdown is checked first.

## HTTP test placement and changes

The test lane is determined by its registered root, not simply by whether a
socket is used. `testing-tickoni.md` allows a localhost mock of an outside
system in the integration lane. The system lane starts a real `llama.cpp`
server and downloaded model. Keep deterministic protocol assertions in
integration so they run without that service; put actual provider
compatibility in system. Add a separate process integration root for the
`fd_stem` tile, because `test_model_tile_http.zig` never launches one.

| Existing case in `test_model_tile_http.zig` | Planned treatment | Reason / required assertion |
| --- | --- | --- |
| `hello round-trip via mock server` | Replace with a small live-server smoke in `src/tickoni/test/system/` after the approved live I/O path exists; remove the redundant mock-only case. | The current mock returns its canned thesis regardless of the prompt, so this case does not prove a model answered “hello.” The live case should check a nonempty response, model attribution, and valid usage without requiring exact model wording. |
| `thesis returns valid structured content from mock server` | Keep in integration as a backend protocol contract, preferably under a name such as `test_model_http_backend.zig`. | Assert POST path, serialized model/messages/sampling, response parsing, finish reason, and usage mapping. The restricted-ticker check only inspects canned JSON; financial recommendation policy belongs in the domain fixture tests, and any live semantic check belongs in system. |
| `two sequential calls both succeed against mock server` | Keep in integration. | Assert two HTTP requests, two separately owned responses, and no stale state or connection failure. This is deterministic backend behavior, not a multi-system deployment proof. |
| `wrong endpoint fails closed with HttpStatusError` | Keep in integration, but name the case for the actual condition. | It uses the right host/port with the `/v1` prefix omitted, so the mock returns HTTP 404. A genuinely unreachable endpoint, timeout, malformed response, or oversized response needs its own focused case if the approved contract requires it; do not call this case a network-outage test. |

First remove the unconditional `shouldSkip = true` guards. The mock-server
bind probe may only skip for an explicitly unsupported host with a recorded
reason; an unexpected bind or HTTP failure on a supported host must fail the
test. Keep the mock-server self-tests in their existing root. After moving or
renaming a root, update `build-lib/lanes/integration.zig` and the registered
run count so the intended cases execute; moving a file without build-lane
registration does not move its evidence.

The current `test_investment_fixture_live.zig` system root also needs a
separate correction before it can count as live evidence: `use_fixture = true`
selects `runFixtureModel`, even though the orchestrator starts `llama.cpp`.
For the live gate, set up a case that selects `runLiveModel` or the approved
tile path, proves a request reached the server, and records the endpoint and
model used. A direct `runLiveModel` case proves backend compatibility only;
the live tile still needs its own process-system case. Keep the deterministic
fixture scenario as a separate, honestly named proof if it remains useful.
Do not turn the whole system suite into a live semantic test by changing one
flag without checking which assertions depend on canned ticker content.

## Decision gate: approve the runtime contract before implementation

These choices change link semantics, public model messages, audit/replay
behavior, or service authority. The framework owner must decide and record
them in the owning architecture/topology/capability documents before code is
changed. This plan deliberately does not choose values for them.

1. **Response route and ordering.** Define how `tkmodl` returns a result or
   denial to `tkagnt`, how request IDs correlate across fan-in, and how
   results and audit events are ordered. State whether a new result link is
   required, its producer/consumer, and its failure behavior.
2. **Wire contracts and link bounds.** Define bounded request, response,
   failure, and audit payloads; versioning; oversized prompt/response
   handling; content-addressed evidence references; and exact depth/MTU.
   `TkModlRequest` and `ModelResponse` contain Zig slices and cannot be copied
   into Tango as pointer-bearing structs. An MTU of 1024 or 256 does not by
   itself prove the payload fits.
3. **Provider I/O boundary.** Choose the approved non-blocking transport or
   governed I/O proxy, its tile/process ownership, allowlisted endpoints,
   sandbox/network permissions, timeout/cancellation behavior, bounded
   in-flight work, and behavior under backpressure and provider failure.
   `tkmodl` must remain the authority for provider access; agents do not get
   direct network access. Do not introduce a daemon or proxy silently.
4. **Governance and replay authority.** Specify where `tkpoly`'s capability
   decision is bound to each model request, how per-run budgets are reserved
   and charged across concurrent calls, how retries and token usage are
   audited, and how captured substitutions are supplied during replay.
   Replay must have no reachable live-provider path.
5. **Lifecycle and scope.** Decide whether the first runnable topology is a
   focused `tkmodl` fixture topology or the complete investment workflow;
   specify restart, in-flight request recovery, cancellation, and shutdown
   drain rules. Neither exists as a runnable product path today.

For each approved link, the decision record must answer owner tile, workspace,
mapping mode, producer/consumer, depth/MTU, reliability, overrun behavior,
restart behavior, shutdown behavior, and health metrics. If only fixture/replay
operation is approved initially, label the implementation fixture/replay only;
do not present synchronous HTTP as stem-compatible live mode.

## Preserved model contract

- Every request carries actor/role, workflow, run or case identity,
  capability envelope, policy version, budget, model ID, and replay mode.
  The approved wire contract must say which fields are mandatory; missing or
  malformed required scope fails closed before any provider call. The current
  Zig validator does not enforce every numeric identity field.
- Preserve the current `TkModlDecision` outcomes and `validator.zig` branch
  precedence unless a separately approved policy change says otherwise.
  Confirm the configured limits and defaults against the approved contract;
  migration must not silently redefine what zero or an empty allowlist means.
- Preserve provider-request and response hashing, request ID correlation,
  model attribution, retry count, latency, and token usage. Model payloads
  and outcomes must be captured for audit/replay without treating CNC
  counters as evidence.
- Replay substitutes captured model output by the approved identifier,
  validates the captured request/result relationship, and never calls HTTP,
  a local LLM server, or another provider.
- Keep model work outside the deterministic financial event path. No agent,
  UI, or ordinary API handler gains direct provider credentials or access.

## Testable work breakdown

### Phase 0 — freeze the baseline

- [ ] Record the current model call sites, topology status/link table,
  registry and C dispatch absence, the four unconditional HTTP test skips,
  and the fixture selection in the system root.
  **Verify:** source references identify an in-process model module and no
  runnable `tkmodl` child.
- [ ] Run `just build-tk`, `just test-unit-tk`, and the relevant existing
  investment fixture integration lane. Record pre-existing failures and the
  working-tree revision; do not attribute them to this migration.

### Phase 1 — decide contracts and write acceptance tests

- [ ] Resolve the five decision-gate items above and update the owning
  topology/architecture/capability requirements first. **Verify:** every
  message and link has an explicit producer, consumer, bounds, and failure
  outcome; a response reaches the requester.
- [ ] Add schema tests for truncated, oversized, malformed, mismatched-ID,
  wrong-version, and pointer-bearing wire input. **Verify:** each is rejected
  before tile state changes or provider work starts.
- [ ] Add governance and replay tests for missing scope, model not allowed,
  output/context/retry/budget limits, replay substitution missing, and
  provider-disabled replay. **Verify:** no denied or replayed request reaches
  the live I/O boundary; outcomes match the approved Zig contract.
- [ ] Repair the deterministic HTTP backend tests as described in the HTTP
  test table: remove unconditional skips, keep protocol/sequential/404 cases
  in the infra integration lane, and define the later live smoke separately.
  **Verify:** `just test-integration-tk-infra` executes each retained
  mock-server test and reports real pass/fail results.
- [ ] Register a real-process integration root with the selected test
  topology. Include one final-request proof, more requests than link depth,
  failed-provider and HALT cases, evidence correlation, and, if live mode is
  in scope, a deterministic mock HTTP result through the approved asynchronous
  boundary. **Verify:** named
  cases execute in `test-integration-tk-infra`; expected-red cases fail for
  missing tile functionality, not test setup. This root must start a real
  `tkmodl` child; a direct `HttpBackend.call` is insufficient.

### Phase 2 — build the stem tile and bounded bridge

- [ ] Define `tk_model_stem.c` and its `tk_model_stem.h` descriptor/ABI only
  after the approved wire and I/O contracts exist. Use one tile-specific
  `fd_stem.c` specialization with bounded scratch, a context-derived tile
  scratch alignment, explicit burst, lazy interval, and CNC HALT handling.
  **Verify:** unit identity/footprint tests and `topob.c` reservation agree.
- [ ] In `DURING_FRAG`, clear staging validity, validate link metadata and
  payload bounds, and copy a complete request into tile scratch. Do not
  validate business policy, reserve tokens, enqueue I/O, mutate counters,
  or publish here. **Verify:** an abandoned/invalid fragment leaves no
  observable work or state.
- [ ] In `AFTER_FRAG`, commit only the validated request: correlate it,
  apply the approved governance boundary, enqueue bounded work or produce a
  denial, and advance progress. Drive asynchronous completions from a
  separately justified, bounded callback path; reserve output credits for
  the maximum publications that path can make. **Verify:** last-request,
  backpressure, completion-order, and shutdown tests show no lost or double
  published result/audit record. A direct synchronous `Backend.call` in a
  stem callback fails this phase.
- [ ] Implement audit/replay capture and result publication at the approved
  boundaries. **Verify:** response, denial, timeout, and replay records share
  the expected request/run/capability identifiers and hash chain, and replay
  makes zero live-provider calls.

### Phase 3 — register and launch the tile

- [ ] Add the specialization to `build-lib/lib/{shims,topo_run,codec}.zig`,
  the Zig C ABI module/export and unit lane, `topob.c` scratch dispatch, and
  `tile_run.c` descriptor selection. **Verify:** `just build-tk` and
  `just test-unit-tk` have no missing/duplicate symbols, and descriptor and
  topology scratch values match.
- [ ] Register `tkmodl` with its approved link cardinalities and named CNC
  counters in `tile_registry.zig`; add `__stem-run` selection and the approved
  configuration handoff to the supervisor/child path. Configuration must
  validate presence, shape, and version before joining a provider or link.
  **Verify:** missing/malformed configuration exits nonzero with no model
  output or provider request.
- [ ] Start the approved runnable topology, preserving all explicit link
  properties. **Verify:** real processes join the intended workspaces, the
  gateway is identified as `tkmodl`, and the requester receives the exact
  correlated result while `tkaudt` records the boundary event.

### Phase 4 — cut over and close

- [ ] Switch only the approved caller path from an in-process model call to
  the tile request/result contract. Retain pure Zig validation/backend code
  where still owned and tested; remove only code made unreachable by this
  cutover. **Verify:** the selected product path does not bypass `tkmodl`.
- [ ] For an approved live-mode delivery, register the rewritten live smoke
  in `build-lib/lanes/system.zig`, correct the fixture-only system root as
  described above, and add a live process case if the corrected root still
  calls `runLiveModel` directly. **Verify:** at least one system case sends a
  request from a real `tkmodl` child to the local server and receives the
  correlated result; no live claim passes solely on fixture data.
- [ ] Run the unit lane, real-process integration lane, investment fixture
  integration lane, and relevant quality/security gates. For a live HTTP
  claim, run the rewritten live smoke and a corrected
  `test_investment_fixture_live.zig` path through the configured
  `just test-system-tk` gate with a real local server. **Verify:** report
  actual executed tests; skipped or unavailable tests are not passes.
- [ ] Update `tile-delivery-status.md` and the orchestration migrated-tile
  list only after process evidence exists. Record open provider/restart work
  accurately. Rename this file to `-done.md` only when all required checks
  pass and every decision gate is resolved.

## Risks and completion gate

- **The declared topology is one-way for model results.** No migration can
  claim a working agent/model round trip until the response contract is
  approved and tested.
- **Synchronous HTTP blocks stem progress.** A timeout bounds total waiting
  time but does not make the callback non-blocking; asynchronous transport
  and a bounded in-flight policy are required for live mode.
- **A model response may exceed the current link MTUs.** Decide the bounded
  inline/evidence-reference format before allocating scratch or adding links.
- **An audit link alone is not an audit guarantee.** Prove committed evidence,
  request/result attribution, and replay substitution through `tkaudt` and
  `tkrepl`; CNC counters are operational hints only.

Completion means an approved topology contract, passing registered unit and
real-process tests, no model-provider bypass, zero external effects in replay,
and a clearly stated live-provider status. Do not close this plan based on a
compiled shim or fixture-only tests.
