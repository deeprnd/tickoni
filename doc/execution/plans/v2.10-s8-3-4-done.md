# Story 8.3.4 — Test `just tests-all` from all sides

## Goal

Build a comprehensive test plan for `just tests-all` that covers all constituent
recipes, all execution paths, all failure modes, and all six platform/compiler
combinations. Everything runs locally. No CI. No remote calls except the tools
those commands themselves make.


DONT RUN ANYTHING IN PARALLEL!!!!

---

## What `just tests-all` does

```
just build-all              # build-fd && build-tk
just quality-format-check-all   # format-check-tk && format-check-fd
just quality-lint-check-tk      # zig build lint-check (tk only)
just quality-proto-check-all    # buf lint/check (proto files)
just security-check-all         # full security bundle
just security-engine-check-changes  # gitleaks diff scan
just test-all
```

**test-all chain:**

```
test-unit-all → test-unit-tk && test-unit-fd
test-integration-all → test-integration-tk && test-integration-fd (@true)
test-cov-all → test-cov-tk && test-cov-fd (@true)
test-system-all → test-system-tk && test-system-fd (@true)
test-e2e-all → test-e2e-fd && test-e2e-tk (@true)
```

**Dependency notes per platform:**

| Platform | test-unit-fd | test-unit-tk | build-fd | build-tk | notes |
|----------|-------------|-------------|----------|----------|-------|
| Linux x86 | real (hugepages) | real | GCC | Zig | full path |
| Linux ARM | real (hugepages) | real | GCC | Zig | full path |
| macOS x86 | @true (delegates to tk only) | real | Xcode clang | Zig | FD tests skip |
| macOS ARM | @true (delegates to tk only) | real | Xcode clang | Zig | FD tests skip |
| Windows x86 | @true (delegates to tk only) | real (cross-compile FD) | MSVC | Zig | FD tests skip |
| Windows ARM | @true (delegates to tk only) | real (cross-compile FD) | MSVC | Zig | FD tests skip |

this plan focuses solely on `just tests-all`. Key differences:

- **security-check-all**: was `@true` (documented IBT linker failure skip) in 8.3.3;

- **quality-lint-check-tk**: now explicitly separate from `quality-lint-check-fd`

  (which was the full lint check then)
- **quality-proto-check-all**: new recipe not in 8.3.3 (buf-based proto lint)
- **test-demo-tk**: new deterministic demo conformance suite — not in 8.3.3
  but important for cross-platform validation
- **test-cov-fd**: documented as `@true` with reduced parallelism note
- **test-system-tk**: documented as requiring LLM infra, with Windows-specific
  runner (`run_live_investment_demo_win.sh`)
- **test-e2e-fd**: documented as Firedancer integration-test target (not a

- **Platform coverage**: 8.3.3 did not address per-platform test routing;
  this plan adds Phase 3 with all six platform/compiler combinations
- **Badge wrapping**: `test-unit-all` now uses `run-badged-command.py` for

- **Clean-room run**: 8.3.3 included `setup-env` in the full run; this plan
  focuses on `tests-all` alone, with clean-room as a separate verification

## Risks and Mitigations

1. **Wall time.** `just tests-all` on Linux x86_64 may take 20-40 minutes
   (FD build + Zig build + all test lanes). macOS may take 25-40. Windows
   may take 45-60. Document baselines per platform.

2. **System tests require LLM models.** `test-system-tk` needs llama.cpp and
   a GGUF model downloaded from HuggingFace. This requires `hf` CLI auth and
   significant disk space. On CI, this may skip; locally, test with and
   without LLM infra to document both behaviors.

3. **Windows ARM is untested.** No existing CI tests `test-unit-tk-windows-arm`
   or `test-integration-tk-windows-arm`. The first run will likely fail.
   Consider starting with just `just build-all` on Windows ARM before
   adding the full test sequence.

4. **Disk space.** Full build + FD libs + Zig cache + test artifacts may
   exceed the 14GB runner disk on Windows. Monitor `du -sh` at key points.

5. **Clang dual-install on Linux.** `setup-env` installs both gcc and clang
   toolchains. This is heavy but necessary for dev parity.

6. **macOS security tools.** `SECURITY=off` path on macOS means some security
   sub-checks in `security-check-all` may be skipped or fail. Document which
   sub-checks are available on macOS vs Linux.

7. **hugepage dependency.** `test-unit-fd` requires hugepage setup on Linux.
   Without it, the fallback to normal pages is expected but may change test
   performance characteristics. Document the fallback path.

## Notes

- This plan does NOT implement anything; it documents the test plan so a
  developer can execute it task-by-task.
- `tests-all` is the full local handoff gate: build, quality, security, tests.
- Each phase builds on the previous one: individual recipes first, then
  aggregate, then platforms, then edge cases.
- When a lane is a placeholder (`@true`), document why and what's needed
  to make it real, rather than removing it from the justfile.

  path before running `tests-all`, since Zig cross-compiles FD libs for
  Windows before running TK tests.
