# Plan: Migrate Tickoni Orchestrator to Firedancer Pattern

## Objective

Replace the current Tickoni self-exec supervisor pattern with Firedancer's process model — fork + exec + pipe death detection — as-is. No improvements, no restart logic, no new features. Just make it work.

The Firedancer orchestrator is a simple process supervisor:
- Forks each tile as a child process
- Sets CPU affinity before fork
- Passes config via a memfd (shared memory file descriptor)
- Polls pipes for tile exit
- Any tile death → kills the entire group

Tickoni's current pattern:
- Writes LaunchSpec files + topology.spec to disk
- Self-exec the supervisor binary with `__tile-run <file>`
- Child reads LaunchSpec, rebuilds topology, joins workspace
- Supervisor monitors via cnc heartbeats + SIGTERM/SIGKILL
- Child waits for file-based readiness marker

## Key Design Decisions (as-is, no improvements)

1. **Keep normal-page shmem** — no hugetlbfs. Tickoni already uses `FD_SHMEM_NORMAL_PAGE_SZ` with `wkspNewNamed`. This works fine.
2. **Keep Tickoni topology build** — `topo_build.build()` in Zig. Identical inputs → identical offsets. No change.
3. **Keep Tickoni tile binaries** — no Firedancer tiles. Tiles self-exec the supervisor binary and call `tile_process.run()`.
4. **Replace file-based handoff with memfd** — Firedancer passes the full config via `memfd_create()` + `--config-fd`. This eliminates file I/O races (LaunchSpec + readiness marker + topology.spec).
5. **Replace cnc heartbeat monitoring with pipe-based death detection** — Firedancer's `poll()` on per-tile pipes. Simpler, atomic, no heartbeat logic needed.
6. **Group-kill on tile death** — same as Firedancer. If any tile dies, kill everything. No restart logic yet.

## What to Reuse from Firedancer (src/app/shared/commands/run/run.c)

1. **`execve_tile()` pattern** (line 231-284): fork + execve with CPU affinity + pipe IPC
2. **Pipe-based death detection** (line 393-399, 403-406): per-tile pipe, read grandchild PID from pipe
3. **Group-kill loop** (line 494-538): poll all pipes + any exit → terminate everything
4. **Config via memfd** (line 322-323): `fd_config_to_memfd()` → `--config-fd` to each tile

## What to Replace with Tickoni

1. **Config system** — Firedancer requires TOML files, network config, Solana settings. We use Tickoni topology spec (Zig struct) → serialize to memfd.
2. **Workspace creation** — Firedancer uses `fd_topo_create_workspace()` + hugetlbfs. We use `wkspNewNamed()` + normal pages. Same shmem path format (`tickoni_<name>.wksp`).
3. **Topology build** — Firedancer uses `fd_topo_create_workspace()` + hugetlbfs. We use `wkspNewNamed()` + normal pages. Same shmem path format (`tickoni_<name>.wksp`).
4. **Topology build** — Firedancer uses `fd_topo_create_workspace()` + hugetlbfs. We use `wkspNewNamed()` + normal pages.
5. **Tile definitions** — Firedancer tiles (net, quic, dedup, pack, execle, poh, etc.) are Solana-specific. We have Tickoni tiles (tkings, tkrnorm, tkdedu, etc.). Same binary, different launch args.

## Migration Steps

### Step 1: Serialize Tickoni topology to memfd (C shim)

Create a C shim function `tickoni_topology_to_memfd()` that:
- Takes the Tickoni topology spec (TopoSpec struct)
- Creates a memfd via `memfd_create("tickoni-topo", 0)`
- Writes the TopoSpec bytes to the memfd
- Returns the memfd fd

This replaces Firedancer's `fd_config_to_memfd()` which serializes a TOML config.

### Step 2: Replace LaunchSpec file writes with memfd-passed topology

Current: supervisor writes `topology.spec` + `tile_{idx}.spec` (LaunchSpec) to disk.

New: supervisor creates the topology memfd once (shared by all tiles), writes per-tile LaunchSpec to disk (only tile_idx, tile_id, crash_after_heartbeats — no workspace path needed, that comes from the topo_build app_name constant).

Actually, simpler: write all topology data into the memfd, and per-tile data into the LaunchSpec. The LaunchSpec no longer needs workspace path (it's computed from app_name + workspace_name via topo_build.concreteWorkspaceName).

### Step 3: Replace self-exec with pipe-based spawn

Current: supervisor spawns `tickoni-supervisor --cmd __tile-run tile_{idx}.spec` via `std.process.Child`.

New: supervisor forks + execve the tile binary directly:
```c
// Same binary (tickoni-supervisor), different subcommand
// Instead of __tile-run, use a new subcommand:
// tile_run <tile_idx> --topo-memfd <fd>
```

The tile process:
1. Reads tile_idx from argv
2. Reads topology from the memfd (passed as fd)
3. Rebuilds topology via `topo_build.build()`
4. Joins workspace via `fd_topo_join_workspace()` (same as before)
5. Calls `tile_process.run()` (same as before)

### Step 4: Replace cnc heartbeat monitoring with pipe death detection

Current: supervisor polls cnc heartbeats every 20ms, classifies stale tiles, sends SIGTERM/SIGKILL.

New: supervisor polls per-tile pipes. When a pipe closes → tile died. Immediately SIGKILL all tiles + self.

No heartbeat logic. No stale detection. Just: pipe closed → group death.

### Step 5: Replace readiness marker with pipe IPC

Current: child waits for file-based readiness marker (`{run_dir}/.normal/{name}.ready`).

New: pipe IPC replaces this. Parent writes the workspace gaddr to the pipe after workspace is ready. Child reads it and proceeds. No file I/O.

### Step 6: Keep Tickoni tile code unchanged

Tile code (`tile_process.zig`, `tk_tile_privileged_init`, `tk_tile_run`) calls into Firedancer's `fd_topo_run_tile()` via `c_abi.topo_run`. This is unchanged — the tile still:
- Rebuilds topology
- Joins workspace
- Joins cnc
- Sets BOOT→RUN
- Runs work
- Heartbeats
- Responds to HALT

The only change is how the tile gets launched (memfd + pipe vs. file + readiness marker), not what the tile does.

## Implementation Order

1. **C shim: topology memfd** — `tickoni_topology_to_memfd()`
2. **Supervisor: memfd creation** — create topo memfd, pass to tiles
3. **Tile: memfd read** — read topology from memfd instead of file
4. **Supervisor: pipe spawn** — fork + exec + pipe IPC instead of std.process.Child
5. **Supervisor: pipe death detection** — poll pipes instead of cnc heartbeats
6. **Tile: pipe-based workspace join** — read workspace gaddr from pipe, join via gaddr
7. **Cleanup**: remove LaunchSpec file writes, readiness marker, cnc heartbeat monitoring
8. **Test**: run integration tests, verify no SIGABRT

## Verification

- Integration tests pass (no SIGABRT in children)
- `just test-integration-tk` passes
- `just test-integration-all` passes
- Child tile processes survive supervisor restart (workspace persists)
- Multiple test binaries can run in parallel (unique workspace names)

## Risks

1. **Pipe buffer overflow** — Firedancer pipes carry 8-byte PIDs. Tickoni needs to carry workspace gaddr + cnc gaddr. Ensure pipe buffer is large enough.
2. **Memfd ownership** — if supervisor dies before tiles read the memfd, tiles will see EBADF. Acceptable: same as current "supervisor dies → children die" behavior.
3. **Non-Linux builds** — `memfd_create()` and `pipe2()` are Linux-only. Firedancer already restricts `fd_topo_run_tile` to Linux. Tickoni can do the same.
4. **Seccomp sandbox** — Firedancer applies seccomp to tile processes. Tickoni currently does not. For "as-is" migration, skip seccomp. Add it later if needed.

## Out of Scope (for now)

- Tile restart on death
- Individual tile crash isolation (no restart)
- Seccomp/landlock sandboxing
- Memory accounting
- Tile-level metrics collection
- Config file generation (TOML)
- Hugetlbfs support (we keep normal pages)
- Firedancer Solana tile code (not relevant)
- PID namespace (not needed for "as-is" migration)

## TODO: Future Improvements

These are tracked for later phases, not included in the "as-is" migration.

### Tile Retry (v2.NN — after orchestrator migration)

**Problem:** Firedancer's group-kill model means one failing tile kills the entire pipeline. For Tickoni's financial event runtime, a single tile crash should not stop processing for healthy tiles.

**Approach:** Modify the pipe death detection loop to support per-tile restart instead of group-kill.

**Steps:**
1. Track tile PID and exit status per-tile (already stored in `child_pids[]` + `child_idxs[]` arrays in Firedancer's `main_pid_namespace`)
2. When `poll()` returns on a tile pipe, log the exit code/signal but do NOT terminate the group
3. If the tile is marked as `allow_shutdown` (existing `fd_topo_tile_t::allow_shutdown` field), exit normally — this is expected behavior
4. If the tile crashed unexpectedly (non-zero exit, signal), increment a crash counter for that tile
5. Optionally apply a backoff delay (e.g., 100ms → 200ms → 400ms → 800ms, cap at 1s) before restart
6. Re-spawn the tile: `fork()` + `execve()` with the same memfd + pipe as before
7. Re-use the existing pipe read-end for the new tile (parent must re-register it in the poll set)
8. If crash counter exceeds a threshold (e.g., 5 crashes in 60s), THEN kill the entire group (unrecoverable tile)

**What changes:**
- The poll loop adds an `allow_restart` field per tile
- On pipe close: read exit status, check if `allow_restart`, optionally delay, then `fork()` + `execve()` again
- Pipe read-end is reusable: after reaping the old child, the read-end fd stays open for the new child's pipe write-end
- Parent-side child array grows to track restart count per tile

**What stays the same:**
- Pipe IPC mechanism (same pipe + fork + execve pattern)
- Memfd topology handoff (same memfd, reused across restarts)
- Tile binary (same `tickoni-supervisor --cmd tile_run` subcommand)
- Group-kill on unrecoverable failure (exceeds crash threshold)

### Tile Process Isolation (v2.NN — after retry)

**Problem:** Even with retry, a crashed tile's shmem pointers (dcache, mcache, fseq, cnc) are stale in the shared workspace. When the tile restarts and rebuilds the topology, it joins the same workspace but the objects it uses may have been in an inconsistent state when it crashed.

**Approach:** Give each tile its own isolated workspace slice within the shared workspace, with a clean initialization path on restart.

**Steps:**
1. Use `fd_wksp_alloc()` to give each tile a private memory region within the shared workspace for its per-tile state (scratch, private data structures)
2. On tile restart, the new process allocates from this private region and zero-fills it — old state is discarded, not reused
3. Link objects (mcache/dcache) stay shared and persistent across restarts (they're not tile-private)
4. Tile-private state (tile's internal buffers, caches, per-tile counters) is allocated fresh on every start
5. Add a `tile_reset()` function that the tile calls before its first work iteration — clears private state, reinitializes tile-local data structures
6. Audit callback (`tk_tile_run`) ensures no tile-private state leaks across restarts

**What changes:**
- Topology build allocates per-tile private slices in the workspace
- Tile private state path: `wksp_alloc()` → `memset(0)` → use
- Restart path: same alloc + memset + reset
- Shared objects (mcache/dcache) never freed or re-created — they survive tile restarts

**What stays the same:**
- Shared workspace (one `tickoni_<name>.wksp` file)
- Link objects (mcache/dcache) remain shared, persistent, unchanged across restarts
- Tile restart mechanism (same fork + execve + pipe IPC)

### Seccomp/Sandboxing (v2.NN — optional hardening)

**Problem:** Tile processes currently run with full system access. Firedancer's `fd_topo_run_tile()` supports seccomp sandboxing that restricts which syscalls a tile can make.

**Approach:** Adopt Firedancer's sandbox pattern for tickoni tile processes.

**Steps:**
1. Add `populate_allowed_seccomp()` callback per tile (list of allowed syscalls)
2. Add `populate_allowed_fds()` callback per tile (list of allowed file descriptors)
3. Tile processes call `fd_sandbox_enter()` before running their work loop
4. Start with a permissive sandbox (allow only essential syscalls: read, write, mmap, munmap, futex, poll, nanosleep, exit, brk, mmap)
5. Gradually restrict syscalls per tile based on actual usage (observe tile's syscalls via `strace` or seccomp audit mode)
6. Add landlock for filesystem access (read-only workspace, read-only topology spec, no network unless the tile needs it)

**What changes:**
- Each tile gets a seccomp filter at boot time
- Tile processes enter sandbox before calling their work loop
- Sandbox is permissive initially, tightened over time

**What stays the same:**
- Process model (fork + execve + pipe IPC)
- Tile lifecycle (BOOT→RUN→halt)
- Shared workspace (sanchp persists, sandboxed tiles can read/write it)

### PID Namespace (v2.NN — optional isolation)

**Problem:** Tile processes are direct children of the supervisor. If the supervisor dies, all children die (via SIGKILL in `deinit()`). This is correct for Firedancer (PID namespace makes the supervisor the init process), but Tickoni's supervisor is more like a process manager that should survive individual tile crashes (with restart).

**Approach:** Use Firedancer's PID namespace pattern so the supervisor acts as the init process for all tile children.

**Steps:**
1. Supervisor calls `clone(main_pid_namespace, stack, CLONE_NEWPID, &args)` to create a PID namespace
2. Inside the PID namespace, the supervisor forks tiles as direct children (they see PID 1 as the supervisor within the namespace)
3. If the supervisor (init of PID namespace) dies, the kernel SIGKILLs all tile children automatically
4. If a tile dies, the supervisor's poll loop detects it and restarts it (no group-kill)
5. Parent process (outside PID namespace) only talks to the supervisor via the main pipe (same as Firedancer)

**What changes:**
- Supervisor uses `clone(CLONE_NEWPID)` instead of direct fork
- Tiles see the supervisor as PID 1 within their namespace
- Kernel handles group-kill when supervisor dies

**What stays the same:**
- Pipe IPC (same mechanism, works inside PID namespace)
- Memfd topology handoff (memfds are namespace-agnostic)
- Tile restart logic (supervisor restarts tiles within the namespace)
