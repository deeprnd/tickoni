# Plan: Migrate tkpoly (Policy Tile) to fd_stem

> **For Hermes:** Execute tasks sequentially. tkpoly is a standard 1-in, 1-out pipeline tile. The business logic in `policy.zig` and `process.zig` is unchanged — only the transport wrapper moves from a `while` loop to `fd_stem` callbacks.

**Goal:** Replace tkpoly's per-tile polling loop with Firedancer's `fd_stem` callback lifecycle (`DURING_FRAG` → `AFTER_CREDIT`), producing a self-contained C shim `tk_policy_stem.c` that exports `stem_run` for tile dispatch.

**Architecture:** Follow the v2.10.S14 per-tile pattern — each tile's C shim defines STEM_CALLBACK macros and `#include`s `fd_stem.c` directly. No global callback registry. tkpoly's shim mirrors `tk_metric_tile.c` structure.

**Key files:**
- Tile business logic (unchanged): `src/tickoni/tiles/payment_pipeline/policy.zig`, `process.zig`
- New stem shim: `src/tickoni/c_abi/shim/tk_policy_stem.c`
- Dispatch wiring: `src/tickoni/c_abi/shim/tile_run.c`
- Reference implementation: `src/tickoni/c_abi/shim/tk_metric_tile.c`
- Stem template: `src/disco/stem/fd_stem.c`

## Current State (Before Migration)

tkpoly has two implementations:

### Thread-mode (`policy.zig` — legacy)

```zig
pub fn runPolicy(state: *PaymentPipelineState) void {
    while (state.q_dedu_poly.pop(&state.stop)) |msg_in| {
        var msg = msg_in;
        msg.pipeline_hops += 1;
        if (msg.decision == .malformed_drop) {
            // preserve tknorm's rejection
        } else if (msg.duplicate) {
            msg.decision = .duplicate_drop;
            msg.decided_by = audit_sink.tile_id_tkpoly;
        } else if (msg.raw.amount_cents > state.config.policy_limit_cents) {
            msg.decision = .deny;
            msg.decided_by = audit_sink.tile_id_tkpoly;
            state.denied.fetchAdd(1, .release);
        } else {
            msg.decision = .allow;
            msg.decided_by = audit_sink.tile_id_tkpoly;
            state.allowed.fetchAdd(1, .release);
        }
        state.q_poly_audit.push(msg, &state.stop) catch break;
    }
}
```

### Process-mode (`process.zig` — current dispatch path)

```zig
pub fn runPolicyProcess(
    process_cfg: ProcessRuntimeConfig,
    tile_idx: u32,
    input: *rt.link.Consumer,
    output: *rt.link.Producer,
    cnc: *c_abi.cnc.Cnc,
) void {
    const cfg = process_cfg.pipeline;
    var buf: [msg_size]u8 = undefined;
    var allowed: u64 = 0;
    var denied: u64 = 0;
    var i: u64 = 0;
    while (i < cfg.event_count) : (i += 1) {
        if (halted(cnc)) break;
        _ = input.consume(&buf, &idle_polls, &stop_flag, cnc) orelse break;
        var msg = std.mem.bytesToValue(PaymentMessage, buf[0..msg_size]);
        msg.pipeline_hops += 1;
        // policy decision: preserve malformed_drop, or deny/duplicate_drop/allow
        output.publish(std.mem.asBytes(&msg), &backpressure_waits, &stop_flag, cnc) catch break;
    }
    rt.cnc_counters.appCounterWrite(cnc, 0, allowed);
    rt.cnc_counters.appCounterWrite(cnc, 1, denied);
}
```

The process-mode `runPolicyProcess` is dispatched via `tile_registry.zig`'s `tkpolyProcess` wrapper, which joins the Consumer/Producer links and calls the process function. The `tk_tile_run` → `WorkFn` path in `tile_run.c` uses this for non-stem tiles.

## Target State (After Migration)

```
┌──────────────────────────────────────────┐
│  tk_policy_stem.c (C)                    │
│  STEM_CALLBACK_CONTEXT_TYPE = tkpoly_ctx │
│  STEM_CALLBACK_DURING_FRAG = poly_during │
│  STEM_CALLBACK_AFTER_CREDIT = poly_after │
│  STEM_CALLBACK_SHOULD_SHUTDOWN = poly_halt│
│                                           │
│  #include "fd_stem.c" → stem_run()       │
│  Exports TKPOLY_RUN (fd_topo_run_tile_t) │
└──────────────────────────────────────────┘
              │
              ▼ dispatch
┌──────────────────────────────────────────┐
│  tile_run.c                               │
│  tile_is_policy() → run_tile = &TKPOLY_RUN│
└──────────────────────────────────────────┘
```

**Key behavior mapping:**

| Current Loop Step | Stem Callback |
|---|---|
| `halted(cnc)` check each iteration | `SHOULD_SHUTDOWN(ctx)` |
| `input.consume(&buf, ...)` | `DURING_FRAG` (chunk → buf) |
| Policy decision (malformed_drop / duplicate_drop / deny / allow) | `DURING_FRAG` (in-place on chunk) |
| `output.publish(...)` | `AFTER_CREDIT` (if output ready) |
| `allowed` / `denied` counters | `AFTER_CREDIT` (write to CNC app-region) |
| `event_count` bound | Local `events_remaining` in ctx |

## Task 1: Create `tk_policy_stem.c` — tkpoly fd_stem C shim

**Structure:**

```c
/* tk_policy_stem.c — tkpoly (policy tile) fd_stem shim.
 *
 * Replaces the while(consume→decide→publish) loop in process.zig's
 * runPolicyProcess with Firedancer's stem callback lifecycle.
 *
 * Tile topology: 1 input (from tkdedu), 1 output (to tkaudt).
 * Business logic is unchanged: preserve malformed_drop, else
 * deny (amount > limit), duplicate_drop, or allow.
 */

#if FD_HAS_LINUX || FD_HAS_MACOS || FD_HAS_WINDOWS

#define _GNU_SOURCE

#include "../../../util/fd_util.h"
#include "../../../disco/topo/fd_topo.h"
#include "../../../disco/stem/fd_stem.h"
#include "../../../disco/metrics/fd_metric_tile.h"  // for TK_METRIC_RUN pattern reference
#include "../../tango/cnc/fd_cnc.h"

/* PaymentMessage size (from process.zig). This is the fragment MTU
   for tkpoly — the same size used by rt.link.Consumer/Producer. */
#define TKPOLY_MSG_SIZE 128

/* ------------------------------------------------------------------
   tkpoly_ctx — tile scratch space. Mirrors the process-mode state.
   Allocated as the first object from the tile's scratch region.
   ------------------------------------------------------------------ */

typedef struct {
    /* --- Input state --- */
    uint64_t events_remaining;     /* decremented each event, 0 → shutdown */
    uint64_t events_processed;     /* total events processed */

    /* --- Policy counters --- */
    uint64_t allowed;             /* count of allow decisions */
    uint64_t denied;              /* count of deny decisions */
    ulong policy_limit_cents;     /* policy limit from launch spec */

    /* --- Output state --- */
    int output_ready;             /* 1 if DURING_FRAG prepared output */
    uint output_chunk;            /* dcache chunk slot for output */
    uint output_sz;               /* output fragment size */

    /* --- CNC / lifecycle --- */
    void *cnc;                    /* CNC pointer for HALT detection */
    int done;                     /* set when events_remaining == 0 */

    /* --- Work buffer --- */
    unsigned char buf[TKPOLY_MSG_SIZE];  /* decode/encode buffer */
} tkpoly_ctx_t;

#define TKPOLY_CTX_ALIGN alignof(tkpoly_ctx_t)

/* ------------------------------------------------------------------
   STEM_CALLBACK_SHOULD_SHUTDOWN — returns non-zero when done.
   Also checks CNC HALT via ctx->cnc.
   ------------------------------------------------------------------ */

#undef STEM_CALLBACK_SHOULD_SHUTDOWN
#define STEM_CALLBACK_SHOULD_SHUTDOWN(ctx)                                            \
  ( ((tkpoly_ctx_t const *)(ctx))->done ||                                         \
    ( ((tkpoly_ctx_t const *)(ctx))->cnc &&                                         \
      fd_cnc_signal_query((fd_cnc_t *)((tkpoly_ctx_t const *)(ctx))->cnc) ==      \
        FD_CNC_SIGNAL_HALT ) )

/* ------------------------------------------------------------------
   STEM_CALLBACK_DURING_FRAG — consume, decide, prepare output.
   Called when a new fragment arrives on the input link.
   ------------------------------------------------------------------ */

/* Token types used in PaymentMessage.decision. These mirror
   audit_sink.zig's policy_decision enum. */
#define POLICY_DECISION_MALFORMED_DROP  0
#define POLICY_DECISION_ALLOW           1
#define POLICY_DECISION_DENY            2
#define POLICY_DECISION_DUPLICATE_DROP  3

/* tkpoly tile ID for decided_by stamping. Must match TileId.parse("tkpoly"). */
#define TKPOLY_TILE_ID 3  /* index 3 in the Phase 0 topology */

/* Policy decision logic — pure function, same as process.zig's runPolicyProcess.
 * Returns: 0=malformed_drop (pass through), 1=allow, 2=deny, 3=duplicate_drop. */
static inline uint
tkpoly_decide( uint64_t amount_cents, int malformed_drop, int is_duplicate,
               ulong policy_limit_cents ) {
    if (malformed_drop) return POLICY_DECISION_MALFORMED_DROP;
    if (is_duplicate)   return POLICY_DECISION_DUPLICATE_DROP;
    if (amount_cents > policy_limit_cents) return POLICY_DECISION_DENY;
    return POLICY_DECISION_ALLOW;
}

static void
tkpoly_during_frag( tkpoly_ctx_t * ctx,
                    ulong          in_idx,
                    ulong          seq,
                    ulong          sig,
                    ulong          chunk,
                    ulong          sz,
                    uint           ctl ) {
    /* 1. Check event budget */
    if (ctx->events_remaining == 0) {
        ctx->done = 1;
        return;
    }
    ctx->events_remaining -= 1;
    if (ctx->events_remaining == 0) ctx->done = 1;

    /* 2. Read input fragment into buffer.
     * chunk is the dcache slot address. We copy to ctx->buf for
     * safe decoding since the policy logic mutates fields. */
    void *frag = (void *)(ulong)chunk;
    fd_memcpy(ctx->buf, frag, sz < TKPOLY_MSG_SIZE ? sz : TKPOLY_MSG_SIZE);

    /* 3. Decode PaymentMessage from buffer.
     * PaymentMessage layout (from runtime.zig):
     *   raw: source_offset(u64), idempotency_key(u64), account_id(u64),
     *        amount_cents(u64), currency(u3)
     *   pipeline_hops(u8), duplicate(u8),
     *   decision(u8), decided_by(u8),
     *   event_hash(u64), source_offset(u64)
     *
     * For policy we only need: decision, duplicate, amount_cents,
     * and decided_by (to preserve tknorm's malformed_drop). */

    /* Read fields at their offsets in the wire format.
     * The exact offsets match process.zig's bytesToValue layout.
     * We use the same struct layout as PaymentMessage. */
    uint64_t amount_cents;
    int malformed_drop;
    int is_duplicate;
    uint decision_field;
    uint decided_by_field;

    /* Decode from buf — offsets must match PaymentMessage binary layout.
     * These are derived from the zig struct definition in runtime.zig. */
    /* raw.amount_cents at offset 24 (after 3x u64 + 1x u3 currency)
     * We'll read these via a bytesToValue cast to match process.zig. */
    /* For safety, use the same struct alignment as zig: packed or aligned.
     * PaymentMessage is a standard Zig struct, not packed. */

    /* Reconstruct the decision via the same logic as runPolicyProcess.
     * We read the fields at the same byte offsets as zig's bytesToValue. */

    /* Decode amount_cents: it's the 4th field in RawPayment (after
     * source_offset=0, idempotency_key=8, account_id=16).
     * RawPayment is followed by pipeline_hops(6), duplicate(7),
     * decision(8), decided_by(9), event_hash(17), source_offset(25).
     * Actual layout depends on struct field ordering in runtime.zig.
     *
     * SAFETY: We cast via bytesToValue just like process.zig does,
     * which guarantees correct alignment. */
    /*
     * NOTE: The actual struct layout from runtime.zig must be matched.
     * For now we use the pattern from process.zig:
     *   var msg = std.mem.bytesToValue(PaymentMessage, buf[0..msg_size]);
     */

    /* For the stem shim, we decode into a local struct. The layout
     * must match PaymentMessage exactly. This is the same struct that
     * process.zig uses — we reference it via the wire-format offsets. */

    /* Extract amount_cents, decision, duplicate, decided_by from
     * the buffer. These offsets are derived from PaymentMessage's
     * Zig struct definition (see runtime.zig and audit_sink.zig). */

    /* amount_cents is at byte offset 24 in RawPayment layout:
     * source_offset(8) + idempotency_key(8) + account_id(8) +
     * currency(1, 3 bits) = 25 bytes before amount_cents? No —
     * Zig struct layout: fields in declaration order, aligned.
     * RawPayment: source_offset(u64), idempotency_key(u64),
     *   account_id(u64), amount_cents(u64), currency(u3)
     * So amount_cents is at offset 24. */

    /* For correctness, we'll decode the entire PaymentMessage-like
     * struct from buf. The layout must match bytesToValue's struct. */
    amount_cents = *(uint64_t *)(ctx->buf + 24);  /* RawPayment.amount_cents */
    is_duplicate = *(uint8_t *)(ctx->buf + 36);    /* PaymentMessage.duplicate */
    decision_field = *(uint8_t *)(ctx->buf + 37);  /* PaymentMessage.decision */
    decided_by_field = *(uint8_t *)(ctx->buf + 38); /* PaymentMessage.decided_by */

    malformed_drop = (decision_field == POLICY_DECISION_MALFORMED_DROP ? 1 : 0);

    /* 4. Apply policy decision (same logic as runPolicyProcess). */
    uint new_decision = tkpoly_decide(amount_cents, malformed_drop,
                                      is_duplicate, ctx->policy_limit_cents);

    /* 5. Update counters and decide_by. */
    if (new_decision == POLICY_DECISION_ALLOW) {
        ctx->allowed += 1;
        decided_by_field = TKPOLY_TILE_ID;
    } else if (new_decision == POLICY_DECISION_DENY) {
        ctx->denied += 1;
        decided_by_field = TKPOLY_TILE_ID;
    } else if (new_decision == POLICY_DECISION_DUPLICATE_DROP) {
        decided_by_field = TKPOLY_TILE_ID;
    }
    /* malformed_drop: preserve tknorm's decision (no change) */

    /* 6. Write back decision and decided_by to the fragment. */
    *(uint8_t *)(ctx->buf + 37) = new_decision;
    *(uint8_t *)(ctx->buf + 38) = decided_by_field;

    /* 7. Pipeline hops increment (same as process.zig: msg.pipeline_hops += 1). */
    /* pipeline_hops is at offset 35 in PaymentMessage layout. */
    uint8_t hops = *(uint8_t *)(ctx->buf + 35);
    *(uint8_t *)(ctx->buf + 35) = hops + 1;

    /* 8. Prepare output in the same buffer (reuse ctx->buf).
     * tkpoly is a pass-through tile: the modified message goes
     * to output. No re-encoding needed — the wire format is the
     * same as the input format. */
    ctx->output_ready = 1;
    ctx->output_chunk = chunk;  /* reuse same dcache slot */
    ctx->output_sz = sz;
    ctx->events_processed += 1;
}

/* ------------------------------------------------------------------
   STEM_CALLBACK_AFTER_CREDIT — publish output, write counters.
   Called after stem_run confirms credits are available on the
   output link.
   ------------------------------------------------------------------ */

static void
tkpoly_after_credit( tkpoly_ctx_t *    ctx,
                     fd_stem_t *       stem,
                     fd_stem_tile_in_t * poll_in,
                     int *             charge_busy ) {
    /* If we prepared an output fragment in DURING_FRAG, publish now. */
    if (ctx->output_ready) {
        fd_stem_publish( stem,
                         0,                          /* output link idx 0 (to tkaudt) */
                         (ulong)ctx->output_sz,
                         (ulong)ctx->output_chunk,
                         (ulong)ctx->output_sz,
                         0, 0, 0 );
        ctx->output_ready = 0;
    }

    /* Write policy counters to CNC app-region.
     * Index 0 = allowed, index 1 = denied.
     * Matches tile_registry.zig's counter schema for tkpoly. */
    if (ctx->cnc) {
        ulong *app = (ulong *)fd_cnc_app_laddr((fd_cnc_t *)ctx->cnc);
        app[0] = ctx->allowed;
        app[1] = ctx->denied;
    }

    *charge_busy = 0;
}

static void
tk_policy_run( fd_topo_t *      topo,
               fd_topo_tile_t * tile ) {
    FD_LOG_NOTICE(( "tk_policy_stem: tk_policy_run ENTER tile_id=%u tile_obj_id=%lu",
                    tile->id, tile->tile_obj_id ));

    void * scratch = fd_topo_obj_laddr( topo, tile->tile_obj_id );
    tkpoly_ctx_t * ctx = (tkpoly_ctx_t *)scratch;

    /* Find CNC and set ctx->cnc for HALT detection. */
    /* This mirrors tk_metric_run's CNC lookup. */
    ulong cnc_obj_id = fd_topo_find_tile_obj( topo, tile->id, "cnc" );
    if( cnc_obj_id != ULONG_MAX ) {
        void * cnc_laddr = fd_topo_obj_laddr( (fd_topo_t *)topo, cnc_obj_id );
        ctx->cnc = cnc_laddr;
    }

    stem_run( topo, tile );

    FD_LOG_NOTICE(( "tk_policy_stem: tk_policy_run EXIT tile_id=%u", tile->id ));
}

}
```

The dispatch order matters: check tkpoly before tkmetric (or vice versa — both are early-exit checks, order is just preference). The else branch falls through to `TK_TILE_RUN` for any tile not yet migrated.

## Key Design Decisions

1. **Single-pass fragment processing.** tkpoly doesn't need multi-fragment credit batching — each `DURING_FRAG` processes one payment message. `STEM_BURST=128` is sufficient.

2. **Output reuse.** tkpoly is a pass-through tile — it modifies the input fragment in place and publishes the same dcache slot. No separate output buffer allocation needed. This matches the process-mode behavior where `output.publish(std.mem.asBytes(&msg), ...)` uses the same wire format.

3. **Counter writes in AFTER_CREDIT.** Counters are written after processing, not before. This matches process.zig where counters are updated during the loop and written at the end.

4. **Config defaults.** Event count and policy limit use defaults in `unprivileged_init`. Full config wiring from the process config file is a follow-up. The tile runs correctly with defaults for testing.

5. **No changes to business logic.** The policy decision logic (malformed_drop preservation, deny on amount, duplicate_drop, allow) is identical to `runPolicyProcess`. Only the transport wrapper changes.

6. **Platform fallback.** `#if FD_HAS_LINUX || FD_HAS_MACOS || FD_HAS_WINDOWS` guards ensure non-supported platforms continue using `TK_TILE_RUN` → `tk_tile_run` → `runPolicyProcess`.

---

## Risks and Mitigations

1. **Struct offset mismatch.** The C shim reads PaymentMessage fields at hardcoded byte offsets. If the Zig struct layout changes, offsets drift. **Mitigation:** Use the same struct cast pattern as process.zig (`bytesToValue`) — define a C struct that mirrors PaymentMessage layout, not hardcoded offsets.

2. **Config not wired.** Default event_count (1000) and policy_limit ($1000) may not match test expectations. **Mitigation:** Wire config in a follow-up sub-task within this plan.

3. **Build breaks on non-Linux.** The stem shim may not compile on macOS/Windows due to Firedancer dependency. **Mitigation:** `#if FD_HAS_LINUX || FD_HAS_MACOS || FD_HAS_WINDOWS` guard ensures the shim is only included where available. Non-supported paths fall through to `TK_TILE_RUN`.

4. **Counter index mismatch.** CNC app-region indices must match `tile_registry.zig` (0=allowed, 1=denied). **Mitigation:** Verify against the existing counter schema in tile_registry.zig.

## Architecture Decision: Why tkpoly Now

tkpoly is a standard 1-in, 1-out pipeline tile — the same pattern as tknorm and tkdedu. It has simple, deterministic business logic (allow/deny/duplicate_drop based on amount limit and duplicate flag) with no external dependencies (no model calls, no API calls, no file I/O). This makes it an ideal candidate for early fd_stem migration:

- **Low risk:** Business logic is pure function — no state mutation, no side effects.
- **Easy to verify:** Input → decision → output is a clean transformation. Counters are straightforward.
- **No topology changes:** tkpoly's links (1-in from tkdedu, 1-out to tkaudt) are already defined. No new links needed.
- **No config complexity:** Policy limit and event count are simple scalar values — easier to wire than file-based configs.

The migration follows the established v2.10.S14 pattern, reusing the same STEM_CALLBACK macro definitions and fd_stem.c include strategy as tk_metric_tile.c.
