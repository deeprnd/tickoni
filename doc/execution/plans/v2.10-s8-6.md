# Story 8.3.3 — Consolidate contrib/test into a pure test-script directory with a test orchestrator

## Context

`contrib/test/` currently holds 13 files (excluding `__pycache__/`) of mixed responsibility:

- **Test runners** — actual test execution scripts
- **Infrastructure orchestrators** — start/stop external servers (llama.cpp), build toolchains
- **Validation checkers** — verify justfile/CI contract surface
- **Coverage configs** — JSON threshold files
- **One-off / stale scripts** — never invoked by any justfile recipe or CI workflow
- **Data files** — commit SHAs, shared shell helpers

The user's stated goals:

1. `contrib/test/` should **only** have test scripts.
2. Mark files not used by any justfile/CI workflow for removal.
3. Mark one-off scripts like `test_pip_strategy.py` for removal.
4. `run_system_model_tests.sh` must not run the llama.cpp server — each script should do one clearly defined task.
5. The solution should follow the pattern of `contrib/setup/orchestrator.py` and `contrib/build/orchestrator.py` — a Python orchestrator that delegates to focused strategies, with test scripts calling the orchestrator for infrastructure setup.

## Problem: run_system_model_tests.sh does three jobs

Current flow in `run_system_model_tests.sh`:

```
Phase 1: Call orchestrator.py llm-server (setup + build)
Phase 2: Start llama-server (background process)
Phase 3: Wait for health endpoint (poll loop)
Phase 4: Run Zig system-test (zig build system-test)
Phase 5: Kill server (EXIT trap)
```

The same script also does **setup** (orchestrator call), **infrastructure** (start/wait/kill server), and **test execution** (zig build system-test). This violates the principle: each script should do one clearly defined task.

Compare to the working pattern from `contrib/setup/orchestrator.py` + `contrib/build/orchestrator.py`:

- `orchestrator.py` is a facade that delegates to install strategies (e.g. `llama_cpp_build.py`, `hf_model.py`)
- Each strategy has a single responsibility: clone+build llama.cpp, or download model
- The justfile recipes call orchestrator for setup, then call a focused test script

We need the same split for tests.

### Step 1: Create the test orchestrator

Create `contrib/test/orchestrator.py` following the same pattern as `contrib/setup/orchestrator.py`:

```
contrib/test/orchestrator.py      — Facade: single API for test infrastructure
contrib/test/infra/               — Strategy directory
contrib/test/infra/llama_server.py  — Start/stop llama.cpp server, health-wait
contrib/test/infra/zig_build.py     — Run zig build for test targets
contrib/test/infra/coverage.py      — Run coverage.sh logic
```

The orchestrator provides commands:

```bash
python3 contrib/test/orchestrator.py llm-server-start     # start server, wait for health, print PID
python3 contrib/test/orchestrator.py llm-server-stop      # kill server by PID
python3 contrib/test/orchestrator.py zig-test --target system-test  # build + run Zig test
python3 contrib/test/orchestrator.py zig-build --target demo    # just build (no run)
```

Each strategy owns exactly one responsibility:

**llama_server.py** — start server with config, wait for health, return PID. No test logic.
**zig_build.py** — invoke `zig build <target> --summary all` or `zig build <target> run-tests`. No server logic.

This mirrors the setup orchestrator pattern:

- `contrib/setup/orchestrator.py` — orchestrates **setup** (clone, build, download)
- `contrib/test/orchestrator.py` — orchestrates **test infrastructure** (start/stop server, run Zig builds)

### Step 2: Split run_system_model_tests.sh into two scripts

**`contrib/test/run_system_model_tests.sh`** (test runner — does ONE thing):

```bash
#!/usr/bin/env bash
set -euo pipefail
# Run Zig system-test against a pre-started llama.cpp server.
# Caller is responsible for starting the server and cleaning up.
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# Use orchestrator to run the Zig test
ZIG_GLOBAL_CACHE_DIR=.zig-global-cache python3 "$(dirname "$SCRIPT_DIR")/test/orchestrator.py" zig-test --target system-test
```

**`contrib/test/run_live_investment_demo.sh`** (new — infrastructure + test):

```bash
#!/usr/bin/env bash
set -euo pipefail
# End-to-end live investment demo: setup → start server → run tests → cleanup.
# This is the script that replaces the current monolithic run_system_model_tests.sh.
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# Phase 1: Setup via orchestrator (build llama.cpp + download model)
python3 "$(dirname "$SCRIPT_DIR")/setup/orchestrator.py" llm-server

# Phase 2: Start llama.cpp server (infrastructure)
python3 "$(dirname "$SCRIPT_DIR")/test/orchestrator.py" llm-server-start

# Phase 3: Run system test (test)
bash contrib/test/run_system_model_tests.sh

# Phase 4: Cleanup (stop server)
python3 "$(dirname "$SCRIPT_DIR")/test/orchestrator.py" llm-server-stop
```

The Windows variant gets the same treatment:

- `run_system_model_tests_win.sh` → `run_system_model_tests_win.sh` becomes just the Zig test runner (test)
- New `run_live_investment_demo_win.sh` — setup + start + test + cleanup
