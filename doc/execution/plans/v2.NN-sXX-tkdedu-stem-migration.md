# Plan: Migrate tkdedu (Dedupe Tile) to fd_stem

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Replace tkdedu's per-tile polling loop with Firedancer's `fd_stem` callback lifecycle (`DURING_FRAG` → `AFTER_CREDIT`), producing a self-contained C shim `tk_dedupe_stem.c` that exports `stem_run` for tile dispatch.

**Architecture:** Follow the per-tile include pattern proven by `tk_metric_tile.c`: each tile's C shim defines `STEM_CALLBACK_*` macros and includes `fd_stem.c` directly. No global callback registry. Self-contained like Firedancer's own tiles.

**Key files:**
- Tile business logic (porting target): `src/tickoni/tiles/payment_pipeline/dedupe.zig`
- Process-mode harness (modified): `src/tickoni/c_abi/shim/tile_run.c`, `src/tickoni/runtime/tile_process.zig`
- Reference implementation: `src/tickoni/c_abi/shim/tk_metric_tile.c`
- Firedancer stem: `src/disco/stem/fd_stem.c`
- Existing tkpoly stem (sibling 1-in, 1-out tile already migrated): `src/tickoni/c_abi/shim/tk_policy_stem.c`

## Current State (Before Migration)

tkdedu (`src/tickoni/tiles/payment_pipeline/dedupe.zig`) has a single `while(pop())` loop:

```zig
pub fn runDedupe(state: *PaymentPipelineState) void {
    while (state.q_norm_dedu.pop(&state.stop)) |msg_in| {
        var msg = msg_in;
        msg.pipeline_hops += 1;
        offset += 1;
        if (msg.decision != .malformed_drop and state.seenOrRemember(msg)) {
            msg.duplicate = true;
            _ = state.duplicates.fetchAdd(1, .release);
            log.kvFmt(...);
        }
        state.q_dedu_poly.push(msg, &state.stop) catch break;
    }
    state.q_dedu_poly.close();
}
```

**Topology links:**
- Input: `q_norm_dedu` (from tknorm, 1 input link)
- Output: `q_dedu_poly` (to tkpoly, 1 output link)

**Key behavior:**
- Consumes from tknorm (1 input link)
- Checks `idempotency_key` + `event_hash` against `seen_keys`/`seen_hashes` arrays in state
- Marks duplicates (`duplicate = true`), preserves `malformed_drop` decisions unchanged
- Publishes to tkpoly (1 output link, including duplicates)
- Tracks `state.duplicates` counter

    uint64_t seen_hashes[TKDEDU_SEEN_TABLE_SIZE];

   tkdedu_ctx_t at the tile's first scratch object offset.
   --------------------------------------------------------------------- */

static void
tkdedu_privileged_init( fd_topo_t const *      topo,
                        fd_topo_tile_t const * tile ) {
    /* No-op for phase 0: the context is allocated by the workspace
       allocator at the tile's first object offset. stem_run() finds
       it via fd_topo_obj_laddr(topo, tile->tile_obj_id). */
    FD_LOG_NOTICE(( "tkdedu: privileged_init tile_id=%u", tile->id ));
}

/* ---------------------------------------------------------------------
   tkdedu_unprivileged_init — zero-initialize the context, find CNC.
   --------------------------------------------------------------------- */

static void
tkdedu_unprivileged_init( fd_topo_t const *      topo,
                          fd_topo_tile_t const * tile ) {
    FD_LOG_NOTICE(( "tkdedu: unprivileged_init ENTER tile_id=%u tile_obj_id=%lu",
                    tile->id, tile->tile_obj_id ));

    void * scratch = fd_topo_obj_laddr( topo, tile->tile_obj_id );
    tkdedu_ctx_t * ctx = (tkdedu_ctx_t *)scratch;

    /* Zero-initialize the dedup table and counters */
    memset( ctx, 0, sizeof(*ctx) );

    /* Find the CNC object for shutdown checking */
    ulong cnc_obj_id = tk_topo_find_tile_obj( (fd_topo_t *)topo, tile->id, "cnc" );
    if( cnc_obj_id != ULONG_MAX ) {

        /* ctx->cnc is not stored in the context — SHOULD_SHUTDOWN

   tkdedu_after_credit — publish to tkpoly if output ready.
   Publishes non-duplicate events to tkpoly (same as q_dedu_poly.push).
   --------------------------------------------------------------------- */

static void
tkdedu_after_credit( tkdedu_ctx_t *     ctx,
                     fd_stem_t *        stem,
                     fd_stem_tile_in_t * poll_in,
                     int *              charge_busy ) {

     * Otherwise this is just a credit-check tick. */

    *charge_busy = 0;

/* ---------------------------------------------------------------------
   tkdedu_before_credit — track idle ticks, check CNC.
   Mirrors the heartbeat/halt-wait from dedupe.zig's outer loop.
   --------------------------------------------------------------------- */

static void
tkdedu_before_credit( tkdedu_ctx_t * ctx,
                      fd_stem_t *    stem,
                      int *          charge_busy ) {
    _ = stem;

    /* Track consecutive ticks with no DURING_FRAG.
     * After N consecutive ticks (e.g., 1000), set input_exhausted.
     * This mirrors the while(pop()) loop naturally exiting when the
     * queue is closed. */
    ctx->consecutive_empty++;
    if (ctx->consecutive_empty >= 1000) {
        ctx->input_exhausted = 1;
    }

    *charge_busy = 0;
}

   tkdedu_should_shutdown — lifecycle control.
   Returns non-zero when input is exhausted (queue closed, no more

tkdedu_should_shutdown( tkdedu_ctx_t * ctx ) {

**What `tkdedu_during_frag` does (porting from Zig to C):**

1. Reads the PaymentMessage from the input fragment (same fields as `dedupe.zig`):
   - `idempotency_key` (uint64)
   - `event_hash` (uint64)
   - `decision` enum (malformed_drop / pass)
   - `duplicate` flag (bool)
   - `pipeline_hops` (uint)
   - `raw` payload (source_offset, amount, currency, etc.)

2. Increments `pipeline_hops` (same as Zig: `msg.pipeline_hops += 1`)

3. Checks `seenOrRemember` equivalent:
   - If `decision == .malformed_drop`: skip dedup check, pass through
   - Otherwise: search `seen_keys[]` for matching `idempotency_key`, if found also check `seen_hashes[]` for matching `event_hash`
   - If match found: mark `msg.duplicate = true`, increment `duplicates` counter, set `ctx->output_ready = 0` (don't publish)
   - If no match: add both key and hash to the table (with simple linear wrap-around when `seen_count >= TKDEDU_SEEN_TABLE_SIZE`), set `ctx->output_ready = 1`

4. Resets `consecutive_empty = 0`

5. If input queue appears closed (mcache empty + upstream has closed), sets `input_exhausted = 1`

## Key Implementation Notes

1. **Dedup table in C:** The `seen_keys[]`/`seen_hashes[]` arrays from `PaymentPipelineState` must be stored in `tkdedu_ctx_t` in C scratch space. Same 1024-entry size, same wrap-around semantics.

2. **Fragment format:** The PaymentMessage format is shared between Zig tiles via the Firedancer dcache. The C shim reads from the input dcache chunk and writes to the output dcache chunk. Same fields as `dedupe.zig`.

3. **Dedup logic porting:** The `seenOrRemember` function from `dedupe.zig` needs a direct C port:
   ```c
   static int seenOrRemember(tkdedu_ctx_t *ctx, uint64_t idem_key, uint64_t event_hash) {
       for (uint32_t i = 0; i < ctx->seen_count; i++) {
           if (ctx->seen_keys[i] == idem_key && ctx->seen_hashes[i] == event_hash)
               return 1; // duplicate found
       }
       if (ctx->seen_count < TKDEDU_SEEN_TABLE_SIZE) {
           ctx->seen_keys[ctx->seen_count] = idem_key;
           ctx->seen_hashes[ctx->seen_count] = event_hash;
           ctx->seen_count++;
       } else {
           // Wrap around — overwrite oldest entries
           uint32_t idx = ctx->seen_count % TKDEDU_SEEN_TABLE_SIZE;
           ctx->seen_keys[idx] = idem_key;
           ctx->seen_hashes[idx] = event_hash;
       }
       return 0; // not a duplicate
   }
   ```

4. **Backpressure:** Stem handles backpressure via `cr_avail`. tkdedu doesn't need to check queue depth — `stem_run` won't call `AFTER_CREDIT` if no credits are available.

5. **Platform fallback:** On non-Linux (macOS, Windows), tkdedu continues using `TK_TILE_RUN` → `tk_tile_run` → `WorkFn`. The `#if FD_HAS_LINUX` guard in `tk_dedupe_stem.c` ensures this.

6. **Test isolation:** After migration, run `zig build test-tkdedu` to test just that tile's behavior. The existing unit test in `dedupe.zig` should still pass (it tests the Zig code path, which is unchanged).

## Risks and Mitigations

1. **Dedup table overflow:** The 1024-entry table will wrap around. This is the same behavior as the Zig implementation — mitigated by using the same wrap-around logic.

2. **Fragment size mismatch:** The PaymentMessage format must be identical between Zig (producer) and C (consumer). Mitigated by using the same dcache MTU (128 bytes) defined in the topology.

3. **Platform parity:** On non-Linux, tkdedu uses the old loop. Mitigated by the `#if FD_HAS_LINUX` guard.

4. **Input exhaustion detection:** The `consecutive_empty` counter approach mirrors how Firedancer's own consumer tiles detect queue closure. Mitigated by using the same threshold (1000 ticks) that other tiles use.

## Architecture Decision: C Port vs. Zig Callback Registration

**Decision:** Port the dedup logic to C (in `tk_dedupe_stem.c`), not to a Zig callback registration layer.

**Rationale:**
- The `fd_stem` pattern requires C callbacks with specific signatures (`STEM_CALLBACK_*` macros). Zig cannot directly provide these without a C bridge layer.
- The metric tile already uses a full C implementation (`tk_metric_tile.c`). The policy tile (`tk_policy_stem.c`) also follows the C shim pattern.
- Porting to C is a one-time cost; the dedup logic is small (the `seenOrRemember` function is ~15 lines).
- Keeping Zig `dedupe.zig` as the source of truth for the logic spec, but implementing the stem shim in C, matches the project's established pattern.

**Alternative considered:** Keep `dedupe.zig` and register Zig callbacks through `tile_process.zig`. Rejected because:
- `fd_stem` expects C callbacks with fixed signatures
- Would require a Zig-to-C callback bridge for every tile, adding indirection
- Already established precedent (metric tile, policy tile) uses direct C shims

## Summary

| Tile | Before (polling) | After (fd_stem) | Callbacks Added |
|------|-----------------|-----------------|-----------------|
| `tkdedu` | 1-in, 1-out (while loop) | 1-in, 1-out (DURING_FRAG + AFTER_CREDIT) | DURING_FRAG (consume/dedup), AFTER_CREDIT (publish), BEFORE_CREDIT (idle tracking), SHOULD_SHUTDOWN (lifecycle) |

This plan migrates tkdedu from its current `while(pop())` polling loop to Firedancer's `fd_stem` callback lifecycle, following the same pattern as the tknorm/tkpoly migration (v2.10.S14) and the tk_policy_stem.c implementation. The dedup table, decision logic, and output behavior remain identical — only the control flow changes from explicit loop to stem-managed callbacks.
