# Plan: V2.10.S2 — build.zig modularization (incremental, strategy-based)

## Status: Plan (not yet executed)
## Epic: V2.10
## Predecessor: `v2.10-s2.md` (single-bang refactor, regression in integration tests, stuck on `build-improvements-new`)
## Pattern: GoF Strategy — each lane is an independent strategy module

---

## Problem Statement

The previous plan (`v2.10-s2.md`) attempted to extract all helpers, modules, specs, and registry in one pass, then replace `build.zig` in a single commit. This created:

- **Unverifiable intermediate state**: no point where a subset worked independently.
- **Massive diff on every change**: hard to find what caused a regression.
- **Integration test memory-layout regression** that could not be isolated — by the time it was noticed, all lanes had been converted simultaneously.
- **No CI feedback between phases**: the entire refactor was one commit with one CI run.

**Key constraint: Phase 1 preserves the current build process exactly. We are only refactoring how `build.zig` delegates work — not changing compile flags, link order, or memory layout.**

---

## Approach: Strategy Pattern

Each build lane becomes an independent strategy module. `build.zig` is the coordinator — it calls into strategy functions. Each strategy file is self-contained: it can be read, understood, and verified in isolation.

**Why Strategy (not Template Method or Factory):**
- Strategy: each lane is a self-contained function + spec data. Swap one lane without touching others.
- Template Method would embed lane logic in a hierarchy — hard to add new lanes.
- Factory would add indirection around module creation — unnecessary for this problem.

### Architecture

```
build.zig              → coordinator: calls strategy functions
build/lanes/fd.zig     → Firedancer build strategy
build/lanes/tk.zig     → Tickoni build strategy
build/lanes/unit.zig   → Unit test strategy
build/lanes/integration.zig → Integration test strategy
build/lanes/system.zig → System test strategy
build/lanes/cov.zig    → Coverage test strategy
build/lane.zig         → LaneStrategy type + registry dispatch
build/lib/*.zig        → extracted helpers (phase 0)
build/mod/*.zig        → extracted modules (phase 0)
```

Each lane strategy file has:
- `TestSpec` struct (or lane-specific variant)
- Spec array (data-driven: list of tests with their linkage)
- Strategy function: `fn strategy(b: *std.Build, target, optimize, fd_lib_dir, step) void`

`build.zig` after full refactor: **< 60 lines**.

### 1a. Define LaneStrategy type in `build/lane.zig`

```zig
pub const TestSpec = struct {
    name: []const u8,
    source_file: []const u8,
    imports: []const ModuleImport,
    linkage: TestLinkage,
    action: TestAction,
};

pub const TestLinkage = packed struct(u8) {
    needs_codec: bool = false,
    needs_firedancer: bool = false,
    needs_topo_run: bool = false,
    needs_tile_run: bool = false,
    needs_libc: bool = false,
    _pad: u3 = 0,
};

pub const TestAction = enum { run, cov, system_run };

pub const ModuleImport = struct {
    name: []const u8,
    module: *std.Build.Module,
};
```

## Phase 5: Rewrite build.zig

**Goal:** Final cleanup — `build.zig` becomes < 60 lines. All logic is in strategy files.

### 5a. Replace inline build.zig with coordinator

```zig
const std = @import("zig");
const build_lib = @import("build/lib");
const build_mod = @import("build/mod");
const build_lane = @import("build/lane");
const build_lanes = @import("build/lanes");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});
    const fd_lib_dir = b.option([]const u8, "fd-lib-dir", "...") orelse "build/native/gcc/lib";
    const build_tests = b.option(bool, "test", "...") orelse false;
    const clap_dep = b.dependency("clap", .{});
    const clap_mod = clap_dep.module("clap");

    // Module declarations
    const modules = build_mod.modules(b, target, optimize);

    // Supervisor executable (unchanged)
    const exe = build_lib.supervisorExe(b, modules, target, optimize, fd_lib_dir);
    b.installArtifact(exe);

    // Check step
    build_lib.checkStep(b, target);

    if (build_tests) {
        const test_step = b.step("test", "...");
        const run_tests_cmd = build_lanes.runTestsCmd(b);

        // Unit tests
        build_lanes.unit.unitStrategy(b, modules, target, optimize, fd_lib_dir, test_step);

        // Integration tests
        build_lanes.integration.integrationStrategy(b, modules, target, optimize, fd_lib_dir, b.step("integration-test", "..."));

        // System tests
        build_lanes.system.systemStrategy(b, modules, target, optimize, fd_lib_dir, b.step("system-test", "..."));
    }

    // Coverage lane
    const cov_step = b.step("cov", "...");
    build_lanes.cov.covStrategy(b, modules, target, optimize, fd_lib_dir, cov_step);
}
```

### 5b. Verification

- `zig build` — supervisor executable builds
- `zig build -Dtest=true test` — unit tests
- `zig build -Dtest=true run-tests` — runs
- `zig build -Dtest=true integration-test` — integration tests
- `zig build -Dtest=true system-test` — system tests
- `zig build cov` — coverage
- `zig build` output identical to pre-migration
- `build.zig` < 60 lines

## Verification Gates (Mandatory)

| Phase | Gate | Command |
|-------|------|---------|
| 0 | `zig build` identical | `zig build && zig build -Dtest=true test && zig build cov` |
| 1 | Unit tests pass | `zig build -Dtest=true run-tests` |
| 2 | Integration tests pass | `zig build -Dtest=true integration-test` |
| 3 | Coverage lane passes | `zig build cov && ls zig-out/cov/` |
| 4 | System tests pass | `zig build -Dtest=true system-test` |
| 5 | All lanes + build.zig < 60 lines | All of the above + wc -l build.zig |

**Rule: Do NOT proceed to the next phase until the current phase's gate passes.** If a gate fails, the regression is in that phase only — easy to isolate.

---

## Risks / Mitigations

| Risk | Mitigation |
|------|-----------|
| Memory layout regression in integration tests (as happened before) | Phase 2 is its own gate. If it fails, compare compiled binaries with `zig build --help` flags dump. Old code is untouched in build.zig until Phase 2 passes. |
| Inline loop file-path matching in unit tests | Mapped to explicit spec entries — no dynamic matching. Each spec has explicit linkage flags. |
| `addPlainTestRun` for integration tests needs supervisor dependency | Handled in integration strategy — `dependOn(&supervisor_install.step)` before test run step. |
| Coverage lane has ~19 array + ~14 manual tests | Both consolidated into spec arrays in `build/lanes/cov.zig`. |
| Windows linkage differs from Linux | Strategy functions receive `target` and `optimize` — Windows codec shim uses archive linking, Linux uses pkg-config. Verified per-lane. |
| Large spec arrays still hard to review | Each lane spec array is in its own file — git blame shows per-test changes. ~5 lines per test entry. |

## Commit Strategy

Each phase is its own commit. This ensures:
- `git bisect` can find exactly which phase introduced any regression.
- Each commit is reviewable in isolation.
- Rollback is a single `git revert` of one phase.

Suggested commit messages:
```
refactor(build): extract helper functions to build/lib/
refactor(build): extract module declarations to build/mod/
refactor(build): introduce LaneStrategy type and registry
refactor(build): convert unit test lane to strategy pattern
refactor(build): convert integration test lane to strategy pattern
refactor(build): convert coverage test lane to strategy pattern
refactor(build): convert system test lane to strategy pattern
refactor(build): rewrite build.zig as coordinator (<60 lines)
```
