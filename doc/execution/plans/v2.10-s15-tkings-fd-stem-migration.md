# V2.10.S15: tkings — fd_stem Migration (TDD)

> **For Hermes:** TDD migration for tkings (the synthetic event producer) from `LaunchMode.tile` + `process_fn` to `fd_stem`. Each step is: **write test → verify it fails → implement → verify it passes**. Steps are independently completable and verifiable.

**Goal:** Migrate tkings to Firedancer's `fd_stem` callback lifecycle using the per-tile C shim pattern proven by `tk_metric_tile.c`, `tk_policy_stem.c`, `tknorm`, `tkdedu`, `tkaudt`, and `tkdiag`.

**Architecture:** Follow existing per-tile pattern — define a C context struct, stem callbacks via `STEM_CALLBACK_*` macros, `#include "disco/stem/fd_stem.c"`, define `fd_topo_run_tile_t TK_INGEST_RUN`, wire into `tile_run.c`'s `tk_topo_run_tile_simple()`.

## Why tkings is different from all other stem tiles

All migrated tiles are **consumers** (1-in, 0-out or 1-in, 1-out) whose stem loop is driven by fragment arrival on an input link. tkings is the **only producer-only tile** (0-in, 1-out). It has no input link, so there is no `DURING_FRAG` callback. The stem loop still runs (`stem_run` always calls `BEFORE_CREDIT` even with no input), but event generation must live in a callback that fires every iteration.

### Producer-only callback mapping

| Callback | Role |
|----------|------|
| `DURING_HOUSEKEEPING` | CNC liveness (heartbeat + BOOT→RUN) — via `stem_helpers.h` |
| `BEFORE_CREDIT` | HALT check and deterministic event staging |
| `AFTER_CREDIT` | Publish once to the reliable pipeline link, then update the counter and exhaustion gate |
| `SHOULD_SHUTDOWN` | `event_count` reached OR CNC HALT |

**Credit safety correction (approved for S15):** `fd_stem` invokes
`BEFORE_CREDIT` before checking the reliable consumer's credits. Publishing
there can overrun the link. The tile stages the event in `BEFORE_CREDIT`,
publishes it in `AFTER_CREDIT`, and sets `input_exhausted` only after the final
publish. A zero event count leaves the producer idle until CNC HALT.

## Tile Context

```c
typedef struct {
    /* CNC reference for shutdown detection and counter publishing */
    void *cnc;

    /* Event generation state */
    uint64_t produced;          /* Total events produced (published) */
    uint64_t event_count;       /* Stop after this many events */
    tkings_payment_generator_t generator; /* Zig syntheticPayment hook */

    /* Output dcache state (computed in unprivileged_init) */
    void *   out_wksp;
    ulong    out_chunk0;
    ulong    out_wmark;
    ulong    out_chunk;

    /* Event count gating */
    int      input_exhausted;   /* Set when produced >= event_count */

    /* Optional diagnostic output, shared with the other stem tiles */
    stk_diag_out_t diag;
} tkings_ctx_t;

#define TKINGS_CTX_ALIGN alignof(tkings_ctx_t)
```

### Step 4: Create the stem shim

The shim must compile and link into every normal supervisor/test shim library.
The `c_abi/tkings.zig` test checks the descriptor, scratch accessors, and
wire sizes; the integration test checks the child lifecycle. No temporary C
compile test is needed.

**Step 4a — Create the main stem shim:**

**File:** `src/tickoni/c_abi/shim/tk_ingest_stem.c`

Use the compiled stem tile in this repository as the implementation contract.
It owns the fixed scratch context, output dcache cursor, CNC counter, and
optional `stk_diag_out_t`. The child loads `payment_pipeline.config` before
calling Firedancer and installs a Zig callback that calls the existing
`syntheticPayment()` function. `BEFORE_CREDIT` stages that payment;
`AFTER_CREDIT` publishes only when the reliable consumer has credit, advances
the dcache cursor, writes CNC slot 0, emits the lossy diagnostic fragment, and
sets exhaustion after the final event. `SHOULD_SHUTDOWN` observes exhaustion
and CNC HALT. The run descriptor uses the same C signatures, scratch accessors,
workspace lookup, and `STK_DEFINE_RUN_TILE_ACCESSORS` form as the other stem
tiles. The test-only stuck hook remains available for process health tests.

The original C sketch for this step published before checking credits and used
several nonexistent helper signatures. It has been replaced by this contract.

**Step 4b — Compile test:**
Build the project — if the shim compiles and links without errors, the test passes.

**Verify:** Run `just build-tk` — tkings stem shim compiles, `TK_INGEST_RUN` symbol resolves.

## Key Design Decisions

1. **Stage in `BEFORE_CREDIT` and publish in `AFTER_CREDIT`.** Firedancer checks reliable output credit between them. The final event is published before the post-publish event gate sets exhaustion.

2. **Event count gates after publication.** `STK_EVENT_EXHAUSTED` runs after the CNC and diagnostic updates in `AFTER_CREDIT`. Zero means an idle producer that waits for CNC HALT.

3. **No `DURING_FRAG`.** 0 input links means no `stem_run` callback is generated for `DURING_FRAG`. This is the simplest stem pattern after `SHOULD_SHUTDOWN` only.

4. **Diagnostic fan-in preserved.** tkings continues to send diagnostic fragments to tkdiag via an unreliable link, using the `stem_diag.h` pattern shared by the other stem tiles.

5. **The test-only model-request source is a second source of the same stem tile.** The Zig child installs exactly one source before the harness runs: the payment generator, or, in test builds only, a request builder (`tkings_set_request_source`). The C tile stages one request in `BEFORE_CREDIT` (a Zig-built message, hashed by `tk_mp_tx_begin`) and publishes one multipart fragment per `AFTER_CREDIT`, so the credit contract is the same as for payments; a message counts as produced after its last fragment, and the counter and exhaustion gate follow that. Stream faults (`drop_middle`, `omit_last`, `corrupt_payload`) are decided in Zig by a per-fragment hook that may edit or withhold the fragment, so the C tile carries no fault vocabulary. The source publishes no diagnostic fragment, as before. Every source uses `__stem-run`.

6. **Event generation logic unchanged.** The `runtime.syntheticPayment()` function and its determinism are unchanged. The stem shim invokes it through a Zig callback installed from the validated process config, producing identical events in the same order.

## Summary

| Tile | Before | After | Callbacks |
|------|--------|-------|-----------|
| `tkings` | 0-in, 1-out, `LaunchMode.tile`, `process_fn` | 0-in, 1-out, `LaunchMode.stem`, `process_fn = null` | `DURING_HOUSEKEEPING` (liveness), `BEFORE_CREDIT` (stage), `AFTER_CREDIT` (publish), `SHOULD_SHUTDOWN` (exhaustion + HALT) |

This is the **first producer-only tile** in the fd_stem migration. All previously migrated tiles (tknorm, tkdedu, tkpoly, tkaudt, tkdiag, tkmodl, tkagnt, tkdisp, tkcase, tktool, tkadpt) are consumers. tkings is the sole producer, and its migration establishes the pattern for any future producer tiles (tkrepl re-injection feeds into tkings, not a second producer).
