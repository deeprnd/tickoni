# Plan: V2.10.S3 — Qt Hello-World Build Validation

## Goal

Prove the Qt 6 CMake build path works by creating the smallest possible
terminal source tree (one C++ file, one QML file) and wiring `just build-qt`
into the justfile. Developer installs Qt via the setup orchestrator.

## Version Model

Qt has two independent version layers — both driven entirely from
`tool-versions.json`. No version numbers are hardcoded in the strategy code.

1. **Installer version** (e.g. `4.11.0`) — the Qt Online Installer CLI tool
2. **Qt library version** (e.g. `6.11.2`) — the actual Qt framework being installed

These live under `versions.qt-installer` in tool-versions.json:

```json
"qt-installer": {
  "version": "4.11.0",
  "options": {
    "base_url": "https://qt.mirror.constant.com/archive/online_installers/4.11",
    "qt_module": {
      "linux-x86": "qt.qt6.6112.linux_gcc_64",
      "linux-arm": "qt.qt6.6112.linux_arm",
      "macos-x86": "qt.qt6.6112.macOS_clang_64",
      "macos-arm": "qt.qt6.6112.macOS_clang_64",
      "windows-x86": "qt.qt6.6112.win64_msvc2022_64",
      "windows-arm": "qt.qt6.6112.win64_msvc2022_64"
    },
    "asset_name": {
      "linux-x86": "qt-online-installer-linux-x64-{version}.run",
      "linux-arm": "qt-online-installer-linux-arm64-{version}.run",
      "macos-x86": "qt-online-installer-macOS-universal-{version}.dmg",
      "macos-arm": "qt-online-installer-macOS-universal-{version}.dmg",
      "windows-x86": "qt-online-installer-windows-x64-{version}.exe",
      "windows-arm": "qt-online-installer-windows-arm64-{version}.exe"
    },
    "sha256": {
      "linux-x86": "40b76bdf74f6a396341efb70ae2e754fcd878474babb6cd9d7f07eff12a85c62",
      "linux-arm": "7f2a9be88098c1e2e0a608458252dc9864be513a16be6af7190769922536b3f5",
      "macos-x86": "917fb4048226db081b780b751138c896165f66df523f3b0f4385bcfb4a1c59da",
      "macos-arm": "917fb4048226db081b780b751138c896165f66df523f3b0f4385bcfb4a1c59da",
      "windows-x86": "ae919bc9b224b8ccdada69ec787a9f69330001f227f3fcbfb4a11a4adb3786f6",
      "windows-arm": "3c4635366059172b52fe5776b164bc4c56a36772cf01122e0473619a48463e32"
    }
  }
}
```

How the two versions relate:

- `version` (top-level, e.g. `"4.11.0"`) is the **installer version**.
  It is resolved by the strategy via `resolve_version_from_config()` and
  substituted into the `asset_name` patterns (replacing `{version}`),
  producing actual download URLs like
  `qt-online-installer-linux-x64-4.11.0.run`.
- The **Qt library version** (e.g. `6.11.2`) is encoded in the `qt_module`
  IDs under `options.qt_module` (e.g. `qt.qt6.6112.linux_gcc_64`).
  It does not have a separate top-level field because the module ID is
  the authoritative reference for which Qt version the installer will
  fetch. The Qt sub-directory name (e.g. `linux_gcc_64`) is extracted
  from the last dot-separated segment of the module ID.
- SHA-256 hashes are per-platform and keyed by `platform_str`
  (e.g. `linux-x86`, `macos-arm`).

## Steps

### Step 1: Create source tree

**Files:**

`src/tickoni/terminal/app/main.cpp`:
```cpp
#include <QQuickWindow>
#include <QQmlApplicationEngine>
#include <QGuiApplication>

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    QQmlApplicationEngine engine;
    engine.load(QUrl(QStringLiteral("qrc:/Main.qml")));
    if (engine.rootObjects().isEmpty())
        return -1;
    return app.exec();
}
```

`src/tickoni/terminal/qml/Tickoni/Main.qml`:
```qml
import QtQuick 2.15
import QtQuick.Controls 2.15

ApplicationWindow {
    width: 640
    height: 480
    visible: true
    title: "tickoni"

    Rectangle {
        anchors.fill: parent
        color: "#f0f0f0"

        Text {
            anchors.centerIn: parent
            text: "tickoni"
            font.pixelSize: 32
            color: "#000000"
        }
    }
}
```

`src/tickoni/terminal/CMakeLists.txt`:
```cmake
cmake_minimum_required(VERSION 3.16)
project(tickoni-terminal LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_AUTOMOC ON)

find_package(Qt6 REQUIRED COMPONENTS Quick)

qt_standard_project_setup()

qt_add_executable(tickoni-terminal
    app/main.cpp
)

qt_add_qml_module(tickoni-terminal
    URI Tickoni
    VERSION 1.0
    QML_FILES
        qml/Tickoni/Main.qml
)

target_link_libraries(tickoni-terminal PRIVATE Qt6::Quick)

install(TARGETS tickoni-terminal RUNTIME DESTINATION bin)
```

### Step 2: Add justfile recipe

**File:** `justfile`

Add after existing build recipes (near `build-all`):

```
# Qt terminal — CMake-based, independent of build.zig
build-qt:
    #!/usr/bin/env bash
    set -euo pipefail
    cmake -S src/tickoni/terminal -B build/tickoni-terminal
    cmake --build build/tickoni-terminal -j {{ cpu_count }}
```

Single recipe — no per-platform variants. CMake handles platform detection.

### Step 3: Add Qt install strategy to orchestrator

**File:** `contrib/setup/install/strategies/qt_installer.py`

The strategy reads all version data from `tool-versions.json` — no version
numbers are hardcoded. The flow:

1. Resolve installer version via `resolve_version_from_config(config, 'qt-installer')`.
2. Resolve per-platform metadata from `tool-versions.json` via
   `_resolve_from_config(platform_str, config)` — this returns
   `qt_module`, `asset_name`, `sha256`, and `base_url`.
3. Substitute `{version}` into the `asset_name` pattern (e.g.
   `qt-online-installer-linux-x64-{version}.run` →
   `qt-online-installer-linux-x64-4.11.0.run`).
4. Download the installer with its vendor-specific name.
5. Verify SHA-256 from `tool-versions.json`.
6. Rename to canonical name (`qt-installer.run` / `.dmg` / `.exe`) — this
   normalizes vendor naming so the invocation command is always the same.
7. Invoke the installer CLI: `<installer> --root <install_dir> <flags> <qt_module>`.

Platform canonical names and invocation flags are defined in a small
constant dict (`_CANONICAL`) — only the platform → binary name and flags
mapping, not versions:

```python
_CANONICAL = {
    'linux-x86': ('qt-installer.run', '--accept-licenses --default-answer --confirm-command install'),
    'linux-arm': ('qt-installer.run', '--accept-licenses --default-answer --confirm-command install'),
    'macos-x86': ('qt-installer.dmg', '--accept-licenses --default-answer --confirm-command install'),
    'macos-arm': ('qt-installer.dmg', '--accept-licenses --default-answer --confirm-command install'),
    'windows-x86': ('qt-installer.exe', '/S /accept-licenses --confirm-command install'),
    'windows-arm': ('qt-installer.exe', '/S /accept-licenses --confirm-command install'),
}
```

The Qt module ID (`qt_module`) and all version strings come from
`tool-versions.json`. The idempotency check derives the Qt sub-directory
name from the last dot-separated segment of `qt_module` (e.g.
`qt.qt6.6112.linux_gcc_64` → `linux_gcc_64`).

**File:** `contrib/setup/install/strategies/__init__.py`

Add `qt_installer` to the import list to trigger the `@register('qt_installer')` decorator.

### Step 4: Add Qt category, dependency, and tool entry to tool-versions.json

**Categories block** — add:
```json
"qt": {
  "description": "Qt 6 framework and build tools",
  "tools": ["qt-installer"],
  "platforms": ["linux", "macos", "windows"]
}
```

**Dependencies block** — add:
```json
"qt": ["core", "build", "toolchain"]
```

**Tools block** — add:
```json
"qt-installer": {
  "category": "qt",
  "platform": "all",
  "install_method": "qt_installer",
  "parameters": {
    "install_dir": "~/Qt",
    "version_ref": "qt-installer"
  },
  "idempotent_check": "command -v qmake"
}
```

Note: the idempotent check uses a generic `command -v qmake`. A more
precise check could resolve the Qt sub-directory from `qt_module` at
runtime, but `command -v qmake` is sufficient since the installer always
puts `qmake` on PATH for the active Qt version.

## Risks

- CMake config may fail if Qt 6 is not on PATH or PREFIX. The `build-qt`
  recipe uses bare `cmake` — if the dev has Qt installed via system
  package manager this works; if via Qt Online Installer, they may need
  `-DCMAKE_PREFIX_PATH`. The story accepts this as a developer
  responsibility.
- `qml/Tickoni/Main.qml` is loaded via `qt_add_qml_module` (qrc). If the
  engine load path doesn't match the module URI, the QML won't resolve.
  `qrc:/Main.qml` should work with `qt_standard_project_setup`.
- The Qt Online Installer requires network access and a Qt account for
  some modules. The free/open-source Qt modules (`linux_gcc_64`,
  `macOS_clang_64`) install without authentication; enterprise modules
  may require login.
