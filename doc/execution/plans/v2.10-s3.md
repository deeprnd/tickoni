# Plan: V2.10.S3 — Qt Build POC

## Goal

Prove the Qt 6 CMake build path works for the terminal scaffolding by wiring
`just build-qt` into the justfile, adding a `just setup-qt` recipe, creating a
Qt install strategy for the orchestrator, and adding Qt 6.11 to tool-versions.json.

## What Exists Today

- `just build-all` (line 382): runs `build-fd && build-tk`
- `justfile` has platform dispatchers for `build-tk`, `build-fd`, setup lanes
- `contrib/setup/tool-versions.json` has categories, tools, install strategies
- `contrib/setup/install/strategies/` has strategy modules (apt, pip, zig, etc.)
- `orchestrator.py` dispatches install by `install_method` key
- No Qt tool in tool-versions.json, no Qt install strategy, no Qt just recipes

## Steps

### Step 1: Create Qt install strategy

**File:** `contrib/setup/install/strategies/qt_install.py`

New strategy that implements the `qt_install` install method.

Platform detection from `platform_str` determines:
- Installer download URL (Windows: `.exe`, macOS: `.dmg`, Linux: `.run`)
- Qt component package name
- Installation root path

Installer binary download URL pattern:
```
https://download.qt.io/online/qt517/<version>/qt-unified-<os>-<arch>-online.run
```
where `<os>` maps to `windows`, `macos`, `linux` and `<arch>` is `x64`.

For unattended install:
```bash
qt-unified-<OS>-x64-<VERSION>-online.<ext> \
  --root <INSTALL_DIR> \
  --accept-licenses \
  --default-answer \
  --confirm-command \
  install <COMPONENT>
```

Component names (Qt 6.11.0 per docs):
- Linux: `qt.qt6.6.11.0.gcc_64`
- macOS: `qt.qt6.6.11.0.clang_64`
- Windows: `qt.qt6.6.11.0.win64_msvc2022_64`

For the POC (Linux x86 only), only the Linux recipe is fully wired.
macOS and Windows get stub recipes that echo a TODO.

**Idempotent check:** `test -d "$QT_HOME/6.11.0/gcc_64"` or equivalent.

**Install dir:** `$HOME/.local/qt/6.11`

### Step 2: Add Qt to tool-versions.json

**File:** `contrib/setup/tool-versions.json`

Under `"versions"`:
```json
"qt6.11": {
  "version": "6.11.0",
  "options": {
    "linux_gcc_64": "qt.qt6.6.11.0.linux_gcc_64",
    "macos_clang_64": "qt.qt6.6.11.0.macos_clang_64",
    "windows_msvc2022_64": "qt.qt6.6.11.0.win64_msvc2022_64"
  }
}
```

Under `"categories"`, add:
```json
"qt": {
  "description": "Qt 6 framework for terminal UI",
  "tools": ["qt6.11"],
  "platforms": ["linux"]
}
```

Under `"dependencies"`, add:
```json
"qt": [
  "core",
  "essential",
  "build"
]
```

Under `"tools"`, add:
```json
"qt6.11": {
  "category": "qt",
  "platform": "linux",
  "install_method": "qt_install",
  "parameters": {
    "install_dir": "$HOME/.local/qt/6.11",
    "version_ref": "qt6.11"
  },
  "idempotent_check": "test -d \"${QT_HOME:-$HOME/.local/qt}/6.11.0/gcc_64\""
}
```

### Step 3: Add Qt justfile recipes

**File:** `justfile`

#### Qt build recipes (after `build-tk-windows-arm`, before `build-all`)

```
# Qt terminal build — CMake-based, independent of build.zig
build-qt-linux-x86:
    cmake -S src/tickoni/terminal -B build/tickoni-terminal -DCMAKE_PREFIX_PATH="{{ qt_home }}/6.11.0/gcc_64"
    cmake --build build/tickoni-terminal -j {{ cpu_count }}

build-qt-linux-arm: build-qt-linux-x86

build-qt-macos-x86:
    @echo "TODO: Qt build on macOS — stub until S3 implementation"

build-qt-macos-arm: build-qt-macos-x86

build-qt-windows-x86:
    @echo "TODO: Qt build on Windows — stub until S3 implementation"

build-qt-windows-arm: build-qt-windows-x86

# Bare dispatcher
build-qt:
    #!/usr/bin/env bash
    set -euo pipefail
    case "{{ os }}-{{ arch }}" in
      linux-x86) exec just build-qt-linux-x86 ;;
      linux-arm) exec just build-qt-linux-arm ;;
      macos-x86) exec just build-qt-macos-x86 ;;
      macos-arm) exec just build-qt-macos-arm ;;
      windows-x86) exec just build-qt-windows-x86 ;;
      windows-arm) exec just build-qt-windows-arm ;;
      *) echo "unsupported host platform for build-qt: {{ os }}-{{ arch }}" >&2; exit 1 ;;
    esac
```

## Not In This Plan

  exists or will be created as a separate implementation step under this story
- macOS/Windows Qt build implementation — stubbed with TODO for now
- CI lane wiring — deferred to S6 (CI cutover)
- Qt packaging — explicitly out of scope per story
- Full Qt component list (Quick, QuickControls2, Network, Svg, Multimedia) —
  the CMakeLists.txt from the story will declare what it needs
- Qt setup for all platforms in tool-versions.json — only Linux is in scope

## Risks

- Qt Online Installer requires a Qt account for full access. The POC may need
  a free account. The plan assumes the installer URL is publicly accessible
  for the essentials package (qt.qt6.6.11.0.linux_gcc_64).
- The `qt` category is new. If `orchestrator.py`'s strategy registry lookup
  fails with an unknown method, the install will error. Step 4 addresses this.
- `build-all` now includes Qt — if Qt setup is missing, `build-all` will
  fail at the CMake configure step (not the setup step). The `run-badged-command.py`
  will report the failure. This is intentional: the build-all surface should
  reflect the full toolchain.
