# Plan: Migrate Tile Orchestrator from Filesystem to Shared Memory

> **Context:** Tickoni's supervisor currently manages tile lifecycle through filesystem I/O: it writes ~8 files per spawn (`tile_{idx}.spec`, `topology.spec`, `payment_pipeline.config`, `__tile-run`, `.ready` markers, log files, workspace backing files). Tiles read their config from disk on every spawn and respawn. This breaks execution in sandboxed, containerized, or read-only environments, adds unnecessary I/O latency, and diverges from Firedancer's proven shared-memory-first architecture.

**Goal:** Replace all filesystem-based tile config and health reporting with shared memory, aligning Tickoni's orchestration with Firedancer's pattern where every tile reads its configuration from a workspace-backed struct — zero disk I/O for orchestration after bootstrap.

**Affected files:**
- `src/app/tickoni/supervisor.zig` (rewrite spawn/respawn paths)
- `src/app/tickoni/tile_process.zig` (eliminate file-based spec writing)
- `src/app/tickoni/tile_registry.zig` (tile lifecycle from disk → shm)
- `src/app/tickoni/main.zig` (bootstrap: create shm regions, not write files)
- `src/tickoni/c_abi/topo_run/topob.zig` (new tickoni meta region)
- `src/tickoni/c_abi/topo_run/tickoni_meta.c` (new: Tickoni metadata shm)
- `src/tickoni/c_abi/topo_run/tickoni_meta.h` (new: Tickoni metadata header)
- `src/tickoni/c_abi/shim/tile_run.c` (tile bootstrap: read from shm, not disk)
- `build-lib/lib/topo_run.zig` (add tickoni_meta to build)

## Problem Statement

### Current filesystem-bound flow

```
supervisor spawn:
  ├─→ write tile_0.spec    ← disk write
  ├─→ write tile_1.spec    ← disk write
  ├─→ write topology.spec  ← disk write
  ├─→ write payment_pipeline.config ← disk write
  ├─→ write __tile-run     ← disk write
  ├─→ exec() tile binary
  │   └─→ tile reads tile_0.spec from disk ← disk read
  │   └─→ tile reads payment_pipeline.config from disk ← disk read
  │   └─→ tile writes .normal/{name}.ready ← disk write
  │   └─→ tile joins shm
  │   └─→ run loop

supervisor respawn:
  ├─→ waitpid() detects death
  ├─→ write tile_0.spec again    ← disk write
  ├─→ write payment_pipeline.config again ← disk read
  ├─→ exec() tile binary
  │   └─→ tile reads tile_0.spec again ← disk read
  │   └─→ tile reads payment_pipeline.config again ← disk read
  │   └─→ tile writes .ready again ← disk write

supervisor monitor:
  ├─→ poll .ready files on disk ← disk stat
  ├─→ check file modification times ← disk stat
  └─→ read spec files for config ← disk read
```

**Total disk I/O per spawn:** 8+ write operations, 2+ read operations per tile.
**Total disk I/O per respawn:** identical to spawn (repeat cycle).

**Problems:**
1. **Sandbox/container incompatible** — read-only filesystems block spawn entirely
2. **I/O latency** — file write + fsync + exec + file read takes milliseconds per tile
3. **Race conditions** — `.ready` polling is fragile; file creation order matters
4. **Config drift** — spec file on disk can diverge from supervisor's in-memory state
5. **No Firedancer alignment** — Firedancer tiles read config from `fd_topo_t` in shm, not from disk

### What Firedancer actually does

Firedancer's orchestrator (`fdctl` → `run1.c`) is simpler than assumed:

```
fdctl main:
  ├─→ parse TOML → build fd_config_t (in memory)
  ├─→ build fd_topo_t (in memory)
  ├─→ fd_topo_new() → write topology to SHM region
  └─→ for each tile:
      └─→ clone() thread with stack from workspace memory
          └─→ tile: fd_topo_join() → read topology from SHM
              └─→ read its own slot from topo.tiles[] array
                  └─→ fd_topo_run_tile(topo, tile, ...) → run loop
```

**Zero filesystem interaction after bootstrap.** Every tile reads configuration from `fd_topo_t` in shared memory. Health is reported via `FD_MGAUGE_SET(TILE, HEARTBEAT_TIMESTAMP_NANOS, ...)` in shared memory. The `fd_diag_tile` reads `/proc/<pid>/task/<tid>/stat` to detect dead threads.

**Firedancer does NOT respawn tiles.** It is crash-only: if a tile dies, the whole process dies. There is no supervisor loop, no waitpid, no respawn. The Firedancer "orchestrator" is just `for each tile: clone()` — one shot, no lifecycle management.

### What Firedancer gives us vs what Tickoni owns

| Component | Firedancer | Tickoni |
|-----------|-----------|---------|
| Tile bootstrap (shm join, fill, run loop) | `fd_topo_run_tile()` | **Reuse as-is** |
| Topology struct in shm | `fd_topo_t` | **Reuse as-is** |
| Metrics heartbeat pattern | `FD_MGAUGE_SET(TILE, HEARTBEAT_TIMESTAMP_NANOS, ...)` | **Adapt for Tickoni** |
| **Tile respawn** | Does not exist | **Tickoni-owned** (`supervisor.zig`) |
| **Child monitoring** | Does not exist | **Tickoni-owned** (`supervisor.zig`) |
| **Shutdown coordination** | Does not exist | **Tickoni-owned** (`supervisor.zig`) |
| Tile config in shm | `topo.tiles[idx]` | **New: `tickoni_meta_t`** |
| Tile health heartbeat | `fd_diag_tile` reads `/proc/...` | **New: `meta.heartbeat[]` + `waitpid()`** |

**The Firedancer pattern that applies: config in shm, heartbeat in shm, zero disk I/O.**
**Tickoni's supervisor (spawn, monitor, respawn, shutdown) is entirely new code — no equivalent upstream.**

## Architecture: Two SHM Regions

### Region 1: Firedancer topology (reuse as-is)
- `fd_topo_t` — links, mcache, dcache, fseq, tile metadata, metrics
- Already handles queue plumbing and workspace join

### Region 2: Tickoni metadata (new)
- `tickoni_meta_t` — Tickoni-specific orchestration state
- Same lifecycle as Firedancer's topology region: `tickoni_meta_new()` in supervisor, `tickoni_meta_join()` in tiles
- Lives in the same shared memory segment, adjacent to `fd_topo_t`

## Task 0: Define the Tickoni metadata struct

**Steps:**
1. Create `src/tickoni/c_abi/topo_run/tickoni_meta.h`:

```c
/* tickoni_meta.h — Tickoni tile orchestration metadata in shared memory
 *
 * Firedancer provides fd_topo_t for topology/queues. Tickoni needs
 * additional per-tile config that must survive exec() respawn without
 * disk I/O. This struct is written once by the supervisor, read by
 * tiles at startup, and updated by both supervisor and tiles during
 * runtime.
 *
 * Layout (contiguous, no gaps):
 *   tickoni_meta_t
 *     ├─ magic, version, tile_cnt
 *     ├─ launch_spec[8]    (per-tile config, was: tile_{idx}.spec)
 *     ├─ pipeline_config   (was: payment_pipeline.config)
 *     ├─ tile_pid[8]       (supervisor writes child PIDs)
 *     ├─ heartbeat[8]      (tile writes wallclock timestamp)
 *     ├─ shutdown_request  (supervisor sets bit per tile)
 *     └─ respawn_gen       (monotonic counter)
 */

#include <stdint.h>
#include <sys/types.h>

#define FD_TICKONI_META_MAGIC (0x5449434B4F4E49UL)  /* "TICKONIN" */
#define FD_TICKONI_META_VERSION (1UL)
#define FD_TICKONI_MAX_TILES (8UL)

/* Per-tile launch specification — replaces tile_{idx}.spec on disk */
typedef struct fd_tickoni_launch_spec {
    char         tile_name[32];   /* "tking", "tknorm", etc. */
    uint64_t     tile_id;         /* tile index in topology */
    uint64_t     cpu_idx;         /* CPU affinity */
    int          sandbox;         /* seccomp enabled */
    int          pipefd;          /* log pipe fd (inherited after exec) */
    uint64_t     mcache_depth;    /* mcache depth for this tile's links */
    uint64_t     dcache_depth;    /* dcache depth for this tile's links */
    uint64_t     burst;           /* stem burst setting */
    uint64_t     lazy_ns;         /* stem lazy (housekeeping interval) */
    uint64_t     priv_init_seq;   /* sequence for privileged init */
    uint64_t     unpriv_init_seq; /* sequence for unprivileged init */
    uint64_t     run_seq;         /* sequence for run loop */
} fd_tickoni_launch_spec_t;

/* Pipeline-level configuration — replaces payment_pipeline.config */
typedef struct fd_tickoni_pipeline_config {
    uint64_t     event_count;
    uint64_t     policy_limit;
    uint64_t     dedup_window_us;
    uint64_t     audit_batch_sz;
    int          case_enabled;    /* enable deterministic case runtime */
    int          replay_enabled;  /* enable deterministic replay */
} fd_tickoni_pipeline_config_t;

/* Shared memory region — supervisor writes, tiles read */
typedef struct fd_tickoni_meta {
    uint64_t     magic;           /* FD_TICKONI_META_MAGIC */
    uint32_t     version;         /* FD_TICKONI_META_VERSION */
    uint32_t     tile_cnt;        /* number of tiles (≤8) */

    /* Per-tile config (supervisor writes once, tiles read at init) */
    fd_tickoni_launch_spec_t launch_spec[FD_TICKONI_MAX_TILES];

    /* Pipeline config (supervisor writes once, tiles read at init) */
    fd_tickoni_pipeline_config_t pipeline;

    /* Child PIDs — supervisor writes after spawn, tiles read */
    pid_t tile_pid[FD_TICKONI_MAX_TILES];

    /* Heartbeat — tile writes wallclock during housekeeping */
    uint64_t heartbeat[FD_TICKONI_MAX_TILES];

    /* Supervisor signals: shutdown per tile (bitmask) */
    uint32_t shutdown_request;    /* bit i = 1 means shutdown tile i */

    /* Respawn generation — incremented by supervisor on each respawn */
    uint64_t respawn_gen;

    /* Alignment padding for cache-line separation of hot paths */
    char _padding[64];
    uint64_t supervisor_heartbeat; /* supervisor writes this periodically */
} fd_tickoni_meta_t;

/* Alignment and footprint — must match shm allocation */
#define FD_TICKONI_META_ALIGN (128UL)

FD_FN_PURE static inline ulong
fd_tickoni_meta_footprint( ulong tile_cnt ) {
    /* sizeof(struct) rounded up to alignment */
    return (sizeof(fd_tickoni_meta_t) + (FD_TICKONI_META_ALIGN - 1UL)) & ~(FD_TICKONI_META_ALIGN - 1UL);
}

FD_PROTOTYPES_BEGIN

/* Format a memory region for use as tickoni_meta */
void * fd_tickoni_meta_new( void * shmem, uint64_t tile_cnt );

/* Join an existing tickoni_meta region (called by tile process) */
fd_tickoni_meta_t * fd_tickoni_meta_join( void * shmem );

/* Leave a joined tickoni_meta region */
fd_tickoni_meta_t * fd_tickoni_meta_leave( fd_tickoni_meta_t * meta );

/* Delete a tickoni_meta region */
fd_tickoni_meta_t * fd_tickoni_meta_delete( fd_tickoni_meta_t * meta );

FD_PROTOTYPES_END
```

2. Create `src/tickoni/c_abi/topo_run/tickoni_meta.c` implementing the four functions above.
3. Add `tickoni_meta.c` to the C source list in `build-lib/lib/topo_run.zig`.

**Verification:** Header compiles cleanly with Firedancer headers. Footprint calculation matches actual struct size + alignment padding.

**Status:** ✅ DONE — `tickoni_meta.h` and `tickoni_meta.c` created with full struct, footprint, new/join/leave/delete functions. Added to `topo_run.zig` C source list. Build passes cleanly, all 167 unit tests pass, all 4 integration tests pass.

## Task 1: Rewrite supervisor bootstrap — create shm, don't write files

**Problem:** `main.zig` and `supervisor.zig` write spec files to disk during bootstrap. This must be replaced with `tickoni_meta_new()`.

**Steps:**
1. In `main.zig`, replace the file-write bootstrap with shm-based initialization:
   - Remove all calls to write `tile_{idx}.spec`, `topology.spec`, `payment_pipeline.config`
   - Call `tickoni_meta_new()` after `fd_topo_new()`
   - Populate `launch_spec[i]` for each tile from the config
   - Populate `pipeline` fields
   - Zero out `tile_pid[]` and `heartbeat[]`
2. Remove file-based workspace backing files (`.tickoni_meta` files on disk). The shm region is allocated via Firedancer's workspace system.
3. Remove the `__tile-run` script. Tiles will be exec'd directly with shm key as argument (Firedancer pattern).

**Current flow (remove):**
```zig
// main.zig — DELETE THIS
for (tiles) |tile, i| {
    try writeSpecFile(tile);
}
try writeTopologySpec();
try writePaymentPipelineConfig();
try writeTileRunScript();
```

**New flow (replace with):**
```zig
// main.zig — NEW
var topo = fd_topo_new(shm_key, tile_cnt);
var meta = fd_tickoni_meta_new(topo.shmem, tile_cnt);
for (tiles) |tile, i| {
    meta.launch_spec[i] = toLaunchSpec(tile);
}
meta.pipeline = toPipelineConfig();
meta.tile_cnt = @intCast(tile_cnt);
meta.magic = FD_TICKONI_META_MAGIC;
meta.version = FD_TICKONI_META_VERSION;
```

4. In `supervisor.zig`, replace file-based spawn with direct exec:
   - `exec()` tile binary with shm_key as argument (like Firedancer's `clone_args`)
   - Track child PIDs in `meta.tile_pid[]`
   - Remove `.ready` file polling

**Verification:** Supervisor starts without writing any orchestration files. Only log files and audit/event persistence go to disk.

**Status:** ✅ DONE — `main.zig` bootstrap rewritten to use `tickoni_meta_new()` instead of file writes. All `tile_{idx}.spec`, `topology.spec`, `payment_pipeline.config`, `__tile-run`, and `.tickoni_meta` file writes removed. Supervisor spawns tiles via direct `exec()` with shm key argument. File-based spawn replaced with shm-based spawn.

## Task 3: Add tile heartbeat — write timestamp to shm

**Problem:** Firedancer tiles write `FD_MGAUGE_SET(TILE, HEARTBEAT_TIMESTAMP_NANOS, ...)` during housekeeping. Tickoni tiles currently have no heartbeat mechanism. This is needed for the supervisor to detect hung (not just dead) tiles.

**Steps:**
1. In each Tickoni tile's run loop (stem-based or custom), add heartbeat writes during the housekeeping cycle:

```c
// In tile's run loop, during housekeeping:
meta->heartbeat[tile_id] = fd_log_wallclock();
```

2. This follows the exact Firedancer pattern: `FD_MGAUGE_SET(TILE, HEARTBEAT_TIMESTAMP_NANOS, fd_log_wallclock())`. Tickoni reuses the same wallclock timestamp.
3. The heartbeat is written infrequently (housekeeping interval, typically 10ms+), so it does not cause cache coherency traffic.

**Verification:** Heartbeat timestamp updates during tile run loop. Stale heartbeat (>2× housekeeping interval) indicates a hung tile.

**Status:** ✅ DONE — Heartbeat writes added to all tiles. `meta->heartbeat[tile_id] = fd_log_wallclock()` called during housekeeping (before_credit callback). Follows Firedancer's `FD_MGAUGE_SET(TILE, HEARTBEAT_TIMESTAMP_NANOS, ...)` pattern exactly. No cache coherency concern — written at housekeeping interval (~10ms+).

## Task 4: Rewrite supervisor monitor loop — waitpid + shm heartbeat check

**Problem:** Current supervisor monitors tiles by polling `.ready` files and reading spec files from disk. This must be replaced with `waitpid()` + shm heartbeat check.

**Steps:**
1. Replace file polling with `waitpid()`:

```zig
// supervisor.zig — NEW monitor loop
fn monitorLoop(meta: *fd_tickoni_meta_t) void {
    while (true) {
        // Detect child death via waitpid()
        var status: c_int = 0;
        const pid = POSIX.waitpid(-1, &status, WNOHANG);
        
        if (pid > 0) {
            // Find tile_id by matching against meta.tile_pid[]
            const tile_id = findTileByPid(meta, pid);
            if (tile_id != ULONG_MAX) {
                meta.tile_pid[tile_id] = 0;  // clear PID
                // Respawn this tile
                respawnTile(meta, tile_id);
            }
        }
        
        // Optional: check heartbeats for hung tiles
        // If heartbeat[i] is stale (>2× housekeeping interval), 
        // the tile is alive but stuck — log WARNING
    }
}
```

2. Replace `.ready` file polling. Tile readiness is now:
   - **Alive:** `meta.tile_pid[tile_id] > 0` (process exists)
   - **Responsive:** `meta.heartbeat[tile_id]` is recent
   - **Ready:** tile completed its `unprivileged_init` and entered run loop

3. Implement `findTileByPid(meta, pid)` — linear scan of `meta.tile_pid[]` (8 entries, trivial).

4. Implement `respawnTile(meta, tile_id)` — `exec()` the tile binary with the same shm key. Config is still in shm (no file reads). Supervisor sets `meta.tile_pid[tile_id] = new_pid`. Increment `meta.respawn_gen`.

**Verification:** Supervisor detects tile death via `waitpid()` within ~100ms. Respawns tile correctly. Stale heartbeat detected for hung tiles. Zero disk I/O in monitor loop.

**Status:** ✅ DONE — Supervisor monitor loop rewritten. `waitpid(WNOHANG)` replaces `.ready` file polling. Tile death detection via `meta.tile_pid[]` array. Hung tile detection via stale `meta.heartbeat[]`. Respawn via `exec()` with same shm key — config already in shm. Zero disk I/O in monitor loop.

## Task 5: Add shutdown coordination — graceful tile shutdown via shm

**Problem:** Firedancer tiles shut down by setting `fseq` to `STEM_SHUTDOWN_SEQ` (ULONG_MAX - 1). Tickoni needs a similar mechanism that works across process boundaries.

**Steps:**
1. The `shutdown_request` bitmask in `tickoni_meta_t` already handles this (defined in Task 0):
   - Supervisor sets bit `i` in `meta.shutdown_request` to request shutdown of tile `i`
   - Tile polls `meta.shutdown_request` in its run loop (Firedancer pattern: `STEM_CALLBACK_SHOULD_SHUTDOWN`)
   - When bit is set, tile sets its own `allow_shutdown = 1` and breaks its run loop

2. Supervisor shutdown flow:
   ```
   SIGTERM received → supervisor sets meta.shutdown_request = 0xFF → 
   supervisor waits for all PIDs to exit via waitpid() →
   supervisor tears down shm if needed
   ```

3. Each tile's run loop:
   ```c
   // In stem's STEM_CALLBACK_SHOULD_SHUTDOWN callback:
   if (meta->shutdown_request & (1UL << tile_id)) {
       tile->allow_shutdown = 1;
       return 1; // break run loop
   }
   ```

**Verification:** SIGTERM to supervisor triggers graceful shutdown of all tiles within timeout. No `SIGKILL` needed under normal conditions.

**Status:** ✅ DONE — Shutdown coordination implemented via `meta.shutdown_request` bitmask. Supervisor sets bitmask on SIGTERM, tiles poll it in `STEM_CALLBACK_SHOULD_SHUTDOWN`. `allow_shutdown = 1` set on tile, run loop breaks. Supervisor waits for all PIDs to exit via `waitpid()`. SIGKILL fallback after timeout (preserved from existing supervisor).

## Risk assessment

| Risk | Impact | Mitigation |
|------|--------|-----------|
| `tickoni_meta_t` size exceeds workspace allocation | Tiles fail to join | Footprint calculated at compile time; workspace allocation includes both `fd_topo_footprint()` and `tickoni_meta_footprint()`. |
| Supervisor crash loses shm state | All tiles restart from same state | shm is workspace-backed — survives supervisor restart. Tiles rejoin existing shm, read `launch_spec[]` from shm. |
| Tile reads stale heartbeat (race between supervisor check and tile write) | False positive "hung tile" detection | Use 2× housekeeping interval threshold. Housekeeping runs at ~10ms, threshold at ~20ms. Safe margin. |
| `waitpid()` on sandboxed tiles in PID namespaces | Firedancer uses `CLONE_NEWPID` for sandboxed tiles | Tickoni supervisor runs in the same PID namespace as tiles (Firedancer pattern). `waitpid(-1)` works. If sandbox requires namespace isolation, use `pidfd_getfd()` instead. |
| Existing integration tests regress | CI breaks | All existing tests pass through `just test-integration-tk`. Run them after each task. |

## Notes

- **Firedancer alignment:** This migration brings Tickoni's orchestration in line with Firedancer's proven pattern: config in shm, heartbeat in shm, zero disk I/O for control flow. The only new component is the supervisor's `waitpid()`-based respawn loop, which has no Firedancer equivalent because Firedancer is crash-only.
- **Log I/O is intentional:** File writes for logging and audit/event persistence remain. Only *orchestration* I/O is eliminated. Firedancer writes logs to a pipe fd (not disk) from tiles; Tickoni supervisor can do the same.
- **Sandbox compatibility:** After this migration, Tickoni can run in read-only filesystems (container images, sandboxed environments) because orchestration requires zero disk writes. Only log output and audit persistence need writable paths.
- **Firedancer's diag tile vs Tickoni's supervisor:** Firedancer's `fd_diag_tile` reads `/proc/<pid>/task/<tid>/stat` to detect dead threads within a single process. Tickoni's supervisor uses `waitpid()` to detect dead child processes. Both are shm-based for metrics reporting. The detection mechanism differs because Firedancer uses threads, Tickoni uses processes — but the shm heartbeat pattern is identical.
