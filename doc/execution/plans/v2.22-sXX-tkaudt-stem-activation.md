# Activate tkaudt stem tile — step-by-step plan

> **Status:** Plan only — not yet executed.
> **Prerequisite:** Step 0 baseline must pass before any changes.
> **Scope:** Wire `TK_AUDIT_RUN` from `tk_audit_stem.c` into the supervisor's execution path for tkaudt, verify each step independently, then clean up dead process-mode code.
> **Root cause of previous regression:** Task 5 deleted `audit_stage.zig` / `audit_sink.zig` before the stem tile was ever activated — removing the only code that was actually running.

### What is actually running
```
supervisor.startPaymentPipelineProcess()
  → __tile-run (main.zig line 91)
    → tile_main.run() → tile_process.run()
      → tile_registry.findById("tkaudt").process_fn()
        → tkaudtProcess() → runAuditProcess()   ← process-mode loop
```

### What is dead code
`tile_run.c`'s `tile_is_audit()` → `TK_AUDIT_RUN` → `stem_run()` path is **never called** from the execution path. `fd_topo_run_tile()` (the Firedancer runner) is never invoked by the supervisor for tkaudt — the supervisor uses `__tile-run` (Zig self-exec) which goes through the registry's process-mode dispatch.

- `audit_stage.zig` still exists (line 1-56)
- `audit_sink.zig` still exists (line 1-111)
- `process.zig` still has `runAuditProcess()` (line 239-267)

- The cleanup plan's own Task 5 says "✅ DONE (2026-10-28)" — this is the stale claim that caused the regression

### Why the cleanup plan's Task 5 caused a regression
Task 5 deleted `audit_stage.zig` and `audit_sink.zig` — the only code the production path actually used. The stem tile was compiled but never activated. Deleting the only-live code = breaking everything.

### Step 3: Wire the stem tile into the child binary

**Goal:** Make the supervisor spawn tkaudt via the stem path instead of the process-mode path.

**The change:**

1. Add a `__stem-run` subcommand to `main.zig` (similar to `__tile-run` but calls Firedancer's run loop):
   ```
   if (std.mem.eql(u8, cmd, "__stem-run")) {
       const run_dir = if (arg_count > 1) args[1] else std.process.exit(1);
       // bootstrap → join workspace → find topology from shm → find own tile → call fd_topo_run_tile()
   }
   ```

2. Update the supervisor's spawn loop (`startPaymentPipelineProcess`) to detect tkaudt tile (name `audit_tile`) and exec with `__stem-run` instead of `__tile-run`:
   ```
   if (tile.name == "audit_tile") argv_buf[1] = "__stem-run";
   else argv_buf[1] = "__tile-run";
   ```

3. The `__stem-run` path joins the workspace, finds the topology from shared memory, finds its own tile entry, and calls `tk_topo_run_tile_simple(topo_ptr, tile_ptr)` — which dispatches to `TK_AUDIT_RUN` → `stem_run()`.

**Key insight:** The topology is already created in shared memory by the supervisor's `topo_build.build()`. The child process needs to:
   1. Join the workspace (already done in `tile_process.run()`'s bootstrap)
   2. Find the topology object in the workspace
   3. Find its own tile entry
   4. Call `fd_topo_run_tile()` with the stem tile's `fd_topo_run_tile_t`

**Verification:**
- Build succeeds
- The existing integration test that goes through the supervisor still passes (tkaudt now uses stem mode)
- The standalone stem tile test from Step 2 still passes (tests stem tile directly, unaffected)

**Risk:** Medium — changes the runtime path for tkaudt. The Step 2 test is critical: if it passes, we know the stem tile code is correct, so if the integration test fails we know the wiring is wrong, not the stem code.

## Why this is different from the previous attempt

1. **Stem tile is verified BEFORE any production code changes** (Step 2 writes an independent test that exercises stem callbacks directly).
2. **Nothing is deleted until the stem tile is proven working in production** (Steps 2-4 must pass before Step 5).
3. **`audit_stage.zig` and `audit_sink.zig` stay alive** for the sequential test path even after the stem tile is active — needed for `mod.zig`'s tests.
4. **Each step has a clear pass/fail gate.** If Step 2 fails, we stop — we know the stem tile code has bugs before touching production.
