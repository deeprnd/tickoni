# Refactor: Consolidate Tickoni build scripts

**Status:** Plan — verified 2025-08-31, ready for execution
**Created:** 2025-08-29
**Updated:** 2025-08-31
**Scope:** Clarify ownership boundary between Firedancer matrix build and Tickoni runtime build; remove stale references; eliminate the stale `contrib/build/deps.sh` copy; clean CI path filters.

---

## Problem Statement

`contrib/build/` and `contrib/setup/` have blurry boundaries. Three stale files in `contrib/build/` are never called by Tickoni justfile or CI. One file (`build.sh`) belongs to Firedancer upstream's CI matrix and must stay. One file (`deps.sh`) is a stale copy already maintained in `contrib/setup/helpers/`. The plan consolidates by clarifying ownership, removing dead code, and cleaning CI references.

Key principle: **Firedancer's CI matrix build (`build.sh`) stays**. Tickoni's runtime build stays separate. Only stale/dead artifacts are removed.

### Ownership boundary

```
Firedancer upstream CI (build.sh):
  └── contrib/build/build.sh  — matrix orchestrator, gcc/clang discovery,
      per-machine/per-target iteration, deps install, logging.
      Used by Firedancer's own CI; kept as upstream-owned copy.

Tickoni runtime build (justfile → fd-build-lib.sh/zigw.sh):
  ├── justfile build-tk-*     → zigw.sh → zig build
  ├── justfile build-fd-*     → fd-build-lib.sh → fd_build_fd() → make
  ├── justfile test-*         → zigw.sh / fd-build-lib.sh + make
  └── contrib/build/*         — Tickoni runtime build scripts
```

### How justfile actually routes

All Tickoni build recipes use the justfile dispatcher:

```
build-tk-* → bash contrib/build/zigw.sh build -Dfd-lib-dir=...
build-fd-* → bash contrib/build/fd-build-lib.sh <blddir> <cc> [extras]
test-unit-fd-* → bash contrib/build/fd-build-lib.sh <blddir> <cc> test
test-unit-tk-* → bash contrib/build/zigw.sh build -Dtest=true ...
```

No justfile recipe calls `build.sh` or `contrib/build/deps.sh`.

## Risks and Mitigations

1. **Firedancer's standalone build needs deps.sh.** Firedancer's own build process calls `contrib/setup/helpers/deps.sh` directly (not via Tickoni). This is correct — the orchestrator does the same thing. No wrapper needed.

2. **build.sh ownership.** `contrib/build/build.sh` is Firedancer's CI matrix driver. It lives in this repo as a maintained copy. Any changes to the upstream version should be synced, but it is not Tickoni code and should not be modified here without explicit direction.

3. **CI path filters.** CI workflows that use broad `contrib/build/` path filters will correctly trigger on remaining files (`fd-tk-libs.sh`, `zigw.sh`, etc.). The only stale filter is `contrib/build/deps.sh$` in `build-tk.yml` line 31, which is harmless noise but should be cleaned up.

4. **Orchestrator.py dependency.** All setup recipes now depend on `orchestrator.py`. If this script changes, all `setup-fd-deps-*` lanes are affected. This is intentional — the orchestrator is the single entry point for Firedancer setup.
