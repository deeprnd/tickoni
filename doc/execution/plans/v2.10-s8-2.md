# Refactor: Consolidate contrib/build/ into orchestrator.py

**Status:** Plan — ready for execution
**Created:** 2025-08-29
**Updated:** 2025-08-31

---

## Problem

`contrib/build/` has 12 files: 4 dead scripts never called by Tickoni, 6 redundant shell wrappers around Firedancer's Makefile, 1 CPU-isolation wrapper duplicating platform-agnostic logic, and 1 test runner that belongs in `contrib/test/`.

All of it can be replaced by one Python orchestrator + one JSON config + strategy modules. Same pattern as `contrib/setup/orchestrator.py` + `tool-versions.json`.

---

## Proposed Structure

```
contrib/build/
  build-config.json          # Data: targets, platforms, compilers, libs, source sets
  orchestrator.py            # CLI: build-fd, build-tk, coverage
  strategies/
    __init__.py              # Strategy registry
    linux.py                 # Linux: trivial make/ar resolution
    macos.py                 # macOS: llvm-ar resolution
    windows.py               # Windows: clang discovery, space-in-path, libuuid_stub
  GNUmakefile                # Firedancer-owned (stays)

contrib/test/
  run_test_series.sh         # Moved from contrib/build/
```

### Build orchestrator API

```
python3 orchestrator.py build-fd <target> <mode>
  target: fd-tickoni-fd
  mode: libs, test, cov
  Builds FD libs. mode=test also builds unit-test binary.
  mode=cov builds with llvm-cov EXTRAS (coverage instrumentation).

python3 orchestrator.py build-tk [fd-lib-dir]
  Compiles Tickoni Zig exe via zig build.
  Requires build-fd to have been run first (manifests must exist).

python3 orchestrator.py --dry-run build-fd fd-tickoni-fd test
  Shows what command would run without executing.
```

**Key principle:** The build orchestrator only compiles artifacts. It never runs tests. Test execution belongs in `contrib/test/` and in justfile recipes.

### Strategy modules

Each strategy implements:

```python
class PlatformStrategy:
    def resolve_make(self) -> str     # Find GNU make
    def resolve_ar(self) -> str       # Find ar (macOS: llvm-ar)
    def pre_build(self, target: str) -> dict                      # Returns env vars, compiler paths
    def post_build(self, target: str, mode: str) -> None  # Windows: write manifests, compile libuuid_stub
```

- `strategies/linux.py` — trivial: returns PATH binaries
- `strategies/macos.py` — resolve llvm-ar from Homebrew opt paths
- `strategies/windows.py` — clang discovery with x86intrin.h check, space-in-path symlink, libuuid_stub compilation

## Justfile Changes

All build recipes become thin wrappers calling the orchestrator. Test recipes keep their `make run-unit-test` step (execution, not build):

```
# Before
build-fd-linux-x86-gcc:
    bash contrib/build/fd-build-lib.sh fd-tickoni-fd gcc

test-unit-fd-linux-x86-gcc:
    bash contrib/build/fd-build-lib.sh {{ fd_tickoni_build }} gcc-12 test "" ""
    {{ make }} -f contrib/build/GNUmakefile -j"{{ cpu_count }}" MACHINE=tickoni_fd BUILDDIR={{ fd_tickoni_build }} \
        LDFLAGS_EXE="-Wl,-z,shstk" run-unit-test TEST_OPTS="--page-sz normal -j 3"

# After
build-fd-linux-x86-gcc:
    python3 contrib/build/orchestrator.py build-fd fd-tickoni-fd libs

test-unit-fd-linux-x86-gcc:
    python3 contrib/build/orchestrator.py build-fd {{ fd_tickoni_build }} test
    {{ make }} -f contrib/build/GNUmakefile -j"{{ cpu_count }}" MACHINE=tickoni_fd BUILDDIR={{ fd_tickoni_build }} \
        LDFLAGS_EXE="-Wl,-z,shstk" run-unit-test TEST_OPTS="--page-sz normal -j 3"
```

The `make run-unit-test` part stays — it's test execution, not build. The orchestrator only handles compilation.
