# Refactor: Separate `contrib/setup/` (install) from `contrib/build/` (compile)

**Status:** Plan — verified 2025-08-31, ready for execution
**Created:** 2025-08-29
**Scope:** `contrib/setup/` = INSTALL only · `contrib/build/` = COMPILE only
**Goal:** Clear ownership — setup installs 3rd-party tools and system packages, build compiles and links Firedancer and Tickoni source.

---

## Problem Statement

`contrib/setup/` and `contrib/build/` have blurry boundaries. The current plan merges build into setup, which inverts the responsibility:

- `contrib/setup/` should be **INSTALL ONLY** — installs system packages, 3rd-party dependencies (OpenSSL, RocksDB, Snappy), dev toolchains (Zig, compilers), and dev tooling.
- `contrib/build/` should be **BUILD ONLY** — compiles, links, and produces Firedancer libs and Tickoni Zig binaries. No 3rd-party building.
- Third-party tools (OpenSSL, RocksDB, Snappy, Zig) are installed once by setup; build never builds them.

The key principle: **third-party builds don't belong in the build folder.** They can always be swapped with a package-manager install. The build folder is for Firedancer and Tickoni source only.

### `contrib/build/` files that are **never called by Tickoni**

- `build.sh` — Pure Firedancer CI matrix. No justfile recipe, no CI workflow references it.
- `deps-bundle.sh` — Firedancer redistribution packaging. Tickoni doesn't redistribute deps.
- `ci-run-build-tk.sh` — Calls `just build-tk` with a `tee` to temp log. CI calls `just build-tk` directly; this wrapper is redundant.
- `deps.sh` — **Misplaced.** This is install logic (system package check, git fetch, OpenSSL build). It already lives at `contrib/setup/helpers/deps.sh`. The copy in `contrib/build/` is stale.

### How justfile actually routes (updated from original plan)

The original plan assumed `setup-fd-deps-*` recipes called `contrib/build/deps.sh` directly. They don't — they all route through the orchestrator:

```
setup-fd-deps-linux-x86-gcc   → python3 contrib/setup/orchestrator.py fd
setup-fd-deps-linux-x86-clang → python3 contrib/setup/orchestrator.py fd
setup-fd-deps-linux-arm-gcc   → python3 contrib/setup/orchestrator.py fd
setup-fd-deps-macos-x86       → python3 contrib/setup/orchestrator.py fd
setup-fd-deps-macos-arm       → python3 contrib/setup/orchestrator.py fd
```

The orchestrator internally calls `contrib/setup/helpers/deps.sh`. No direct `deps.sh` references in justfile.

### CI path filter cleanup only

The only stale reference in CI is one path filter in `build-tk.yml`:

```yaml
# .github/workflows/build-tk.yml line 31
paths: '...contrib/build/deps.sh$)'
```

This is stale noise — `contrib/build/deps.sh` is not a real Tickoni build artifact. CI workflows that reference `contrib/build/` broadly (like `build-fd.yml`, `tests-long.yml`, `tests-xlong.yml`) are fine as path filters since they match the actual build scripts.

### No files move between folders

The key decision: **no files migrate between setup and build**. Both folders already own the right scripts. The refactor is:

1. Delete unused files from `contrib/build/` (`build.sh`, `deps-bundle.sh`, `ci-run-build-tk.sh`)
2. Delete the stale `contrib/build/deps.sh` (it already exists in `contrib/setup/helpers/`)
3. Update CI path filter in `build-tk.yml` to remove stale `contrib/build/deps.sh` reference

## Risks and Mitigations

1. **Firedancer's standalone build needs deps.sh.** Firedancer's own build process calls `contrib/setup/helpers/deps.sh` directly (not via Tickoni). This is correct — the orchestrator does the same thing. No wrapper needed.

2. **CI path filters.** CI workflows that use broad `contrib/build/` path filters will correctly trigger on remaining files (`fd-tk-libs.sh`, `zigw.sh`, etc.). The only stale filter is `contrib/build/deps.sh$` in `build-tk.yml` line 31, which is harmless noise but should be cleaned up.

3. **Orchestrator.py dependency.** All setup recipes now depend on `orchestrator.py`. If this script changes, all `setup-fd-deps-*` lanes are affected. This is intentional — the orchestrator is the single entry point for Firedancer setup.
