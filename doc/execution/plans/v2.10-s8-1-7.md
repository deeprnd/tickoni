## Call Chain Analysis

### deps.sh callers

`justfile` does **not** call `deps.sh` directly. The `fd-deps-*` justfile recipes call `contrib/build/orchestrator.py` with mode=libs or mode=test, which internally builds FD libs. `deps.sh` is the legacy Firedancer dep builder — it's called explicitly by users or CI lanes that need Firedancer deps (e.g. `just fd-deps-linux-x86-gcc`). It does NOT receive platform info from justfile — it detects its own.

### install-openssl.sh callers

Called from `just fd-openssl-*` recipes and `just setup-fd`. Both already pass `--platform` from justfile vars that come from platform.sh. The script sources platform.sh but its internal functions still use uname.

### tool-versions.json

Read by `contrib/setup/orchestrator.py`. The `idempotent_check` is a shell string executed via subprocess. The orchestrator already detects platform via `contrib/setup/platform.py` → `contrib/platform.sh`, so it has platform info available.

### run_unit_tests_dynamic.sh callers

**justfile lines 408-409:** `dynamic-test-opts:` recipe sources it.
**justfile line 429:** `test-unit-fd-linux-x86-gcc` calls `eval "$(bash contrib/test/run_unit_tests_dynamic.sh | grep ...)"`.

User's correct observation: this should NOT be called directly from justfile. It should be wrapped through `contrib/test/orchestrator.py` like all other test infrastructure.

## Plan

### Phase 1: Migrate install-openssl.sh

**File:** `contrib/setup/helpers/install-openssl.sh`

The script already sources platform.sh and uses `$(tk_os)` at the dispatch point. The build functions (`build_linux`, `build_macos`, `build_windows`) need to use `$(tk_arch)` instead of `$(uname -m)`.

**Changes:**

1. **Line 95:** Replace `"$(uname -m)"` with `"$(tk_arch)"` in the echo message.
2. **Line 98:** Replace `host_arch="$(uname -m)"` with `host_arch="$(tk_arch)"`. Note: `tk_arch` returns `x86` or `arm`, but the case statement on line 104 checks `x86_64|i686`. Need to map: `x86` → match both `x86_64` and `i686` patterns. Fix: change case to check `"${host_arch}"` against `x86` instead of `x86_64|i686`.
3. **Line 149:** Replace `"$(uname -m)"` case check. Same mapping issue — change `x86_64` to `x86`.
4. **Line 190:** Replace `"$(uname -m)"` with `"${FD_WINDOWS_ARCH:-$(tk_arch)}"`. Same mapping for line 196: `arm64|aarch64` → `arm`.

**Verify:** Run `bash contrib/setup/helpers/install-openssl.sh --prefix /tmp/test-openssl` (dry run or skip actual build) — the dispatch at line 314 uses `tk_os()` which is already correct. The arch mapping is the key change.

### Phase 2: Migrate deps.sh

**File:** `contrib/setup/helpers/deps.sh`

deps.sh does NOT source platform.sh. It needs to be added.

**Changes:**

1. **After line 8**, add: `source "$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")/../../platform.sh" && pwd)"` — this mirrors how install-openssl.sh sources it.
2. **Line 11:** Replace `OS="$(uname -s)"` with `OS="$(tk_os)"`. Note: `tk_os` returns `linux`, `macos`, `windows` — but the case statement on line 12 checks `Darwin`, `Linux`, `MINGW*`. Update the case to match normalized values:
   - `macos)` → replaces `Darwin)`
   - `linux)` → replaces `Linux)`
   - `windows)` → replaces `MINGW*|MSYS*|CYGWIN*)`
3. **Line 52:** Replace `"$(uname -m)"` check with `tk_arch`. Change `x86_64` to `x86`.
4. **Line 524:** Replace `"$(uname -m)"` with `"${FD_WINDOWS_ARCH:-$(tk_arch)}"`. Update line 547 to check `arm` instead of `arm64|aarch64`.

**Verify:** The check function (line 381+) uses `$OS` to dispatch to `check_macos_pkgs`, `check_windows_pkgs`, or distro-specific checks. Since `tk_os` returns normalized names (`linux`, `macos`, `windows`), the case dispatch changes handle this.

### Phase 3: Migrate tool-versions.json

**File:** `contrib/setup/tool-versions.json`

The `idempotent_check` for `make` is:
```json
"case \"$(uname -s 2>/dev/null)\" in Darwin) command -v gmake ;; *) command -v make ;; esac"
```

This is a shell string executed by `build_check` in `contrib/setup/install/checks.py`. The orchestrator already has platform info — it detects it once via `contrib/setup/platform.py`.

**Approach:** Move Darwin gmake detection out of JSON entirely and into orchestrator.py logic.

**Changes:**

1. **tool-versions.json line 419:** Simplify the `idempotent_check` to just `command -v gmake || command -v make`. This always works — it finds gmake on Darwin (which is just a symlink to make on Homebrew) and make on Linux. The Darwin-specific gmake distinction is unnecessary for an idempotency check because:
   - Homebrew make on macOS IS gmake (brew installs `make` which IS `gmake`)
   - The `command -v gmake` check is already satisfied by brew's make
   - On Linux, `command -v gmake` fails but `command -v make` succeeds
   - So `command -v gmake || command -v make` is correct and uname-free

**Verify:** Run `python3 contrib/setup/orchestrator.py --dry-run build` and confirm make passes idempotency check on all platforms.

### Phase 4: Migrate run_unit_tests_dynamic.sh through orchestrator.py

**File:** `contrib/test/run_unit_tests_dynamic.sh`
**File:** `contrib/test/orchestrator.py`
**File:** `justfile`

**Problem:** `run_unit_tests_dynamic.sh` is called directly from justfile (line 429: `eval "$(bash contrib/test/run_unit_tests_dynamic.sh ...)"`). This is wrong — all test infrastructure should pass through `contrib/test/orchestrator.py`.

**The script's actual purpose:** Dynamically compute TEST_OPTS (page size, page count, job count) and LDFLAGS_EXE based on available system RAM and CPU cores. This is resource-detection logic, not OS detection per se.

**Changes:**

1. **run_unit_tests_dynamic.sh:**
   - Replace `uname -qDar` on lines 24 and 40 with `tk_os` from platform.sh.
   - Source platform.sh at the top: `source "$(dirname -- "${BASH_SOURCE[0]}")/../platform.sh"`
   - Replace the BSD sysctl guards with `tk_os` dispatch:
     - Line 24: Instead of `sysctl &>/dev/null && uname -qDar`, use: `case "$(tk_os)" in macos) sysctl -n hw.memsize ;; esac`
     - Line 40: Same pattern for CPU cores.

2. **orchestrator.py:** Add a new `dynamic-test-opts` command:
   ```python
   def dynamic_test_opts(self):
       """Run dynamic resource detection and output TEST_OPTS + LDFLAGS_EXE."""
       from infra.dynamic_test_opts import run_dynamic_test_opts
       return run_dynamic_test_opts()
   ```

3. **infra/dynamic_test_opts.py:** New file that contains the logic from run_unit_tests_dynamic.sh as a Python function returning a dict `{"TEST_OPTS": "...", "LDFLAGS_EXE": "..."}`. This eliminates the shell script entirely for orchestrator.py callers.

4. **justfile changes:**
   - Remove the `dynamic-test-opts` recipe (line 408-409) — it's no longer needed since the orchestrator handles it.
   - Replace `eval "$(bash contrib/test/run_unit_tests_dynamic.sh | grep ...)"` with:
     ```
     export TEST_OPTS := `python3 contrib/test/orchestrator.py dynamic-test-opts 2>/dev/null | grep '^TEST_OPTS=' | cut -d= -f2- | tr -d '"'`
     export LDFLAGS_EXE := `python3 contrib/test/orchestrator.py dynamic-test-opts 2>/dev/null | grep '^LDFLAGS_EXE=' | cut -d= -f2- | tr -d '"'`
     ```
   - Or better: have the Python function print the values and justfile evals them.

**Note on backward compatibility:** `run_unit_tests_dynamic.sh` should remain as a shell-compatible shim for direct justfile use (in case other recipes source it), but it should delegate to platform.sh internally. The orchestrator path is the primary path.

## Risks

- **deps.sh case dispatch changes:** The current case uses raw OS names (`Darwin`, `Linux`, `MINGW*`). After switching to `tk_os()`, these become `macos`, `linux`, `windows`. Need to verify all downstream references to `$OS` and `$ID` variables are updated consistently.
- **tk_arch normalization:** `tk_arch` returns `x86`/`arm` (normalized), not `x86_64`/`aarch64`. All case arms that checked raw arch values need updating. This is a one-time migration but affects multiple conditional branches.
- **tool-versions.json idempotent_check simplification:** `command -v gmake || command -v make` works because Homebrew's `make` IS `gmake` (brew doesn't install separate `gmake`). On Linux, `gmake` may not be installed but `make` will be. This is correct but worth verifying on each platform.
- **orchestrator.py dynamic-test-opts:** The Python resource detection needs to replicate the shell logic faithfully. Need to handle macOS `sysctl -n hw.memsize` and `sysctl -n hw.ncpu` correctly.
