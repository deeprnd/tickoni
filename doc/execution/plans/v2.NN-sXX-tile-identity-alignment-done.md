# Align TileDescriptor with Firedancer tile identity model

> **Status:** Plan only — not yet executed.
> **Root cause:** TileDescriptor.id is a 6-char string (`TileId`) while TileDescriptor.name is a free-form `[]const u8`. Firedancer uses `ulong id` (positional index) + `char name[7]` (dispatch key). Our names exceed 6 chars ("ingest_tile"=11, "normalize_tile"=14, "audit_tile"=10), overflowing Firedancer's `char name[7]` buffer. Channel wiring uses TileId strings that get looked up by name via an unnecessary indirection loop. tile_infos construction panics when it parses a 10-char name as TileId (max 6 chars).
>
> **Fix:** Make TileDescriptor.id a `usize` (positional index, like Firedancer's id). Make TileDescriptor.name a `TileId` (6-char dispatch name, like Firedancer's name[7]). Channels already use TileId — they wire correctly after this change.

### Step 6: Update topo_build.zig — remove id→name lookup loop

**Goal:** Remove the O(n²) per-channel lookup loop. Use `t.name.slice()` directly for Firedancer registration.

**File:** `src/tickoni/runtime/topo_build.zig`

**Changes:**
1. **Tile registration** (line 254-258): Already uses `t.name` (from prior fix attempt). Keep as-is but remove `tileIdToName` helper if unused.

2. **Channel wiring** (line 316-334): Replace the lookup loop with direct name use:
   ```zig
   // Before: for (topo_desc.tiles) |t| { if (t.id.eql(ch.src_id)) src_name = t.name; ... }
   // After: find tile by name matching ch.src_id (since name IS the dispatch key now)
   ```
   
   Actually, since `Channel.src_id` is now the same as `TileDescriptor.name`, the lookup simplifies to:
   ```zig
   for (topo_desc.tiles) |t| {
       if (t.name.eql(ch.src_id)) src_name = t.name;
       if (t.name.eql(ch.dst_id)) dst_name = t.name;
   }
   ```
   Or even better: since `ch.src_id` IS the dispatch name, and `t.name` IS the dispatch name, we can just use `ch.src_id` directly as the Firedancer tile name (no lookup needed).

3. **tile_infos construction** (line 438-460): Replace `tile.TileId.parse(name_buf[0..len])` with direct TileId from the descriptor:
   ```zig
   // Before: parse name from Firedancer topo → TileId.parse(name) — panics on >6 chars
   // After: use the descriptor's name directly (already TileId)
   ```

4. **Remove** `tileIdToName()` helper — no longer needed (name IS TileId now).

5. **Remove** `tile_name_buf` buffers — no longer needed for conversion.

**Verification:** Compile — should succeed after this step.

**Risk:** Medium — this is the main logic change. Verify channel wiring produces correct Firedancer tile indices.

## Why this is correct

1. **Firedancer's model is `ulong id` + `char name[7]`** — our `id` was a string TileId (6-char), and `name` was a free-form string. They're swapped from Firedancer's perspective.

2. **TileId (6-char string) IS Firedancer's name** — it's bounded to match `char name[7]`. The channel wiring that uses `TileId` for `src_id`/`dst_id` is correct — it wires by dispatch name.

3. **Firedancer's `id` is a positional `ulong`** — auto-incrementing, never used for dispatch. Our `id` was also a string but used for channel wiring (incorrectly).

4. **After alignment:**
   - `TileDescriptor.id: usize` = Firedancer's `fd_topo_tile_t.id` (positional)
   - `TileDescriptor.name: TileId` = Firedancer's `fd_topo_tile_t.name[7]` (dispatch key)
   - `Channel.src_id: TileId` = dispatch name (same as `TileDescriptor.name`)
   - No lookup loop needed — `ch.src_id` IS the tile's dispatch name

5. **No Firedancer code changes needed** — we align our data model to match what Firedancer expects.
