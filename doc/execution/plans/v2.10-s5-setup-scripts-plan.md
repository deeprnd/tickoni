# V2.10.S5: contrib/setup/ Folder — Platform Setup Scripts

## Goal

Create `contrib/setup/` with one shell/PowerShell script per supported machine
variation. Developers run `bash contrib/setup/linux-x86-gcc.sh` (or the single
`just setup-env` command) to install everything a lane needs before building
or testing. CI calls the same scripts so developer and CI installs are
provably identical. Recipes are wired into `justfile` so `just setup-env` is
the single entry point.

## Supported Variations

| Script path | Platform | Arch | Compiler |
|---|---|---|---|
| `linux-x86-gcc.sh` | Linux | x86_64 | gcc-12 |
| `linux-x86-clang.sh` | Linux | x86_64 | clang-18 |
| `linux-arm-gcc.sh` | Linux | aarch64 | gcc-14 |
| `macos-x86.sh` | macOS (15, 26) | x86_64 | clang (Xcode) |
| `macos-arm.sh` | macOS (15, 26) | arm64 | clang (Xcode) |
| `windows-x86.ps1` | Windows | x86_64 | clang (LLVM) |
| `windows-arm.ps1` | Windows | arm64 | clang (LLVM) |

A bare `just setup-env` (in justfile) auto-detects platform using `uname` and
`contrib/setup/helpers/detect-windows-arch.sh` (moved from `contrib/`) and
routes to the correct `setup-` recipe. No separate dispatcher scripts in the
repo — justfile handles routing. If/when V2.10.S1 lands `contrib/platform.sh`,
the justfile recipe will switch to call it.

## Folder Structure

```
contrib/setup/
  zig-version             # Single source of truth for Zig version (e.g. "0.16.0")
  linux-x86-gcc.sh
  linux-x86-clang.sh
  linux-arm-gcc.sh
  macos-x86.sh
  macos-arm.sh
  windows-x86.ps1
  windows-arm.ps1
  helpers/
    common.sh               # Shared POSIX functions (log, check tool, install zig, install firedancer-deps)
    common.ps1              # Shared Windows PowerShell functions
    install-zig.py          # Moved from contrib/install-zig.py — official Zig binary installer wrapper
    detect-windows-arch.sh  # Moved from contrib/detect-windows-arch.sh — Windows arch normalization
    firedancer-deps.sh      # Thin wrapper around .github/actions/deps/deps.sh
```

## Design Principles

1. **One source of truth.** Scripts are the single source of truth for what tools
   a lane needs. CI's `setup-public-gh-runner/action.yml` is converted to a thin
   wrapper that calls `just setup-*`, which calls the same scripts.
2. **Setup may use sudo.** The V1.21 no-sudo constraint applies to daily
   operations (build, test, quality, security). Setup is a one-time privileged
   operation — it runs `sudo` where needed (apt-get, system packages, cmake
   install) without restriction. Daily dev after setup does not need sudo.
3. **Idempotent.** Every script checks before installing. Re-running is a no-op
   if tools are already present.
4. **Transparent.** Each script echoes what it's doing, exits non-zero on any
   failure, and leaves the user with a clear error message about which tool
   failed and why.

## Script Responsibilities

### lane scripts (linux-x86-gcc.sh, etc.)

Each lane script installs the tools for that specific platform+arch+compiler
combination. They source `helpers/common.sh` (or `helpers/common.ps1` on
Windows) and call the helper functions.

Contents of each lane script:

```
1. Source common helpers
2. Set compiler-specific vars (CC, CXX, gcc_version)
4. Install Zig via helpers/install-zig.py with version from `contrib/setup/zig-version`
4. Install OS package manager tools (GNU make on macOS, LLVM on Windows)
5. Install Firedancer deps via helpers/firedancer-deps.sh
6. Install lane-specific tools (shellcheck, pre-commit, gitleaks, kcov for
   coverage lanes, buf, etc.)
7. Print summary of what was installed
```

### helpers/common.sh

Shared POSIX functions sourced by all POSIX lane scripts:

- `log_info(msg)` — print a timestamped info line
- `log_error(msg)` — print a red error line to stderr
- `tool_exists(name)` — check if a tool is on PATH
- `ensure_zig()` — call helpers/install-zig.py with version from `contrib/setup/zig-version`
- `ensure_firedancer_deps()` — call helpers/firedancer-deps.sh with compiler
- `ensure_gitleaks()` — install gitleaks (system package on Linux, Homebrew on
  macOS, scoop/choco on Windows)
- `ensure_kcov()` — install kcov from source (only for coverage lanes)
- `ensure_shellcheck()` — install shellcheck (system package / Homebrew)
- `ensure_precommit()` — install pre-commit via pipx (user-level, no sudo)
- `ensure_buf()` — install buf via bufbuild/buf-install (user-level)

### helpers/install-zig.py (moved from contrib/install-zig.py)

Reads Zig version from `contrib/setup/zig-version`. Passes `--version` from the
file. On Windows ARM, passes `--target x86_64-windows` to install the x64
binary (stable under emulation). Single source of truth — update `zig-version`
once and all platforms + CI pick it up automatically.

### helpers/firedancer-deps.sh / firedancer-deps.ps1

Thin wrapper around `.github/actions/deps/deps.sh` that:
- Sets `CC` and `CXX` env vars
- Sets `FD_AUTO_INSTALL_PACKAGES=1`
- Calls `check`, then `fetch install`
- Calls `contrib/deps-bundle.sh`

### helpers/common.ps1

PowerShell equivalent of common.sh for Windows lane scripts. Uses `Write-Host`
for logging, `Test-Command` for tool checks.

## Test Infrastructure (NOT moved — stays in contrib/test/)

These scripts handle runtime model serving and testing, not developer setup.
They stay in `contrib/test/` and are called by CI/test runners:

|---|---|
| `contrib/test/ensure_llama_cpp.sh` | Clones + builds llama.cpp locally |
| `contrib/test/ensure_llama_cpp_win.sh` | Windows variant with MSVC/SDK setup |
| `contrib/test/ensure_hf_model.sh` | Downloads GGUF model from HuggingFace |
| `contrib/test/run_system_model_tests.sh` | Orchestrates ensure → server → zig test |

## justfile Integration

### New recipes:

```
# Single entry point — detects platform and routes to the correct setup script
# Uses uname (Linux/macOS) and contrib/setup/helpers/detect-windows-arch.sh (Windows)
# until contrib/platform.sh (V2.10.S1) lands, then this switches to call it.
setup-env:
    @#!/usr/bin/env bash
    @set -euo pipefail
    os="$(uname -s | tr '[:upper:]' '[:lower:]')"
    arch="$(uname -m)"
    case "$os" in
        linux)
            case "$arch" in
                x86_64) just "setup-linux-x86-gcc" ;;
                aarch64|arm64) just "setup-linux-arm-gcc" ;;
                *) echo "unsupported Linux arch: $arch" >&2; exit 1 ;;
            esac ;;
        darwin)
            case "$arch" in
                x86_64) just "setup-macos-x86" ;;
                arm64) just "setup-macos-arm" ;;
                *) echo "unsupported macOS arch: $arch" >&2; exit 1 ;;
            esac ;;
        *)
            # Assume Windows — use detect-windows-arch.sh
            win_arch="$(bash contrib/setup/helpers/detect-windows-arch.sh 2>/dev/null || echo x86_64)"
            case "$win_arch" in
                x86_64) just "setup-windows-x86" ;;
                arm64) just "setup-windows-arm" ;;
                *) echo "unsupported Windows arch: $win_arch" >&2; exit 1 ;;
            esac ;;
    esac
    # Note: defaults to gcc compiler. Users who need clang
    # should call `just setup-{os}-{arch}-clang` explicitly.

# Linux
setup-linux-x86-gcc:
    bash contrib/setup/linux-x86-gcc.sh

setup-linux-x86-clang:
    bash contrib/setup/linux-x86-clang.sh

setup-linux-arm-gcc:
    bash contrib/setup/linux-arm-gcc.sh

# macOS
setup-macos-x86:
    bash contrib/setup/macos-x86.sh

setup-macos-arm:
    bash contrib/setup/macos-arm.sh

# Windows
setup-windows-x86:
    pwsh -File contrib/setup/windows-x86.ps1

setup-windows-arm:
    pwsh -File contrib/setup/windows-arm.ps1
```

### Existing justfile changes:

The `setup-public-gh-runner` composite action is updated to call:
```yaml
- name: Run platform setup
  shell: bash
  run: |
    os="${{ runner.os == 'Linux' && 'linux' || runner.os == 'macOS' && 'macos' || 'windows' }}"
    arch="${{ runner.arch == 'ARM64' && 'arm' || 'x86' }}"
    compiler="${{ inputs.compiler }}"
    if [ "$os" = "linux" ] && [ "$compiler" = "clang" ]; then
      just "setup-${os}-${arch}-clang"
    else
      just "setup-${os}-${arch}-gcc"
    fi
```

## Maintenance

- Each lane script is self-contained and sourceable. Changes to a single lane
  should not affect others.
- Shared logic lives in helpers/. If a helper needs changing, review all lane
  scripts for compatibility.
- The `setup-windows.ps1` at `.github/actions/setup-public-gh-runner/scripts/`
  is the existing CI Windows bootstrap script. New Windows lane scripts call it
  rather than re-implementing its logic. When that script is updated, Windows
  lane scripts automatically benefit.
- `contrib/setup/zig-version` controls the Zig version everywhere — no need to
  hardcode versions in setup scripts. Update the single file and all lanes + CI
  pick it up automatically.
- `contrib/platform.sh` (V2.10.S1, not yet created) will eventually be the
  single source of truth for platform detection. Until then, the `setup-env:`
  recipe uses `uname` + `detect-windows-arch.sh`. When S1 lands, just update
  the recipe to call `contrib/platform.sh` instead.

## Open Decisions

**D1 — Windows package manager:** Windows has no universal package manager. The
scripts should prefer scoop (user-level, no admin) as the primary installer,
falling back to chocolatey or winget if scoop is not present. LLVM can be
installed via scoop (scoop install llvm) or via the existing
`setup-windows.ps1` (which uses chocolatey).

**D2 — kcov on macOS:** kcov requires building from source with cmake. Can
use `sudo make install` to `/usr/local` for simplicity.

**D3 — Pre-commit/buf:** These are Python/Rust tools. Use pipx (Python user
install) and buf build's official installer respectively — both work without
sudo on all platforms.

**D4 — Idempotency checks:** Each tool installation step must check existence
before proceeding. `tool_exists()` checks PATH, Zig checks the install
directory, deps.sh uses its own cache key.
