### Specific issues

1. **Cov lane is 483 lines with 27 near-identical test blocks.**
   Every test does: `b.addTest(name, root_module)` + optional linkage +
   `cov_step.dependOn(&b.addInstallArtifact(test, {.dest_dir = .{ .override = .{ .custom = "cov" } }}))`.
   Zero data-driven structure. Adding a new cov test requires copy-pasting 14 lines.

2. **Unit lane is 964 lines with the same repetitive pattern.**
   Each of ~47 tests repeats `b.addTest(...)` + linkage call(s) + `test_step.dependOn(...)`
   + `run_cmd.addArtifactArg(...)`.

3. **Module graph duplicated between unit.zig and integration.zig.**
   Both files create `tkpoly_int_mod`, `model_int_mod`, `adapter_int_mod`,
   `tool_int_mod`, `replay_int_mod`, `investment_support_int_mod`,
   `investment_demo_test_mod` — the same 7+ modules with identical `b.createModule`
   calls and identical import graphs. ~400 lines of duplicate module creation.

4. **CovShared/CovTm in cov.zig duplicate Shared/TestModules.**
   `CovShared` has the same 15 shared-module fields as `Shared` from modules.zig.
   `CovTm` has the same 3 test-module fields as `TestModules` from test_modules.zig.
   Three struct definitions for the same data.

5. **"ballet.c" hardcoded in 5 locations across build-lib/.**
   - `lib/shims.zig:13` — `"ballet.c"` in shim_c_files
   - `lib/codec.zig:84` — `"src/tickoni/c_abi/shim/ballet.c"` in supervisor shim
   - `lib/codec.zig:105` — `"src/tickoni/c_abi/shim/ballet.c"` in codec shim
   - `lib/codec.zig:138` — `"src/tickoni/c_abi/shim/ballet.c"` in addTickoniCodecShim
   - `lanes/unit.zig:229` — inline comment (not a bug, but shows awareness of the problem)

6. **Strategy pattern applied at wrong granularity.**
   Each lane is a separate file (good) but the strategy functions are just long
   procedural loops — no spec data, no factory, no builder. The data-driven
   spec array design from v2.10-s2 was abandoned mid-implementation.

## GoF Patterns to Apply

### 1. Factory pattern for modules

**Problem:** 7+ identical module creation calls duplicated across unit.zig and integration.zig.

**Solution:** A `ModuleFactory` that encapsulates module creation logic.

```zig
pub const ModuleFactory = struct {
    b: *std.Build,
    shared: Shared,
    tm: TestModules,
    target: std.Build.ResolvedTarget,
    optimize: std.builtin.OptimizeMode,

    pub fn createTkpolyMod(self: *ModuleFactory) *std.Build.Module { ... }
    pub fn createModelMod(self: *ModuleFactory) *std.Build.Module { ... }
    pub fn createAdapterMod(self: *ModuleFactory) *std.Build.Module { ... }
    pub fn createToolMod(self: *ModuleFactory) *std.Build.Module { ... }
    pub fn createReplayMod(self: *ModuleFactory, tool_mod: *std.Build.Module) *std.Build.Module { ... }
    pub fn createInvestmentSupportMod(self: *ModuleFactory) *std.Build.Module { ... }
    pub fn createInvestmentDemoTestMod(self: *ModuleFactory, tool_mod: *std.Build.Module) *std.Build.Module { ... }
    // ... etc
};
```

Both unit.zig and integration.zig use the same `ModuleFactory` instance — no more duplication.

### 2. Spec-driven data model + Builder pattern

**Problem:** 483-line cov lane and 964-line unit lane are procedural loops.

**Solution:** Spec structs (from the original v2.10-s2 plan) + a `TestBuilder` that handles the repetitive `addTest + linkage + dependOn + install/run` sequence.

```zig
pub const TestSpec = struct {
    name: []const u8,
    source_file: []const u8,
    imports: []const ModuleImport,
    linkage: TestLinkage,
    action: TestAction,
};

pub const TestLinkage = packed struct(u8) {
    needs_codec: bool = false,
    needs_firedancer: bool = false,
    needs_topo_run: bool = false,
    needs_tile_run: bool = false,
    needs_libc: bool = false,
    _pad: u3 = 0,
};

pub const TestAction = enum { run, cov, system_run };

/// Builder handles: addTest, linkage, dependOn, addArtifactArg, installArtifact.
pub const TestBuilder = struct {
    b: *std.Build,
    shared: Shared,
    tm: TestModules,
    target: std.Build.ResolvedTarget,
    optimize: std.builtin.OptimizeMode,
    fd_lib_dir: []const u8,

    /// Register tests from spec array. Handles linkage and step wiring.
    pub fn registerTestLanes(self: *TestBuilder, specs: []const TestSpec, step: *std.Build.Step) void {
        for (specs) |spec| self.registerOne(spec, step);
    }

    fn registerOne(self: *TestBuilder, spec: TestSpec, step: *std.Build.Step) void {
        const t_mod = self.createTestModule(spec);
        const t = self.b.addTest(.{ .name = spec.name, .root_module = t_mod });

        // Apply linkage from spec
        if (spec.linkage.needs_codec) codec.linkTickoniCodec(self.b, t, self.fd_lib_dir);
        if (spec.linkage.needs_firedancer) firedancer.linkTickoniFiredancer(self.b, t, self.fd_lib_dir);
        // ... etc

        // Dispatch on action
        switch (spec.action) {
            .run => { step.dependOn(&t.step); self.b.step("run-tests").dependOn(&t.step); },
            .cov => { step.dependOn(&self.b.addInstallArtifact(t, .{.dest_dir = .{.override = .{.custom = "cov"}}}).step); },
            .system_run => { step.dependOn(&t.step); },
        }
    }
};
```

**Cov lane:** 483 lines → ~200 lines (spec array of ~30 entries at ~5 lines each + ~20 lines builder code).

**Unit lane:** 964 lines → ~600 lines (spec array for ~47 tests at ~7-8 lines each due to variable imports + ~50 lines for the 7 pre-created integration modules + ~20 lines builder code).

### 3. Template Method pattern for lane registration

**Problem:** Each lane file has its own `strategy()` function with slightly different wiring.

**Solution:** A base `TestLane` with template method `registerTests()`. Each lane overrides it.

```zig
pub const TestLane = struct {
    b: *std.Build,
    step: *std.Build.Step,
    // ... shared context
    pub fn register(self: *TestLane) void {
        // Default: no-op. Override in subclasses.
    }
    pub fn registerCovTests(self: *TestLane) void {
        // Default: use TestBuilder.registerTestLanes with .cov action
        self.test_builder.registerTestLanes(self.covSpecs(), self.step);
    }
};

pub const CovLane = struct {
    base: TestLane,
    pub fn register(self: *self) void { self.base.registerCovTests(); }
};
```

This is less critical than the spec/builder changes but makes it clearer how lanes differ.

### 4. Constant extraction for hardcoded strings

**Problem:** `"src/tickoni/c_abi/shim/ballet.c"` in 3 places in codec.zig.

**Solution:** Single constant in `shims.zig` (or codec.zig itself):

```zig
const ballet_c = "src/tickoni/c_abi/shim/ballet.c";
```

| Risk | Mitigation |
|------|-----------|
| TestBuilder adds indirection | It replaces ~1000 lines of procedural repetition. The indirection is the point. |
| Spec arrays are still large (~300 lines for unit) | Each entry is ~7 lines of structured data — much more reviewable than ~14 lines of procedural code per test. |
