# Story 8.3 — Refactor contrib/test folder — one way, setup-style

## Goal

Replace the current mixed collection of scripts in `contrib/test/` with the same
`tk-platform-toolchain` pattern used in `contrib/setup/` — one script per
platform/compiler pair, with a thin justfile dispatcher routing to them.

---

## Current state

Phase 1 (move 3rd-party provisioning to setup) is **DONE** — completed via
`doc/execution/plans/v2.10-s8-3-1-done.md` and committed as `6e9230418` + `077f2a8e7`.

What was moved to `contrib/setup/`:
- `ensure_llama_cpp.sh` → `contrib/setup/install/strategies/llama_cpp_build.py` (Python strategy, replaces shell script)
- `ensure_llama_cpp_win.sh` → merged into `llama_cpp_build.py` (cmake preset approach)

Current `contrib/setup/install/strategies/` now contains:
`apt.py`, `build.py`, `download.py`, `hf_model.py`, `llama_cpp_build.py`, `pip.py`,
`python_script.py`, `zig.py`, `none.py` — all registered in `__init__.py`.

installs llama.cpp and downloads the GGUF model via these strategies. CI justfile recipes
(`test-system-tk`, `test-system-tk-windows-*`) call `orchestrator.py llm-server` before tests.
