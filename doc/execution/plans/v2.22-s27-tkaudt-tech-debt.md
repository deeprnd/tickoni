## Issues

### 1. Duplicate `audit_consts.zig`

Two identical copies exist:

| File | Purpose |
|------|---------|
| `src/tickoni/codec/audit/audit_consts.zig` | Build-system registered module (`audit_consts`) — canonical source |
| `src/tickoni/tiles/payment_pipeline/audit_consts.zig` | **Unused duplicate** — imported via filesystem fallback |

**Consumers:**

| File | Import | Resolves to |
|------|--------|-------------|
| `codec/audit/hash.zig` | `@import("audit_consts.zig")` | `codec/audit/audit_consts.zig` (filesystem) |
| `payment_pipeline/audit_sink.zig` | `@import("audit_consts.zig")` | `payment_pipeline/audit_consts.zig` (filesystem) |

The build system registers only the `codec/audit/` copy as the `audit_consts` module.
The `payment_pipeline/audit_consts.zig` is loaded by Zig's filesystem fallback, not by
build-module resolution. Both are byte-identical (642 bytes each).

**Risk:** Future changes to one file silently diverge from the other, breaking hash
consistency between codec and audit_sink.

### 2. Stale comment in `process.zig`

`process.zig` L8 still references `audit_shared`:

```
/// src/tickoni/tiles/payment_pipeline/{runtime,audit_shared}.zig; only the
```

`audit_shared.zig` was deleted in step 4 of the dedup plan. This comment is stale
documentation — no code impact, just a correctness issue.

### 3. Constants file location (audit_consts.h vs audit_schema.h)

The dedup plan called for constants in `audit_schema.h`. They landed in a separate
`audit_consts.h`/`audit_consts.zig` pair instead.

**Assessment:** This is **not a bug**. The separation is actually better — it avoids
the self-import problem that `audit_schema.h` → translate-c → Zig would create (since
`audit_schema.h` defines types used by `audit_consts.zig` consumers). The current layout
is:
- `audit_consts.h` — C header with SipHash constants
- `audit_consts.zig` — Zig module mirroring C values (avoids translate-c self-import)
- `audit_schema.h` includes `audit_consts.h` (C dependency chain)

This is a plan deviation, not tech debt. Should be documented as an approved deviation.

### 4. PolicyOutcome approach deviation

The dedup plan called for `pub const PolicyOutcome = c_schema.PolicyOutcome` (direct
C re-export). Implementation uses:

```zig
pub const PolicyOutcome = enum(u8) {
    allow = 0,
    deny = 1,
    require_approval = 2,
    malformed_drop = 3,
    duplicate_drop = 4,
    escalate = 5,
    require_more_evidence = 6,
};

comptime {
    std.debug.assert(@backingInt(PolicyOutcome.allow) == c_schema.POLICY_ALLOW);
    // ... one assert per variant
}
```

**Assessment:** This is **not a bug**. The Zig enum with comptime asserts is
strictly better:
- Type-safe in Zig (not a bare `c_uint`/`c_uint8`)
- Compile-time verification against C values
- All existing enum usage continues to work
- No runtime change

This is an approved deviation. Should be documented.

### Step 1: Remove duplicate `audit_consts.zig` + wire build-module import

**File:** `src/tickoni/tiles/payment_pipeline/audit_consts.zig` — **delete**

**File:** `src/tickoni/tiles/payment_pipeline/audit_sink.zig` — change import

```zig
// Before:
const audit_consts = @import("audit_consts.zig");

// After:
const audit_consts = @import("audit_consts");
```

Zig resolves `@import("audit_consts.zig")` as a **filesystem path** relative to the
importing file's directory. This is what currently picks up the duplicate file. To use the
build-module canonical copy, we switch to `@import("audit_consts")` (no `.zig` suffix),
which resolves via the build-module registry.
