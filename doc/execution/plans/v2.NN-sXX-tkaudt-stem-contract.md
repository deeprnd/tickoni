# Plan: Bring tkaudt onto the fd_stem Callback Contract

**Status:** Done. Implemented with a simpler approach than this plan first
proposed — see "Approach as built" below; the original proposal is kept as
"Approach as planned" because the reasoning about the footprint hazard is
still the reason the simpler option was chosen.

**Goal:** Move `tkaudt`'s audit-record commit out of `DURING_FRAG` and into
`AFTER_FRAG`, so a fragment that `fd_stem` abandons as an overrun can no
longer append a record or advance the audit hash chain.

**Contract:** `doc/execution/contribution/tickoni.md`, "fd_stem Callback
Contract". Restated at the top of `src/tickoni/c_abi/shim/stem_helpers.h`.

## Why this is separate from the tknorm/tkdedu pass

`tknorm` and `tkdedu` stage into a scratch `PaymentMessage` that already
exists, so moving their commit work into `AFTER_FRAG` is a local edit with no
layout change. `tkaudt` has no staging buffer: `tk_audit_during_frag` builds
the `AuditEvent` directly into `ctx->audit_records[ctx->audit_count]`,
computes `record_hash`, and advances `ctx->prev_hash` and `ctx->audit_count`
— all before `fd_stem` re-checks the input sequence number.

Fixing that needs somewhere to stage, which changes
`tk_audit_scratch_footprint_tile()`. Scratch footprint changes are the hazard
documented in `tk_dedu_stem.c` ("Dedupe table size: explicit runtime layout
parameter"): the supervisor and every child must derive a byte-identical
layout, or objects after tkaudt's shift and the tile reads a corrupted
workspace. That deserves its own verified pass.

## Current defect

`src/tickoni/c_abi/shim/tk_audit_stem.c`, `tk_audit_during_frag`:

1. Reads the `PaymentMessage` from the input dcache.
2. Writes a fully-populated `AuditEvent` into the committed ring slot.
3. Computes `record_hash` and sets `ctx->prev_hash = record_hash`.
4. Advances `ctx->audit_count` and `ctx->audited`.
5. Applies `STK_EVENT_EXHAUSTED` and `stk_publish_progress`.

`fd_stem` then re-checks `this_in_mline->seq`. If the producer overran the
reader, the frag is abandoned — but steps 2-5 have already happened. The
audit log is append-only and hash-chained, so a record built from a torn read
cannot be withdrawn: `prev_hash` has moved and every later record chains onto
it. This violates the framework invariant that audit records are append-only
and hash-chained over authenticated events.

Severity note: the overrun path requires a producer that violates `fd_stem`
flow control, so this is latent rather than routinely reachable. It is still a
fail-open on unvalidated input, which the security posture in `AGENTS.md`
forbids.

## Approach as planned

1. Add a staging `PaymentMessage` to `tk_audit_ctx_t` (preferred over staging
   an `AuditEvent`: it is smaller, and it keeps hash computation on the
   commit side where `prev_hash` is read).
2. Extend `tk_audit_scratch_footprint_tile()` by one aligned
   `PaymentMessage`, and point `ctx->staged_msg` at it in
   `privileged_init` using the same single-resolution-point discipline the
   dedupe table uses — the footprint reservation and the pointer arithmetic
   must agree by construction.
3. `DURING_FRAG`: clear `stage_valid`, `stk_validate_frag`, copy the
   `PaymentMessage` into `ctx->staged_msg`, set `stage_valid`. Nothing else.
4. `AFTER_FRAG`: if `stage_valid`, build the `AuditEvent` from
   `ctx->staged_msg` into the ring slot, compute `record_hash`, advance
   `prev_hash`/`audit_count`/`audited`, apply `STK_EVENT_EXHAUSTED`, publish
   progress, clear `stage_valid`. No publish — `out_cnt == 0`.
5. Keep the ring-full guard (`audit_count >= TKAUDT_AUDIT_CAPACITY`) on the
   commit side.

## Approach as built

The staging buffer turned out to be unnecessary, and with it the footprint
change and its layout hazard.

1. `DURING_FRAG` builds the record into `ctx->audit_records[ctx->audit_count]`
   — the *next* slot, which is still uncommitted because `audit_count` has not
   advanced. Nothing observes that slot: not a later record's chain, and not
   `test_tkaudt_integration.zig`'s `auditRecords()`, which returns
   `records[0..audit_count]`. A fragment fd_stem abandons leaves only an
   unobserved slot that the next fragment overwrites.
2. `DURING_FRAG` leaves `seq`, `prev_hash` and `record_hash` unset, so the
   chain is read and advanced in exactly one place.
3. `AFTER_FRAG` stamps `seq` and `prev_hash`, computes `record_hash`, advances
   `prev_hash`, then commits by incrementing `audit_count` and `audited`,
   applies `STK_EVENT_EXHAUSTED` and publishes progress.
4. The only new state is a single `int32_t stage_valid`, and
   `tk_audit_scratch_footprint_tile()` is untouched.
5. The layout coupling that made this risky is gone rather than asserted.
   `test_tkaudt_integration.zig` used to hand-write `extern struct` mirrors of
   `tk_audit_ctx_t`, `AuditHeader`, `PolicyDecisionPayload` and `AuditEvent`
   — padding fields included — and locate the record array at
   `scratch + @sizeOf(AuditContext)`. Those mirrors are deleted. The tile now
   exposes `tk_audit_record_count` and per-field record accessors, so the C
   file is the only place that knows its own scratch layout, and
   `tk_audit_records_of()` is the single definition of the record-array
   offset, used by both `privileged_init` and the accessors. See "Stem Tile
   Test And FFI Pattern" in `doc/execution/contribution/tickoni.md`.
6. A cross-process trap surfaced while doing this: the first version of the
   accessors read `ctx->audit_records`, which is an address in the tile
   process. The supervisor maps the same workspace at a different base, so the
   integration test segfaulted. The accessors recompute the offset from the
   scratch base the caller passes in.

## Verification

1. Footprint parity → **done**: no footprint change was needed, and the new
   `_Static_assert` fails the build if `tk_audit_ctx_t` ever grows.
2. Hash chain unchanged for the non-overrun path → **done**: the existing
   `tkaudt_integration: Hash chain verification` test passes unchanged
   (`prev_hash[0] == 0`, `prev_hash[k] == record_hash[k-1]`, `seq[i] == i`,
   `records.len == event_count`).
3. Last event still committed → **done**: new test
   `tkaudt_integration: the final event is committed (event_count = 1)`.
4. Counters match committed records → **done**: new test
   `tkaudt_integration: committed record count matches the audited counter`.
5. Full lanes → **done**: `just test-unit-tk`, `just test-integration-tk`,
   `just test-integration-tk-infra`, `just quality-format-check-tk`,
   `just quality-lint-check-tk` all pass.

Not covered by a test: the overrun path itself. Reaching it needs a producer
that violates fd_stem flow control, which the integration lane cannot
produce. The guarantee rests on the callback contract and on `audit_count`
being the sole commit point.

## Ask before changing

The audit record schema, hash-chaining rule, and append-only behavior must not
change. This plan moves *when* a record is committed, not *what* a record is.
If the staging change appears to require a schema or chaining change, stop and
get guidance.
