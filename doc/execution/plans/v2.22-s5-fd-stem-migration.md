## Per-Tile Requirements

### Pipeline tiles (1-input or 0-input)

**Common callback pattern:**
- `should_shutdown` → read `stop_flag` (checked via cnc signal)
- `before_credit` → set `charge_busy`: 1 if output dcache full (producer tiles), 0 if ready
- `during_frag` → read fragment from input dcache via `chunk` → `laddr(wksp)` conversion, run decision logic, write to output dcache
- `after_credit` → set `poll_in`: 1 if input has more fragments, 0 if no more. Set `charge_busy`: 1 if output dcache full, 0 if flushed.

**GCtx fields available to callbacks (set during link joining in tile_process.zig):**
- `out_mcache`, `out_dcache_base`, `out_fseq` — output link handles
- `out_depth`, `out_mtu`, `out_next_seq` — output link metadata
- `in_mcache`, `in_fseq` — input link handles
- `in_depth`, `in_mtu`, `in_next_seq` — input link metadata
- `seen_keys`, `seen_hashes`, `seen_count` — dedup state (tkdedu only)
- `audit_log` — audit log pointer (tkaudt only)
- `stop_flag` — atomic bool, set to true on HALT
- `wksp_ptr` — workspace pointer for chunk→laddr conversion
- Counters: `produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`, `audited`

**Process.zig decision functions** (pure logic, reusable):
- `runIngestProcess` — generates synthetic events, publishes to output
- `runNormalizeProcess` — validates framing, increments pipeline_hops, publishes
- `runDedupeProcess` — checks seen_keys/seen_hashes, marks duplicates, publishes
- `runPolicyProcess` — policy decision (allow/deny/duplicate_drop), publishes
- `runAuditProcess` — appends to audit_log

The callbacks in tile_registry.zig should call these same decision functions with the GCtx state, or inline the decision logic directly. The key difference from the current while loops: instead of a `while(i < cfg.event_count)` that loops over all events, fd_stem calls the callbacks for each individual fragment. The callbacks process one fragment per call (or batch-process until dcache is full), and fd_stem handles the backpressure coordination.

### Non-pipeline tiles

**tkrepl (replay):** 0 inputs, 0 outputs. Only `before_credit` (poll replay source, feed to output via dcache if available) and `should_shutdown`. Similar to tkings but reads from a file instead of generating synthetic events.

**tkmetr (metric):** 0 inputs, 0 outputs. Only `before_credit` (poll HTTP server for metrics, write counters) and `should_shutdown`. Same pattern as Firedancer's fd_metric_tile.c.

**tkdiag (diag):** 0 inputs, 0 outputs. Only `before_credit` (periodic diagnostic snapshots) and `should_shutdown`.

## Task 1: Create `tk_stem.c` — C bridge between `fd_stem` and Tickoni

**File:** `src/tickoni/c_abi/shim/tk_stem.c` (DONE, 108 lines)

**Structure:**
```c
// tk_stem.c — bridges Firedancer fd_stem with Tickoni Zig tiles

#include "fd_util.h"
#include "fd_topo.h"
#include "fd_metrics.h"
#include "fd_tango.h"
#include "fd_stem.h"

/* Per-tile context placed in workspace at tile->tile_obj_id — populated by
   Tile's Zig code during privileged_init.  The fd_stem run loop reads the
   function pointers from this struct and dispatches into Zig. */
typedef struct tk_stem_ctx {
    void *                      zig_state;
    int   (*should_shutdown)(void *zig_state);
    void  (*before_credit)(void *zig_state, fd_stem_context_t *stem, int *charge_busy);
    void  (*during_frag)(void *zig_state, uint idx, ulong seq, uint sig, ulong chunk, uint sz, uint ctl);
    void  (*after_credit)(void *zig_state, fd_stem_context_t *stem, int *poll_in, int *charge_busy);
    void  (*metrics_write)(void *zig_state);
} tk_stem_ctx_t;
```

**What `tk_stem_run` does:**
1. Reads `tk_stem_ctx_t` from the workspace (same workspace fd_stem uses)
2. Runs `fd_stem`'s control loop
3. `fd_stem` calls back into the registered functions
4. When `SHOULD_SHUTDOWN` returns true, `fd_stem` returns
5. Control returns to Tickoni for heartbeat/halt-wait

**No per-tile code in `tk_stem.c`.** All tile logic is in Zig, called back through the C bridge.

## Task 4: Implement all 25 fd_stem callbacks for 5 pipeline tiles

**File:** `src/app/tickoni/tile_registry.zig` (lines 161-355 — current stub implementations)

**NOT DONE.** All 25 callbacks are stubs with `TODO (v2.22.S5.T3)` comments. Each stub does:
- `before_credit`: sets `charge_busy.* = 0` (never signals busy)
- `during_frag`: no-op (ignores all parameters)
- `after_credit`: sets `poll_in.* = 1`, `charge_busy.* = 0` (always claims input ready, output flushed)
- `metrics_write`: no-op
- `should_shutdown`: returns 0 (never shuts down)

**These are fundamentally incorrect.** They tell fd_stem that the tile is always ready and never busy, which means fd_stem will call the callbacks in a tight spin loop with zero backpressure awareness.

### Per-tile callback implementations:

**1. tkings (ingest) — 0 inputs, 1 output**

- `before_credit`: check output dcache for available space. If output dcache is full, set `charge_busy.* = 1` (fd_stem will not call during_frag). If space is available, set `charge_busy.* = 0`.
- `during_frag`: no-op (tkings is a producer tile, has no input to consume).
- `after_credit`: generate synthetic payment events and publish to output dcache. Check if output dcache has room — if full, set `charge_busy.* = 1`. If space available, publish the event. Set `poll_in.* = 1` (no input, always "ready"). Increment `g_ctx.produced`. Check `g_ctx.stop_flag` — if true, the tile should prepare to shut down.
- `metrics_write`: no-op (tkings counters are written via cnc app-region counters).
- `should_shutdown`: check `g_ctx.stop_flag` (set when cnc signal == HALT). Return 1 if stopping.

**2. tkrnorm (normalize) — 1 input, 1 output**

- `before_credit`: check input mcache for available fragments. If no input, `charge_busy.* = 0` (nothing to do, fd_stem won't call during_frag). If input available, `charge_busy.* = 0` (ready to process).
- `during_frag`: read fragment from input dcache using `chunk` → `laddr(wksp_ptr)`. Validate framing (call `payment_runtime.validFraming()`). Check for HALT (`g_ctx.stop_flag`). Validate and increment `pipeline_hops`, compute `event_hash`. Write validated fragment to output dcache via mcache/fseq coordination. Update counters (`normalized`, `invalid`).
- `after_credit`: set `poll_in.* = 1` if input has more fragments (check mcache), 0 otherwise. Set `charge_busy.* = 1` if output dcache full, 0 if flushed.
- `metrics_write`: no-op.
- `should_shutdown`: check `g_ctx.stop_flag`.

**3. tkdedu (dedupe) — 1 input, 1 output**

Same pattern as tkrnorm, but with dedup logic:
- `during_frag`: read input fragment, compute idempotency key + hash, check against `seen_keys`/`seen_hashes`. If duplicate, mark `msg.duplicate = true`. Otherwise, add to seen arrays (if `seen_count < cap`). Publish to output. Update `duplicates` counter.
- `after_credit`: set `poll_in.*` based on input availability, `charge_busy.*` based on output dcache fullness.

**4. tkpoly (policy) — 1 input, 1 output**

Same pattern as tkrnorm:
- `during_frag`: read input fragment. If already malformed_drop (from tkrnorm), preserve it. If duplicate, set `decision = .duplicate_drop`. If amount exceeds `policy_limit_cents`, set `decision = .deny`. Otherwise, set `decision = .allow`. Increment `allowed`/`denied` counters. Publish to output.
- `after_credit`: same as tkrnorm.

**5. tkaudt (audit) — 1 input, 0 outputs**

- `before_credit`: check input mcache for available fragments. If no input, `charge_busy.* = 0`. If input available, `charge_busy.* = 0`.
- `during_frag`: read input fragment, append to `audit_log` (via `g_ctx.audit_log`). Increment `audited` counter. Check HALT.
- `after_credit`: set `poll_in.* = 1` if input has more fragments, 0 otherwise. `charge_busy.* = 0` (no output to flush).
- `metrics_write`: no-op.
- `should_shutdown`: check `g_ctx.stop_flag`.

### Process mode vs fd_stem mode

The current `process.zig` functions (`runIngestProcess`, `runNormalizeProcess`, etc.) are designed for the old `g_ctx.work()` loop — they take `rt.link.Consumer`/`rt.link.Producer` handles and do a full while-loop over `event_count` messages.

The fd_stem callbacks must NOT call these process-mode functions. Instead, each callback should:
1. Do the per-fragment work (one fragment per call)
2. Write results to dcache/mcache via the handles in g_ctx
3. Let fd_stem handle the coordination (backpressure, sequencing, ordering)

The decision logic from `process.zig` (validFraming, event_hash computation, dedup comparison, policy decision, audit record building) is pure and reusable — it should be called from within the callbacks, not from the old loop functions.

## Architecture Decision: 1-process-N-threads vs N-processes

Firedancer runs 1-process-N-threads on Linux for P2P throughput. Tickoni runs N-processes for crash isolation. This is not a divergence — it's a deliberate tradeoff:

| Aspect | Firedancer (Linux) | Tickoni |
|---|---|---|
| Model | 1 process, N threads | N processes, 1 thread each |
| Isolation | Shared memory, signal-based | Process crash = tile crash (no spread) |
| Sandbox | seccomp/Landlock per tile | process_mode sandbox=none (hosted) |
| fd_stem | Universal loop for all tile types | One instance per tile process |
| Throughput | Maximized (no fork overhead) | Slightly higher per-tile overhead (crash isolation) |
| Reasoning | Validator needs max TPS | AI harness needs crash containment |
