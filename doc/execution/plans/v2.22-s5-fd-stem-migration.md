# Plan: Migrate Tickoni Tiles to fd_stem

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Replace all per-tile polling loops (8 existing pipeline tiles + metric tile) with a single `fd_stem` run loop. Each tile provides callbacks (`before_credit`, `during_frag`, `after_credit`, `metrics_write`, `should_shutdown`) instead of its own loop body.

**Architecture:**
- `fd_stem` is Firedancer's universal tile run loop — same code runs P2P, verify, pack, RPC, and metric tiles
- Tickoni tiles currently each have their own `while` loop in `tile_process.zig` → `rt.link.Consumer/Producer`
- We create a C bridge (`tk_stem.c`) that wraps `fd_stem` and calls back into Tickoni Zig tile logic
- On Linux: `fd_stem` runs via `fd_topo_run_tile()` (already used by Tickoni's shim)
- On macOS: fall back to Tickoni's existing per-tile loop (same code as before)

---

## Current State (Before Migration)

Each tile in `src/tickoni/tiles/payment_pipeline/process.zig` has:
```zig
fn runIngestProcess(cfg, cnc, wksp) void {
    while (i < cfg.event_count) {
        in.consume(&buf, ...);
        process_fragment(&buf);
        out.publish(&buf, ...);
        i += 1;
    }
    cnc.appCounterWrite(0, 1, 1); // metrics
}
```

This is the same pattern repeated 8 times (ingest, normalize, dedupe, policy, audit, replay, diag, metric). The only difference is:
- Pipeline tiles (ingest, norm, dedu, poly, audt): `consume()` → `process()` → `publish()`
- Replay tile (repl): processes from a file, no consumer links
- Diag tile (diag): no inputs, no outputs, just periodic snapshots
- Metric tile (metr): no inputs, no outputs, just HTTP server polling

## Task 1: Create `tk_stem.c` — C bridge between `fd_stem` and Tickoni

**Objective:** A single C file that includes `fd_stem.c` and provides callbacks for all tiles.

**File:** `src/tickoni/c_abi/shim/tk_stem.c` (new)

**Structure:**
```c
// tk_stem.c — bridges Firedancer fd_stem with Tickoni Zig tiles

#include "fd_stem.h"
#include "fd_stem.c"  // template — generates stem_run()

// Per-tile state stored in workspace (same workspace fd_stem uses)
typedef struct tk_stem_tile_ctx {
    void *zig_ctx;        // pointer back to tile's Zig state
    void (*before_credit_fn)(void *ctx, fd_stem_t *stem, int *busy);
    void (*during_frag_fn)(void *ctx, uint idx, ulong seq, uint sig, ulong chunk, uint sz, uint ctl);
    void (*after_credit_fn)(void *ctx, fd_stem_t *stem, int *poll_in, int *busy);
    void (*metrics_write_fn)(void *ctx);
    void (*should_shutdown_fn)(void *ctx);
} tk_stem_tile_ctx_t;

// Global callback registry indexed by tile ID
static tk_stem_tile_ctx_t tk_stem_registry[FD_TOPO_MAX_TILES];

// --- fd_stem callbacks (used by #include "fd_stem.c") ---

#ifdef STEM_CALLBACK_BEFORE_CREDIT
void STEM_CALLBACK_BEFORE_CREDIT(void *ctx, fd_stem_t *stem, int *charge_busy) {
    tk_stem_tile_ctx_t *tile_ctx = (tk_stem_tile_ctx_t *)ctx;
    if (tile_ctx->before_credit_fn)
        tile_ctx->before_credit_fn(tile_ctx->zig_ctx, stem, charge_busy);
}
#endif

#ifdef STEM_CALLBACK_DURING_FRAG
void STEM_CALLBACK_DURING_FRAG(void *ctx, uint idx, ulong seq, uint sig, ulong chunk, uint sz, uint ctl) {
    tk_stem_tile_ctx_t *tile_ctx = (tk_stem_tile_ctx_t *)ctx;
    if (tile_ctx->during_frag_fn)
        tile_ctx->during_frag_fn(tile_ctx->zig_ctx, idx, seq, sig, chunk, sz, ctl);
}
#endif

#ifdef STEM_CALLBACK_AFTER_CREDIT
void STEM_CALLBACK_AFTER_CREDIT(void *ctx, fd_stem_t *stem, int *poll_in, int *charge_busy) {
    tk_stem_tile_ctx_t *tile_ctx = (tk_stem_tile_ctx_t *)ctx;
    if (tile_ctx->after_credit_fn)
        tile_ctx->after_credit_fn(tile_ctx->zig_ctx, stem, poll_in, charge_busy);
}
#endif

#ifdef STEM_CALLBACK_METRICS_WRITE
void STEM_CALLBACK_METRICS_WRITE(void *ctx) {
    tk_stem_tile_ctx_t *tile_ctx = (tk_stem_tile_ctx_t *)ctx;
    if (tile_ctx->metrics_write_fn)
        tile_ctx->metrics_write_fn(tile_ctx->zig_ctx);
}
#endif

#ifdef STEM_CALLBACK_SHOULD_SHUTDOWN
int STEM_CALLBACK_SHOULD_SHUTDOWN(void *ctx) {
    tk_stem_tile_ctx_t *tile_ctx = (tk_stem_tile_ctx_t *)ctx;
    if (tile_ctx->should_shutdown_fn)
        return tile_ctx->should_shutdown_fn(tile_ctx->zig_ctx);
    return 0;
}
#endif

// Entry point: called by Tickoni instead of tk_tile_run()
void tk_stem_run(uint tile_id, void *tile_ctx_ptr,
                 void (*before_credit)(void*, fd_stem_t*, int*),
                 void (*during_frag)(void*, uint, ulong, uint, ulong, uint, uint),
                 void (*after_credit)(void*, fd_stem_t*, int*, int*),
                 void (*metrics_write)(void*),
                 int (*should_shutdown)(void*)) {
    // Register callbacks in global registry
    tk_stem_registry[tile_id] = (tk_stem_tile_ctx_t){
        .zig_ctx = tile_ctx_ptr,
        .before_credit_fn = before_credit,
        .during_frag_fn = during_frag,
        .after_credit_fn = after_credit,
        .metrics_write_fn = metrics_write,
        .should_shutdown_fn = should_shutdown,
    };

    // Run fd_stem with this tile's callbacks
    // (fd_stem's run() uses tk_stem_registry[tile_id] via ctx pointer)
    stem_run(&tk_stem_registry[tile_id]);
}
```

**What `tk_stem_run` does:**
1. Registers the tile's callback functions in a global table
2. Calls `stem_run()` from `fd_stem` with the tile's context pointer
3. `stem_run()` calls back into the registered functions via the global table
4. When `SHOULD_SHUTDOWN` returns true, `stem_run()` returns
5. Control returns to Tickoni for heartbeat/halt-wait

**No per-tile code in `tk_stem.c`.** All tile logic is in Zig, called back through the C bridge.

## Task 3: Modify `tile_process.zig` — register callbacks per tile

**File:** `src/tickoni/runtime/tile_process.zig`

**Change:** Replace the direct `work()` call with callback registration:

Current:
```zig
export fn tk_tile_run(cnc: ?*Cnc, wksp: ?*Wksp, ctx: ?*anyopaque) void {
    const state = @as(*PaymentPipelineState, @ptrCast(@alignCast(ctx)));
    var stop: bool = false;
    while (!state.replay_checked and !stop) {
        state.work();
        stop = signalQuery(cnc) == signal_halt;
        if (!stop) {
            signalNotify(cnc);
            backpressureWaits(cnc, &state.backpressure_waits);
        }
    }
}
```

New:
```zig
// Zig callback wrappers — these are passed to tk_stem_run() in C
fn tile_before_credit(ctx: ?*anyopaque, stem: ?*anyopaque, busy: *c_int) c_int {
    // Called before each credit check — tile can do work here
    _ = stem;
    return 0;
}

fn tile_during_frag(ctx: ?*anyopaque, idx: c_uint, seq: c_ulong, sig: c_uint,
                     chunk: c_ulong, sz: c_uint, ctl: c_uint) void {
    // Called for each new fragment — tile processes it here
    _ = ctx; _ = idx; _ = seq; _ = sig; _ = chunk; _ = sz; _ = ctl;
}

fn tile_after_credit(ctx: ?*anyopaque, stem: ?*anyopaque, poll_in: *c_int, busy: *c_int) void {
    // Called after credit check — tile can publish here
    _ = ctx; _ = stem; _ = poll_in; _ = busy;
}

fn tile_metrics_write(ctx: ?*anyopaque) void {
    // Called at shutdown — tile reports final counters
    _ = ctx;
}

fn tile_should_shutdown(ctx: ?*anyopaque) c_int {
    // Called each iteration — check HALT flag
    _ = ctx;
    return 0; // default: never shut down
}

export fn tk_tile_run(cnc: ?*Cnc, wksp: ?*Wksp, ctx: ?*anyopaque) void {
    const tile_id = get_tile_id_for_ctx(ctx); // determine which tile this is
    tk_stem_run(@as(c_uint, @intCast(tile_id)), ctx,
                tile_before_credit,
                tile_during_frag,
                tile_after_credit,
                tile_metrics_write,
                tile_should_shutdown);
    // After fd_stem returns (should_shutdown was true), do heartbeat/halt
    while (signalQuery(cnc) != signal_halt) {
        signalNotify(cnc);
    }
}
```

**Key point:** The `tk_tile_run` wrapper remains the same. Only the inner logic changes from `work()` loop to `tk_stem_run`.

## Task 4: Migrate each tile — remove loops, add callbacks

**Files:** `src/tickoni/tiles/payment_pipeline/process.zig` and `src/tickoni/tiles/*/process.zig`

**Migration pattern (applied to each of the 8 existing tiles):**

**Before (current):**
```zig
pub fn runIngestProcess(cfg: Config, cnc: *Cnc, wksp: *Wksp, state: *PaymentPipelineState) void {
    var i: usize = 0;
    while (i < cfg.event_count) : (i += 1) {
        var buf: [MAX_FRAGMENT_SZ]u8 = undefined;
        if (in.consume(&buf, &backpressure_waits, stop_flag)) |len| {
            process_fragment(&buf[0..len]);
            out.publish(&buf, len, &backpressure_waits, stop_flag);
        }
    }
    cnc.appCounterWrite(0, 1, 1); // produced
}
```

**After (with fd_stem):**
```zig
// Tile state passed via tk_stem_run's ctx pointer
fn before_credit_fn(ctx: ?*anyopaque, stem: ?*anyopaque, busy: *c_int) c_int {
    const state = @as(*PaymentPipelineState, @ptrCast(@alignCast(ctx)));
    // Check HALT
    if (signalQuery(state.cnc) == signal_halt) {
        state.stop_flag = true;
        return 1;
    }
    // Signal heartbeat
    signalNotify(state.cnc);
    // Any per-iteration setup (e.g., HTTP polling for metric tile)
    _ = stem; _ = busy;
    return 0;
}

fn during_frag_fn(ctx: ?*anyopaque, idx: c_uint, seq: c_ulong, sig: c_uint,
                   chunk: c_ulong, sz: c_uint, ctl: c_uint) void {
    const state = @as(*PaymentPipelineState, @ptrCast(@alignCast(ctx)));
    // Read fragment from dcache slot (same as current consume logic)
    var buf: [MAX_FRAGMENT_SZ]u8 = undefined;
    @memcpy(buf[0..sz], /* dcache slot */);
    // Process (same logic as current)
    process_fragment(&buf[0..sz], state);
    // Publish to output (same logic as current)
    out.publish(&buf, sz, &state.backpressure_waits, state.stop_flag);
    // Update counters (same as current)
    state.cnc.appCounterWrite(0, 1, 1);
}

fn should_shutdown_fn(ctx: ?*anyopaque) c_int {
    const state = @as(*PaymentPipelineState, @ptrCast(@alignCast(ctx)));
    // Stop when HALT or when all events processed
    return @intFromBool(
        signalQuery(state.cnc) == signal_halt or state.stop_flag
    );
}
```

2. **tknorm (normalize):** 1 input, 1 output. Standard `DURING_FRAG` → process → `AFTER_CREDIT` → publish.

3. **tkdedu (dedupe):** 1 input, 1 output. Same pattern as norm.

## Task 5: Handle metric tile (special case — HTTP server)

**File:** `src/tickoni/tiles/payment_pipeline/process.zig` (or `metric.zig` if extracted)

The metric tile uses `fd_stem` only for its `BEFORE_CREDIT` callback:

```c
// In tk_stem.c, the metric tile's BEFORE_CREDIT:
void metric_before_credit(void *ctx, fd_stem_t *stem, int *busy) {
    // Check HALT
    tk_stem_tile_ctx_t *tile_ctx = (tk_stem_tile_ctx_t *)ctx;
    if (tile_ctx->should_shutdown_fn(tile_ctx->zig_ctx))
        return;

    // Poll HTTP server — this is the metric tile's actual work
    *busy = fd_http_server_poll(ctx->metrics_server, 1);
}
```

No `DURING_FRAG`, no `AFTER_CREDIT`. Just `BEFORE_CREDIT` + `SHOULD_SHUTDOWN`.

This is exactly what Firedancer's `fd_metric_tile.c` does — it uses `fd_stem`'s `before_credit` callback for HTTP polling, with zero input/output links. The overhead of `fd_stem` is minimal for this case since it just loops calling the callback.

## Architecture Decision: 1-process-N-threads vs N-processes

Firedancer runs 1-process-N-threads on Linux for P2P throughput. Tickoni runs N-processes for crash isolation. This is not a divergence — it's a deliberate tradeoff:

| | Firedancer (Linux) | Tickoni |
|---|---|---|
| **Model** | 1-process, N-threads | N-processes |
| **Thread creation** | `pthread_create` | `std.process.spawn()` |
| **Stack allocation** | Huge pages (`MAP_HUGETLB`) | Normal pages |
| **CPU affinity** | Per-thread (`sched_setaffinity`) | Per-process (Linux only) |
| **Sandbox** | Per-thread (seccomp/landlock) | Per-process (Tickoni sandbox) |
| **Crash isolation** | Poor (one thread crashes → all die) | Good (supervisor restarts just the crashed tile) |
| **Cross-platform** | Linux-only | Linux, macOS, Windows |
| **Performance** | Optimized for Linux P2P throughput | Slightly slower startup, better isolation |

Firedancer's supervisor (`run.c`) also uses fork+exec to manage the overall runtime. The actual tile execution happens within threads. Firedancer could run tiles as separate processes — it just doesn't by default.

Tickoni's process-per-tile model is the right choice for its use case:
- **Crash isolation**: If one tile crashes (financial logic, agents, adapters), supervisor restarts just that tile. Others keep running.
- **Cross-platform**: Works on Linux, macOS, Windows. Firedancer's thread model is Linux-only.
- **Simpler lifecycle**: Supervisor owns everything, per-tile restart is just kill + spawn.

The tradeoff: slightly slower startup and more memory overhead, but much better crash isolation and cross-platform support.

## Risks and Mitigations

1. **`fd_stem` is Linux-only:** Mitigated by platform check in Task 6. On macOS, existing loops continue to work.

2. **Tile lifecycle mismatch:** `fd_stem`'s loop is infinite. Mitigated by `SHOULD_SHUTDOWN` callback that checks both HALT flag and per-tile "work complete" condition (e.g., `i < event_count`).

3. **Callback granularity:** `fd_stem` calls `DURING_FRAG` per-fragment. Existing code processes `cfg.event_count` events in a loop. Mitigated by tracking `event_count` in a tile-local variable in the callback.

4. **Platform parity:** On macOS, tiles use the old loop. This means the codebase has two code paths (fd_stem on Linux, per-tile loop on macOS). Mitigated by keeping the per-tile loop as a fallback until fd_stem is ported to non-Linux.

5. **Metric tile HTTP server:** The metric tile's HTTP server (`fd_http_server_poll`) must not block `fd_stem`'s polling loop. Mitigated by using non-blocking socket mode (default in Firedancer) and `fd_http_server_poll`'s timeout parameter (1ms).
