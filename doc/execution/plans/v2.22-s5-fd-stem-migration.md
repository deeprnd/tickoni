- On Linux: `fd_stem` runs with no-op stubs (spinning uselessly); real work runs in `tk_tile_run`'s loop
- On macOS/Windows: fall back to Tickoni's existing per-tile loop (same code as before migration)

## Task 1: Create `tk_stem.c` — C bridge between `fd_stem` and Tickoni

**Objective:** A single C file that includes `fd_stem.c` and provides callbacks for all tiles.

**File:** `src/tickoni/c_abi/shim/tk_stem.c` (DONE, 108 lines)

**Structure:**
```c
// tk_stem.c — bridges Firedancer fd_stem with Tickoni Zig tiles

#include "fd_util.h"
#include "fd_topo.h"
#include "fd_metrics.h"
#include "fd_tango.h"
#include "fd_stem.h"

/* Per-tile context placed in workspace at tile->tile_obj_id — populated by
   Tile's Zig code during privileged_init.  The fd_stem run loop reads the
   function pointers from this struct and dispatches into Zig. */
typedef struct tk_stem_ctx {
    void *                      zig_state;
    int   (*should_shutdown)(void *zig_state);
    void  (*before_credit)(void *zig_state, fd_stem_context_t *stem, int *charge_busy);
    void  (*during_frag)(void *zig_state, uint idx, ulong seq, uint sig, ulong chunk, uint sz, uint ctl);
    void  (*after_credit)(void *zig_state, fd_stem_context_t *stem, int *poll_in, int *charge_busy);
    void  (*metrics_write)(void *zig_state);
} tk_stem_ctx_t;
```

**What `tk_stem_run` does:**
1. Reads `tk_stem_ctx_t` from the workspace (same workspace fd_stem uses)
2. Runs `fd_stem`'s control loop
3. `fd_stem` calls back into the registered functions
4. When `SHOULD_SHUTDOWN` returns true, `fd_stem` returns
5. Control returns to Tickoni for heartbeat/halt-wait

**No per-tile code in `tk_stem.c`.** All tile logic is in Zig, called back through the C bridge.

## Architecture Decision: 1-process-N-threads vs N-processes

Firedancer runs 1-process-N-threads on Linux for P2P throughput. Tickoni runs N-processes for crash isolation. This is not a divergence — it's a deliberate tradeoff:

| Aspect | Firedancer (Linux) | Tickoni |
|---|---|---|
| Model | 1 process, N threads | N processes, 1 thread each |
| Isolation | Shared memory, signal-based | Process crash = tile crash (no spread) |
| Sandbox | seccomp/Landlock per tile | process_mode sandbox=none (hosted) |
| fd_stem | Universal loop for all tile types | One instance per tile process |
| Throughput | Maximized (no fork overhead) | Slightly higher per-tile overhead (crash isolation) |
| Reasoning | Validator needs max TPS | AI harness needs crash containment |
