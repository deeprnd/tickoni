# Plan: v2.10-s8-1-8 — YAML lint and spell checker

## Problem

The quality gate has no YAML linting enforcement in CI (commented out since the
original yamllint addition) and no spell checking at all. YAML configuration files
across the repo can silently drift into bad formatting. Markdown docs, config files,
and commit messages have no spell checking, allowing typos to accumulate.

## Goals

1. Enable yamllint on all YAML files (not just `.github/`).
2. Add cspell for markdown, YAML, and source-file comments.
3. Integrate both into the CI quality stage.
4. Fix all pre-existing issues so CI passes on first run.

## Current State

- yamllint 1.38.0 is installed and configured (`.yamllint`), passes on `.github/`
- `just quality-yaml-check-linux-x86` exists but only scans `.github/`
- `_ci-quality.yml` has the YAML check commented out with note: "YAML check disabled temporarily (lintyaml)"
- No cspell configuration or script exists anywhere
- No other YAML files exist outside `.github/` at repo root (pre-commit-config.yaml,
  dependabot.yml are inside `.github/`)

## Plan

### Phase 1: Expand yamllint scope and enable in CI

**Status: DONE**

**Scope:** All YAML files in the repo, excluding vendored/submodule content.

**Changes to `.yamllint`:**
- Keep the existing config (extends: relaxed, 2-space indent, trailing-spaces,
  new-line-at-end-of-file, no document-start required).
- The existing `ignore` list already excludes `node_modules/`, `build/`, `target/`,
  `zig-out/`. Add `opt/` to exclude vendored upstream code (openssl, rocksdb, etc.).
- Add `contrib/setup/` and `contrib/build/` to the ignore list if they contain
  vendor-pulled YAML; otherwise leave as-is.

**Changes to `justfile`:**
- Replace `quality-yaml-check-linux-x86` to scan the entire repo instead of
  just `.github/`:
  ```
  quality-yaml-check-linux-x86:
      yamllint -f parsable . --yaml-files "*.yaml" "*.yml"
  ```
  Or better, use a find-based approach to avoid scanning irrelevant dirs:
  ```
  quality-yaml-check-linux-x86:
      find . -name '*.yaml' -o -name '*.yml' \
        | grep -vE '^./(opt|node_modules|.zig-global-cache|build|target|zig-out)/' \
        | xargs yamllint -f parsable
  ```

- Add the recipe to `quality-lint-check-all` or create a new `quality-check-all`
  sequence. Since yamllint is a lint-level check (not format), add it alongside
  other lint steps.

**Changes to `_ci-quality.yml`:**
- Uncomment and restore the YAML check job.
- Update the command to the new scope.

**Files to modify:**
- `.yamllint` — add `opt/` to ignore list
- `justfile` — expand yamllint scope
- `.github/workflows/_ci-quality.yml` — uncomment YAML check

**Verify:** Run `yamllint` on the expanded scope manually before enabling in CI.

### Phase 2: Add cspell configuration

**Status: DONE**

**Tool:** cspell (Node.js, installable via `npm install -g cspell` or pip via
`cspell` package).

**Configuration:** `.cspell.json` at repo root with:

- **dictionary words** (custom dictionary, not exhaustive — just domain terms):
  - firedancer, tickoni, tkings, tknorm, tkdedu, tkcase, tkpoly, tkaudt, tkrepl,
    tkmetr, tkdiag, tkdisp, tkagnt, tkmodl, tktool, tkadpt, tkapi, tkexec,
    tkapi, tickoni, agentops, caseops, agentic
  - finance terms: notional, idempotency, canonicalize, dedupe, ledger, auditor,
    audittrail, secp256k1, secp256r1, tigerbeetle, duckdb
  - CI/infra terms: actionlint, shellcheck, yamllint, cspell, codeql, gitleaks,
    cbmc, litani, subagent, orchestrator, precommit
  - Platform/arch terms: arm64, x86_64, aarch64, macos, ubuntu, msys2, msvc, ucrt

- **language settings:**
  - `.md` files: `markdown`
  - `.yaml`/`.yml` files: `yaml`
  - `.zig` files: `zig` (for comments and string literals)
  - `.sh` files: `bash` (for comments)
  - `.py` files: `python` (for comments and docstrings)

- **global patterns to ignore:**
  - `opt/` directory (upstream vendored code)
  - `node_modules/`
  - `build/`, `target/`, `zig-out/`
  - `.zig-global-cache/`
  - Binary files (`*.bin`, `*.gz`, etc.)
  - Git-generated content (`.git/`)

- **ignore words from upstream (optional):**
  - Common words from openssl, rocksdb, etc. that will pollute results.

- Spell check runs on ubuntu-24.04 (needs cspell/npm install).

**tool-versions.json:**

- Add it to the quality dependencies.

### Execution Order

1. Expand yamllint scope in justfile and `.yamllint` (add opt/ to ignore)
2. Run yamllint on full scope — fix any violations
3. Create `.cspell.json` with custom dictionary
4. Install cspell and run on full scope
5. Fix all cspell violations (typos -> fix, domain terms -> dictionary)
6. Add recipes to justfile
7. Add to tool-versions.json
8. Update `_ci-quality.yml` — uncomment and add both checks
9. Update `quality-check-all` in justfile
10. Commit everything

### Risks

- **Spell checker noise:** cspell may flag many words in documentation. Must
  distinguish actual typos from domain terms that go into the custom dictionary.
- **CI runtime:** Adding two more matrix jobs adds ~2-3 minutes to quality stage.
  Acceptable trade-off for quality.
- **False positives:** Custom dictionary needs careful curation. Start with
  domain terms only, add on-demand.
