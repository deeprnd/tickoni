# Plan: Migrate tkdiag tile to fd_stem — minimal observer

**Status:** Implemented and verified (2026-11-19). See "Implementation record" at the end for where the code sketches below were corrected, the shutdown decision that supersedes the idle threshold in this plan, and what was run.

> **For Hermes:** Execute this plan task-by-task. Each task is self-contained — the build compiles after each one. Unit tests run in `test-unit-tk`; integration tests run in `test-integration-tk-infra`.

**Goal:** Migrate tkdiag (tile 7, index 7) from `launch_mode = .tile` to Firedancer's `fd_stem` callback lifecycle. tkdiag is an observer tile (0-in, 0-out) that reads diagnostic counters from shared state and writes them to CNC app-region slots 0/1. This follows the tkmetric pattern (delegates through an existing tile) but tkdiag has no Firedancer backend to delegate to — so we write a minimal self-contained stem tile.

**Scope:** Minimal cross-platform observer. Two CNC counters only. No /proc reading, no fan-in links, no HTTP, no fragment publishing. Fan-in and OS-level diagnostics are deferred to a future plan.

**Key files:**
- New C shim: `src/tickoni/c_abi/shim/tk_diag_stem.c`
- New shared header: `src/tickoni/c_abi/topo_run/tk_diag_stem.h`
- Modify: `src/tickoni/c_abi/shim/tile_run.c` (add tile_is_diag dispatch)
- Modify: `src/tickoni/c_abi/shim/topob.c` (add scratch footprint query)
- Modify: `src/app/tickoni/tile_registry.zig` (set launch_mode = .stem)
- Modify: `build-lib/lib/topo_run.zig` (add C file to addTickoniTopoRunShims)

### What's missing

The tkdiag stem tile needs to implement:

1. **Context struct** (`tkdiag_ctx_t`) — CNC pointer, idle_ticks counter, done flag
2. **Scratch layout** — `tkdiag_scratch_align()` = 8 (alignof of context), `tkdiag_scratch_footprint()` = sizeof(ctx) + alignment
3. **BEFORE_CREDIT callback** — Read crashed_tile and sandbox_failures from shared metrics system → write to CNC app-region slots 0/1, set done flag when idle threshold reached
4. **SHOULD_SHUTDOWN macro** — CNC HALT + idle threshold (10000 ticks)
5. **privileged_init** — Get ctx from scratch, init counters
6. **unprivileged_init** — Find CNC object, set ctx->cnc
7. **tkdiag_run entry point** — Get ctx from scratch, enter stem loop
8. **fd_topo_run_tile_t** — TK_DIAG_RUN with all callbacks wired + seccomp/fd allowlist
9. **Shared header** — Extern declaration for TK_DIAG_RUN, tk_get_diag_run_tile(), scratch footprint accessor
10. **Dispatch chain** — tile_is_diag() in tile_run.c
11. **Supervisor wiring** — launch_mode = .stem in tile_registry → supervisor auto-selects __stem-run
12. **Build wiring** — topo_run.shims, shims.zim, codec.zig, topob.c

### Key differences from tkmetric tile

Metric delegates through `fd_metric_tile.c` (Firedancer's HTTP server + Prometheus). tkdiag has no Firedancer backend — it is its own standalone tile with a minimal BEFORE_CREDIT polling loop. The structure is the same (observer, 0-in/0-out, CNC app-region writes) but tkdiag writes its own logic rather than delegating.

### Key differences from tkaudt

tkaudt is a pipeline tile (1-in, 0-out) with DURING_FRAG callbacks. tkdiag is an observer (0-in, 0-out) with only BEFORE_CREDIT — no fragment I/O at all. tkdiag is simpler than tkaudt.

## Task 1: Create tkdiag stem C files

### 1a: Create `src/tickoni/c_abi/shim/tk_diag_stem.c`

**Structure:**

```c
/* tk_diag_stem.c — Stem fd_stem tile for tkdiag.
 *
 * Tile behavior:
 *   - BEFORE_CREDIT: read crashed_tile and sandbox_failures from
 *     shared metrics system → write to CNC app-region slots 0/1
 *   - SHOULD_SHUTDOWN: CNC HALT + idle threshold (10000 ticks)
 *
 * Observer tile — 0 input links, 0 output links.
 * Same pattern as tkmetric but with custom logic (no Firedancer delegation).
 */

#define _GNU_SOURCE

#include "firedancer.h"
#include "audit_schema.h"
#include "../../../tango/cnc/fd_cnc.h"
#include "../../../util/fd_wksp.h"
#include "../../../util/fd_util.h"

#include <string.h>
#include <stddef.h>

/* Context — MUST be defined BEFORE STEM_CALLBACK_CONTEXT_TYPE */
typedef struct {
    /* CNC reference for shutdown detection */
    void     *cnc;

    /* Idle threshold tracking */
    long     idle_ticks;

    /* Tile pointer */
    fd_topo_tile_t const *tile;

    /* Done flag — set when idle threshold reached */
    int      done;
} tkdiag_ctx_t;

#define TKDIAG_CTX_ALIGN alignof(tkdiag_ctx_t)
#define TKDIAG_IDLE_THRESHOLD 10000L

/* Generate stem specialization */
#define STEM_NAME                         tkdiag
#define STEM_BURST                        (1UL)
#define STEM_LAZY                         ((long)10e6)
#define STEM_CALLBACK_CONTEXT_TYPE        tkdiag_ctx_t
#define STEM_CALLBACK_CONTEXT_ALIGN       TKDIAG_CTX_ALIGN
#define STEM_CALLBACK_BEFORE_CREDIT       tkdiag_before_credit
#define STEM_CALLBACK_SHOULD_SHUTDOWN(ctx) \
  ( (ctx)->done || \
    ( (ctx)->idle_ticks > TKDIAG_IDLE_THRESHOLD ) || \
    ( (ctx)->cnc && fd_cnc_signal_query( (fd_cnc_t *)(ctx)->cnc ) == FD_CNC_SIGNAL_HALT ) )

#include "../../../disco/metrics/fd_metrics.h"
#include "../../../disco/stem/fd_stem.c"

#undef STEM_NAME
#undef STEM_CALLBACK_CONTEXT_TYPE
#undef STEM_CALLBACK_CONTEXT_ALIGN
#undef STEM_CALLBACK_BEFORE_CREDIT
#undef STEM_CALLBACK_SHOULD_SHUTDOWN

/* ─── Scratch footprint ─── */

static ulong
tkdiag_scratch_align( void ) {
    return TKDIAG_CTX_ALIGN;
}

static ulong
tkdiag_scratch_footprint_tile( fd_topo_tile_t const * tile ) {
    (void)tile;
    return fd_ulong_align_up( sizeof(tkdiag_ctx_t), TKDIAG_CTX_ALIGN );
}

ulong
tkdiag_scratch_footprint( void ) {
    return tkdiag_scratch_footprint_tile( NULL );
}

/* ─── Callbacks ─── */

static void
tkdiag_privileged_init( fd_topo_t const * topo, fd_topo_tile_t const * tile ) {
    (void)topo;
    (void)tile;

    void * scratch = fd_topo_obj_laddr( (fd_topo_t *)topo, tile->tile_obj_id );
    tkdiag_ctx_t * ctx = (tkdiag_ctx_t *)scratch;

    ctx->cnc = NULL;
    ctx->idle_ticks = 0;
    ctx->done = 0;

    FD_LOG_NOTICE(( "tkdiag: privileged init ctx=%p", ctx ));
}

static void
tkdiag_unprivileged_init( fd_topo_t const *      topo,
                          fd_topo_tile_t const * tile ) {
    (void)topo;
    (void)tile;

    void * scratch = fd_topo_obj_laddr( (fd_topo_t *)topo, tile->tile_obj_id );
    tkdiag_ctx_t * ctx = (tkdiag_ctx_t *)scratch;

    /* Find CNC object for shutdown detection */
    ulong cnc_obj_id = tk_topo_find_tile_obj( (fd_topo_t *)topo, tile->id, "cnc" );
    if( cnc_obj_id != ULONG_MAX ) {
        ctx->cnc = fd_topo_obj_laddr( (fd_topo_t *)topo, cnc_obj_id );
    }

    FD_LOG_NOTICE(( "tkdiag: unprivileged init tile_id=%lu cnc=%p", tile->id, ctx->cnc ));
}

static void
tkdiag_before_credit( tkdiag_ctx_t * ctx,
                      fd_stem_t *    stem,
                      int *          charge_busy ) {
    (void)stem;

    /* Increment idle ticks */
    ctx->idle_ticks += 1;

    /* Read from shared metrics system (fd_metrics) and write to CNC app-region.
     * Index 0 = diag_crashed_tile, Index 1 = diag_sandbox_failures.
     * These values come from shared state written by the payment pipeline
     * diag worker (PaymentPipelineState.snapshotDiag()). */
    if( ctx->cnc ) {
        ulong * app_laddr = (ulong *)fd_cnc_app_laddr( (fd_cnc_t *)ctx->cnc );
        /* Write diag_crashed_tile (slot 0) and diag_sandbox_failures (slot 1)
         * from shared metrics. For now, these are read from the metrics system
         * which other tiles write into. A future version will read from
         * PaymentPipelineState snapshotDiag() directly. */
        app_laddr[0] = 0;  /* diag_crashed_tile — placeholder, set by supervisor */
        app_laddr[1] = 0;  /* diag_sandbox_failures — placeholder */
    }

    /* Set done flag when idle threshold reached */
    if( ctx->idle_ticks > TKDIAG_IDLE_THRESHOLD ) {
        ctx->done = 1;
    }

    *charge_busy = 0;
}

/* ─── Run entry point ─── */

static void
tkdiag_run( fd_topo_t *      topo,
            fd_topo_tile_t * tile ) {
    void * scratch = fd_topo_obj_laddr( topo, tile->tile_obj_id );
    tkdiag_ctx_t * ctx = (tkdiag_ctx_t *)scratch;

    tkdiag_run(topo, tile);  /* stem_run loop */
}

/* ─── fd_topo_run_tile_t ─── */

fd_topo_run_tile_t TK_DIAG_RUN = {
    .name                     = TILE_ID_TKDIAG,
    .keep_host_networking     = 0,
    .allow_connect            = 0,
    .allow_renameat           = 0,
    .rlimit_file_cnt          = 0,
    .rlimit_address_space     = 0,
    .rlimit_data              = 0,
    .rlimit_nproc             = 0,
    .for_tpool                = 0,
    .max_event_sz             = NULL,
    .populate_allowed_seccomp = NULL,
    .populate_allowed_fds     = NULL,
    .scratch_align            = tkdiag_scratch_align,
    .scratch_footprint        = tkdiag_scratch_footprint_tile,
    .loose_footprint          = NULL,
    .privileged_init          = (void (*)(fd_topo_t const *, fd_topo_tile_t const *))tkdiag_privileged_init,
    .unprivileged_init        = (void (*)(fd_topo_t const *, fd_topo_tile_t const *))tkdiag_unprivileged_init,
    .run                      = (void (*)(fd_topo_t *, fd_topo_tile_t *))tkdiag_run,
    .rlimit_file_cnt_fn       = NULL,
};

fd_topo_run_tile_t const *
tk_get_diag_run_tile( void ) {
    return &TK_DIAG_RUN;
}
```

**Pitfalls to watch:**
- No DURING_FRAG or AFTER_CREDIT — tkdiag has 0 input/output links. Only BEFORE_CREDIT.
- No fragment validation — no chunks to validate.
- CNC app-region writes are placeholders (0/0). The real values will be wired when the shared state path is connected. The supervisor reads these slots to get diagnostic state.
- No /proc reading — cross-platform by design.
- No seccomp/fd allowlist — observer tile with no external I/O beyond shared memory.

## Risks and Mitigations

1. **CNC app-region slot conflict:** The supervisor reads slots 0/1 from tkdiag's CNC for diag_crashed_tile and diag_sandbox_failures. If another tile writes to these slots, data corrupts. **Mitigation:** tkdiag is the sole writer to its own CNC app-region slots 0/1. The supervisor reads from tkdiag's CNC object specifically.

2. **Observer tile idle shutdown:** tkdiag has no input-driven lifecycle trigger. It exits solely on idle_ticks threshold. **Mitigation:** The idle threshold (10000 ticks) is sufficient for a diagnostic observer. In production, the supervisor's HALT signal will drive shutdown first.

3. **Scratch alignment mismatch:** If topob.c and the stem tile compute different scratch sizes, the topology won't build correctly. **Mitigation:** Both use `sizeof(tkdiag_ctx_t)` + alignment. The header exports `tkdiag_scratch_align()` and `tkdiag_scratch_footprint()` so there's a single source of truth.

4. **Non-Linux compilation:** The C shim uses `_GNU_SOURCE` but no Linux-specific APIs. **Mitigation:** All code is POSIX-compliant. The `#define _GNU_SOURCE` is included for Firedancer header compatibility (same as all other stem tiles).

## Critical Invariants

- **NEVER add fragment I/O to this tile.** It is an observer (0-in, 0-out). Fan-in is a future plan.
- **CNC app-region slots 0/1 are exclusively diag_crashed_tile / diag_sandbox_failures.** No other tile writes to these slots in tkdiag's CNC.
- **Tile name must match topology exactly.** Both `TK_DIAG_RUN.name` and `tile_is_diag()` must use `TILE_ID_TKDIAG` = `"tkdiag"`.
- **Launch mode drives supervisor dispatch.** `launch_mode = .stem` → `__stem-run`. This is the only Zig change needed for supervisor routing.
- **No external I/O.** The observer tile only reads shared memory and writes CNC app-region. No file I/O, no network, no /proc.

## Decisions recorded 2026-11-19

**Shutdown: CNC HALT only (owner decision).** The plan specified `SHOULD_SHUTDOWN` = CNC HALT or an idle threshold of 10,000 ticks, with a verification criterion that tkdiag "exits at idle threshold". The first implementation followed that and the threshold proved to count stem loop iterations, not time: a 0-input stem loop spins, so tkdiag stopped itself right after starting, where on the generic path it lived until HALT. "Risk 2" had assumed HALT would arrive first. The owner chose to follow the only other 0-input observer, `metric`, whose shutdown is HALT only (`fd_metric_tile.c`). Consequently:

- `tkdiag_ctx_t` holds only `cnc`; `idle_ticks`, `done` and `TKDIAG_IDLE_THRESHOLD` do not exist.
- This supersedes, in this plan: Gap Analysis items 1 and 4, the `SHOULD_SHUTDOWN` and `BEFORE_CREDIT` idle logic in the Task 1a sketch, the Task 8 criterion "exits at idle threshold" (now: stays running until HALT, then stops cleanly), and Risk 2.
- The same pattern in `tk_normalize_stem.c` (`idle_ticks > 10000L`) is dead code (never incremented) and was left alone; it is already listed in `doc/knowledge/tile-orchestration.md`.

**CNC liveness for every stem tile (owner decision, follow-up to the audit finding "no heartbeat at all").** A stem tile that never signals `RUN` is invisible to the supervisor's stale check, so a wedged or stopped tkdiag (or any other stem tile) looked healthy. Fixing tkdiag alone would have made it the only stem tile subject to staleness, so the owner chose one change for all nine stem tiles (tkaudt, tknorm, tkdedu, tkpoly, tkmodl, tkagnt, tkdisp, the tkcase/tktool/tkadpt `tk_pass_stem.c`, and tkdiag):

- `shim/stem_helpers.h` gains `stk_cnc_liveness`: one heartbeat write per call, and on the first call a compare-and-swap `BOOT -> RUN` that never overwrites a HALT. It takes the clock from `tk_monotonic_nanos()` and writes through `tk_cnc_heartbeat`, the units the Zig supervisor compares against.
- Each tile defines `STEM_CALLBACK_DURING_HOUSEKEEPING` as `stk_cnc_liveness( (ctx)->cnc )`. tkdiag's `unprivileged_init` and slot writes are unchanged.
- RUN is signalled from the loop, not the run entry. The first implementation signalled it from the run entry; the integration lane then showed every stem tile with a heartbeat about 500 ms old, because the stem's first `fd_tempo_tick_per_ns` call calibrates for about half a second between the run entry and the loop, so a 100 ms stale threshold would have classified every stem tile stale at boot.
- Supervisor CNC indexing (owner decision, found by the liveness tests): `ProcessState.cncs` is indexed by Firedancer tile index, but `handles`/`children` by topology position, and `topo_build` moves metric last, so tkdiag and metric swapped places and `refreshProcessHealth` paired tkdiag's handle with metric's CNC. A frozen tkdiag would have marked the metric tile stale instead. `ProcessState.tile_cnc_idx` now maps each position to its Firedancer index and is used by `refreshProcessHealth`, the HALT in `stopProcess`, the snapshot readers and the launch spec. Unit tests: `tile CNC indices ...` in `supervisor.zig`.
- Tests first: `test_stem_heartbeat.zig` (payment pipeline) and two tests in `test_tile_tkagnt.zig` (the 14-tile investment workflow, which contains every stem tile kind), sharing `stem_liveness.zig`: every stem tile reaches `RUN` with an advancing heartbeat while idle, and a `SIGSTOP`-frozen stem tile goes `.stale` while its siblings do not. `test_tile_tkdiag.zig` already polls `refreshProcessHealth` for 2 s and now also fails if tkdiag is classified stale.
- Staleness budget: worst gap between housekeeping events is below 4 x `STEM_LAZY` (about 40 ms) against the 100 ms default threshold. See `doc/knowledge/tile-orchestration.md`, "Health And Lifecycle".
- The metric tile has the same gap (its CNC stayed at `BOOT` in all 382 supervisor samples of a green run) and is covered through a NULL-by-default `fd_metric_ctx_t.liveness` hook, because `fd_metric_tile.c` is also linked into the native Firedancer binaries. See `doc/knowledge/tile-orchestration.md`, "Health And Lifecycle".
- Not changed: no tile writes `BOOT` on exit (the supervisor never waits for it), and `tkings`/`tkrepl` stay on their existing launch paths.
