# Plan: Pass metric_port through the full topology chain

## Problem

`ProcessPipelineConfig.metric_port` and `topo_build.build()` signature already accept the port parameter, but:
1. `topo_build.build()` still hardcodes port 7999 at line 274 instead of using the `metric_port` parameter
2. All 3 callers of `topo_build.build()` still use the old 4-arg call site
3. `TopologySpec` has no `metric_port` field, so children cannot rebuild with the correct port
4. Wire format version is still 1
5. All integration tests that start the process pipeline share port 7999, causing `EADDRINUSE` when tests run in parallel or back-to-back (kernel TIME_WAIT on the socket)

pub fn metricPort() u16 {

## Risks

- Version bump to TopologySpec v2: any stale topology.spec files from prior builds will be rejected at runtime. Since these files live under the supervisor's run directory and are rewritten every boot, this is safe.
- Adding a field to TopologySpec changes `@sizeOf(TopologySpec)` by 2 bytes. The `readFromFile()` length check (`n != @sizeOf(TopologySpec)`) will catch truncated v1 files correctly (they'll be shorter).
- Static counters in each integration test file mean the counter state is per-module, not global across files. This is correct — each file is a separate test binary compilation unit, so they never share state. The counter starts at 7999 in each file, meaning two tests in different files could collide if run in parallel. If that becomes an issue later, use a file-unique offset (e.g., 7900 + file_number) instead of a flat increment.
