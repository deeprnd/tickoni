# Minimal Topology Scoping for fd_stem + Metrics Tile Regression

## Problem

The fd_stem migration introduced a regression where the supervisor attaches
to the metrics workspace fine, but all child tiles fail to attach to
`tickoni_metrics.wksp` (line 448 in `tile_process.zig`). The main workspace
attach works. Pipeline tiles crash with SIGPIPE during bootstrap before any
meaningful log output, cascading failures from the metrics attach failure.

## Root Cause Analysis

1. **Supervisor creates workspaces** in `<run_dir>/.normal/tickoni_metrics.wksp`
   via `wkspNewNamed(shmem_normal_page_sz=0x1000)`.

2. **Child calls `fd_shmem_info(name, 0UL, ...)`** → iterates page sizes:
   gigantic → huge → normal, returns the first matching lg_page_sz.

3. **Path mismatch**: if it matches gigantic/huge (stale or wrong),
   `fd_shmem_private_path` builds `<run_dir>/.gigantic/tickoni_metrics.wksp`
   instead of `.normal/`, `open()` fails → `wkspAttach` returns NULL.

4. **Pipeline tiles crash on NULL**: they try to join the metrics workspace
   unconditionally, `wkspAttach` fails, process exits, and the SIGPIPE chain
   starts across the supervisor's pipe handles.

5. **Current topology spawns 14+ tiles**, most of which are dead in process
   mode (`process_fn = null`): tkcase, tkrepl, tkdisp, tkagnt, tkdiag.
   This adds massive debug surface for a problem that may only involve
   tkings + tkmetr.

## Goal

Reduce debug surface to the minimum tiles needed to isolate the metrics attach
failure: **1 tile + metrics tile** (tkings + tkmetr, 0 data channels).

## Channels to REMOVE

All inter-tile data channels between pipeline tiles. The minimal topology uses
only shared workspaces (main + metrics), not data flow channels. tkings produces
events into its own workspace; tkmetr reads metrics from the metrics workspace.

## Implementation Plan

### Option D: Replace the const arrays (recommended)

The topology is already a const array in `topologies.zig`:
`payment_tiles` and `payment_channels`. Both `paymentPipeline()` and
`paymentPipelineProcess()` reference these same arrays. Just replace their
contents with the 2 tiles and 0 channels we need:

```zig
// topologies.zig — replace payment_tiles
const payment_tiles = [_]TileDescriptor{
    .{ .id = TileId.parse("tkings") catch unreachable, .name = "ingest_tile" },
    .{ .id = TileId.parse("tkmetr") catch unreachable, .name = "metric_tile" },
};

// topologies.zig — replace payment_channels
const payment_channels = [_]Channel{};
```

And for process mode (references `payment_process_channels`):

```zig
// topologies.zig — clear payment_process_channels
const payment_process_channels = [_]Channel{};
```

No flags, no gating, no separate `minimalProcess()` function, no
`needs_metrics_wksp` field. One change: 2 const arrays. The supervisor
already calls `paymentPipelineProcess()` for process mode — it picks up
the minimal set automatically.

**Why this is best:**
- The topology was always a const array. Just change the contents.
- No new abstractions, no dead code, no skip logic.
- If something assumes 8 tiles, that's a hardcoded dependency to find and
  fix — not hide behind a flag.
- Easy to restore: the old content can be commented in above the new
  definition.
- One place to look: the const arrays at the top of `topologies.zig`.

### Step 2: Revert dead code from earlier attempts

Remove `minimalProcess()`, `minimal_process_tiles`,
`minimal_process_channels`, `minimal_process_status` from
`topologies.zig` — these were created as part of Option A and are no longer
needed.

Remove `needs_metrics_wksp: bool` from `TileEntry` in
`tile_registry.zig` — dead code with this approach.

Revert the metrics gate in `tile_process.zig` (the
`std.mem.eql(spec.tile_id.slice(), "tkmetr")` conditional) — it's no
longer needed since only tkmetr exists in the topology.

### Step 3: Fix hardcoded tile-count assertions

After reducing to 2 tiles, find and fix any code that assumes exactly 8
tiles:

- `supervisor.zig` — check for `assert(topo.tiles.len == 8)` or similar
- `test_process_topology.zig` and siblings — 8-tile assertions in test
  bodies
- `tile_registry.zig` — any hardcoded tile-role-to-tile-idx mapping
- `main.zig` — CLI command routing that references tile indices

The pattern is: replace `== 8` with `== topo.tiles.len`, or parameterize
the loop over `topo.tiles` instead of indexing into positions 0-7.

### Step 4: Verify minimal topology

After the supervisor only spawns tkings and tkmetr:

1. **Does tkings still crash?** → If yes, the problem is NOT the metrics wksp
   attach (it's the main workspace or something earlier in the chain).

2. **Does tkings survive but tkmetr crashes?** → Confirms the metrics wksp
   path/page_sz issue. Focus on `fd_shmem_info` vs `fd_shmem_private_path`
   mismatch.

3. **Does tkings produce events and terminate cleanly?** → The event pipeline
   works at the basic level; the crash was cascading from some other tile.
