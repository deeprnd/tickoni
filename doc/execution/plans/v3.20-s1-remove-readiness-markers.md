# Plan: Remove Readiness Markers via Explicit Workspace Sync

**Goal:** Eliminate the readiness marker polling from tile processes by adding explicit `fsync` on workspace files after `wkspNewNamed` completes. This matches Firedancer's implicit synchronization (hugetlbfs synchronous ftruncate) with an explicit mechanism for normal-page files.

---

## Problem Statement

### What is the readiness marker?

The readiness marker is a `.ready` file placed in the workspace's backing directory (`{shmem_path}/.normal/{concrete_wksp_name}.ready`). The tile process polls for this file (up to 5 seconds, 1-second intervals) before attempting `fd_wksp_join`. If absent, the tile aborts.

**Current locations:**
- **Writer:** `supervisor.zig` — `writeReadinessMarker()` (line 221), called after `topoWkspNew` for each workspace
- **Reader:** `tile_process.zig` — polling loop (lines 200-235), waits for `{shmem_path}/.normal/{concrete_name}.ready`

### Why does it exist?

Normal-page `fd_shmem_create_multi` creates a sparse file via `ftruncate` + `mmap`. The kernel does not synchronously allocate all pages — only the workspace header (a few KB) is written. `munmap` + `close` synchronizes file metadata, but the dirty pages containing workspace structures (mcache/dcache/fseq headers) may not be flushed to the filesystem before child processes try to `open` + `mmap` the file.

Firedancer doesn't need readiness markers because hugetlbfs `ftruncate` **synchronously allocates all pages** — by the time `fd_topo_create_workspace` returns, the file is fully populated and immediately joinable by children.

### Why remove it?

- It's a Firedancer-incompatible workaround (Firedancer uses no such mechanism)
- Polling with fixed timeouts is fragile under load (5s may be too short, 1s poll interval is wasteful)
- It couples tile startup to a file-system signaling primitive not present in Firedancer's architecture
- The real problem (async pagecache writeback) has a proper fix: explicit `fsync`

## Analysis

### Firedancer vs Tickoni workspace creation

| Aspect | Firedancer (hugetlbfs) | Tickoni (normal-page) |
|--------|----------------------|----------------------|
| `ftruncate` | Synchronous (all pages allocated on hugetlbfs) | Sparse (no pages allocated) |
| mmap + write | Writes workspace header | Same |
| munmap + close | File fully populated, dirty pages already on backing | Only file metadata synced, dirty pages in pagecache |
| Child `open` + `mmap` | Data immediately available | Race window — data may not be flushed yet |
| Readiness marker | Not needed | Required |

### The fix

After `topoWkspNew` completes (workspace header fully written to the mmap'd region), call `fsync` on the workspace file before any child process spawns. This forces all dirty pages for that file to be flushed to the filesystem, ensuring child processes that `open` the file see fully-written workspace data.

### Platform analysis

| Platform | shmem backend | fsync available | Fix |
|----------|--------------|----------------|-----|
| **Linux** | `fd_shmem_create_multi` (open + ftruncate + mmap) | `fsync(fd)` syscall | Call `fsync` on workspace file after wkspNewNamed |
| **macOS** | Same POSIX path (no hugetlbfs, no Linux-only NUMA) | `fsync(fd)` syscall (also `fcntl(fd, F_FULLFSYNC)`) | Call `fsync` (or `F_FULLFSYNC` on APFS) after wkspNewNamed |
| **Windows** | Stub (ENOTSUP) | `FlushFileBuffers(fd)` | N/A — shmem doesn't work yet, but infrastructure should be prepared |

Key observations:
- **Linux:** `fsync(fd)` is the standard syscall. Works on ext4, xfs, hugetlbfs. APFS is macOS-specific.
- **macOS:** `fsync(fd)` works but `fcntl(fd, F_FULLFSYNC)` provides stronger guarantees on APFS (verifies data reaches storage). For Tickoni's use case, regular `fsync` is sufficient since we're not doing financial transaction durability — just ensuring the file is visible to child processes.
- **Windows:** All shmem create/join operations are stubs. `FlushFileBuffers` is the Win32 equivalent. The fix should be written with a `#if FD_HAS_WINDOWS` path even though shmem is currently stubbed.

### Why fsync instead of pre-touching all pages?

Pre-touching (iterating over every page and writing a byte) forces all pages dirty, which combined with fsync guarantees visibility. But for Tickoni's current workspace sizes (~tens of MB per workspace, 3 workspaces), pre-touching is wasteful — only the workspace headers are actually written. fsync flushes whatever dirty pages exist (the headers), which is all children need to see.

## Plan

### Phase 1: Add platform-safe fsync utility

**Objective:** Create a utility function for explicit file descriptor sync that works on Linux, macOS, and Windows.

**Files:**
- Create: `src/tickoni/util/fsync.zig` (or add to existing `src/tickoni/util/`)

**Step 1:** Define platform-specific fsync wrappers

```
src/tickoni/util/fsync.zig (new file):

// Explicit file descriptor sync utility for workspace synchronization.
// Replaces the readiness marker with an explicit fsync after workspace
// creation, ensuring workspace data is flushed to the filesystem before
// child processes attempt to join.
//
// Platform behavior:
// - Linux: fsync(fd)
// - macOS: fsync(fd) — F_FULLFSYNC available but unnecessary for this use
// - Windows: FlushFileBuffers(fd) (via Win32 API)

const fsync: struct {
    fn sync(fd: std.posix.fd_t) !void;
    fn syncOnDisk(fd: std.posix.fd_t) !void; // stronger guarantee on APFS
};
```

**Verification:**
- Compiles on Linux (zig build check)
- Compiles on macOS (cross-compile check if available)
- Compiles on Windows stub path (no shmem, but fsync infrastructure must compile)

**Step 2:** Implement `syncWorkspace` helper

The supervisor needs to construct the workspace file path and fsync it. The path follows the pattern:
```
{run_dir}/.normal/{concrete_wksp_name}
```

Where `concrete_wksp_name` = `{app_name}_{wksp_name}` (Firedancer convention).

```
syncWorkspace(io, workspace_name: []const u8, wksp_idx: u32):
  1. Compute concrete name via topo_build.concreteWorkspaceName()
  2. Construct path: {run_dir}/.normal/{concrete_name}
  3. Open file O_RDONLY (or O_RDWR to match creation mode)
  4. Call fsync(fd)
  5. Close fd
  6. Return error if fsync fails
```

**Verification:**

Current code to remove:
```zig
// Wait for supervisor's readiness marker so the workspace file is fully
// synced before we try to join it.  Without this we race with the
// kernel's delayed commit of the `.wksp` file, which causes ENOENT.
//
// The concrete workspace name is {app_name}_{raw_name} (Firedancer
// convention: fd_topo.c:fd_topo_join_workspace builds "tickoni_test0"
// from app_name="tickoni" + wksp.name="test0"), so the readiness
// marker must also use the concrete name.

const concrete_name = topo_build.concreteWorkspaceName(&concrete_name_buf, spec.workspace_name.slice()) catch |err| {
    std.debug.print("tile_process: failed to compute concrete workspace name for tile {d}: {t}\n", .{ spec.tile_idx, err });
    return 1;
};
var readiness_path_buf: [launch_spec.shmem_path_cap + 128]u8 = undefined;
const readiness_path = std.fmt.bufPrint(&readiness_path_buf, "{s}/.normal/{s}.ready", .{ spec.shmemPath(), concrete_name }) catch {
    std.debug.print("tile_process: readiness path too long for tile {d}\n", .{spec.tile_idx});
    return 1;
};
{
    const deadline = util.process.monotonicNanos() + 5 * std.time.ns_per_s;
    var found: bool = false;
    while (util.process.monotonicNanos() < deadline) : (util.process.sleepNanos(1 * std.time.ms_per_s)) {
        const exists: bool = blk: {
            std.Io.Dir.access(std.Io.Dir.cwd(), io, readiness_path, .{}) catch break :blk false;
            break :blk true;
        };
        if (exists) {
            found = true;
            break;
        }
    }
    if (!found) {
        std.debug.print("tile_process: readiness marker not found for tile {d} after 5s\n", .{spec.tile_idx});
        return 1;
    }
}
```

Replace with a direct comment explaining why fsync makes this unnecessary:
```zig
// Workspace file is fsync'd by the supervisor after topoWkspNew completes
// (supervisor.zig:syncWorkspace). Child processes can join immediately
// without polling — the workspace data is guaranteed to be flushed.
```

### Workspace Synchronization

The supervisor explicitly fsyncs each workspace file after topoWkspNew
completes and before spawning child tile processes. This ensures child
processes see fully-written workspace data when they open the workspace
file for the first time.

**Why explicit fsync is needed:** Firedancer creates workspaces backed by

return). Tickoni uses normal-page files where ftruncate creates a sparse

**Platform behavior:**
- Linux: fsync(fd) flushes dirty pages to the filesystem
- macOS: fsync(fd) flushes dirty pages; F_FULLFSYNC provides stronger

- Windows: FlushFileBuffers(fd) — shmem operations are currently stubbed

## Risk Assessment

| Risk | Mitigation |
|------|-----------|
| fsync is slow for large workspaces | Only workspace headers are dirty (not the full workspace), so fsync is fast (~ms) |
| macOS fsync may not guarantee visibility | `F_FULLFSYNC` available on macOS; fallback to regular fsync is sufficient for process visibility |
| Windows shmem is stubbed | Windows fsync infrastructure is written but unused; shmem stubs return ENOTSUP regardless |
| Race between fsync completion and tile spawn | Supervisor calls fsync before spawning any tiles — sequential, no race |
| fsync fails silently | fsync returns errors; supervisor treats fsync failure as fatal (same as workspace creation failure) |
