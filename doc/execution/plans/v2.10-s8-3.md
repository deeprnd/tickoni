# Refactor contrib/test folder — one way, setup-style

## Goal

Replace the current mixed collection of scripts in `contrib/test/` with the same
`tk-platform-toolchain` pattern used in `contrib/setup/` — one script per
platform/compiler pair, with a thin justfile dispatcher routing to them.

Move all 3rd-party tool provisioning (llama.cpp, huggingface model download) into
`contrib/setup/` so tests never install or build anything. Delete files that are
no longer referenced by any justfile recipe, CI workflow, or sourced script.

### Script pattern

Each `tk-<platform>[,<compiler>]` file:
1. Detects platform/compiler from `contrib/platform.sh`
2. Validates prerequisites exist (libs, build dir, etc.)
3. Runs the actual test command
4. Returns exit code

The justfile stays thin — one dispatcher per test category that calls the
`tk-<platform>` script. No build, no install, no download inside test scripts.

## Detailed plan

### Phase 1: Move 3rd-party provisioning into contrib/setup

**Move these files:**
- `contrib/test/llama_cpp_env.sh` → `contrib/setup/helpers/install-llama-cpp.sh`
- `contrib/test/ensure_llama_cpp.sh` → merge into `install-llama-cpp.sh`
- `contrib/test/ensure_llama_cpp_win.sh` → merge into `install-llama-cpp.sh`
- `contrib/test/ensure_hf_model.sh` → `contrib/setup/helpers/install-hf-model.sh`

**Changes to `install-llama-cpp.sh`:**
- Unified script: `install-llama-cpp [--gpu] [--check-only]`
- Detects platform via `contrib/platform.sh`
- Linux: clones + builds llama.cpp (CPU or CUDA)
- Windows: clones + builds llama.cpp (CPU, MSVC or clang)
- Sets `TK_LLAMA_CPP_DIR` default (same as current: `~/work/models/llama.cpp`)
- Copies binaries to root of checkout dir (same behavior)
- Provides `tk_resolve_llama_cpp_dir()` function for sourcing scripts

**Changes to `install-hf-model.sh`:**
- Unified script: `install-hf-model [--check-only]`
- Uses `hf` CLI (installable via pip if missing)
- Downloads model to `~/work/models/gemma/gemma-4-E2B-it-qat-GGUF/`
- Provides `tk_resolve_hf_model_path()` function

**New setup justfile recipes** (add to justfile):
- `infra-llama-cpp` — calls `install-llama-cpp.sh`
- `infra-hf-model` — calls `install-hf-model.sh`
- `infra-run-llamacpp` — runs llama-server (replaces current infra-run recipes)
- `infra-run-llamacpp-win` — runs llama-server.exe

**The old `infra-ensure-llamacpp`, `infra-ensure-llamacpp-win`, `infra-ensure-model`,
`infra-run-llamacpp`, `infra-run-llamacpp-win` justfile recipes** are replaced
by the above.

### Phase 3: Consolidate test scripts into platform pattern

**A. Tickoni unit + integration tests**

Currently these are Zig build commands in the justfile (not shell scripts).
The justfile recipes `test-unit-tk-linux-x86`, `test-integration-tk-linux-x86`,
etc. call `zigw.sh build ...` directly.

Keep this pattern but create thin platform wrappers:

`contrib/test/tk-linux-x86` — justfile calls `just test-unit-tk-linux-x86`
which sources `contrib/test/tk-linux-x86` for unit tests.

Actually, looking at the current structure more carefully: the justfile already
has per-platform recipes that call `zigw.sh build`. The only platform-specific
difference is the build dir and compiler. Windows needs the extra `bash -lc`
wrapping.

The simplest refactor: keep justfile recipes as-is (they are already
`test-unit-tk-linux-x86`, `test-integration-tk-linux-x86`, etc.) but move the
platform-specific logic into `tk-<platform>` scripts.

**B. System tests (live LLM)**

Current flow: `just test-system-tk` → `run_system_model_tests.sh` →
`ensure_llama_cpp.sh` → `ensure_hf_model.sh` → `run_llm_server.sh` →
Zig system-test binary.

After Phase 1, the flow becomes: `just test-system-tk` → `test-system.sh` →
llama.cpp and model already installed by `infra-*` recipes → llama-server
launcher → Zig system-test binary.

**C. Demo conformance**

Current flow: `just test-demo-tk` → `run_cli_demo_tests.sh` →
`just export-demo-conformance-*` → `export_demo_conformance_bundle.py` →
`just compare-demo-conformance` → `compare_demo_conformance.py`

Keep these scripts but rename to follow the pattern:
- `run_cli_demo_tests.sh` → `test-demo.sh`
- `export_demo_conformance_bundle.py` → `test-demo-export.py`
- `compare_demo_conformance.py` → `test-demo-compare.py`

**D. Coverage**

Current: `just test-cov-tk` → `coverage.sh coverage-tk`
Keep as-is. Rename `coverage.sh` → `test-cov.sh` for consistency.

### Phase 4: Restructure the justfile test section

Replace the current ad-hoc test recipes with the unified `tk-<platform>` pattern:

```

test-all:
    @just test-unit-all
    @just test-integration-all
    @just test-cov-all
    @just test-system-all
    @just test-e2e-all

# ── Tickoni unit tests ───────────────────────────────────────────────────

test-unit-tk:
    case "{{ os }}-{{ arch }}" in
      linux-x86)  exec just test-unit-tk-linux-x86 ;;
      linux-arm)  exec just test-unit-tk-linux-arm ;;
      macos-x86)  exec just test-unit-tk-macos-x86 ;;
      macos-arm)  exec just test-unit-tk-macos-arm ;;
      windows-x86) exec just test-unit-tk-windows-x86 ;;
      windows-arm) exec just test-unit-tk-windows-arm ;;
      *) echo "unsupported host platform" >&2; exit 1 ;;
    esac

test-unit-tk-linux-x86:
    ZIG_GLOBAL_CACHE_DIR=.zig-global-cache TK_LOG_LEVEL=0 \
      bash contrib/test/tk-linux-x86 test-unit

test-unit-tk-linux-arm: test-unit-tk-linux-x86
test-unit-tk-macos-x86: test-unit-tk-linux-x86
test-unit-tk-macos-arm: test-unit-tk-linux-x86

test-unit-tk-windows-x86:
    # ... Windows-specific wrapper
test-unit-tk-windows-arm: test-unit-tk-windows-x86

test-unit-all:
    {{ python }} contrib/tool/readme/run-badged-command.py unit bash -c "just test-unit-tk && just test-unit-fd"

# ── Tickoni integration tests ────────────────────────────────────────────

test-integration-tk:
    case "{{ os }}-{{ arch }}" in
      linux-x86)  exec just test-integration-tk-linux-x86 ;;

test-integration-tk-linux-x86:
    ZIG_GLOBAL_CACHE_DIR=.zig-global-cache \
      bash contrib/test/tk-linux-x86 test-integration

# ── Tickoni system tests (live LLM) ──────────────────────────────────────

test-system-tk:
    bash contrib/test/test-system.sh

# ── Tickoni demo conformance ─────────────────────────────────────────────

test-demo-tk:
    bash contrib/test/test-demo.sh

export-demo-conformance-linux:
    # ... export platform-specific conformance

compare-demo-conformance:
    # ... compare all platforms

# ── Coverage ─────────────────────────────────────────────────────────────

test-cov-tk:
    ZIG_GLOBAL_CACHE_DIR=.zig-global-cache {{ python }} contrib/tool/readme/run-badged-command.py \
      cov-tk bash contrib/test/test-cov.sh coverage-tk
```

## Risks and mitigations

1. **CI breakage**: CI workflows call justfile recipes. If a recipe name changes,
   the workflow step must be updated. Mitigation: run `check-just-recipe-grid.sh`
   after the change to validate all CI references.

2. **Llama.cpp rebuild on every test**: After moving provisioning to setup,
   the `infra-*` recipes become no-ops if llama.cpp is already built. The
   `--check-only` flag in the new scripts handles this.

3. **Model auth (hf token)**: `install-hf-model.sh` requires `hf` CLI with
   auth. On CI runners this may need `HF_TOKEN` env var. Document this.

4. **Windows ARM llama.cpp**: The Windows ARM llama.cpp build is complex
   (no CUDA, clang-only, no MSVC). This complexity lives in `install-llama-cpp.sh`
   now. Keep it well-documented.
