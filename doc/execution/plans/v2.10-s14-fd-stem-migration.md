# V2.10.S14: fd_stem Migration — Per-Tile Implementation Plan

> **For Hermes:** Execute tasks sequentially. Each tile is a self-contained migration — the pipeline stops working after that tile is migrated until the remaining tiles are also migrated. You may stop at any tile boundary and the build will still compile, but the full pipeline will hang (the unmigrated tiles' WorkFn loops will not receive credits from stem).

**Goal:** Migrate Tickoni pipeline tiles from the `tile_process.zig` WorkFn closure pattern to Firedancer's `fd_stem` callback lifecycle (`BEFORE_CREDIT` → `DURING_FRAG` → `AFTER_CREDIT`), one tile at a time. Each tile is independently completable.

**Architecture:** Follow Firedancer's own pattern — each tile's C shim defines `STEM_CALLBACK_*` macros and includes `fd_stem.c` directly. No global callback registry. Each tile is self-contained like `tk_metric_tile.c` already is.

**Key files:**
- Tile business logic (unchanged): `src/tickoni/tiles/payment_pipeline/ingest.zig`, `normalize.zig`, `dedupe.zig`, `policy.zig`, `audit_stage.zig`, `replay.zig`, `diag.zig`
- Process-mode harness (modified): `src/tickoni/runtime/tile_process.zig`, `src/tickoni/c_abi/shim/tile_run.c`, `src/tickoni/c_abi/shim/topob.c`
- Reference implementation: `src/tickoni/c_abi/shim/tk_metric_tile.c`
- Firedancer stem: `src/disco/stem/fd_stem.c`

## How fd_stem Works (Per-Tile Pattern)

Each tile that needs stem follows this pattern, proven by `tk_metric_tile.c`:

```c
// 1. Define stem-specific macros for this tile
#define STEM_CALLBACK_CONTEXT_TYPE    tile_ctx_t      // tile's scratch context
#define STEM_CALLBACK_CONTEXT_ALIGN   TILE_CTX_ALIGN   // alignment constant
#define STEM_BURST                    128              // max fragments per iteration
#define STEM_LAZY                     0                // no lazy mode

// 2. Define callbacks as static functions
#define STEM_CALLBACK_BEFORE_CREDIT  tile_before_credit
#define STEM_CALLBACK_DURING_FRAG    tile_during_frag
#define STEM_CALLBACK_AFTER_CREDIT   tile_after_credit
#define STEM_CALLBACK_SHOULD_SHUTDOWN tile_should_shutdown

// 3. Include fd_stem.c — generates stem_run() with this tile's callbacks baked in
#include "../../../../../../disco/stem/fd_stem.c"
```

The `stem_run()` function:
- Finds the tile's scratch context (first object in tile's workspace)
- Joins CNC, checks `SHOULD_SHUTDOWN` each iteration
- Calls `BEFORE_CREDIT` every iteration (even if no input)
- Calls `DURING_FRAG` when new fragments arrive on input links
- Calls `AFTER_CREDIT` after processing (if credit available)
- Exits when `SHOULD_SHUTDOWN` returns non-zero

## Tile 1: tkaudt (1-in, 0-out) — DURING_FRAG only, complete implementation

**Status:** TODO

**Objective:** Migrate tkaudt from WorkFn to fd_stem. Only `DURING_FRAG` — no `AFTER_CREDIT` (no output links). Best 1:1 mapping from current `while(pop())` → `DURING_FRAG`.

**Spike:** Minimal — current `while(pop())` loop is complete, only needs stem callback wiring.

**Files:**
- Create: `src/tickoni/c_abi/shim/tk_audit_stem.c`
- Modify: `src/tickoni/runtime/tile_process.zig` (register stem run callback)
- Modify: `src/tickoni/c_abi/shim/tile_run.c` (dispatch to tkaudt stem)

**Key behavior:**
- Consumes from tkpoly (1 input link)
- Appends to append-only audit log (hash-chained)
- Tracks max_latency_hops
- Sets `input_exhausted` flag when no fragments received for N consecutive ticks

**DURING_FRAG implementation:**

```c
static void
tkaudt_during_frag( tkaudt_ctx_t * ctx,
                    ulong          in_idx,
                    ulong          seq,
                    ulong          sig,
                    ulong          chunk,
                    ulong          sz,
                    uint           ctl ) {
    /* 1. Read policy decision from fragment */
    /* 2. Compute record hash (exclude timestamp_ns) */
    /* 3. Append to audit log */
    /* 4. Update max_latency_hops */
    /* 5. Increment audited counter */
    /* 6. Reset consecutive_empty counter */
    ctx->consecutive_empty = 0;
}
```

**BEFORE_CREDIT (minimal — just track idle ticks):**

```c
static void
tkaudt_before_credit( tkaudt_ctx_t * ctx,
                      fd_stem_t *    stem,
                      int *          charge_busy ) {
    /* Track consecutive ticks with no DURING_FRAG.
     * After N consecutive ticks (e.g., 1000), set input_exhausted. */
    ctx->consecutive_empty++;
    if (ctx->consecutive_empty >= TKAUDT_IDLE_THRESHOLD) {
        ctx->input_exhausted = 1;
    }
    *charge_busy = 0;
}
```

**SHOULD_SHUTDOWN:** Returns non-zero when `ctx->input_exhausted` OR CNC HALT.

**Why this is the easiest:**
- `while(pop())` → `DURING_FRAG` is a near-perfect 1:1 mapping
- No output to manage (no `AFTER_CREDIT`, no publish logic)
- Only 2 callbacks to implement
- Logic is simple consume → append → done

**Status:** TODO

**Spike:** Minimal — current `while(pop())` loop is complete, only needs stem callback wiring.

**Files:**
- Create: `src/tickoni/c_abi/shim/tk_normalize_stem.c`
- Modify: `src/tickoni/c_abi/shim/tile_run.c` (dispatch to tknorm stem)

**Key behavior:**
- Consumes from tkings (1 input link)
- Validates framing, computes event hash, makes decision
- Publishes to tkdedu (1 output link)

**DURING_FRAG implementation:**

```c
static void
tknorm_during_frag( tknorm_ctx_t * ctx,
                    ulong          in_idx,
                    ulong          seq,
                    ulong          sig,
                    ulong          chunk,
                    ulong          sz,
                    uint           ctl ) {
    /* Process the fragment:
     * 1. Read the raw payment from input chunk
     * 2. Validate framing (validFraming)
     * 3. Compute event hash (stableEventHash)
     * 4. Make decision (malformed_drop or pass through)
     * 5. Prepare output fragment in output dcache
     * 6. Set ctx->output_ready = 1
     */
}
```

**AFTER_CREDIT implementation:**

```c
static void
tknorm_after_credit( tknorm_ctx_t *    ctx,
                     fd_stem_t *       stem,
                     fd_stem_tile_in_t * poll_in,
                     int *             charge_busy ) {
    /* If output fragment is ready from during_frag, publish now.
     * Otherwise this is just a credit-check tick. */
    if (ctx->output_ready) {
        fd_stem_publish(stem, 0, output_sz, output_chunk, output_sz, 0, 0, 0);
        ctx->output_ready = 0;
    }
    *charge_busy = 0;
}
```

**Why second:** Standard consume-process-publish pattern. `DURING_FRAG` maps directly from the current `while(pop())` loop body.

## Tile 5: tkings (0-in, 1-out) — producer-only is the hardest stem pattern, but logic is complete

**Status:** TODO

**Objective:** Migrate tkings from WorkFn to fd_stem. Producer-only tile — `BEFORE_CREDIT` + `AFTER_CREDIT` only, no `DURING_FRAG` (no input links).

**Spike:** Minimal — current `while(!state.stop)` loop with event generation is complete, only needs stem callback wiring and fd_stem_publish() replacement.

**Files:**
- Create: `src/tickoni/c_abi/shim/tk_ingest_stem.c`
- Modify: `src/tickoni/c_abi/shim/tile_run.c` (dispatch to tkings stem)

**Current spike behavior:** Generates synthetic payment events (0 to event_count-1), pushes each to output queue, checks `state.stop` each iteration, tracks `state.produced` counter, has sandbox_fail_at test hook.

**Firedancer topology:** 0 input links, 1 output link (to tknorm).

**Firedancer-specific requirements:**
- **Before migration:** Must implement actual fragment generation and publishing logic
- **Context:** `tkings_ctx_t` stores event_counter, event_count, produced_count, sandbox_fail_at, stop_flag
- **BEFORE_CREDIT:** HALT check via CNC, update stop flag
- **AFTER_CREDIT:** Generate next event, publish to output dcache
- **SHOULD_SHUTDOWN:** event_count reached OR CNC HALT

**Why later in the order:** Producer-only is the hardest stem pattern. There's no input to naturally drive the loop — stem's randomized round-robin and credit system are designed for consumers, not producers. The tile must work against the callback flow to generate events.

**Status:** TODO

**Objective:** Migrate tkrepl from WorkFn to fd_stem. Observer tile that reads replay capsules from input link, re-injects them, and publishes divergence reports to tkings via output link.

**Spike:** Minimal — current `while(!audit_done)` with shared-memory atom is complete, but Firedancer topology requires real capsule I/O logic (reading from input dcache, publishing to output dcache) that does not exist yet.

**Files:**

**Current spike behavior:** Waits for audit_done flag, recomputes expected audit chain deterministically, compares record-by-record against actual audit log, reports divergences. Uses shared memory atoms.

**Firedancer topology:** 0 input links (spike), **1 input link** (replay capsules from replay entrypoint), 1 output link (replay capsule events to tkings).

**Missing logic that must be written first:**
- **Input I/O:** Read replay capsules from input dcache (new functionality)
- **Output I/O:** Publish replay capsule events to tkings output dcache (new functionality)
- **Divergence reporting:** Adapt `deterministicReplayDivergences` to work with stem callbacks

**BEFORE_CREDIT implementation:**

```c
static void
tkrepl_before_credit( tkrepl_ctx_t * ctx,
                      fd_stem_t *    stem,
                      int *          charge_busy ) {
    /* Check if replay capsules available on input link.
     * If yes, process them: re-inject, compare, report divergences.
     * If no capsules available, just tick.
     * If replay complete, set work_done = 1. */
}
```

**AFTER_CREDIT implementation:**

```c
static void
tkrepl_after_credit( tkrepl_ctx_t *    ctx,
                     fd_stem_t *       stem,
                     fd_stem_tile_in_t * poll_in,
                     int *             charge_busy ) {
    /* If divergence report is ready, publish to tkings output link. */
    if (ctx->divergence_report_ready) {
        fd_stem_publish(stem, 0, report_sz, report_chunk, report_sz, 0, 0, 0);
        ctx->divergence_report_ready = 0;
    }
    *charge_busy = 0;
}
```

**SHOULD_SHUTDOWN:** Returns non-zero when `ctx->work_done` (replay complete and all divergences reported) OR CNC HALT.

**Why last among complex tiles:** The replay logic (`deterministicReplayDivergences`) is the most complex function in the codebase — 40+ lines of deterministic computation. Getting it right requires writing the missing capsule I/O logic first.

## Key Implementation Notes

1. **Context layout:** Each tile's stem context (`tkings_ctx_t`, `tknorm_ctx_t`, etc.) is the first object allocated from the tile's scratch space. `stem_run()` finds it via `fd_topo_obj_laddr(topo, tile->tile_obj_id)`.

2. **CNC integration:** Each tile must find its CNC object via `tk_topo_find_tile_obj()` (already used by tk_metric_tile.c) to check for HALT in `SHOULD_SHUTDOWN`.

3. **Fragment publishing:** Use `fd_stem_publish()` instead of `rt.link.Producer`. The signature matches what Firedancer's tiles already use.

4. **Backpressure:** Stem handles backpressure via `cr_avail`. Tiles don't need to check queue depth — `stem_run` won't call `AFTER_CREDIT` if no credits are available.

5. **Non-Linux fallback:** Until all tiles are migrated, the non-migrated tiles continue using `TK_TILE_RUN` → `tk_tile_run` → `WorkFn`. This means the pipeline works on non-Linux with partial migration.

6. **Test isolation:** Each tile's test should be runnable independently. Run `zig build test-tkings` (or similar) to test just that tile's migration.

7. **No global state:** Each tile's C shim is self-contained. No `tk_stem_registry` or shared callback table. This follows Firedancer's per-tile include pattern.
