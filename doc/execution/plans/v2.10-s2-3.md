# Plan: v2.10-s2-3 — Split justfile into import-based sub-files

**Story:** v2.10-s2-3
**Status:** planned
**Predecessor:** v2.10-s2 (single-bang refactor — regression in integration tests, stuck)
**Successor:** (post-migration) v2.10-s2-4 — refactor duplicated dispatch logic after structural split

## Problem

The monolithic `justfile` is 1,052+ lines and mixes five concerns. CI calls specific platform recipes directly (`just build-fd-linux-x86-gcc`, `just test-unit-tk-macos-arm`), so all CI-facing recipe names must be stable and follow a consistent naming pattern.

## Target naming pattern

All platform-qualified recipes use the same naming convention:

| Category | Pattern | Example |
|----------|---------|---------|
| Build | `build-{fd|tk}-{platform}-{arch}[-compiler]` | `build-fd-linux-x86-gcc`, `build-tk-macos-arm` |
| Test unit | `test-unit-{fd|tk}-{platform}-{arch}[-compiler]` | `test-unit-tk-linux-arm`, `test-unit-fd-macos-x86` |
| Test integration | `test-integration-{fd|tk}-{platform}-{arch}` | `test-integration-tk-windows-x86` |
| Test demo | `test-demo-tk-{platform}-{arch}` | `test-demo-tk-macos-15-x86_64` |
| Test system | `test-system-{fd|tk}-{platform}-{arch}` | `test-system-tk-linux-x86` |
| Test e2e | `test-e2e-{fd|tk}` (no platform) | `test-e2e-tk` |
| Test coverage | `test-cov-{fd|tk}[-platform-arch[-compiler]]` | `test-cov-tk-linux-x86` |
| Quality format | `quality-format-check-{fd|tk|qt}[-platform-arch]` | `quality-format-check-linux-x86` |
| Quality lint | `quality-lint-check-{fd|tk|actions|qt}[-platform-arch]` | `quality-lint-check-fd-linux-x86` |
| Quality proto | `quality-proto-check-{fd|tk}[-platform-arch]` | `quality-proto-check-tk-linux-x86` |
| Quality yaml | `quality-yaml-check-{platform}` | `quality-yaml-check-linux` |
| Quality spell | `quality-spell-check-{platform}` | `quality-spell-check-linux` |
| Security codeql | `security-codeql-check-{fd|tk|qt}[-platform-arch]` | `security-codeql-check-fd-linux-x86` |
| Security gitleaks | `security-gitleaks-check-{fd|tk|qt}[-platform-arch]` | `security-gitleaks-check-tk-linux-x86` |
| Security seccomp | `security-seccomp-check-{fd|tk|qt}[-platform-arch]` | `security-seccomp-check-fd-linux-x86` |
| Security proof | `security-proof-check-{fd|tk|qt}[-platform-arch]` | `security-proof-check-fd-linux-x86` |
| Security sanitize | `security-sanitize-check-{fd|tk|qt}[-platform-arch]` | `security-sanitize-check-tk-linux-x86` |
| Security engine | `security-engine-check-{changes|orchestration}[-platform-arch]` | `security-engine-check-changes-linux-x86` |

**Platform encoding:** `linux`, `macos`, `windows` + `x86` or `arm`
**Compiler suffix:** Used for Linux (`gcc`, `clang`, `arm-gcc`) and any platform where compiler choice matters. macOS and Windows default to their system compiler and use no suffix.

**Aggregate recipes** (no platform): `{domain}-check-all`, `{domain}-all` where domain = build, test, quality, security.

**Setup recipes** already follow the pattern and must remain unchanged — they are the CI-facing entry points.

### Root justfile

The root justfile will contain:
- `default` and `help` (or in common.just)
- `import` statements (all recipes from imported files appear in global namespace)
- Cross-category dispatchers: `tests-all` (calls build-all, quality-check-all, security-check-all, test-all)

Wait — dispatchers reference recipes in imported files. `import` is processed before recipe definitions, so a dispatcher defined in the root justfile CAN reference recipes from imported files. The root justfile gets `tests-all` and the build dispatchers.

Actually, dispatchers like `build-tk` and `build-fd` call `just build-tk-linux-x86` etc. They don't need to be in the root — they can live in `build/all.just` after all platform files are imported. But `all.just` is imported before the dispatchers reference it, so it's fine.

Let me restructure: the root justfile has imports + `default`/`help`. Everything else goes in sub-files.

## Risk assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| `import` path resolution fails | Low | High | Test locally with `just --dump` before committing |
| Variable scope leaks between files | Low | Medium | All shared vars go into `common.just`; imported files reference them by name |
| Dispatcher references recipes in wrong file | Medium | Medium | Every dispatcher references must be cross-checked against import list |
| CI breaks after merge | Low | High | CI uses `just <recipe>` — imports don't change resolution. Spot-check all CI commands. |
| Too many new alias recipes (~180) | Medium | Low | Aliases are zero-cost (no body). They increase `just --list` noise but have no functional impact. |

## Rollback plan

If the split introduces issues:
1. Revert the commit — the monolithic `justfile` is untouched until the split commits land.
2. Each file split is a separate commit, so individual phases can be reverted.
3. The structural split is purely mechanical — no behavior changes means no functional regression risk.
