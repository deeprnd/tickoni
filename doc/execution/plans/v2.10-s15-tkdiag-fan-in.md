# V2.10.S15: tkdiag Fan-In — Diagnostic Fragment Receive Logic

> **For Hermes:** This is a future enhancement plan. The current tkdiag spike uses `snapshotDiag()` shared-memory polling (0-in, 0-out, same as tkmetr). This plan defines the Firedancer topology fan-in model where every pipeline tile sends diagnostic fragments TO tkdiag via `*_tkdiag` links.

**Goal:** Define the fragment format, producer tile send logic, and tkdiag receive/aggregation logic for the fan-in diagnostic model.

**Prerequisite:** All pipeline tiles (`tknorm`, `tkdedu`, `tkpoly`, `tkaudt`) must be migrated to fd_stem first (v2.10.S14), so they can each implement `DURING_FRAG` or `AFTER_CREDIT` fragment publishing for diagnostics.

---

## Architecture Decision

**Current state (spike):** tkdiag polls `snapshotDiag()` from shared memory every tick via `BEFORE_CREDIT`. Zero links. Same as tkmetr.

**Target state (Firedancer topology):** Each pipeline tile sends diagnostic snapshots to tkdiag via dedicated `*_tkdiag` output links. tkdiag receives fragments via `DURING_FRAG` from multiple input links (fan-in) and aggregates them into a coherent diagnostic view.

**Why fan-in:**
- Decouples diagnostic collection from shared-memory polling
- Each tile pushes its own diagnostics (no race on shared state reads)
- Enables per-tile diagnostic granularity (which tile crashed, what state it was in)
- Aligns with Firedancer's fragment-based communication model

---

## Fragment Format

Each producer tile sends a diagnostic fragment with this structure:

```c
/* diag_fragment_t — diagnostic snapshot sent by pipeline tiles to tkdiag */
typedef struct {
    uint32_t tile_id;           /* ID of the sending tile */
    uint32_t tile_type;         /* TK_DIAG_TYPE_NORMALIZE, TK_DIAG_TYPE_DEDUPE, etc. */
    uint64_t seq;               /* Tile's current sequence counter */
    uint64_t timestamp_ns;      /* Snapshot timestamp */
    
    /* Per-tile diagnostic fields (tile-specific, optional) */
    uint64_t events_processed;  /* Total events processed by this tile */
    uint64_t errors;            /* Error count (malformed, denied, etc.) */
    uint64_t backpressure_waits;/* Backpressure wait count */
    uint64_t max_queue_depth;   /* Peak queue depth */
    
    /* Crash/sandbox fields (from PaymentPipelineState.crashed_tile) */
    int32_t crashed;            /* 0 = no crash, tile_id = crash detected */
    uint64_t sandbox_failures;  /* Sandbox failure count */
    
    /* Audit/replay fields (shared state) */
    uint64_t audit_records;     /* Current audit record count */
    int32_t replay_checked;     /* 0 = not checked, 1 = checked */
    int32_t replay_match;       /* 0 = not matched, 1 = matched */
    
    /* Padding to 128 bytes (typical fragment MTU) */
    uint8_t reserved[64];
} diag_fragment_t;

#define TK_DIAG_TYPE_NORMALIZE   1
#define TK_DIAG_TYPE_DEDUPE      2
#define TK_DIAG_TYPE_POLICY      3
#define TK_DIAG_TYPE_AUDIT       4
#define TK_DIAG_TYPE_INGEST      5
```

## Producer Tile Modifications

Each pipeline tile that uses fd_stem must add diagnostic fragment publishing. The pattern is identical for all tiles:

### Pattern: Publish diagnostic fragment in `AFTER_CREDIT` (or `DURING_FRAG` if no output)

```c
/* In tknorm_stem.c (after processing the fragment): */
static void
tknorm_after_credit( tknorm_ctx_t *    ctx,
                     fd_stem_t *       stem,
                     fd_stem_tile_in_t * poll_in,
                     int *             charge_busy ) {
    /* 1. Process the fragment (existing logic) */
    /* 2. Publish to tkdedu (existing logic) */
    
    /* 3. Publish diagnostic fragment to tkdiag (NEW) */
    /* tkdiag_link is the output link index for the *_tkdiag link */
    diag_fragment_t diag = {
        .tile_id = TK_TKNORM,
        .tile_type = TK_DIAG_TYPE_NORMALIZE,
        .seq = ctx->events_processed,
        .timestamp_ns = fd_stem_tick_id(stem),
        .events_processed = ctx->events_processed,
        .errors = ctx->malformed_count + ctx->duplicate_count,
        .backpressure_waits = ctx->backpressure_waits,
        .max_queue_depth = ctx->max_queue_depth,
        .crashed = ctx->crashed ? TK_TKNORM : 0,
        .audit_records = ctx->audit_records,
        .replay_checked = ctx->replay_checked,
        .replay_match = ctx->replay_match,
    };
    
    fd_stem_publish(stem, TK_DIAG_LINK_IDX, sizeof(diag), diag_chunk, sizeof(diag), 0, 0, 0);
    
    *charge_busy = 0;
}
```

**Tile link indices** (defined in topology per `tile-topology.md`):
- `tknorm`: 1 output link (to tkdedu at idx 0), 1 output link (to tkdiag at idx 1)
- `tkdedu`: 1 output link (to tkpoly at idx 0), 1 output link (to tkdiag at idx 1)
- `tkpoly`: 1 output link (to tkaudt at idx 0), 1 output link (to tkdiag at idx 1)
- `tkaudt`: 0 output links to pipeline, 1 output link (to tkdiag at idx 0)
- `tkings`: 1 output link (to tknorm at idx 0), 1 output link (to tkdiag at idx 1)

## tkdiag Fan-In Implementation

### Tile: tkdiag (0-in → N-in, 0-out → N-out)

**After fan-in is implemented, tkdiag becomes:**
- **N input links** (one from each pipeline tile)
- **0 output links** (diagnostics are read via metrics or HTTP endpoint, not published)
- **`DURING_FRAG`** receives diagnostic fragments from all tiles
- **`BEFORE_CREDIT`** polls for shutdown signals

### tkdiag Context

```c
typedef struct {
    /* Aggregated diagnostic state */
    diag_fragment_t latest_from_tile[FD_TILE_MAX];  /* Latest fragment per tile */
    uint32_t tile_cnt;                              /* Number of tiles reporting */
    int32_t any_crashed;                            /* 1 if any tile crashed */
    int32_t replay_checked;                         /* From shared state */
    int32_t replay_match;                           /* From shared state */
    uint64_t total_errors;                          /* Sum of all tile errors */
    uint64_t total_audit_records;                   /* Sum of all tile audit records */
    
    /* Lifecycle */
    int32_t done;                                   /* Set when replay_checked or stop */
} tkdiag_ctx_t;

#define TKDIAG_CTX_ALIGN alignof(tkdiag_ctx_t)
```

### tkdiag DURING_FRAG (fan-in receive)

```c
static void
tkdiag_during_frag( tkdiag_ctx_t * ctx,
                    ulong          in_idx,
                    ulong          seq,
                    ulong          sig,
                    ulong          chunk,
                    ulong          sz,
                    uint           ctl ) {
    /* 1. Validate fragment size */
    if (sz != sizeof(diag_fragment_t)) return;
    
    /* 2. Copy fragment to per-tile slot */
    diag_fragment_t * frag = (diag_fragment_t *)chunk;
    ctx->latest_from_tile[in_idx] = *frag;
    
    /* 3. Update aggregation state */
    if (frag->crashed != 0) {
        ctx->any_crashed = 1;
    }
    ctx->total_errors += frag->errors;
    ctx->total_audit_records = fd_ulong_max(ctx->total_audit_records, frag->audit_records);
    
    /* 4. Track tile count */
    if (!ctx->tile_seen[in_idx]) {
        ctx->tile_seen[in_idx] = 1;
        ctx->tile_cnt++;
    }
}
```

### tkdiag BEFORE_CREDIT (shutdown polling)

```c
static void
tkdiag_before_credit( tkdiag_ctx_t * ctx,
                      fd_stem_t *    stem,
                      int *          charge_busy ) {
    /* Check replay_checked and stop from shared state.
     * These are the same atomics the spike reads. */
    /* TODO: Wire to shared state via fd_shm_join() or topo addr */
    
    if (ctx->replay_checked || ctx->stop) {
        ctx->done = 1;
    }
    
    *charge_busy = 0;
}
```

### tkdiag SHOULD_SHUTDOWN

```c
static int
tkdiag_should_shutdown( tkdiag_ctx_t * ctx ) {
    return ctx->done;
}
```

## Post-Fan-In: Diagnostic Reporting (Future)

After fan-in is working, tkdiag can report diagnostics via:
1. **HTTP endpoint** (like tkmetr) — expose aggregated diagnostic state
2. **Metrics publishing** — write to shared metrics region for Prometheus
3. **Log emission** — emit diagnostic alerts on crash detection
4. **CaseOps integration** — push diagnostics to the CaseOps UI via WebSocket

These reporting mechanisms are out of scope for this plan. The fan-in implementation only covers fragment receive and aggregation.

---

## Key Design Decisions

1. **Fragment size: 128 bytes.** Fits within typical dcache MTU, carries enough per-tile data for meaningful diagnostics.
2. **Publishing in AFTER_CREDIT.** Tiles publish diagnostics after processing a fragment, so the diagnostic state reflects the latest processed event.
3. **Aggregation in tkdiag.** tkdiag merges fragments per-tile and maintains aggregate counters. No shared-memory polling.
4. **Shutdown via replay_checked/stop atomics.** Same trigger as the spike, preserving the pipeline lifecycle.
5. **No output links from tkdiag.** Diagnostics are consumed via HTTP/metrics/log, not via fragment chains.
