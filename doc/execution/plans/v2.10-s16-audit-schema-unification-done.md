# audit-schema: unify C↔Zig types via translate-c re-export

> **Goal:** Make `src/tickoni/c_abi/shim/audit_schema.h` the single authoritative source for `PolicyOutcome`, `Header`, and `PolicyDecisionPayload` across both C and Zig. Eliminate duplicate definitions in `src/tickoni/schema/audit/audit.zig` by having Zig import those types from the translate-c-generated `audit_mod` module and re-export them under their Zig names.

**Prerequisites:**
- `test-unit-tk` passes (existing tests must not break)
- `audit_schema.h` already exists with all three types defined
- `addTranslateC` in `build.zig` already produces `audit_mod`
- All codecs and tiles already import `audit_schema` and use `schema.Header`, `schema.PolicyOutcome`, `schema.PolicyDecisionPayload`

## Task 1: Rewrite `audit.zig` to re-export C-derived types

**File:** `src/tickoni/schema/audit/audit.zig`

Replace the standalone definitions of `PolicyOutcome`, `Header`, and `PolicyDecisionPayload` with imports from `audit_mod`, re-exported under the existing Zig names:

```zig
/// Canonical audit schema shared across replay, tiles, and codec boundaries.
///
/// Audit records are cross-tile contracts and part of replay compatibility.
/// Keep the typed schema here; codecs in src/tickoni/codec/ provide concrete
/// binary, protobuf, JSONL, and hash encodings over this schema.

const c_schema = @import("audit_mod");

pub const audit_schema_version: u16 = 2;

// --- Re-exported from C header (single authoritative source) ---

pub const PolicyOutcome = c_schema.PolicyOutcome;

/// C defines `AuditHeader`; Zig re-exports as `Header` to match
/// existing downstream usage (codec, tiles, version.zig).
pub const Header = c_schema.AuditHeader;

pub const PolicyDecisionPayload = c_schema.PolicyDecisionPayload;

// --- Zig-only types (C cannot express these) ---

pub const LimitType = enum(u8) { ... };
pub const RecordType = enum(u8) { ... };
pub const SourceEventPayload = struct { ... };
// ... all other payload structs unchanged ...

pub const AuditEvent = struct {
    header: Header,
    payload: Payload,
    pub const Payload = union(RecordType) { ... };
};
```

**What this does NOT change:**
- `pub const Header` — same name as before (C side calls it `AuditHeader`, we re-export as `Header`)
- `pub const PolicyOutcome` — same name
- `pub const PolicyDecisionPayload` — same name
- `audit_schema_version` — unchanged (Zig-only constant, no C equivalent needed)
- All 12 payload structs — unchanged
- `AuditEvent` and `Payload` union — unchanged
- All downstream code — zero changes required

**What this removes:**
- ~50 lines of duplicate type definitions (PolicyOutcome enum, Header struct, PolicyDecisionPayload struct)
- The parity test in `types.zig` that verified C↔Zig match (no longer needed — the types can't diverge because there's nothing to define)

## Risks and Mitigations

1. **Naming mismatch:** C generates `AuditHeader`, Zig re-exports as `Header`. All existing code uses `Header` — this is a rename, not a divergence. Verified: no downstream code references `AuditHeader` directly (only `audit_schema.h` and `audit_mod` use that name).

2. **Alignment differences:** `extern struct` in Zig (from translate-c) must match the original Zig `extern struct` layout. If it doesn't, the build fails at compile time. This is the same invariant the parity test was checking — now enforced at compile time instead of test time.

3. **Import cycle:** `audit.zig` imports `audit_mod`, which is a build-time generated module. This is fine — `audit_mod` is a leaf module (just types, no dependencies), and `audit.zig` is a higher-level module. No cycle possible.

4. **Enum value mapping:** C's `typedef enum` from translate-c maps to Zig's `enum`. The values must match exactly (0, 1, 2, ...). Since `audit_schema.h` defines them in the same order as the Zig enum originally did, this is guaranteed.

5. **Struct padding:** The C `AuditHeader` has no padding fields. The original Zig `Header` also had no padding. If someone adds padding to the C header, it will change the struct layout — but that's intentional (they're editing the source of truth).
