# Fix: stem tiles crash because runTileSimple dispatches TK_TILE_RUN instead of tile-specific callbacks

## Problem

Stem tiles (tknorm, tkaudt) crash on startup in process mode because `runTileSimple()` always dispatches `TK_TILE_RUN`, which calls Tickoni's Zig callbacks (`tk_tile_privileged_init`/`tk_tile_run`/`g_ctx.work()`), **not** the tile's actual C stem callbacks (`tknorm_run`/`tk_audit_run` which call `stem_run()`).

### Evidence

- `process_topology_integration` test: tkings produces 8 events, tkaudt audited=0, process exits with signal
- metric tile (stem, no input links) works because `TK_TILE_RUN`→`g_ctx.work()` just polls metrics CNC (no link reads)
- non-stem tiles (tkings, tkdedu, tkpoly) work because `TK_TILE_RUN`→`g_ctx.work()` calls the Zig `work()` function
- tknorm/tkaudt (stem, input links) crash because `TK_TILE_RUN`→`g_ctx.work()` never calls their stem callbacks, so `stem_run()` never runs, so links are never joined, so `fd_chunk_to_laddr()` segfaults

### Root cause

`runTileSimple()` is a hardcoded convenience function that always uses `TK_TILE_RUN`:

```zig
// topo_run.zig line 94-96
pub fn runTileSimple(topo: *Topo, tile: *TopoTile) void {
    tk_topo_run_tile_simple(topo, tile);  // always TK_TILE_RUN
}
```

But stem tiles need their own `fd_topo_run_tile_t` with correct callbacks:
- TKNORM_RUN → `tknorm_privileged_init`/`tknorm_unprivileged_init`/`tknorm_run`
- TK_AUDIT_RUN → `tk_audit_privileged_init`/`tk_audit_unprivileged_init`/`tk_audit_run`
- TK_METRIC_RUN → `fd_metric_tile` callbacks (already correct, metric works)

Firedancer's `fd_topo_run_tile()` **does** join workspaces before callbacks (line 78 of `fd_topo_run.c`), so once the correct callbacks are dispatched, the workspace join happens automatically.

## Solution

Add a tile-aware dispatcher that looks up each tile's `kind_id` and returns the correct `fd_topo_run_tile_t`. This follows Firedancer's own pattern where each tile has its own `fd_topo_run_tile_t` (e.g., `fd_tile_net`, `fd_tile_verify`, `fd_tile_metric`).

### Changes required

#### 1. `src/tickoni/c_abi/shim/tile_run.c` — add `tk_topo_run_tile_for_tile()`

```c
/* Tile-aware dispatcher: looks up kind_id, returns correct fd_topo_run_tile_t.
   Replaces the hardcoded TK_TILE_RUN in runTileSimple for stem tiles. */
void
tk_topo_run_tile_for_tile( void * topo, void * tile ) {
  fd_topo_tile_t * tile_c = (fd_topo_tile_t *)tile;
  fd_topo_run_tile_t * run_tile;

  switch( tile_c->kind_id ) {
    case TK_TILE_KIND_ID:      run_tile = &TK_TILE_RUN; break;
    case TKNORM_TILE_KIND_ID:  run_tile = &TKNORM_RUN; break;
    case TK_AUDIT_TILE_KIND_ID: run_tile = &TK_AUDIT_RUN; break;
    case TK_METRIC_TILE_KIND_ID: run_tile = &TK_METRIC_RUN; break;
    default: run_tile = &TK_TILE_RUN; break;  // fallback for unknown
  }

  /* Dispatch with same params as runTileSimple: sandbox=0, keep_ct=1,
     core_dump=1, uid/gid=current, allow_fd=-1. */
  tk_topo_run_tile( topo, tile, 0, 1, 1, 0, 0, -1, run_tile );
}
```

#### 2. `src/tickoni/c_abi/shim/tile_run.h` — add extern declaration

```c
void
tk_topo_run_tile_for_tile( void * topo, void * tile );
```

#### 3. `src/tickoni/c_abi/topo_run.zig` — add extern binding + Zig wrapper

```zig
// Add to extern declarations section
extern fn tk_topo_run_tile_for_tile(topo: *Topo, tile: *TopoTile) void;

// Add to public Zig wrappers section
pub fn runTileForTile(topo: *Topo, tile: *TopoTile) void {
    tk_topo_run_tile_for_tile(topo, tile);
}
```

#### 4. `src/tickoni/runtime/tile_process.zig` — replace runTileSimple with tile-aware dispatch

```zig
// Line 203: replace
c_abi.topo_run.runTileSimple(built.topo, c_abi.topob.topoTilePtr(built.topo, tile_idx));

// With
c_abi.topo_run.runTileForTile(built.topo, c_abi.topob.topoTilePtr(built.topo, tile_idx));
```

#### 5. `src/tickoni/c_abi/shim/tile_run.c` — define kind_id constants

Ensure all tile kind_id constants are defined and accessible:

```c
// In tile_run.c or a shared header
#define TK_TILE_KIND_ID        0  // generic Zig tile
#define TKNORM_TILE_KIND_ID    1  // tknorm stem tile
#define TK_AUDIT_TILE_KIND_ID  2  // tkaudt stem tile
#define TK_METRIC_TILE_KIND_ID 3  // metric stem tile
// ... add more as needed for future stem tiles
```

Verify these match the kind_id values used in Firedancer's `fd_topo_tile_t` structure.

   - Same behavior as before, no regression

## Risks

- **Kind_id mismatch**: if the kind_id values in the switch don't match Firedancer's assignment, the wrong dispatch happens. Verify against Firedancer's tile enum or topology builder.
- **New stem tiles**: each new stem tile needs a case in the switch. Consider using a registry/factory for scalability, but the switch is fine for now (few stem tiles).
- **Metric tile**: already works with TK_METRIC_RUN via runTileSimple, but metric doesn't need input links, so TK_TILE_RUN→g_ctx.work() happens to work for it. The fix makes it dispatch TK_METRIC_RUN explicitly (correctness, not just happenstance).
