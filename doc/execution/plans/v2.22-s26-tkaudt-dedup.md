# tkaudt: eliminate duplication and redundancy

> **Status:** Plan only — not yet executed.
> **Supersedes:** `v2.22-sXX-tkaudt-cleanup-done.md` (which claimed tasks done that were not).
> **Prerequisites:** Stem tile is live and wired (Phase 4 complete). Schema unification via
> translate-c is complete (`v2.22-s25-tkaudt-schema-unification-done.md`).
> **Scope:** Consolidate duplicate code, align hash constants, remove unnecessary module indirection,
> migrate test harness to stem tile, unify PolicyOutcome type.

---

## Problem statement

The tkaudt tile currently has **four independent layers** of code and **three independent implementations** of the same logic:

1. **C stem tile** (`tk_audit_stem.c`): production audit loop — reads from Firedancer queue links,
   builds `AuditEvent`, computes SipHash, stores in scratch ring buffer.
2. **Zig codec** (`codec/audit/mod.zig` → `hash.zig`): canonical `buildEvent()` and
   `computeWireRecordHash()` — the shared builder and hash function used by all consumers.
3. **Zig test harness** (`audit_sink.zig`, `audit_shared.zig`, `audit_stage.zig`): test-mode audit
   loop — reads from heap queues, builds `AuditEvent`, computes SipHash.
4. **Dead passthrough** (`tiles/audit/mod.zig`): imports from `schema/audit/` and re-exports nothing new.
   Consumed by all payment pipeline audit files via `@import("audit_tile")`.

The test harness **should not** duplicate what the codec already provides. Hash constants are
**different** between C and Zig, meaning the production hash chain and test hash chain will diverge
for the same input event. There is also a dead `tiles/audit/` passthrough layer that adds zero value
and exists only because consumers import it via the build-module name `audit_tile`.

## Inventory of duplication

### 1. Hash key mismatch (real bug)

| Source | `k0` | `k1` | Seed |
|--------|------|------|------|
| C stem (`tk_audit_stem.c` L230) | `0x0000544455414B55` | `2` | `0xDEADBEEF` |
| Zig codec (`hash.zig` L8-9) | `0x0000544455414B54` | `2` | `0xcbf29ce484222325` |
| Zig test (`audit_sink.zig` L18) | — | — | `0xcbf29ce484222325` |

`k0` differs by **1** (`...55` vs `...54`). Seeds differ completely. This means:
- C stem and Zig test produce **different hashes** for the same event.
- The hash chain cannot reconcile between production and test.
- There is no single authoritative source for these constants.

### 2. Duplicate `buildPolicyDecisionEvent()` wrapper

| File | Lines | Calls |
|------|-------|-------|
| `audit_sink.zig` | 51–93 | `audit.buildEvent()` (codec module) |
| `audit_shared.zig` | 20–62 | `audit.buildEvent()` (codec module) |

Both functions are structurally identical. Both call the same codec `audit.buildEvent()`.
The wrapper adds nothing — it just populates a header and delegates. One copy is enough.

### 3. `audit_shared.zig` is unnecessary indirection

| Consumer | Uses from `audit_shared` | Available from `audit_sink` |
|----------|--------------------------|---------------------------|
| `replay.zig` | `audit_seed`, `buildPolicyDecisionEvent` | both are in `audit_sink` |
| `runtime.zig` | `audit_seed` | yes |

`audit_shared.zig` was created as an "extraction" from `audit_sink.zig` but:
- It still imports `audit_sink.zig` (line 12) for the `Decision` type.
- It re-exports `audit_seed` and `buildPolicyDecisionEvent` — both already in `audit_sink.zig`.
- Consumers could import `audit_sink` directly. The extra module adds no value.

### 4. Wire payload union vs C payload structs

Wire types in `wire.zig` are already auto-generated from C via translate-c (re-exported from
`c_schema`). This is correct and needs no change. The Zig-only payload structs in `audit.zig`
are also correct — they serve a different purpose (union-based codec vs scratch-allocated C
structs). No duplication here.

### 5. Test harness duplicates stem tile logic

| Component | C stem tile | Zig test harness |
|-----------|-------------|------------------|
| Event building | `tk_audit_during_frag()` | `audit_sink.buildPolicyDecisionEvent()` → `audit.buildEvent()` |
| Hash chain | SipHash in C | SipHash in Zig |
| Loop logic | `tk_audit_run()` via Firedancer links | `audit_stage.runAudit()` via heap queues |
| Storage | Scratch ring buffer (workspace) | `AuditLog` (heap) |

The test harness duplicates what the stem tile does. Since the stem tile is the production path,
all logic should converge there. The test harness should exercise the stem tile or use the codec
module exclusively.

### 6. `PolicyOutcome` defined in both C and Zig

| Source | Definition |
|--------|------------|
| C header (`audit_schema.h` L47-56) | `typedef uint8_t PolicyOutcome` + `enum { ... }` |
| Zig (`audit.zig` L13-21) | `pub const PolicyOutcome = enum(u8) { ... }` |

C and Zig define `PolicyOutcome` independently. translate-c produces `c_uint`, not a usable Zig
enum. But the Zig enum has different field names and implicit backing values from the C enum.
This is duplication that should be eliminated.

### 7. Dead `tiles/audit/` passthrough module

| File | Imports | Re-exports | Value |
|------|---------|------------|-------|
| `tiles/audit/mod.zig` | `types.zig`, `codec.zig` | all symbols from both | none |
| `tiles/audit/types.zig` | `audit_schema` | all symbols from `audit_schema` | none |
| `tiles/audit/codec.zig` | `audit_codec` | all symbols from `audit_codec` | none |

Consumers:
- `payment_pipeline/audit_sink.zig` → `@import("audit_tile")` → `tiles/audit/mod.zig` → `types.zig`
- `payment_pipeline/audit_stage.zig` → `@import("audit_tile")` → same chain
- `payment_pipeline/audit_shared.zig` → `@import("audit_tile")` → same chain
- `payment_pipeline/replay.zig` → `@import("audit_tile")` → same chain
- `payment_pipeline/runtime.zig` → `@import("audit_tile")` → same chain
- `payment_pipeline/mod.zig` → `@import("audit_tile")` → same chain

All 6 consumers do `@import("audit_tile")` which resolves to `tiles/audit/mod.zig`, which does
nothing but `@import("audit_schema")` and re-export. Every symbol is already in `schema/audit/`.
This is dead indirection.

## Execution plan

### Step 1: Add hash constants to `audit_schema.h`

**File:** `src/tickoni/c_abi/shim/audit_schema.h` (modify)

Add constants at the top of the header so both C and Zig derive them from one source:

```c
/* ─── Audit hash constants ─── */
#define AUDIT_HASH_K0  0x0000544455414B54ULL  /* SipHash key k0 ("TKAUDT\0\0" LE) */
#define AUDIT_HASH_K1  2                        /* SipHash key k1 (schema version) */
#define AUDIT_SEED     0x0000000000000000ULL   /* Initial prev_hash (identity seed) */
```

**Notes:**
- `k0` uses `...54` to match the current Zig codec value. The `...55` in C stem was a typo.
- `AUDIT_SEED` uses `0` (identity). This is the correct initial value for an append-only hash chain
  — a nonce/seed value is not needed. The previous values (`0xDEADBEEF`, `0xcbf29ce484222325`) were
  arbitrary constants with no semantic meaning.

### Step 2: Align C stem — remove all hardcoded audit constants

**File:** `src/tickoni/c_abi/shim/tk_audit_stem.c` (modify)

Three changes to remove all hardcoded audit constants and use header defines:

```c
// Remove local AUDIT_SEED define (L74)
// Before:
// #define AUDIT_SEED 0xDEADBEEF
// After: nothing — AUDIT_SEED resolves from audit_schema.h #include

// Fix SipHash key k0 and use header defines (L230)
// Before:
fd_siphash13_init( sip, 0x0000544455414B55ULL, 2ULL );
// After:
fd_siphash13_init( sip, AUDIT_HASH_K0, AUDIT_HASH_K1 );
```

**Rationale:** C stem had two hardcoded values: `AUDIT_SEED = 0xDEADBEEF` (arbitrary) and `k0 = 0x...55` (typo). Both are replaced by header constants defined in Step 1.

**Impact:** Existing hash chains change (seed and k0 both change). Handled in Step 7.

### Step 6: Regenerate test fixtures

**Files affected:**
- `src/tickoni/test/fixtures/investment/audit_trace.zig` — `buildAllowedTradeChain`, `buildOversizedTradeBlockedChain`, `buildRestrictedInstrumentBlockedChain` all call `audit.buildEvent()` which uses `computeWireRecordHash()` → SipHash with new `k0` and initial `prev_hash = 0`. ### Step 7: Unify PolicyOutcome type

**File:** `src/tickoni/c_abi/shim/audit_schema.h` (modify)
**File:** `src/tickoni/schema/audit/audit.zig` (modify)

Make `PolicyOutcome` authoritative in Zig, re-export from C via translate-c.

**C header — add explicit values matching Zig enum:**
```c
/* ─── PolicyOutcome (unified — Zig is authoritative) ─── */
typedef uint8_t PolicyOutcome;
enum {
    POLICY_ALLOW                 = 0,
    POLICY_DENY                  = 1,
    POLICY_REQUIRE_APPROVAL      = 2,
    POLICY_MALFORMED_DROP        = 3,
    POLICY_DUPLICATE_DROP        = 4,
    POLICY_ESCALATE              = 5,
    POLICY_REQUIRE_MORE_EVIDENCE = 6,
};
```

**Zig — re-export from C via translate-c instead of defining independently:**
```zig
// Before (audit.zig L13-21):
pub const PolicyOutcome = enum(u8) {
    allow,
    deny,
    require_approval,
    malformed_drop,
    duplicate_drop,
    escalate,
    require_more_evidence,
};

// After:
pub const PolicyOutcome = c_schema.PolicyOutcome;

comptime {
    std.debug.assert(@intFromEnum(PolicyOutcome.allow) == 0);
    std.debug.assert(@intFromEnum(PolicyOutcome.deny) == 1);
    std.debug.assert(@intFromEnum(PolicyOutcome.require_approval) == 2);
    std.debug.assert(@intFromEnum(PolicyOutcome.malformed_drop) == 3);
    std.debug.assert(@intFromEnum(PolicyOutcome.duplicate_drop) == 4);
    std.debug.assert(@intFromEnum(PolicyOutcome.escalate) == 5);
    std.debug.assert(@intFromEnum(PolicyOutcome.require_more_evidence) == 6);
}
```

**Rationale:** `PolicyOutcome` is defined in both C header and Zig schema independently. translate-c
from `audit_schema.h` produces the authoritative C values. Zig re-exports and asserts at compile
time that the backing values match. This eliminates the duplicate definition.

**Impact:** Any code that depends on the Zig `PolicyOutcome` enum values must continue to work
because the assert blocks verify backing values match the C enum. No runtime change.

### Step 9: Migrate test harness to use codec module exclusively

**File:** `src/tickoni/tiles/payment_pipeline/audit_stage.zig` (modify)
**File:** `src/tickoni/tiles/payment_pipeline/audit_sink.zig` (modify)
**File:** `src/tickoni/tiles/payment_pipeline/mod.zig` (modify)

Replace the test harness's manual `AuditLog.append()` logic with calls to the codec module
`audit.buildEvent()` + `audit.computeRecordHash()`. The test loop in `runAudit` should:
1. Call `audit.buildEvent(header, payload)` to build each `AuditEvent`
2. Call `audit.computeRecordHash(event)` to compute the record hash
3. Store in `AuditLog` (heap) — same data structure, but event building is unified

**audit_stage.zig changes:**
```zig
// Before (runAudit):
// manually builds header, calls state.audit.append({header, payload})

// After (runAudit):
// uses audit.buildEvent() from codec module for event building
const event = audit.buildEvent(header, payload);
state.audit.append(event);
```

**audit_sink.zig changes:**
- Remove `buildPolicyDecisionEvent()` — consumers should call `audit.buildEvent()` directly.
- Remove `fillEventMetadata()` — same reason.
- Keep `AuditLog` and `Decision` — these are test-harness data structures, not duplication.

**mod.zig changes:**
- The test block already re-exports `audit_sink` and calls `runAudit`. After Step 9, `runAudit`
  will use `audit.buildEvent()` so no mod.zig changes needed beyond removing the old
  `buildPolicyDecisionEvent` import if used.

**Rationale:** The test harness manually builds `AuditEvent` structs (duplicate of what the codec
already provides). By using `audit.buildEvent()` from the codec module, the test harness exercises
the same code path as production. The test loop structure (reading queues, appending to `AuditLog`)
remains — that's test harness, not duplication.

**Impact:** Test logic changes (event building path), but test assertions (hash chain, record count)
remain the same. Hash values may change if the event building produces different field layouts —
unlikely since `audit.buildEvent()` uses the same Zig structs.
