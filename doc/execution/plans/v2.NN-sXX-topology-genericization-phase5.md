# v2.NN-sXX-topology-genericization

## Problem

The topology/orchestrator/supervisor assumes tile ordering and tile count.
Channels reference tiles by array index, not by identity. The supervisor
uses fixed `[8]` arrays everywhere. C shims do `strcmp(tile_name, "tkaudt")`
and `strcmp(tile_name, "metric")` — scattered string comparisons that tie
the runtime to specific tile IDs/names.

Changes that broke things:

1. `topologies.zig`: changed `.name` from `"tkaudt"` → `"tkaudt"`,
   `"tkrepl"` → `"replay_tile"`, `"tkdiag"` → `"diag_tile"`.
2. `tile_run.c`: changed `strcmp(tile->name, "tkaudt")` → `"tkaudt"`.
3. `topob.c`: still checks `"tkaudt"` (TileId string) — **inconsistent**.
   Now `tile_run.c` matches `.name`, `topob.c` matches TileId. They diverge.

Rule: only the tk-audit file and build system should know about `tkaudt`.
The orchestrator, supervisor, topology builder, and C shims must not do
string comparisons against tile IDs.

## Root Cause

- Channels use `src_idx: u32, dst_idx: u32` — positional, not identity-based.
- `topo_build.zig` indexes `topo_desc.tiles[ch.src_idx]` — array position.
- `supervisor.zig` uses `[8]` fixed arrays for CNCs, children, configs.
- `tile_registry.zig` validate() iterates channels by `src_idx/dst_idx` — position-based.
- `launch_spec.zig` bucketing uses `ch.dst_idx == fields.tile_idx` — position-based.
- `topob.c` does `strcmp(tile_name, "tkaudt")` — C-level string matching.
- Firedancer's topology C API (`fd_topo_find_tile(topo, name, kind_id)`) is string-based; Tickoni still needs TileId→name conversion at that boundary.
- No TileId→index resolution step — indices are only meaningful because TileDescriptor order is assumed stable everywhere.
- Two distinct "index" concepts collide: descriptor-array position vs Firedancer tile index (metric tile is at descriptor index 6 but Firedancer index `non_metric_count` because it's registered last, after non-metric tiles).

## Solution Overview

Replace positional topology with identity-based topology. Channels store TileId values. Resolve TileId→index once at build time in `topo_build.zig` (linear scan over tiles — O(n) once, not per-channel). Properties (scratch requirements, audit-stem flag) live on TileDescriptor, not a separate enum registry. Replace fixed `[8]` arrays with `[max_tiles]` arrays (a compile-time constant that absorbs new tile growth). No new enum types lock the topology to a specific tile count.

**TileId stays a struct** (6-byte char array, `tile.zig:5-23`). It is the identity. A separate TileRole enum is not introduced — that would be a rigid enum just as locked to tile count as the current `[8]` arrays, and would require updating the enum plus registry every time a new tile (tkcase, tkmodl, tktool, tkadpt) is added. TileDescriptor already carries `id`, `name`, and `cpu_placement` — scratch/workspace properties go on it as optional fields.

## Index Naming Convention (mandatory)

Two kinds of indices exist and must never be confused:

| Concept | Where it lives | Meaning |
|---------|---------------|---------|
| **Descriptor index** | `topologies.zig` tile array position | Positional, order-dependent. **Deprecated** after Phase 1. |
| **Firedancer tile index** | `topo_build.zig:fd_tile_idx_by_desc`, `BuiltTopo` | Index into Firedancer's internal tile array. Stable across reorders. |

**Renaming rules (applied during Phase 1):**

- `LaunchSpec.tile_idx` → `LaunchSpec.fd_tile_idx` — always carries the Firedancer tile index (the index used for CNC objects, scratch layout, and C-API calls).
- `TileHandle.tile_idx` → `TileHandle.fd_tile_idx` — always carries the Firedancer tile index (used for supervisor diagnostics).
- `BuiltTopoTileInfo` already uses Firedancer index — no rename needed.
- The `fd_tile_idx_by_desc` mapping in `topo_build.zig` is the single source of truth for converting descriptor position → Firedancer index.

**Wire-format note:** `LaunchSpec.tile_idx` → `fd_tile_idx` is a field rename, not a structural change. The layout and byte size stay identical (same u32 offset). Old readers checking `tile_idx` at the same offset will still read the value, just with a stale name. No version bump required. The `init()` caller struct also uses `.tile_idx = fields.tile_idx` — that's a Zig struct literal, not wire, so the rename is free for the caller-facing API.

## Importability Tradeoffs

This change improves importability for specific scenarios and does not for others. Understanding the boundary prevents false expectations.

**Improves:**

- Reordering tiles within an existing topology: channel TileIds are stable, indices are resolved at build time.
- Declaring new topologies: channel definitions reference TileId strings, not array positions.
- Renaming tiles (`.name` field): no C shim or channel wiring breaks.

**Does not improve (by design):**

- Adding new tile types to the runtime: `tile_registry.zig:entries` still requires explicit registry updates. This is intentional — the registry owns process-mode dispatch, counter schemas, and expected link cardinality.
- Adding new tiles to an existing topology: the bijection check in `tile_registry.zig:validate()` requires every registered tile to appear in the topology and vice versa. New tiles need registry entries.
- `max_links_per_tile = 4` on `LaunchSpec`: a compile-time constant on a raw-byte struct that is versioned through a handoff file. Changing this requires a version bump, not just a code change. Keep at 4 for now — if the topology is designed so no tile needs >4 links, this is fine. The constraint is a version-bump away, not a blocker.

## Phases

### Phase 0: Immediate Fix (unbreak the build)

### Phase 1: TileId-based channels — replace index references with TileId values

**Goal:** Channels reference tiles by TileId, not by array index. This is the
single highest-impact change: it breaks the positional dependency at the
schema level and makes reordering tiles in `topologies.zig` harmless.

**Current:**
```zig
.{ .src_idx = 0, .dst_idx = 1, ... }
```

**Target:**
```zig
.{ .src_id = try TileId.parse("tkings"), .dst_id = try TileId.parse("tknorm"), ... }
```

**Design decisions:**

- `src_id` / `dst_id` are `tile.TileId` values (6-byte struct, not an enum).
  TileId is already parsed at comptime in `topologies.zig`, so channel
  definitions stay zero-cost — no runtime parsing overhead.
- TileId→index resolution happens once in `topo_build.zig` before channel
  wiring. A linear scan over the topology's tile array maps each TileId to
  its Firedancer tile index. The resolved index is then used for the actual
  Firedancer C API calls (`topobTileIn`, `topobTileOut`).
- Validation in `topology.zig` checks that each TileId exists in the tile
  list rather than checking `src_idx < tiles.len`.
- The `Topology.validate()` error set gains `UnknownChannelSource` and
  `UnknownChannelDestination` instead of `ChannelSrcOutOfRange` /
  `ChannelDstOutOfRange`.

**Changes:**

1. **`src/tickoni/runtime/link/types.zig`** — Channel struct:
   ```zig
   pub const Channel = struct {
       src_id: TileId,      // was: src_idx: u32
       dst_id: TileId,      // was: dst_idx: u32
       depth: u32,
       mtu: u32,
       backing: LinkBacking = .heap_dev,
       reliability: LinkReliability = .reliable,
       workspace_name: WorkspaceName = .{},
   };
   ```

2. **`src/tickoni/runtime/topology.zig`** — `Topology.validate()`:
   ```zig
   for (self.channels) |ch| {
       if (findById(self.tiles, ch.src_id) == null) return error.UnknownChannelSource;
       if (findById(self.tiles, ch.dst_id) == null) return error.UnknownChannelDestination;
       if (ch.src_id.eql(ch.dst_id)) return error.ChannelSelfLoop;
       // ... depth, workspace checks unchanged
   }
   ```

3. **`src/app/tickoni/topologies.zig`** — all channels use TileId values:
   ```zig
   const payment_channels = [_]Channel{
       .{ .src_id = TileId.parse("tkings") catch unreachable,
           .dst_id = TileId.parse("tknorm") catch unreachable,
           .depth = 64, .mtu = 128 },
       .{ .src_id = TileId.parse("tknorm") catch unreachable,
           .dst_id = TileId.parse("tkdedu") catch unreachable,
           .depth = 64, .mtu = 128 },
       // ...
   };
   ```

4. **`src/tickoni/runtime/topo_build.zig`** — channel wiring: use existing
   `BuiltTopo.tileIdxById()` (line 129-134) for TileId→Firedancer-index resolution.
   No separate helper needed — the method already does a linear scan over
   `tile_infos` (indexed by Firedancer index). Resolution happens after
   `fd_tile_idx_by_desc` is populated, so `tile_infos` maps Firedancer idx →
   metadata. For descriptor→TileId lookup (before build), use a simple linear
   scan:

   ```zig
   // Helper for pre-build descriptor→TileId lookup (validation phase):
   fn tileById(tiles: []const TileDescriptor, id: TileId) usize {
       for (tiles, 0..) |t, i| if (t.id.eql(id)) return i;
       unreachable; // validated already in topology.validate()
   }

   // After build: use BuiltTopo.tileIdxById() instead.
   ```

   Channel wiring loop uses Firedancer indices from the pre-build lookup:
   ```zig
   for (topo_desc.channels, 0..) |ch, i| {
       const src_desc_idx = tileById(topo_desc.tiles, ch.src_id);
       const dst_desc_idx = tileById(topo_desc.tiles, ch.dst_id);
       const src_fd_idx = fd_tile_idx_by_desc[src_desc_idx];
       const dst_fd_idx = fd_tile_idx_by_desc[dst_desc_idx];
       const src_name_z = toZ(&src_name_buf, topo_desc.tiles[src_desc_idx].id.slice());
       const dst_name_z = toZ(&dst_name_buf, topo_desc.tiles[dst_desc_idx].id.slice());
       // ... rest uses src_fd_idx/dst_fd_idx for C API
   }
   ```

5. **`src/app/tickoni/tile_registry.zig`** — `validate()` uses TileId matching:
   ```zig
   for (topo.channels) |ch| {
       if (ch.dst_id.eql(tile_id)) in_cnt += 1;
       if (ch.src_id.eql(tile_id)) out_cnt += 1;
   }
   ```
   **Note:** The current code at `tile_registry.zig:274-281` iterates `topo.tiles` by descriptor index `i` and counts channels via `ch.dst_idx == i`. This must become a TileId-based count that matches each channel against the registry entry's `tile_id`. This is a direct dependency of Phase 1.

6. **`src/tickoni/runtime/launch_spec.zig`** — `LaunchSpec.init()` bucketing
   changes from index-based to TileId-based. The tile's own TileId is
   already on the LaunchSpec struct. Bucketing matches channels where
   `ch.dst_id.eql(tile_id)` (inbound) or `ch.src_id.eql(tile_id)` (outbound):
   ```zig
   for (fields.channels, fields.link_handles) |ch, lh| {
       if (ch.dst_id.eql(fields.tile_id)) {
           if (spec.in_cnt >= max_links_per_tile) return error.TooManyInLinks;
           spec.in_links[spec.in_cnt] = lh;
           spec.in_cnt += 1;
       }
       if (ch.src_id.eql(fields.tile_id)) {
           if (spec.out_cnt >= max_links_per_tile) return error.TooManyOutLinks;
           spec.out_links[spec.out_cnt] = lh;
           spec.out_cnt += 1;
       }
   }
   ```

   **Index rename:** `LaunchSpec.tile_idx` → `LaunchSpec.fd_tile_idx`. The field always carries the Firedancer tile index (the index used for CNC objects and C-API calls). The `fd_tile_idx_by_desc` mapping in `topo_build.zig` is the single source for the descriptor→Firedancer index conversion.

   **Wire-format compatibility:** This is a field rename, not a structural change. Same u32 offset, same size. Old readers checking `tile_idx` at the same offset will still read the value. No version bump required.

7. **`src/app/tickoni/supervisor.zig`** — spawn loop passes TileId-based
   channels to `LaunchSpec.init()`. Loop bounds use `.len`. TileId passed
   to child spec: `tile.id`. Rename all references from `tile_idx` to `fd_tile_idx`.

### Phase 2: Replace fixed `[8]` arrays with `[max_tiles]` arrays

**Goal:** Supervisor handles arbitrary tile counts. No hardcoded 8
anywhere in the process-mode path.

**Design decision:** Keep arrays inside ProcessState but make the capacity
a compile-time constant instead of a hardcoded literal. ProcessState's job
is to hold per-tile state indexed by Firedancer tile index — it is allocated
as a raw bytes chunk via `alignedAlloc`. Replacing `[8]` with heap slices
inside this raw struct is fragile: slices carry `(ptr, len)` pairs that
require separate allocation/free tracking, and `installLifecycleTestState()`
already writes every field manually.

Instead, use `[max_tiles]` arrays where `max_tiles` is a compile-time const
that absorbs new tile growth. Iterate by `.len` (set from `topo.tiles.len`
at init time). This is the minimal change — just a const bump, no slice
lifetime management, no deinit complexity.

**Changes:**

1. **Add `max_tiles` constant** (in `supervisor.zig` or `runtime/`):
   ```zig
   /// Maximum tile count for fixed-size arrays in ProcessState.
   /// Current topology has 8 tiles (payment) / 14 tiles (investment).
   /// Set to 16 for headroom; bump if a topology exceeds this.
   pub const max_tiles: usize = 16;
   ```

2. **`ProcessState`** — replace `[8]` with `[max_tiles]`:
   ```zig
   cnc_gaddrs: [max_tiles]usize,
   cncs: [max_tiles]?*c_abi.cnc.Cnc,
   children: [max_tiles]ChildRecord,
   ```

3. **`ProcessPipelineConfig`** — replace `[8]u32`:
   ```zig
   crash_after_heartbeats: [max_tiles]u32 = std.mem.zeroes([max_tiles]u32),
   ```
   Callers pass a slice matching `topo.tiles.len` (truncated to `max_tiles` at compile time).

4. **`refreshProcessHealth()` / `snapshotProcessMetrics()` / `stopProcess()`** —
   all loops use `state.cncs.len` or `state.children.len` instead of hardcoded
   8. All `suppress_cnc` arrays replaced with `[max_tiles]bool` sized to
   `topo.tiles.len` (which is ≤ `max_tiles`). `link_handles_buf` replaced with
   `[max_tiles]rt.link.LinkHandles` sized to `self.topo.channels.len`.

5. **`installLifecycleTestState()`** — test helper that creates ProcessState
   for lifecycle tests also uses `[max_tiles]` arrays.

6. **`supervisor.zig`** — `ProcessState` initialization (lines 540-542, 584,
   830, 951, 1267-1268, 1293) all changed to use `[max_tiles]...` instead of
   `std.mem.zeroes([8]...)`.

**Verification:** `std.debug.assert(self.topo.tiles.len <= max_tiles)` at
`startPaymentPipelineProcess` to catch configuration drift early.

### Phase 3: Remove C shim string comparisons for scratch properties

**Goal:** Eliminate `strcmp(tile_name, "tkaudt")` and `strcmp(tile_name, "metric")`
from C scratch-property functions in `topob.c`. Tile-specific scratch
requirements (audit stem, metric footprint) declared on `TileDescriptor`,
read directly by `topo_build.zig` at build time without any C-side string
matching.

**Scoping note:** `tile_run.c` has `strcmp` calls for **stem-loop run dispatch**
(`tile_is_audit` → TK_AUDIT_RUN, `tile_is_metric` → TK_METRIC_RUN). This is a
different layer: Firedancer's stem run loop for audit/metric tiles, not a
scratch-property query. The process-mode pipeline dispatch in
`tile_registry.zig` + `tile_main.zig` handles Zig-callback tiles (tkings,
tknorm, tkdedu, tkpoly, tkaudt) — it does NOT replace the Firedancer stem-loop
dispatch in `tile_run.c`. Stem-loop dispatch remains a future refinement (see
Phase 5 note below). Phase 3 only removes strcmp from **scratch-property**
functions.

**Changes:**

1. **`TileDescriptor`** (`src/tickoni/runtime/tile.zig`) — add optional property
   fields:
   ```zig
   pub const TileDescriptor = struct {
       id: TileId,
       name: []const u8,
       cpu_placement: cpu_placement.CpuPlacement = .floating,
       /// Non-null when this tile has a custom scratch footprint/alignment
       /// that the Firedancer layout engine must respect. Used by audit and
       /// metric tiles. Set by the topology author in topologies.zig.
       /// Also serves as the metric tile detection flag for topo_build.zig.
       scratch_reqs: ?TileScratchReqs = null,
   };

   pub const TileScratchReqs = struct {
       align: usize,
       footprint: usize,
   };
   ```
   **Status:** Already implemented.

2. **`topologies.zig`** — audit and metric tiles declare their scratch
   requirements. Audit tile uses known constants from `tk_audit_stem.h`
   (`TKAUDT_CTX_ALIGN = 64`); metric tile uses Firedancer primitives
   (`fd_scratch_smem_align()`). These are set as compile-time known values:
   ```zig
   .{ .id = TileId.parse("tkaudt") catch unreachable,
       .name = "tkaudt",
       .scratch_reqs = .{ .align = 64, .footprint = /* computed at build */ },
   },
   .{ .id = TileId.parse("metric") catch unreachable,
       .name = "metric",
       .scratch_reqs = .{ .align = /* fd_scratch_smem_align() */ 64,
                          .footprint = /* tk_metric_scratch_footprint() */ },
   },
   ```
   Actual footprint values come from C-side functions via `c_abi.topob` at
   build time (comptime-unreachable since topology authors know the values
   or defer to the C accessor).

3. **`topo_build.zig`** — replace the existing C-side call
   `c_abi.topob.tickoniTileScratchRequirements()` with direct access to
   `t.scratch_reqs`. Set tile properties using the TileDescriptor values
   instead of querying the C shim:
   ```zig
   for (topo_desc.tiles) |*t| {
       if (t.scratch_reqs) |reqs| {
           var tile_name_buf: [8]u8 = undefined;
           const name_z = toZ(&tile_name_buf, t.id.slice());
           c_abi.topob.topobSetTileObjPropertyUlong(
               topo, name_z, 0, "tickoni.scratch_footprint", reqs.footprint);
           c_abi.topob.topobSetTileObjPropertyUlong(
               topo, name_z, 0, "tickoni.scratch_align", reqs.align);
       }
   }
   ```

4. **`topob.c`** — remove `strcmp` logic from
   `tk_topob_tickoni_tile_scratch_footprint()` and
   `tk_topob_tickoni_tile_scratch_requirements()`. Make them return default
   values (1) — no tile-specific properties needed from C side anymore.
   The `tile_footprint()` function already queries properties via
   `fd_pod_queryf_ulong` and falls through to 1UL — no changes needed there.

5. **`topob.c` `tile_footprint()`** — this function already queries properties
   set by topo_build.zig and returns 1UL for generic tiles. It has NO strcmp
   calls — it works correctly. No changes needed.

**Also in this phase:** Fix **both** metric tile string comparisons in
`topo_build.zig` in a single pass:

- Lines 188-193: `has_metric_tile` scan — `std.mem.eql(u8, t.id.slice(), "metric")`
- Line 238: `fd_tile_idx_by_desc` assignment — `std.mem.eql(u8, t.id.slice(), "metric")`

Replace both with `t.scratch_reqs != null`. The metric tile declaration in
`topologies.zig` will set `.scratch_reqs = .{ ... }`, so `scratch_reqs != null`
is a precise, zero-overhead detection that doesn't depend on the tile name
string at all.

**Phase 5 (future):** Stem-loop run dispatch in `tile_run.c` currently uses
`strcmp(tile->name, "metric")` and `strcmp(tile->name, "tkaudt")` to
decide whether to use TK_METRIC_RUN or TK_AUDIT_RUN. This is Firedancer's
stem-based run loop, not process-mode pipeline dispatch. A future Phase 5
could replace this with a tile property set by topo_build.zig (e.g. a
`stem_type` enum on TileDescriptor), or a Firedancer-style kind_id field.
This is out of scope for Phase 3.

### Phase 4: TileId→name conversion at Firedancer boundary

**Goal:** Ensure every place that converts TileId to Firedancer C topology
string names is explicit and correct. This is the glue that connects
Tickoni's identity-based topology to Firedancer's string-based C API.

**Changes:**

1. **`src/tickoni/runtime/topo_build.zig`** — single `tileIdToName()`
   function that converts TileId to a null-terminated string buffer for
   Firedancer C calls. All uses go through this function (currently
   scattered across the channel-wiring loop and metric tile setup).

2. **Verify no other files** do ad-hoc TileId→C-string conversion outside
   `topo_build.zig`. The C shim layer should use the same `tileIdToName()`
   helper via an `extern fn` declaration.

**Note:** TileId→name conversion already exists in `topo_build.zig` (lines
309-310) as `toZ(&buf, topo_desc.tiles[idx].id.slice())`. After Phase 1,
the `idx` becomes a Firedancer index from TileId resolution, so this phase
is incremental — formalizing and centralizing existing calls into a single
`tileIdToName(id, buf)` helper rather than inlining `toZ()` at every call
site.

## What NOT to do

- Don't introduce a TileRole enum. It would be a rigid enum just as locked
  to tile count as the current `[8]` arrays, and would require updating the
  enum plus a separate registry every time a new tile (tkcase, tkmodl,
  tktool, tkadpt) is added. TileDescriptor properties are the right place
  for tile-specific behavior flags.
- Don't make TileId an enum. TileId is a 6-byte struct matching Firedancer's
  `char name[7]` constraint. An enum would lock the runtime to a fixed set
  of tile IDs and break Firedancer compatibility.
- Don't add a config file to map tile names to roles. This is compile-time
  knowledge — the topology defines which tiles run and what they do.
- Don't use string-based routing (e.g., "if name starts with 'tk' it's a
  pipeline tile"). Use explicit fields on TileDescriptor.
- Don't change Firedancer's C topology ABI. Tickoni resolves TileId→name
  at its own boundary; Firedancer continues to use string-based lookups.
- Don't rename `tile_idx` to something ambiguous. Always use `fd_tile_idx`
  when the value carries a Firedancer tile index, and avoid bare `tile_idx`
  entirely.
- Don't change `max_links_per_tile` from 4 in this plan. It's a compile-time
  constant on a versioned wire struct; bumping it requires a version bump.
  If the topology is designed so no tile needs >4 links, 4 is fine.
