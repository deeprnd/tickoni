# V2.10.S8.1.1 — Plan

## Scope Summary

`contrib/setup/orchestrator.py` is 1063 lines in a single file. It mixes config loading, dependency resolution, platform detection, install-method implementations, CLI parsing, and main-loop orchestration. No clear boundaries. Hard to test, hard to extend (adding a new install method requires editing the big file).

Apply Gang of Four patterns to split into a small package (`contrib/setup/`) with explicit interfaces:

| Pattern | Where | What it solves |
|---------|-------|----------------|
| **Strategy** | Install methods | Each method is its own strategy class with a unified `execute(tool, config, platform, dry_run)` interface |
| **Registry** | Method lookup | Central registry replaces the dict literal; supports dynamic registration and lookup |
| **Factory** | Strategy creation | Factory class that looks up and instantiates the right strategy for a given `install_method` string |
| **Facade** | Orchestrator | Single `setup_categories(cats)` API hides the dependency-resolution → tool-collection → platform-filter → install pipeline |
| **Command** | Idempotency check | Wrap `idempotent_check` into a Command object for pluggable pre-flight checks |
| **Template Method** | Install base class | Common download/extract/install flow shared by `github_release` and `binary_download` |

Result: 6 source files instead of 1, each under 200 lines.

## GoF Pattern Breakdown

### 1. Strategy Pattern — Install Methods

**File:** `install/base.py` + `install/strategies/`

Every install method becomes a class implementing a unified interface:

```python
# install/base.py
from abc import ABC, abstractmethod

class InstallStrategy(ABC):
    @abstractmethod
    def execute(self, tool: dict, config: dict, platform_str: str, dry_run: bool) -> None:
        """Install the tool using this strategy."""
        ...
```

Concrete strategies live in `install/strategies/`:
- `AptInstallStrategy` (covers apt, brew, winget — dispatches internally by platform)
- `PipInstallStrategy` (pip, pipx, go_install)
- `GitHubReleaseStrategy` (github_release, cbmc_deb, litani_deb)
- `BinaryDownloadStrategy` (binary_download)
- `ZigInstallStrategy` (install_zig)
- `PythonScriptStrategy` (python_script)
- `BuildFromSourceStrategy` (build_from_source)
- `NoneStrategy` (none)

**Why Strategy over a giant if/elif chain:** Each strategy is independently testable. Adding a new method is a new file, no editing the orchestrator.

### 2. Registry Pattern — Method Lookup

**File:** `install/__init__.py`

Central registry replaces the current `INSTALL_METHODS` dict:

```python
# install/__init__.py
from .base import InstallStrategy

_REGISTRY: dict[str, type[InstallStrategy]] = {}

def register(method_name: str):
    """Decorator: register a strategy class under a method name."""
    def decorator(cls: type[InstallStrategy]) -> type[InstallStrategy]:
        _REGISTRY[method_name] = cls
        return cls
    return decorator

def get(method_name: str) -> InstallStrategy:
    cls = _REGISTRY.get(method_name)
    if cls is None:
        raise KeyError(f"unknown install_method '{method_name}'")
    return cls()
```

Strategies register themselves:
```python
# install/strategies/apt.py
from .. import register

@register('apt')
@register('brew')
@register('winget')
class AptInstallStrategy(InstallStrategy):
    def execute(self, ...):
        ...
```

### 3. Factory Pattern — Strategy Instantiation

**File:** `install/__init__.py` (combined with registry)

`get(method_name)` IS the factory. It returns a ready-to-use strategy instance. The client code calls:
```python
strategy = registry.get(method_name)
strategy.execute(tool, config, platform_str, dry_run)
```

### 4. Template Method Pattern — Download/Install Flow

**File:** `install/base.py`

`github_release` and `binary_download` share 80% of their logic: resolve version → download archive → verify checksum → extract → find binary → install. Template Method extracts this:

```python
# install/base.py
class DownloadInstallStrategy(InstallStrategy):
    """Template Method for archive-based installs."""

    def execute(self, tool, config, platform_str, dry_run):
        archive_url = self._resolve_url(tool, config)
        self._download(archive_url, tool, dry_run)
        self._verify_checksum(tool, config, dry_run)
        extract_path = self._extract(archive_url, dry_run)
        self._install_binary(extract_path, tool, dry_run)

    def _resolve_url(self, tool, config) -> str: ...
    def _download(self, url, tool, dry_run): ...
    def _verify_checksum(self, tool, config, dry_run): ...
    def _extract(self, archive_path, dry_run) -> Path: ...
    def _install_binary(self, extract_path, tool, dry_run): ...
```

`GitHubReleaseStrategy` and `BinaryDownloadStrategy` override only the URL resolution hook.

### 5. Command Pattern — Idempotency Checks

**File:** `install/checks/command.py`

Wrap idempotency checks as Command objects:

```python
# install/checks/command.py
from abc import ABC, abstractmethod

class CheckCommand(ABC):
    @abstractmethod
    def is_satisfied(self) -> bool:
        """Return True if the tool is already installed."""
        ...

class ShellCheckCommand(CheckCommand):
    def __init__(self, cmd: str):
        self.cmd = cmd

    def is_satisfied(self) -> bool:
        try:
            subprocess.run(self.cmd, shell=True, capture_output=True, timeout=10)
            return True
        except (FileNotFoundError, subprocess.TimeoutExpired, OSError):
            return False
```

Registry for check commands:
```python
_REGISTRY = {
    'shell': ShellCheckCommand,
    'winget': WingetInstalledCommand,  # parses winget output
}
```

The orchestrator builds the right command from `tool.get('idempotent_check')` and checks before running the install strategy.

### 6. Facade Pattern — Orchestrator

**File:** `orchestrator.py`

Single public API hiding the pipeline:

```python
# orchestrator.py
from .config import load_config
from .resolver import Resolver
from .platform import PlatformMatcher
from .install import get as get_strategy

class Orchestrator:
    """Facade: setup_categories(['fd']) → installs everything."""

    def __init__(self, config: dict):
        self.config = config
        self.resolver = Resolver(config)
        self.matcher = PlatformMatcher()

    def setup(self, categories: list[str], platform_str: str, dry_run: bool) -> list[dict]:
        """Run the full setup pipeline. Returns list of install results."""
        resolved = self.resolver.resolve(categories)
        tools = self.resolver.collect(resolved)
        tools = self.matcher.filter(tools, platform_str)
        results = []
        for tool in tools:
            result = self._install_tool(tool, platform_str, dry_run)
            results.append(result)
        return results

    def _install_tool(self, tool, platform_str, dry_run):
        check_cmd = self._build_check(tool)
        if check_cmd and check_cmd.is_satisfied():
            return {'tool': tool['name'], 'status': 'already_installed'}
        strategy = get_strategy(tool['install_method'])
        strategy.execute(tool, self.config, platform_str, dry_run)
        return {'tool': tool['name'], 'status': 'installed'}
```

Main is now 30-40 lines of CLI wiring calling the facade.

## Risk Assessment

| Risk | Mitigation |
|------|-----------|
| Registry circular imports | Use lazy imports in `__init__.py` (import inside `get()`) or deferred import at end of file |
| Strategy behavior drift during migration | Run `--dry-run` comparison before and after each migration step; output must match exactly |
| Template Method over-engineering | Only extract if 2+ strategies share >50% of logic. If not, keep them as separate strategies without a shared base |
| Winget shell detection complexity | Extract as a standalone `WingetShellResolver` helper class; keep it isolated in apt.py |
| Zig strategy is ~130 lines itself | Accept this; it's a complex strategy with many concerns (index, minisig, extract, PATH). Consider a follow-on split if needed |
