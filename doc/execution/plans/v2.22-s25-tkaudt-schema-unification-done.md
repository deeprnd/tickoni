# Schema Unification — Align audit.zig C↔Zig Structs

> **Status:** Plan only — not yet executed.
> **Prerequisite:** None (standalone refactor, does not depend on stem tile migration).
> **Scope:** Use Zig 0.16+ `addTranslateC` to generate a `audit_mod` module from
> `audit_schema.h`, then re-export `Header` and `PolicyDecisionPayload` from it
> in `audit.zig`. Add compile-time `static assert` layout checks. Keep
> `PolicyOutcome`, `RecordType`, and all Zig-only types as pure Zig.
>
> **Why:** The C schema (`audit_schema.h`) and Zig schema (`audit.zig`) define
> overlapping types independently. If they drift, the stem tile (which builds
> `AuditHeader` in C) will produce records with wrong field offsets, corrupting
> the hash chain and binary codec. Right now alignment is checked by runtime
> tests or not at all. This plan replaces that with compile-time enforcement.

---

## What Changes and What Stays

| Type | Origin | Reason |
|------|--------|--------|
| `Header` (= `AuditHeader`) | **translate-c** from `audit_schema.h` | Struct used by both C (stem tile) and Zig (codec, fixtures). Layout must match exactly. |
| `PolicyDecisionPayload` | **translate-c** from `audit_schema.h` | Struct used by both C (stem tile `AuditEvent`) and Zig (policy codec). Layout must match exactly. |
| `PolicyOutcome` | **Zig enum** | Used only in Zig code. translate-c would produce `c_uint` — not a usable Zig enum. Zig enum with explicit C constant values is the correct type. |
| `RecordType` | **Zig enum** | Union discriminant in Zig `AuditEvent.Payload`. C uses `RecordType` as `uint8_t` — no interop needed. |
| All payload structs (`SourceEventPayload`, `ModelCallPayload`, etc.) | **Zig** | Pure Zig types, no C consumer. |
| `AuditEvent` (Zig) | **Zig** | Zig version is `Header + union(Payload)` with 14 variants. C `AuditEvent` is `Header + RecordType + PolicyDecisionPayload` — different design for scratch allocation. They serve different purposes; no unification. |

**Key insight:** Only the two struct types that exist in both C and Zig need translate-c re-export. Everything else stays as Zig because either translate-c can't produce the right type (enums) or there is no C counterpart at all.

### Step 1: Create `audit_mod` via `addTranslateC` in build system

**File:** `build-lib/mod/modules.zig` (modify)

Add `audit_mod` to the `Shared` struct and create it via `addTranslateC`:

```zig
pub const Shared = struct {
    ...
    audit_schema: *std.Build.Module,
    audit_mod: *std.Build.Module,      // ← NEW: translate-c from audit_schema.h
    ...
};
```

Create the module alongside `audit_schema_mod`:

```zig
const audit_mod = b.addTranslateC(.{
    .root_source_file = b.path("src/tickoni/c_abi/shim/audit_schema.h"),
    .target = target,
    .optimize = optimize,
});
```

Wire it as an import in the shared module consumer list (for `audit_codec`, `audit_tile`, etc.):

```zig
const audit_codec_mod = b.addModule("audit_codec", .{
    .root_source_file = b.path("src/tickoni/codec/audit.zig"),

        .{ .name = "c_abi", .module = c_abi_mod },
        .{ .name = "audit_schema", .module = audit_schema_mod },
        .{ .name = "audit_mod", .module = audit_mod },
```

### Step 2: Rewrite `audit.zig` to re-export structs from `audit_mod`

**File:** `src/tickoni/schema/audit/audit.zig` (modify)

Keep the existing Zig enum definitions (`PolicyOutcome`, `RecordType`, `LimitType`).
Replace struct definitions that have C counterparts with re-exports + layout assertions:

```zig
/// Canonical audit schema shared across replay, tiles, and codec boundaries.
///
/// Audit records are cross-tile contracts and part of replay compatibility.
/// Keep the typed schema here; codecs in src/tickoni/codec/ provide concrete
/// binary, protobuf, JSONL, and hash encodings over this schema.
const std = @import("std");
const c_schema = @import("audit_mod");

pub const audit_schema_version: u16 = c_schema.AUDIT_SCHEMA_VERSION;

// ─── Enums (Zig-only — no C interop needed) ───

pub const PolicyOutcome = enum(u8) {
    allow,
    deny,
    require_approval,
    malformed_drop,
    duplicate_drop,
    escalate,
    require_more_evidence,
};

pub const LimitType = enum(u8) {
    amount,
    frequency,
    holding_period,
    per_day,
    per_month,
};

pub const RecordType = enum(u8) {
    source_event = 0,
    normalization = 1,
    policy_decision = 2,
    model_call = 3,
    financial_adapter_call = 4,
    proposal = 5,
    destination_check = 6,
    limit_check = 7,
    approval_required = 8,
    denial = 9,
    telemetry_checkpoint = 10,
    replay_result = 11,
    deduplication = 12,
    case_creation = 13,
};

// ─── Structs from C schema (single authoritative source via translate-c) ───

/// Re-export of AuditHeader from audit_schema.h.
/// Layout alignment is enforced by the static_assert below.
pub const Header = c_schema.AuditHeader;

comptime {
    // Enforce that the Zig struct layout matches the C struct layout exactly.
    // If any padding, field order, or size diverges, the build fails.
    const c_layout = c_schema.AuditHeader;
    const z_layout = Header;

    // Size check
    static assert(@sizeOf(c_layout) == @sizeOf(z_layout),
        "Header layout size mismatch: C={d} Z={d}", .{
            @sizeOf(c_layout), @sizeOf(z_layout)
        });

    // Field-by-field offset check for critical fields
    inline for (std.meta.fields(c_layout)) |c_field| {
        const z_field = std.meta.fieldInfo(z_layout, c_field.name) catch unreachable;
        static assert(c_field.offset == z_field.offset,
            "Header.{s} offset mismatch: C={d} Z={d}", .{
                c_field.name, c_field.offset, z_field.offset
            });
    }
}

// Re-export PolicyDecisionPayload from C schema.
pub const PolicyDecisionPayload = c_schema.PolicyDecisionPayload;

comptime {
    const c_layout = c_schema.PolicyDecisionPayload;
    const z_layout = PolicyDecisionPayload;

    static assert(@sizeOf(c_layout) == @sizeOf(z_layout),
        "PolicyDecisionPayload size mismatch: C={d} Z={d}", .{
            @sizeOf(c_layout), @sizeOf(z_layout)
        });

    inline for (std.meta.fields(c_layout)) |c_field| {
        const z_field = std.meta.fieldInfo(z_layout, c_field.name) catch unreachable;
        static assert(c_field.offset == z_field.offset,
            "PolicyDecisionPayload.{s} offset mismatch: C={d} Z={d}", .{
                c_field.name, c_field.offset, z_field.offset
            });
    }
}

// ─── Zig-only payload structs (no C counterpart) ───

pub const SourceEventPayload = struct {
    source_system: [16]u8,
    event_type: [32]u8,
    raw_hash: u64,
};

// ... (all other Zig-only payload structs remain unchanged) ...

pub const ModelCallPayload = struct { ... };
pub const FinancialAdapterCallPayload = struct { ... };
pub const ProposalPayload = struct { ... };
pub const DestinationCheckPayload = struct { ... };
pub const LimitCheckPayload = struct {
    limit_type: LimitType,
    value: i64,
    limit: i64,
    outcome: PolicyOutcome,
};
pub const ApprovalRequiredPayload = struct { ... };
pub const DenialPayload = struct { ... };
pub const TelemetryCheckpointPayload = struct { ... };
pub const ReplayResultPayload = struct { ... };
pub const DeduplicationPayload = struct { ... };
pub const CaseCreationPayload = struct { ... };

// ─── Zig AuditEvent (union-based, no C counterpart) ───

pub const AuditEvent = struct {
    header: Header,
    payload: Payload,

    pub const Payload = union(RecordType) {
        source_event: SourceEventPayload,
        normalization: NormalizationPayload,
        policy_decision: PolicyDecisionPayload,
        model_call: ModelCallPayload,
        financial_adapter_call: FinancialAdapterCallPayload,
        proposal: ProposalPayload,
        destination_check: DestinationCheckPayload,
        limit_check: LimitCheckPayload,
        approval_required: ApprovalRequiredPayload,
        denial: DenialPayload,
        telemetry_checkpoint: TelemetryCheckpointPayload,
        replay_result: ReplayResultPayload,
        deduplication: DeduplicationPayload,
        case_creation: CaseCreationPayload,
    };
};
```

**What changed:**
- `audit_schema_version` now comes from `c_schema.AUDIT_SCHEMA_VERSION` (the C `#define`)
- `Header` is now `c_schema.AuditHeader` with compile-time layout assertions
- `PolicyDecisionPayload` is now `c_schema.PolicyDecisionPayload` with compile-time layout assertions
- `PolicyOutcome`, `RecordType`, `LimitType` — unchanged Zig enums
- All payload structs — unchanged Zig-only structs
- `AuditEvent` — unchanged Zig union-based struct

**Verification:** `zig build compile-tk` succeeds. The compile-time assertions pass, confirming C and Zig struct layouts match.

### Step 3: Update consumers

Most consumers import `audit_schema` (which is `audit.zig`) and get the re-exported types transparently. No changes needed for code that uses `audit.PolicyOutcome`, `audit.Header`, or `audit.PolicyDecisionPayload` — the types have the same names and the same layout.

**File:** `src/tickoni/tiles/audit/types.zig` (modify)

This file currently re-exports from `@import("audit_schema")` (which is `audit.zig`). It should continue to work without changes since `audit.zig` still exports `Header`, `PolicyDecisionPayload`, and all other types with the same names.

However, if `types.zig` has any compile-time layout assertions or parity tests, remove them — they are now superseded by the `comptime` assertions in `audit.zig`.

**File:** `src/tickoni/version.zig` (modify)

Already imports `audit_schema` and uses `audit_mod.audit_schema_version`. Change to:

```zig
const audit_mod = @import("audit_mod");
...
.policy_schema_version = audit_mod.AUDIT_SCHEMA_VERSION,
.replay_schema_version = audit_mod.AUDIT_SCHEMA_VERSION,
```

Or alternatively keep the `@import("audit_schema")` import and use `audit.audit_schema_version` which now re-exports from C. The latter is less disruptive and keeps the existing import pattern.

## Risk Summary

| Risk | Severity | Mitigation |
|------|----------|------------|
| `addTranslateC` fails on `audit_schema.h` | Low | Header includes only `<stdint.h>` and `<stddef.h>` — standard C, should translate cleanly |
| Compile-time layout assertions fail | Medium (expected failure = success) | If they fail, it means the schemas have drifted — fix `audit_schema.h` or `audit.zig` to match |
| Consumer breakage from re-exported type | Low | `Header` and `PolicyDecisionPayload` have identical names, fields, and layout — source-compatible |
| `audit_mod` import cycle | Low | `audit_mod` is generated from C header, not from `.zig` files — no dependency on `audit.zig` |
| `PolicyOutcome` alignment not checked | Low | `PolicyOutcome` is Zig-only; C uses it as `uint8_t` with matching numeric values (0-6). The Zig enum values are hardcoded to match. |

## Out of Scope

- `PolicyOutcome` re-export from C — not feasible (translate-c produces `c_uint`, not a Zig enum) and not needed (Zig-only usage). The C values (0-6) are hardcoded in the Zig enum.
- `RecordType` re-export from C — same reasoning as `PolicyOutcome`. Zig-only union discriminant.
- `AuditEvent` unification — C `AuditEvent` is a fixed-layout struct for scratch allocation; Zig `AuditEvent` is a union-based struct for the codec. Different designs for different consumers.
- Stem tile migration — this is orthogonal. The stem tile already includes `audit_schema.h` directly; it does not depend on `audit.zig`.
