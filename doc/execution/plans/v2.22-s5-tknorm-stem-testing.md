### What's missing

The tknorm stem tile (`tk_normalize_stem.c`, 432 lines) has 6 distinct code paths with no tests:

1. **`tknorm_during_frag`** — fragment size check, framing validation (currency A-Z, account_id > 0), FNV-1a hash, malformed path with `POLICY_MALFORMED_DROP`, `pipeline_hops` increment, counter updates
2. **`tknorm_after_credit`** — dcache compact chunk management (`out_chunk0`, `out_wmark`, `fd_dcache_compact_next`), `fd_stem_publish` with chunk offset
3. **`tknorm_before_credit`** — idle threshold (10000 ticks → `input_exhausted`)
4. **`tknorm_privileged_init` / `tknorm_unprivileged_init`** — workspace joining, dcache setup, CNC join
5. **`tknorm_scratch_footprint_tile`** — FD_LAYOUT footprint calculation
6. **`SHOULD_SHUTDOWN` macro** — CNC HALT detection combined with idle timeout

### Build infrastructure gap

`addTickoniNormStemLibrary()` exists in `build-lib/lib/codec.zig` (line 199), but `TestLinkage` in `build-lib/lane.zig` has no `needs_norm_stem` field. The unit lane's `registerCov` and `registerRunTest` must be extended to support norm shim linkage, matching the `needs_audit` pattern.

## Risks and Mitigations

1. **FNV-1a hash parity:** The C inline FNV-1a may produce different output than the Zig `stableEventHash` if Zig uses a different variant. *Mitigation:* The unit test computes the expected hash from first principles (FNV-1a offset basis × prime × XOR chain), so the test validates the C implementation is deterministic. A separate parity test with the Zig implementation is a follow-up.

2. **Scratch overflow in integration tests:** If `tknorm_ctx_t` grows beyond the 4096-byte footprint, the tile will crash. *Mitigation:* The unit test verifies `scratch_footprint_tile()` returns the correct size. The integration test uses the same topology that was verified in `v2.22-s5-tknorm-stem-migration.md`.

3. **Linkage complexity:** Two shim libraries (`addTickoniAuditShimLibrary` + `addTickoniNormStemLibrary`) must link into the same test binary. Both need `libfd_disco.a` as a direct object file link. *Mitigation:* Follow the existing pattern — each shim links its own static archive, and `libfd_disco.a` is added as a direct object file per the documented Zig nested-archive limitation.

4. **Idle threshold timing:** Waiting for 10000 ticks to verify idle shutdown could slow the integration test suite. *Mitigation:* The `event_count` exhaustion path (test 4) tests the bounded-run exit without waiting for idle ticks. The idle threshold test is not needed if event_count exhaustion covers the shutdown path.

5. **Framing validation edge cases:** The inline currency/account_id validation in `tknorm_during_frag` may miss edge cases compared to the Zig `validFraming`. *Mitigation:* The integration test verifies that all 32 fixture events pass (no malformed events in the default fixture), confirming the C and Zig behaviors are equivalent for normal inputs. A dedicated malformed test is a follow-up.
