# Plan: Port Shared Memory to macOS/Windows

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Port Firedancer's `fd_shmem` shared memory infrastructure to macOS and Windows, eliminating the platform-dependent shmem stubs so Tickoni's architecture (multi-process tiles over shared memory) works identically on all platforms.

**Architecture:** Replace the Linux-hugetlbfs-dependent `fd_shmem` implementation with a cross-platform backend:
- **POSIX (Linux/macOS):** `shm_open()` → `mmap(MAP_SHARED | MAP_ANONYMOUS)` — standard POSIX shared memory, no hugetlbfs required.
- **Windows:** `CreateFileMapping(INVALID_HANDLE_VALUE, ...)` → `MapViewOfFile(...)` — Win32 equivalent of anonymous shared memory.

NUMA binding and huge pages are Linux-specific optimizations that become no-ops on macOS/Windows (already stubbed out). The core create/join/unlink operations become portable.

**Tech Stack:** Zig (as per architecture decision flow — Linux-only constraints must be ported to Zig), POSIX `shm_open`/`mmap`, Win32 `CreateFileMapping`/`MapViewOfFile`.

---

## Cross-Platform Invariants

These rules are mandatory for every task in this plan. They are not guidelines — they are hard constraints.

### No Linux-Only Paths

Every code path in this port must execute on Linux, macOS, and Windows. If a feature only works on Linux today, it must either be:

- **Ported** to macOS and Windows (same behavior), or
- **Removed** entirely (no `#if FD_HAS_LINUX` conditional blocks that gate core functionality).

Specifically:

- **CPU affinity (process-tile model):** Firedancer pins threads to cores with `sched_setaffinity` / `cpuset` because threads share an address space — cache locality saves nanoseconds per IPC, which matters at 100K+ TPS. Tickoni's tiles are separate processes. Each process already has its own page tables, its own TLB, and a cold L1/L2 at startup. The IPC boundary (shared memory) already breaks the cache-locality chain that makes pinning valuable. Setting `sched_setaffinity` on a process's main thread prevents OS migration, which saves a handful of TLB misses — nowhere near the cost of inter-process serialization. There is zero measurable performance benefit and no semantic purpose. Remove all `#if FD_HAS_LINUX` blocks that call `sched_setaffinity`, `SetThreadAffinityMask`, `thread_policy_set(THREAD_AFFINITY_POLICY)`, or any CPU placement logic from the supervisor and tile-spawn paths. Affinity is a Firedancer-thread-model optimization that does not apply to the Tickoni-process-model.
- **Seccomp / Landlock:** If seccomp-only sandboxing is used as a tile isolation mechanism, it must be removed. Seccomp does not exist on macOS or Windows. The tile sandbox boundary must rely on process-level isolation (already enforced by Firedancer's process-mode tiles), not Linux-specific syscalls.
- **hugetlbfs:** If hugetlbfs is required for workspace creation, it must be removed. The cross-platform backend uses `shm_open` / `CreateFileMapping` with normal 4KB pages everywhere.

### No Linux-Only Tests

All tests must run on all supported platforms (Linux, macOS, Windows). There are no `@test` blocks gated by `#if FD_HAS_LINUX` or equivalent platform checks. If a test requires Linux-specific behavior, it is either:

- **Refactored** to test the cross-platform equivalent, or
- **Removed** if no cross-platform equivalent exists.

### What This Means in Practice

- Remove all `#if FD_HAS_LINUX ... #else ... #endif` blocks that produce divergent behavior in the shmem, topology, and supervisor paths.
- Remove CPU affinity logic (`sched_setaffinity`, `SetThreadAffinityMask`, `cpu_placement` / `CpuSet` / `util.cpu`) from the supervisor and tile-spawn paths. The supervisor does not call any affinity API; tile processes run with whatever the OS scheduler assigns. This is a Firedancer-thread-model artifact with zero benefit in the process-tile model.
- Every `export fn` in the cross-shmem layer must have a macOS and Windows implementation, even if it is a thin passthrough to the POSIX/Win32 standard library.
- Tests use `std.testing.allocator` and platform-agnostic APIs only. No `seccomp()`, no `memfd_create`.
- If a platform lacks a capability (e.g., no hugetlbfs on macOS), the behavior is documented and the fallback is explicit — not silently skipped via `#if`.

## Task 1: Design the cross-platform shmem interface in Zig

**Status: DONE** (commit 49297280d)

**Objective:** Apply cross-platform fixes directly to Firedancer's C shmem infrastructure — no Zig abstraction layer needed since Firedancer already uses POSIX `open()`/`ftruncate()`/`mmap()` for shmem (not hugetlbfs).

**Implementation:**
- `fd_shmem_admin.c`: macOS uses `/tmp/.fd` instead of `/mnt/.fd` (via `#if FD_HAS_LINUX` / `#else` conditional). NUMA binding is no-op on macOS (already stubbed).
- `fd_shmem_windows.c`: Full CreateFileMapping + MapViewOfFile backend replacing ENOTSUP stubs. Implements all `fd_shmem_*` functions (create, join, leave, unlink, info, acquire, release, boot, halt, NUMA no-ops).
- `Local.mk`: Wired `fd_shmem_windows` into Windows build lane instead of `fd_shmem_windows_stub`.

**Files modified:**
- `src/util/shmem/fd_shmem_admin.c` — conditional shmem path for macOS
- `src/util/shmem/fd_shmem_windows.c` — new file: Windows CreateFileMapping backend
- `src/util/shmem/Local.mk` — build wiring for Windows backend

## Risk Assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| `shm_open` not available on all macOS versions | Low | macOS 10.7+ has `shm_open` (POSIX.1-2008). Older versions need fallback to `tmpfs`. |
| Windows `CreateFileMapping` requires admin for large regions | Low | Tickoni uses small regions (kilobytes to megabytes, not gigabytes). |
| Performance regression vs hugetlbfs | Medium | Normal pages are slower for very large regions, but Tickoni tiles use small memory. No measurable impact. |
| NUMA binding no-op on macOS/Windows | None | Already stubbed; this is expected behavior. |
| Thread safety of cross-shmem registry | Low | Use `std.Thread.Mutex` for the registry map. All platform operations are serialized through the mutex. |
| Zig `@import` path changes break existing code | Medium | Update all `@import("cross_shmem")` references in shim and tile files. |

## What This Does NOT Change

- Firedancer's native hugetlbfs path on Linux — unchanged, used when `FD_HAS_LINUX` is true.
- Tile financial logic — shmem is infrastructure, not business state.
- Firedancer's `fd_topo` and `fd_stem` — topology and lifecycle unchanged.
- Thread-mode (dev/test) — continues using heap-backed rings.
- No changes to Firedancer's `fd_wksp` on Linux — only the stubbed macOS/Windows paths change.
