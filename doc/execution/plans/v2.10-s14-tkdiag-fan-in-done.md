# tkdiag Fan-In — Diagnostic Fragment Receive Logic

**Status:** Implemented and verified (2026-11-20). See "Implementation record" at the end. Owner decisions and corrections to the sketches below are in "Resolved Design"; where a sketch below disagrees with that section, "Resolved Design" wins. This closes Future Work item 2 of [`v2.NN-sXX-tkdiag-fd-stem-migration.md`](v2.NN-sXX-tkdiag-fd-stem-migration.md).

> **For Hermes:** The earlier tkdiag spike was a 0-in, 0-out observer with `BEFORE_CREDIT` only. This plan defines the Firedancer topology fan-in model where every pipeline tile sends diagnostic fragments TO tkdiag via dedicated diagnostic links.

**Goal:** Define the fragment format, producer tile send logic, and tkdiag receive/aggregation logic for the fan-in diagnostic model.

**Prerequisite:** `tknorm`, `tkdedu`, `tkpoly` and `tkaudt` are `fd_stem` tiles (done). `tkings` is **not** an `fd_stem` tile: it is a generic-path Zig process tile and stays one. It publishes its diagnostic fragment through `rt.link.Producer.publishLossy`, not `fd_stem_publish`.

## Resolved Design

Decisions taken before implementation. Each item replaces the corresponding sketch in the sections below.

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Link reliability | Every `*_tkdiag` link is **unreliable (`LinkReliability.lossy`)**: `fd_topob_tile_in(..., reliable=0, polled=1)`. Producers never wait on tkdiag; tkdiag keeps only the latest fragment per tile and fd_stem counts any overrun it suffers. `topo_build.zig` honors `Channel.reliability` (it wired every consumer reliable before). | Diagnostics must not sit on the event critical path. A reliable link would backpressure `tkings`/`tknorm`/`tkdedu`/`tkpoly` when tkdiag is slow, and would deadlock shutdown when tkdiag exits on HALT before its producers. `LinkReliability` already documents "only telemetry links should be lossy". |
| 2 | Scope | Only `paymentPipelineProcess()` (the 8-tile payment process topology) gets the 5 diag links. Minimal topologies without tkdiag and the 14-tile `investmentWorkflow()` are unchanged. Other producers (`tkcase`, `tkdisp`, `tkagnt`, `tkmodl`, ...) are not specified here. |

| 4 | Fragment size | `diag_fragment_t` is exactly **128 bytes**, with explicit natural alignment and a `_Static_assert` on size and field offsets. The sketch below is 152 bytes. | Key Design Decision 1. |
| 5 | Type codes | `TK_DIAG_TYPE_INGEST=1, NORMALIZE=2, DEDUPE=3, POLICY=4, AUDIT=5` (Step 1 numbering; the earlier list in "Fragment Format" is superseded). | One numbering, tile-pipeline order. |

It never adds a cumulative counter into a running total (the sketch's `total_errors += frag->errors` double-counts). | Producer counters are cumulative. |
| 9 | DURING_FRAG / AFTER_FRAG | `DURING_FRAG` only validates and stages the fragment (it may be torn); `AFTER_FRAG` commits it to the per-input slot and updates aggregates and CNC slots. | Same callback contract as decision 3. |
| 10 | Shutdown | `BEFORE_CREDIT` observes the topology every 100 ms and reads `replay_checked`/`replay_match` from **tkrepl's CNC app slots 0 and 1** (the replay result tkrepl publishes, already declared in `tile_registry.zig`); tkdiag sets `done` and `SHOULD_SHUTDOWN` returns true when `replay_checked` is set, or on CNC HALT (the sketch's `stop`). tkdiag declares read-only use of tkrepl's CNC in `topo_build.zig`. | The sketch's `replay_checked`/`stop` atomics live only in the in-process `PaymentPipelineState`; across processes the one place tkrepl publishes its result is its CNC. Until tkrepl has a process-mode role (`plans/v2.10-s14-tkrepl-capsule-io.md`) nothing writes it in a real run, so the trigger is exercised by a test that stands in for tkrepl. |
| 11 | Field population | Every field is filled by the owner of the number. Producers: `events_processed`, `errors`, `audit_records` (`tkaudt`); `backpressure_waits` (a stem tile reads its own `TILE_BACKPRESSURE` metric, `tkings` its producer wait counter); `max_queue_depth` (the peak backlog on the tile's inputs, from the producer's published sequence, or for `tkings` the backlog of its pipeline link: a lower bound, because producers publish their sequence periodically); `crashed` (decision 12). tkdiag owns `sandbox_failures`, `replay_checked` and `replay_match` (decisions 10 and 12) and publishes them as metrics rather than reading them from fragments. | No tile invents a value it does not measure. `sandbox_failures`/`replay_*` are properties of the topology and of tkrepl, not of one tile's event path. |
| 12 | Crash | A crashed process publishes nothing, so tkdiag **observes** every tile the way Firedancer's diag tile does (`fd_diag_tile.c`): a tile whose process is gone while its `TILE_STATUS` gauge is not 2 ("shutdown") died abnormally. If the status was still 0 the tile died before it ran (boot or sandbox entry): also counted in `SandboxFailures` and slot 1. The one such path today is `tkdedu`'s "dedupe table full" abort. Each tile counts once, however it was learned. | Step 7 asks that a crash be seen. ### Link Table

| Link | Owner tile | Workspace / mapping | Producer -> consumer | Depth / MTU | Reliability | Overrun | Restart / shutdown | Health metrics |
|---|---|---|---|---|---|---|---|---|
| `tkings` -> `tkdiag` | `tkings` | `tkpay0` / Tango shm | `tkings` -> `tkdiag` (out idx 1 of `tkings`) | 64 / 128 | **Unreliable** | Producer overwrites; tkdiag's fd_stem counts the overrun and resyncs. Latest-wins is the intended semantics. | Crash-only. A restarted producer restarts its diag `seq` at 1; tkdiag treats a lower `seq` as stale until it passes the previous value. Shutdown: independent of tkdiag. | tkdiag CNC slots 2-4, fd_stem link metrics |
| `tknorm`, `tkdedu`, `tkpoly` -> `tkdiag` | the producer | same | out idx 1 of the producer | 64 / 128 | Unreliable | same | same | same |
| `tkaudt` -> `tkdiag` | `tkaudt` | same | out idx 0 of `tkaudt` | 64 / 128 | Unreliable | same | same | same |

tkdiag input order matches channel order in `paymentPipelineProcess()`: tkings, tknorm, tkdedu, tkpoly, tkaudt.

### Restart and `seq` caveat

Because slots are keyed by input link and `seq` must increase, a producer that restarts under the same link would be ignored until its new `seq` exceeds the old one. Tickoni is crash-only with no in-process restart of a tile inside a run, so a run starts every tile's `seq` at 1 together. If tile restart is added later, tkdiag must reset a slot when the producer's CNC signal returns to BOOT; that is out of scope here.

## Architecture Decision

**Current state (spike):** tkdiag polls `snapshotDiag()` from shared memory every tick via `BEFORE_CREDIT`. Zero links. Same as tkmetr.

**Target state (Firedancer topology):** Each pipeline tile sends diagnostic snapshots to tkdiag via dedicated `*_tkdiag` output links. tkdiag receives fragments via `DURING_FRAG` from multiple input links (fan-in) and aggregates them into a coherent diagnostic view.

**Why fan-in:**
- Decouples diagnostic collection from shared-memory polling
- Each tile pushes its own diagnostics (no race on shared state reads)
- Enables per-tile diagnostic granularity (which tile crashed, what state it was in)
- Aligns with Firedancer's fragment-based communication model

## Fragment Format

> **Superseded in part by "Resolved Design" (4, 5, 11, 12).** The authoritative layout is `src/tickoni/c_abi/shim/tk_diag_fragment.h`. This sketch is 152 bytes, not 128, and its type codes are renumbered.

Each producer tile sends a diagnostic fragment with this structure:

```c
/* diag_fragment_t — diagnostic snapshot sent by pipeline tiles to tkdiag */
typedef struct {
    uint32_t tile_id;           /* ID of the sending tile */
    uint32_t tile_type;         /* TK_DIAG_TYPE_NORMALIZE, TK_DIAG_TYPE_DEDUPE, etc. */
    uint64_t seq;               /* Tile's current sequence counter */
    uint64_t timestamp_ns;      /* Snapshot timestamp */
    
    /* Per-tile diagnostic fields (tile-specific, optional) */
    uint64_t events_processed;  /* Total events processed by this tile */
    uint64_t errors;            /* Error count (malformed, denied, etc.) */
    uint64_t backpressure_waits;/* Backpressure wait count */
    uint64_t max_queue_depth;   /* Peak queue depth */
    
    /* Crash/sandbox fields (from PaymentPipelineState.crashed_tile) */
    int32_t crashed;            /* 0 = no crash, tile_id = crash detected */
    uint64_t sandbox_failures;  /* Sandbox failure count */
    
    /* Audit/replay fields (shared state) */
    uint64_t audit_records;     /* Current audit record count */
    int32_t replay_checked;     /* 0 = not checked, 1 = checked */
    int32_t replay_match;       /* 0 = not matched, 1 = matched */
    
    /* Padding to 128 bytes (typical fragment MTU) */
    uint8_t reserved[64];
} diag_fragment_t;

#define TK_DIAG_TYPE_NORMALIZE   1
#define TK_DIAG_TYPE_DEDUPE      2
#define TK_DIAG_TYPE_POLICY      3
#define TK_DIAG_TYPE_AUDIT       4
#define TK_DIAG_TYPE_INGEST      5
```

## Producer Tile Modifications

> **Superseded in part by "Resolved Design" (3, 15, 16).** The sketch below publishes from `AFTER_CREDIT`, uses fields and calls that do not exist (`ctx->malformed_count`, `fd_stem_tick_id`, a six-argument `fd_stem_publish`), and assumes `tk_ingest_stem.c`. The real helper is `shim/stem_diag.h` (`stk_diag_out_init`, `stk_diag_publish`), called from `AFTER_FRAG`.

Each pipeline tile that uses fd_stem must add diagnostic fragment publishing. The pattern is identical for all tiles:

### Pattern (sketch): publish diagnostic fragment in `AFTER_CREDIT` (or `DURING_FRAG` if no output)

```c
/* In tknorm_stem.c (after processing the fragment): */
static void
tknorm_after_credit( tknorm_ctx_t *    ctx,
                     fd_stem_t *       stem,
                     fd_stem_tile_in_t * poll_in,
                     int *             charge_busy ) {
    /* 1. Process the fragment (existing logic) */
    /* 2. Publish to tkdedu (existing logic) */
    
    /* 3. Publish diagnostic fragment to tkdiag (NEW) */
    /* tkdiag_link is the output link index for the *_tkdiag link */
    diag_fragment_t diag = {
        .tile_id = TK_TKNORM,
        .tile_type = TK_DIAG_TYPE_NORMALIZE,
        .seq = ctx->events_processed,
        .timestamp_ns = fd_stem_tick_id(stem),
        .events_processed = ctx->events_processed,
        .errors = ctx->malformed_count + ctx->duplicate_count,
        .backpressure_waits = ctx->backpressure_waits,
        .max_queue_depth = ctx->max_queue_depth,
        .crashed = ctx->crashed ? TK_TKNORM : 0,
        .audit_records = ctx->audit_records,
        .replay_checked = ctx->replay_checked,
        .replay_match = ctx->replay_match,
    };
    
    fd_stem_publish(stem, TK_DIAG_LINK_IDX, sizeof(diag), diag_chunk, sizeof(diag), 0, 0, 0);
    
    *charge_busy = 0;
}
```

**Tile link indices** (defined in topology per `tile-topology.md`):
- `tknorm`: 1 output link (to tkdedu at idx 0), 1 output link (to tkdiag at idx 1)
- `tkdedu`: 1 output link (to tkpoly at idx 0), 1 output link (to tkdiag at idx 1)
- `tkpoly`: 1 output link (to tkaudt at idx 0), 1 output link (to tkdiag at idx 1)
- `tkaudt`: 0 output links to pipeline, 1 output link (to tkdiag at idx 0)
- `tkings`: 1 output link (to tknorm at idx 0), 1 output link (to tkdiag at idx 1)

## tkdiag Fan-In Implementation

> **Superseded in part by "Resolved Design" (8, 9, 10, 12, 13).** The real tile is `shim/tk_diag_stem.c`; its aggregation is `tkdiag_agg_*` in `tk_diag_fragment.h`. The sketch below mutates state and sums cumulative counters in `DURING_FRAG`, reads a `replay_checked`/`stop` that does not exist, and declares `tile_seen` outside the context.

### Tile: tkdiag (0-in → N-in, 0-out)

**After fan-in is implemented, tkdiag becomes:**
- **N input links** (one from each pipeline tile)
- **0 output links** (diagnostics are read via metrics or HTTP endpoint, not published)
- **`DURING_FRAG`** receives diagnostic fragments from all tiles
- **`BEFORE_CREDIT`** polls for shutdown signals

### tkdiag Context

```c
typedef struct {
    /* Aggregated diagnostic state */
    diag_fragment_t latest_from_tile[FD_TILE_MAX];  /* Latest fragment per tile */
    uint32_t tile_cnt;                              /* Number of tiles reporting */
    int32_t any_crashed;                            /* 1 if any tile crashed */
    int32_t replay_checked;                         /* From shared state */
    int32_t replay_match;                           /* From shared state */
    uint64_t total_errors;                          /* Sum of all tile errors */
    uint64_t total_audit_records;                   /* Sum of all tile audit records */
    
    /* Lifecycle */
    int32_t done;                                   /* Set when replay_checked or stop */
} tkdiag_ctx_t;

#define TKDIAG_CTX_ALIGN alignof(tkdiag_ctx_t)
```

### tkdiag DURING_FRAG (fan-in receive)

```c
static void
tkdiag_during_frag( tkdiag_ctx_t * ctx,
                    ulong          in_idx,
                    ulong          seq,
                    ulong          sig,
                    ulong          chunk,
                    ulong          sz,
                    uint           ctl ) {
    /* 1. Validate fragment size */
    if (sz != sizeof(diag_fragment_t)) return;
    
    /* 2. Copy fragment to per-tile slot */
    diag_fragment_t * frag = (diag_fragment_t *)chunk;
    ctx->latest_from_tile[in_idx] = *frag;
    
    /* 3. Update aggregation state */
    if (frag->crashed != 0) {
        ctx->any_crashed = 1;
    }
    ctx->total_errors += frag->errors;
    ctx->total_audit_records = fd_ulong_max(ctx->total_audit_records, frag->audit_records);
    
    /* 4. Track tile count */
    if (!ctx->tile_seen[in_idx]) {
        ctx->tile_seen[in_idx] = 1;
        ctx->tile_cnt++;
    }
}
```

### tkdiag BEFORE_CREDIT (shutdown polling)

```c
static void
tkdiag_before_credit( tkdiag_ctx_t * ctx,
                      fd_stem_t *    stem,
                      int *          charge_busy ) {
    /* Check replay_checked and stop from shared state.
     * These are the same atomics the spike reads. */
    /* TODO: Wire to shared state via fd_shm_join() or topo addr */
    
    if (ctx->replay_checked || ctx->stop) {
        ctx->done = 1;
    }
    
    *charge_busy = 0;
}
```

### tkdiag SHOULD_SHUTDOWN

```c
static int
tkdiag_should_shutdown( tkdiag_ctx_t * ctx ) {
    return ctx->done;
}
```

## Post-Fan-In: Diagnostic Reporting

> **Done 2026-11-20, the way Firedancer's diag tile does it** ("Resolved Design" 13, 18, 19, 20). Firedancer's diag tile has no HTTP server: it writes metrics and logs, and the metric tile serves them.

After fan-in is working, tkdiag reports diagnostics via:
1. **HTTP endpoint** (like tkmetr): served by the existing metric tile at `/metrics`, from the `tkdiag` metrics kind and the per-tile OS metrics tkdiag writes. tkdiag opens no socket.
2. **Metrics publishing**: the `tkdiag` kind in `metrics.xml`, written from `STEM_CALLBACK_METRICS_WRITE`.
3. **Log emission**: a `WARNING` on the first death of a tile and a `NOTICE` when the replay check finishes (visible with `--verbose`).
4. **CaseOps integration**: not done, by decision of the owner. tkdiag gets no endpoint and no `tkapi` tile is added for it.

## Key Design Decisions

1. **Fragment size: 128 bytes.** Fits within typical dcache MTU, carries enough per-tile data for meaningful diagnostics.
2. **Publishing in AFTER_CREDIT.** Tiles publish diagnostics after processing a fragment, so the diagnostic state reflects the latest processed event.
3. **Aggregation in tkdiag.** tkdiag merges fragments per-tile and maintains aggregate counters. No shared-memory polling.
4. **Shutdown via replay_checked/stop atomics.** Same trigger as the spike, preserving the pipeline lifecycle.
5. **No output links from tkdiag.** Diagnostics are consumed via HTTP/metrics/log, not via fragment chains.

### Findings

1. **`TopologySpec` dropped `Channel.reliability`.** Every child rebuilds the topology from `topology.spec`, so each child rebuilt the diag links as reliable while the supervisor built them unreliable, and every tile died at `fd_topo.c: FAIL: tile->in_link_fseq[ j ]`. The spec now carries reliability (version 5). Any future `Channel` field that changes how the topology is built must be carried the same way.
2. **A zeroed `stk_diag_out_t` must mean "no diagnostic link".** The first version used `ULONG_MAX` as the "none" marker, so the C unit-test fixtures (which zero the context and never call init) published to a NULL workspace. It now has an explicit `present` flag.
3. **The plan's sketches did not compile against the code**: wrong `fd_stem_publish` arity, missing context fields, a 152-byte "128-byte" struct, state mutated in `DURING_FRAG`, cumulative counters summed per fragment, `tk_ingest_stem.c` that does not exist, and a `replay_checked`/`stop` that no shared region holds across processes.
4. **`test_tile_tkagnt.zig` "a HALT mid-run drains every accepted request" failed once** (`expected 11, found 6`) in the first full infra run after the first change, and passed in every run since. That topology has no diagnostic links; the test is timing-sensitive by design and the failure was seen but not explained.
5. **Changing `metrics.xml` changes the shared metrics layout** (`FD_METRICS_TILE_OFF`, `FD_METRICS_TOTAL_SZ`), so the Firedancer libraries must be rebuilt (`just build-fd`) before anything linked against them is trusted.
6. **`--verbose` is the only way to see a tile's `WARNING` or `NOTICE`**; by default a tile logs only `ERR` and above. That is existing behavior, not changed here.

### Limits to know

- **macOS and Windows OS-level probes** are compile-checked for their targets on every lint run and have never been run on those systems. They report less than Linux (documented in `tk_os_stats.h`); Windows memory is the working set, not a heap walk.
- **tkrepl has no process-mode role**, so in a real run nothing sets `replay_checked` and the replay shutdown does not fire; it is verified by a test that writes tkrepl's CNC slots. It starts working when tkrepl does (`plans/v2.10-s14-tkrepl-capsule-io.md`).
- **Only `tkdedu` reports its own fatal fault** (its table-full abort). Other fatal paths are `FD_LOG_ERR` aborts caught by observation. tkaudt's full audit ring is a counted rejection in the stem tile, not a crash.
- **`sandbox_failures` means "died before it ran"**: a sandbox kill is indistinguishable from any other death during boot, so that is how it is counted.
- **`max_queue_depth` is a lower bound**, because producers publish their sequence to the mcache periodically.
- **tkdiag has no seccomp policy**, like every other Tickoni tile; it does list its `/proc` descriptors for sandbox entry. Sandboxed operation of tkdiag has not been exercised (the test runs use `sandbox: disabled`).
- **`tkings` identifies itself by topology position**, which equals its Firedancer index only while it precedes the metric tile; a mismatch would show in `FragmentsRejected`.
- **tkdiag waits up to 30 s at boot for every other tile's pid.** A tile that never starts is then reported as died before it ran.
