# Developer Setup + Full Test Validation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Create a plan (and optional CI workflow) that validates the developer setup by running `just setup-env` followed by `just build-all test-unit-tk test-integration-all test-system-all` on all six platform/compiler combinations: Linux x86, Linux ARM, macOS x86, macOS ARM, Windows x86, Windows ARM.

> **Note:** `test-unit-fd` is excluded from the validation run. It will fail until the blockers in `doc/strategy/roadmap/stories/v2.10-s11.md` are resolved. Once s11 is complete, `test-unit-fd` can be added back.

**Architecture:** A single new CI workflow (`tests-dev-setup.yml`) that mirrors what a developer does locally: checkout → `just setup-env` → `just build-all test-unit-tk test-integration-all test-system-all`. The plan also documents what each step entails per platform and the known blockers.

**Tech Stack:** GitHub Actions, justfile recipes, contrib/setup/ scripts, Zig, Firedancer build system.

---

## What the Recipes Do

### `just setup-env` (bare, no toolchain arg)

Routes to platform-specific scripts:

| Platform | Architecture | Script Path |
|----------|-------------|-------------|
| Linux | x86 | `contrib/setup/linux-x86-essential.sh` ×2 (gcc + clang) + `linux-x86-ops.sh` |
| Linux | arm | `contrib/setup/linux-arm-essential.sh` ×2 (gcc + clang) + `linux-arm-ops.sh` |
| macOS | x86 | `contrib/setup/macos-x86-essential.sh` (SECURITY=off) + `macos-x86-ops.sh` |
| macOS | arm | `contrib/setup/macos-arm-essential.sh` (SECURITY=off) + `macos-arm-ops.sh` |
| Windows | x86 | `contrib/setup/windows-x86.ps1` |
| Windows | arm | `contrib/setup/windows-arm.ps1` |

Each script installs: Zig, compilers (gcc/clang), build deps, git hooks, and optionally LLM tooling.

### `just build-all test-unit-tk test-integration-all test-system-all`

The dev-setup validation runs these recipes in order (not the full `tests-all` which includes `test-unit-fd`):

1. `just build-all` → `just build-fd && just build-tk`
2. `just test-unit-tk` → Firedancer unit tests are **skipped** (`test-unit-fd`) until blockers in `doc/strategy/roadmap/stories/v2.10-s11.md` are resolved
3. `just test-integration-all` → `test-integration-tk`
4. `just test-system-all` → `test-system-tk` (requires LLM model; may skip if `hf` CLI unavailable)

## Known Blockers & Considerations

1. **Windows ARM:** No `setup-windows-arm` justfile recipe exists for CI in the current `setup-env` path — the justfile routes Windows to `setup-windows-x86` only. Windows ARM CI uses `setup-windows-ci-arm`. Need to add `setup-windows-arm` and `setup-windows-ci-arm` recipes, plus the justfile dispatcher paths.

2. **Windows `setup-env` routes to `setup-windows-x86` only.** The justfile `setup-env` recipe (line 103-107) only has `setup-windows-x86` in the Windows branch. Windows ARM needs `setup-windows-arm` added.

3. **System tests require LLM models.** `test-system-tk` needs llama.cpp and a GGUF model downloaded from HuggingFace. This requires `hf` CLI auth and significant disk space. These tests are optional for dev-setup validation but are included in `tests-all`.

4. **Coverage tests.** `test-cov-all` calls `test-cov-tk` which runs `coverage.sh coverage-tk` — requires clang-18/llvm-18 toolchain on Linux. This may not be installed by `setup-env` on all paths.

5. **Security checks.** `security-check-all` calls `security-sanitize-check-fd` which builds with ASan/UBSan — this is a heavy build and may cause timeouts. On macOS, security tools may be limited (SECURITY=off path).

6. **Justfile line 232-242 (`build-tk` bare dispatcher) has a bug:** Windows ARM maps to `just build-tk-windows-arm` but there's no `build-tk-windows-arm` recipe defined — only the bare dispatcher routes to it. Actually looking again, `build-tk-windows-arm: build-tk-linux-x86` exists at line 228. But `build-tk-linux-arm: build-tk-linux-x86` at line 220 means arm just aliases to x86 — this is likely a placeholder and won't actually build for ARM.

7. **Memory/hugepages.** Firedancer unit tests need hugepages. CI currently handles this in workflow YAML (not justfile). Dev setup validation on Linux needs `sudo` for hugepage allocation.

## Plan: CI Workflow for Dev Setup Validation

### Task 1: Create the CI workflow skeleton

**Objective:** Create `.github/workflows/tests-dev-setup.yml` with one detect-changes job and a matrix of platform jobs.

**Files:**
- Create: `.github/workflows/tests-dev-setup.yml`

**Steps:**

The workflow structure mirrors `build-tk.yml` but adds the test sequence after setup:

```yaml
name: Dev Setup Validation

on:
  pull_request:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: dev-setup-${{ github.ref }}
  cancel-in-progress: true

jobs:
  detect-changes:
    name: Detect Changes
    runs-on: ubuntu-slim
    outputs:
      run: ${{ steps.detect.outputs.run }}
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - uses: ./.github/actions/detect-changes
        id: detect

  dev-setup-linux-x86:
    name: Dev Setup / Linux x86_64
    needs: detect-changes
    if: needs.detect-changes.outputs.run == 'true'
    runs-on: ubuntu-24.04
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v7
      - uses: ./.github/actions/setup-public-gh-runner
        with:
          zig: 'true'
          setup-recipe: setup-linux-x86-gcc
      - name: Run validation test suite
        run: just build-all test-unit-tk test-integration-all test-system-all

  dev-setup-linux-arm:
    name: Dev Setup / Linux ARM64
    needs: detect-changes
    if: needs.detect-changes.outputs.run == 'true'
    runs-on: ubuntu-24.04
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v7
      - uses: ./.github/actions/setup-public-gh-runner
        with:
          zig: 'true'
          setup-recipe: setup-linux-arm-gcc
      - name: Run validation test suite
        run: just build-all test-unit-tk test-integration-all test-system-all
```

## Risks and Mitigations

1. **Timeouts.** `build-all test-unit-tk test-integration-all test-system-all` on Linux may take 20-30 minutes (FD build + TK tests). macOS may take 25-40. Windows may take 45-60. Set appropriate timeouts per platform.

2. **Windows ARM is untested.** No existing CI tests `test-unit-tk-windows-arm` or `test-integration-tk-windows-arm`. The first run will likely fail. Consider starting with just the build step (`just build-all`) on Windows ARM before adding the full test sequence.

3. **Disk space.** Full setup + FD libs + Zig cache + test artifacts may exceed the 14GB runner disk on Windows. Consider cleanup steps between phases.

4. **Clang dual-install on Linux.** `setup-env` installs both gcc and clang toolchains. This is heavy but necessary for dev parity.

5. **macOS security tools.** `SECURITY=off` path on macOS means some security checks may be skipped or fail. Document this limitation.
