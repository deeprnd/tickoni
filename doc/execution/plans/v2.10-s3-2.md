# Plan: Qt -qt variation for Security and Quality checks

**Story:** V2.10.S3 — Qt hello-world build scaffolding (CMake + Qt6 C++ source)
**Date:** 2026-09-05
**Status:** PLAN — waiting approval

## 1. Problem Statement

The V2.10.S3 audit found security and quality commands that are N/A or no-op for Qt code:

- `security-seccomp-check-tk` — N/A (Qt is not in the event-path, no seccomp policy)
- `security-proof-check-tk` — N/A (no CBMC proofs for Qt)
- `security-codeql-check-tk` — N/A (no CodeQL)
- `security-sanitize-check-tk` — builds Zig Tickoni code, does NOT compile Qt C++

There are no `-qt` variants of security or quality just commands. Qt C++ files
(`main.cpp`, `CMakeLists.txt`) and QML files (`Main.qml`) are never scanned by
format, lint, sanitizer, or gitleaks. The audit flagged this gap.

## 2. Scope Boundary

- Qt is a separate CMake build tree (`src/tickoni/terminal/`) with no Firedancer
  or Tickoni Zig runtime coupling.
- Seccomp and proof (CBMC) are N/A for Qt — never adding those.
- CodeQL is out of scope for this iteration (pre-existing FD blocker, issue #10058).
- Qt requires Qt6 installation (orchestrator.py qt) and Qt dev packages
  (`qtbase5-dev qtbase5-dev-tools qtmultimedia5-dev` on Linux).

## 3. Design Decisions

### 3.1 Naming Convention

Use `-qt` suffix to mirror the existing `-fd` / `-tk` convention:

```
security-gitleaks-check-qt
security-sanitize-check-qt
quality-format-check-qt
quality-lint-check-qt
```

This keeps all commands within the existing `security-*.check-all` and
`quality-*.check-all` aggregation without adding new top-level categories.

### 3.2 Security Checks for Qt

| Check | What it does | Notes |
|-------|-------------|-------|
| `security-gitleaks-check-qt` | gitleaks scan of `src/tickoni/terminal/` | Reuses existing gitleaks binary |
| `security-sanitize-check-qt` | CMake build with `-fsanitize=address,undefined` | Requires Qt6 installed |
| `security-seccomp-check-qt` | **no-op** | Qt is not in event path |
| `security-proof-check-qt` | **no-op** | No formal verification for Qt |
| `security-codeql-check-qt` | **no-op** | Same blocker as FD |

### 3.3 Quality Checks for Qt

| Check | What it does | Notes |
|-------|-------------|-------|
| `quality-format-check-qt` | clang-format check on C++ sources | Pre-commit already has clang-format |
| `quality-lint-check-qt` | C++ lint (include guards, style grep) + QML basic check | `quality.sh` extension |

### 3.4 CI Integration

**Quality Stage (`_ci-quality.yml`):** Add a matrix entry:

```yaml
- name: Qt Quality Check
  command: just quality-format-check-qt && just quality-lint-check-qt
  timeout_minutes: 15
```

The matrix entry needs `qt-installer` setup before running. Add a setup step
gated on this matrix entry, or better: add `qt` to the existing `setup-quality-linux-x86`
recipe in justfile (the orchestrator already handles qt installation).

**Security Secrets Stage (`_ci-security-secrets.yml`):** Add gitleaks-qt to the
aggregate:

```yaml

  run: just security-gitleaks-check-all   # already includes -qt after wiring
```

**Security Deep Stage (`_ci-security-deep.yml`):** Add a `sanitize-qt` check:

```yaml
- name: Install Qt
  if: inputs.check == 'sanitize-qt'
  run: just setup-qt-linux-x86

- name: Run Qt sanitizer checks
  if: inputs.check == 'sanitize-qt'
  run: just security-sanitize-check-qt
```

Extend the `check` input to include `sanitize-qt`:
```yaml
check:
  type: string
  required: true
  description: "Which check to run (sanitize|sanitize-qt|seccomp|proof|engine)"
```

**Main CI (`ci.yml`):** Add the `sanitize-qt` security-deep job parallel to
`sanitize`, following the same pattern as the existing 4 sub-checks.

## 4. Files to Change

### 4.1 `contrib/security/security.sh` — Add Qt commands

```bash
# In usage():
  sanitize-check-qt   Build qt terminal with Clang ASan + UBSan via CMake

# New function:
cmd_sanitize_check_qt() {
  if ! command -v cmake >/dev/null 2>&1; then
    echo "sanitize-check-qt requires cmake on PATH" >&2
    return 1
  fi
  if ! command -v clang >/dev/null 2>&1; then
    echo "sanitize-check-qt requires clang on PATH" >&2
    return 1
  fi
  # Check Qt6 is available (CMake find_package would fail silently)
  if ! qmake --version >/dev/null 2>&1 && ! pkg-config --exists Qt6Core; then
    echo "sanitize-check-qt requires Qt6 dev packages (qtbase5-dev or qt6-base-dev)" >&2
    return 1
  fi

  run_step "qt cmake sanitize build" \
    cmake -S src/tickoni/terminal -B build/tickoni-terminal-sanitize \
      -DCMAKE_BUILD_TYPE=RelWithDebInfo \
      -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -g" \
      -DCMAKE_C_FLAGS="-fsanitize=address,undefined -g"
  run_step "qt cmake build" \
    cmake --build build/tickoni-terminal-sanitize -j "$(nproc)"
}

# In case statement:
  sanitize-check-qt)   cmd_sanitize_check_qt ;;
```

### 4.2 `contrib/quality/quality.sh` — Add Qt commands

```bash
# In usage():
  format-check-qt     Check Qt C++ source formatting (clang-format)
  lint-check-qt       Lint Qt C++ source (style, include guards)

# New function:
cmd_format_check_qt() {
  if ! command -v clang-format >/dev/null 2>&1; then
    echo "format-check-qt requires clang-format on PATH" >&2
    return 1
  fi
  local qt_files
  mapfile -t qt_files < <(find src/tickoni/terminal -name '*.cpp' -o -name '*.h' | sort)
  [ "${#qt_files[@]}" -gt 0 ] || { echo "no Qt C++ files found"; return 0; }
  run_step "clang-format check" clang-format --dry-run --Werror --style=file "${qt_files[@]}"
}

cmd_format_fix_qt() {
  if ! command -v clang-format >/dev/null 2>&1; then
    echo "format-fix-qt requires clang-format on PATH" >&2
    return 1
  fi
  local qt_files
  mapfile -t qt_files < <(find src/tickoni/terminal -name '*.cpp' -o -name '*.h' | sort)
  [ "${#qt_files[@]}" -gt 0 ] || { echo "no Qt C++ files found"; return 0; }
  run_step "clang-format fix" clang-format -i "${qt_files[@]}"
}

cmd_lint_check_qt() {
  local qt_files
  mapfile -t qt_files < <(find src/tickoni/terminal -name '*.cpp' -o -name '*.h' | sort)
  [ "${#qt_files[@]}" -gt 0 ] || { echo "no Qt C++ files found"; return 0; }

  local ch_files=()
  mapfile -t ch_files < <(printf '%s\n' "${qt_files[@]}" | grep -E '\.(c|cpp|h|hpp)$')
  if [ "${#ch_files[@]}" -gt 0 ]; then
    run_step "style grep" run_style_grep "${ch_files[@]}"
    run_step "include guards" run_include_guard_check "${ch_files[@]}"
  fi
}

# In case statement:
  format-check-qt)    cmd_format_check_qt ;;
  format-fix-qt)      cmd_format_fix_qt ;;
  lint-check-qt)      cmd_lint_check_qt ;;
```

## 6. Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Qt6 not installed on CI runners | Quality + sanitize checks fail | `skip: true` on quality matrix entry; sanitize-qt runs separately with Qt install step |
| Qt install takes long in CI | Timeout on security-deep | 60 min timeout should suffice (install ~2 min, build ~3 min) |
| clang-format not available on CI | Format check fails | CI quality setup installs clang-format (add to `setup-quality-linux-x86` if needed) |
| gitleaks false positives on Qt build artifacts | Spurious failures | gitleaks scans `src/tickoni/terminal/` source only, not `build/` |

## 7. What We Are NOT Doing

- **Seccomp for Qt** — no-op, Qt is not in the financial event path
- **Proof (CBMC) for Qt** — no-op, no formal verification needed
- **CodeQL for Qt** — same blocker as FD, deferred
- **QML linting** — out of scope; would need qmllint (Qt6 tool) and is
  non-trivial to configure. Can add later if needed.
- **CMake linting** — out of scope for now. CMakeLists.txt is build config,
  not runtime code.
- **New CI runners** — we use existing `ubuntu-24.04`; Qt packages are
  installable via apt.
