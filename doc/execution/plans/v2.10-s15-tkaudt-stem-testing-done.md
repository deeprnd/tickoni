# tkaudt — Stem Tile Testing Plan

> **For Hermes:** Execute tasks sequentially. Each task is self-contained — the build compiles after each one. Unit tests run in `test-unit-tk`; integration tests run in `test-integration-tk-infra`.

**Goal:** Add unit and integration tests for the tkaudt `fd_stem` tile shim (`tk_audit_stem.c`), unify the audit schema so both C and Zig share one definition, and remove the old process-mode audit tile code. The migration implementation (task 15) is complete and builds, but the stem tile has zero dedicated tests and the audit schema is duplicated between C and Zig. This plan fills that gap.

**Prerequisite:** `test-unit-tk` passes (existing tests must not break).

**Key files:**
- New unit test: `src/tickoni/tiles/audit/stem_audit_unit.zig`
- New integration test: `src/tickoni/test/integration/test_audit_stem_tile.zig`
- Shared schema header: `src/tickoni/c_abi/shim/audit_schema.h`
- Build lane changes: `build-lib/lanes/unit.zig` (add `test-audit-stem`), `build-lib/lanes/integration.zig` (add infra test)
- Reference test: `src/tickoni/test/integration/test_metric_tile_integration.zig` (12 tests, same infrastructure pattern)
- Reference unit: `src/tickoni/tiles/audit/fixture_events.zig` (audit test patterns, hash chain verification)

## Gap Analysis

### What exists today

| Test binary | Lane | What it covers | Covers tkaudt stem? |
|---|---|---|---|
| `test-audit` | `test-unit-tk` | Audit schema/codec: `computeRecordHash`, binary round-trip, parseBinary validation, hash chain mutation | ❌ Zig schema/codec only. Not the stem tile. |
| `test-payment-pipeline` | `test-unit-tk` | Process-mode payment pipeline (Zig) | ❌ Process-mode only |
| `test_metric_tile_integration.zig` | `test-integration-tk-infra` | 12 tests: topology, HTTP, CNC shutdown, workspace join, sequential runs | ❌ Metric tile only — closest analog |
| `test_process_pipeline.zig` | `test-integration-tk-infra` | Checks `audited >= 32` for process-mode | ❌ Process-mode only |

### What's missing

The tkaudt stem tile (`tk_audit_stem.c`, 453 lines) has 4 distinct code paths with no tests:

1. **`tk_audit_during_frag`** — fragment consumption, audit record building, hash chain chaining, event_count gating, fragment size validation, scratch overflow
2. **`tk_audit_before_credit`** — idle threshold (1000 ticks → `input_exhausted`), event_count exhaustion path (immediate exit)
3. **`stem_run` SHOULD_SHUTDOWN** — CNC HALT detection, idle timeout (via fd_stem template)
4. **Scratch layout** — `tk_audit_scratch_footprint_tile` correctly sizes ctx + audit records array

### Schema duplication (critical)

The audit schema exists in **three places** with different completeness:

| Location | What it defines | Completeness |
|---|---|---|
| `src/tickoni/schema/audit/audit.zig` (canonical Zig schema) | Full `AuditEvent`, `Header`, `Payload` union with 14 record types, `PolicyOutcome` (7 values), `audit_schema_version = 2` | Complete — the source of truth |
| `src/tickoni/tiles/payment_pipeline/audit_sink.zig` (old Zig record builder) | `AuditLog`, `buildPolicyDecisionEvent()`, `tile_id_*` constants, `audit_seed` | Partial — only `policy_decision` payload, uses canonical schema for `AuditEvent` type |
| `src/tickoni/c_abi/shim/tk_audit_stem.c` (C stem tile) | `AuditHeader`, `AuditEvent`, `PolicyOutcome` (4 values), `PolicyDecisionPayload`, FNV-1a hash | Partial — only `policy_decision`, FNV-1a hash in C |

**Problems:**
- `tk_audit_stem.c` defines its own `AuditHeader` and `PolicyOutcome` structs with only 4 enum values, while the canonical Zig schema has 7.
- `normalize.zig`, `policy.zig`, `replay.zig`, `runtime.zig`, `process.zig` all import `tile_id_*` constants from `audit_sink.zig` — but `audit_sink.zig` also implements the old record builder.
- There is no single file that both C and Zig can include/import for the audit event schema.
- The C and Zig hash algorithms produce the same result but are implemented independently.

## Test Architecture

### Unit tests → `test-unit-tk` lane

Tests the C helper functions that can be called from Zig with mock data:
- `tk_audit_scratch_align()` returns 64
- `tk_audit_scratch_footprint_tile()` returns correct size
- Audit hash computation produces known values for known inputs (matches Zig `computeRecordHash`)

These are small, fast, deterministic, and need no Firedancer infra.

### Integration tests → `test-integration-tk-infra` lane

Exercises the full stem tile lifecycle with Firedancer topology:
- Minimal topology with tkpoly → tkaudt
- Fragment delivery through dcache
- CNC counter verification
- Hash chain continuity
- Shutdown via CNC HALT, idle threshold, and event_count

Modeled on `test_metric_tile_integration.zig` — same infrastructure, same test style.

## Task 1: Shared audit schema header

**File:** `src/tickoni/c_abi/shim/audit_schema.h` (new)

Defines the audit event schema in C so both `tk_audit_stem.c` and any future C code share one definition. Matches the Zig canonical schema (`src/tickoni/schema/audit/audit.zig`) field-for-field.

```c
/* audit_schema.h — Shared C definition for the canonical audit event schema.
   Matches src/tickoni/schema/audit/audit.zig exactly.
   Both tk_audit_stem.c and future C code #include this. */

#ifndef __AUDIT_SCHEMA_H__
#define __AUDIT_SCHEMA_H__

#include <stdint.h>
#include <string.h>

/* Canonical schema version — must match Zig audit_schema_version. */
#define AUDIT_SCHEMA_VERSION 2

/* Seed value for FNV-1a hash chain. */
#define AUDIT_SEED 0xcbf29ce484222325ULL

/* Tile IDs used by pipeline stages to stamp msg.decided_by. */
#define TILE_ID_TKNORM "tknorm"
#define TILE_ID_TKDEDU "tkdedu"
#define TILE_ID_TKPOLY "tkpoly"

/* PolicyOutcome — must match all 7 values from Zig PolicyOutcome enum. */
typedef enum {
    POLICY_ALLOW,
    POLICY_DENY,
    POLICY_REQUIRE_APPROVAL,
    POLICY_MALFORMED_DROP,
    POLICY_DUPLICATE_DROP,
    POLICY_ESCALATE,
    POLICY_REQUIRE_MORE_EVIDENCE,
} PolicyOutcome;

/* PolicyDecisionPayload — matches Zig PolicyDecisionPayload. */
typedef struct {
    PolicyOutcome outcome;
    uint32_t rule_id;
    uint8_t failed_scope_dim[32];
    uint64_t source_event_hash;
    uint32_t catalog_schema_version;
    uint8_t taxonomy_id[32];
    uint32_t taxonomy_version;
    uint8_t classification_code[32];
} PolicyDecisionPayload;

/* AuditHeader — matches Zig Header struct field-for-field. */
typedef struct {
    uint16_t schema_version;
    uint32_t _pad0[3];
    uint64_t run_id;
    uint64_t seq;
    uint64_t source_offset;
    uint8_t tile_id[6];
    uint16_t _pad1;
    uint64_t logical_actor_id;
    uint8_t policy_version[32];
    uint64_t capability_envelope_id;
    uint64_t timestamp_ns;
    uint64_t prev_hash;
    uint64_t record_hash;
    uint8_t version[64];
    uint8_t platform_tier[64];
    uint8_t isolation_tier[64];
    uint8_t release_digest[64];
    uint8_t manifest_id[64];
} AuditHeader;

/* AuditEvent — matches Zig AuditEvent struct. */
typedef struct {
    AuditHeader header;
    /* policy_decision payload — the only payload the stem tile uses. */
    PolicyDecisionPayload policy_decision;
} AuditEvent;

#endif /* __AUDIT_SCHEMA_H__ */
```

**Update `tk_audit_stem.c`** to `#include "audit_schema.h"` and remove its local `AuditHeader`, `AuditEvent`, `PolicyOutcome`, `PolicyDecisionPayload`, `AUDIT_SCHEMA_VERSION`, `AUDIT_SEED` definitions (lines 66-116).

**Build change:** Add `audit_schema.h` to the header list that gets included in the audit_stem C library compilation. No new build target needed — it's a header-only change.

**Verification:** After this change, `zig build` still succeeds. `tk_audit_stem.c` compiles with the shared schema instead of local definitions.

## Task 2: Unit test — `test-audit-stem`

**File:** `src/tickoni/tiles/audit/stem_audit_unit.zig` (new)

Tests via Zig `extern` declarations calling C functions from `tk_audit_stem.c`:

```
test "scratch_align returns 64"
  → call tk_audit_scratch_align(), expect 64

test "scratch_footprint includes ctx + 16384 audit records"
  → call tk_audit_scratch_footprint_tile(), verify size >= sizeof(tk_audit_ctx_t) + 16384 * sizeof(AuditEvent)

test "audit record hash matches known fixture for seed input"
  → build a PaymentMessage with known fields, call tk_audit_during_frag (or hash helper), verify record_hash matches expected value

test "FNV-1a hash is deterministic for identical inputs"
  → run same fragment twice, verify both produce identical record_hash
```

## Task 3: Integration test — `test_audit_stem_tile.zig`

**File:** `src/tickoni/test/integration/test_audit_stem_tile.zig` (new)

Modeled on `test_metric_tile_integration.zig`. Tests the stem tile in a real Firedancer topology.

### Tests (7):

```
test "audit_stem topology builds and starts"
  → Build minimal topo with tkpoly → tkaudt, verify tile_obj_id, in_cnt=1, out_cnt=0
  → Verify scratch layout: audit_stem footprint validates
  → Start supervisor, verify tile boots, CNC joined, wksp joined

test "audit_stem: DURING_FRAG consumes and audits"
  → Send N PaymentMessage fragments through dcache from tkpoly
  → Verify CNC counter `audited` == N after pipeline completes
  → Verify audit records in scratch match fragment data (source_offset, decision, tile_id)

test "audit_stem: hash chain is continuous"
  → After N fragments, verify: prev_hash of record[k] == record_hash of record[k-1] for all k > 0
  → Verify first record's prev_hash == AUDIT_SEED (0xcbf29ce484222325ULL)

test "audit_stem: CNC HALT stops tile cleanly"
  → Send partial fragment stream, signal CNC HALT mid-run
  → Verify tile exits gracefully (no crash, no hang)
  → Verify audited counter reflects only completed records

test "audit_stem: idle threshold triggers shutdown"
  → Start pipeline, send 0 fragments (tkpoly produces nothing)
  → Wait > 1000 ticks (idle threshold)
  → Verify tile sets input_exhausted and exits
  → Verify no crash, clean shutdown log

test "audit_stem: event_count bounded run completes"
  → Set CNC app[7] = event_count (e.g., 5)
  → Send exactly 5 fragments
  → Verify tile sets input_exhausted immediately after 5th record
  → Verify clean exit without waiting for idle ticks

test "audit_stem: fragment size mismatch is ignored"
  → Send a fragment with wrong size (not PAYMENT_MSG_SIZE)
  → Verify tile does NOT crash, does NOT increment audited counter
  → Verify subsequent correct fragments still process normally
```

**Build change:** Add to `build-lib/lanes/integration.zig` infra proc files array (line 83-91), after `test_process_fixture_parity.zig`:

```zig
"src/tickoni/test/integration/test_audit_stem_tile.zig",
```

This inherits the same linkage as other infra tests:
- `codec.linkTickoniCodec(b, test_bin, fd_lib_dir)`
- `firedancer.linkTickoniFiredancer(b, test_bin, fd_lib_dir)`
- `topo_run.linkTickoniTopoRun(b, test_bin, fd_lib_dir)`
- `codec.addTickoniAuditShimLibrary(b, target, optimize)` (audit_stem C library)

## Risks and Mitigations

1. **Struct layout mismatch:** The C `AuditHeader` must match the Zig `Header` struct field-for-field (same sizes, same offsets, no padding differences between platforms).
   → **Mitigation:** Use explicit fixed-width types (`uint16_t`, `uint64_t`, etc.) and add compile-time checks in the unit test that `sizeof(AuditHeader)` equals the Zig schema's `@sizeOf(Header)`.

2. **Linkage complexity:** The audit shim C library compiles `fd_stem.c` with `tk_audit_ctx_t`. The test binary must link against this same library to avoid duplicate `stem_run` symbols.
   → **Mitigation:** Follow the existing `test_metric_tile_integration.zig` pattern, which already links `addTickoniAuditShimLibrary`.

3. **Fragment delivery in integration tests:** The test needs to send `PaymentMessage` fragments from tkpoly to tkaudt through the dcache. tkpoly must be stem-driven for this to work (prerequisite).
   → **Mitigation:** The existing `test_process_fixture_parity.zig` and `test_process_pipeline.zig` already exercise the tkpoly → tkaudt path. Use the same supervisor-driven approach.

4. **Idle threshold timing:** Waiting for 1000 ticks to verify idle shutdown could slow the integration test suite.
   → **Mitigation:** Use a separate test binary or a shorter threshold for the idle test (e.g., test with 10 ticks by defining a test constant). Or, verify that `input_exhausted` is set immediately when `event_count` is exhausted (Task 3, test 6).

5. **Scratch memory layout in tests:** The test needs to access audit records in scratch space to verify hash chain continuity. This requires resolving the chunk offset and workspace pointer.
   → **Mitigation:** Follow the metric tile integration test pattern for workspace join and chunk resolution. Use `fd_chunk_to_laddr` with the workspace from the input link.

6. **PolicyOutcome enum mismatch:** The old C code defined 4 enum values; the canonical Zig schema has 7. Changing to 7 values changes the C enum's binary layout.
   → **Mitigation:** Since the stem tile only receives decisions from `PaymentMessage.decision` (which comes from Zig pipeline stages), the C enum only needs to map what pipeline stages actually produce. But to stay compatible with the canonical schema, use all 7 values. The C side receives the enum value from the fragment (a u8), so no binary layout issue — the enum is only used internally in `tk_audit_during_frag`.
