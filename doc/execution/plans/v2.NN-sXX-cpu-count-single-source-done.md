# Single source of truth for CPU job count in build-fd and test-unit-fd

> **Status:** Plan only — not yet executed.
> **Root cause:** `cpu_count` is resolved from `contrib/platform.sh cores` in `just/vars.just` but neither `build-fd` nor `test-unit-fd` uses it. `build-fd` calls `strat.nproc()` (direct platform subprocess calls) and `test-unit-fd` calls `nproc()` in `dynamic_test_opts.py` independently. When platform detection fails, both diverge from the intended value. The `eval` in `test-unit-fd-*-run` recipes also fails to persist TEST_OPTS across justfile recipe lines, causing the test runner to default to `JOBS=1`.
>
> **Fix:** Export `cpu_count` from justfile, update all callers to check a shared env var first, fall back to existing detection. Add echo of resolved job count before execution in both build-fd and test-unit-fd.

### Problems

| Problem | Where | Impact |
|---|---|---|
| Dual CPU-count source (build-fd) | `vars.just` vs `strat.nproc()` | When platform detection differs from `platform.sh cores`, `-j N` in make doesn't reflect intended value |
| Dual CPU-count source (test-unit-fd) | `vars.just` vs `dynamic_test_opts.py` | When `nproc()` differs from `platform.sh cores`, `-j N` in TEST_OPTS doesn't reflect intended value |
| `eval` doesn't persist | `unit.just:72` — `*-run` recipes | `eval` sets TEST_OPTS in a subshell that dies; next line's `$(TEST_OPTS)` expands empty |
| No echo of job count | build-fd and test-unit-fd recipes | Operator sees no indication of how many parallel jobs will run |
| `TEST_OPTS: command not found` | `run_unit_tests.sh:74` | eval failure causes TEST_OPTS to be unset, test script defaults to `JOBS=1` |

### Step 2: Update `contrib/build/strategies/*.py` — `nproc()` env var

All three strategy files share the same pattern. Add `TK_BUILD_CORES` env var check before existing detection:

**`contrib/build/strategies/linux.py` (line 31-36):**
```python
def nproc() -> int:
    """Return CPU count."""
    env = os.environ.get("TK_BUILD_CORES")
    if env:
        try:
            cores = int(env)
            if cores >= 1:
                return cores
        except ValueError:
            pass
    try:
        return int(subprocess.check_output(["nproc"], text=True).strip())
    except (subprocess.CalledProcessError, FileNotFoundError):
        return 1
```

Apply same pattern to:
- `contrib/build/strategies/macos.py:84-90` (replace sysctl body with env check + sysctl fallback)
- `contrib/build/strategies/windows.py:239-243` (replace os.cpu_count body with env check + os.cpu_count fallback)

**Verify:** `TK_BUILD_CORES=4 python3 -c "import sys; sys.path.insert(0,'contrib/build'); from strategies.linux import nproc; print(nproc())"` outputs `4`.

### Step 5: Fix `*-run` recipes in `just/test/unit.just`

**Verify:** `just test-unit-fd` prints job count and runs tests with correct `-j N`.

Replace the current `*-run` recipe pattern (lines 68-90) from:
```justfile
test-unit-fd-linux-x86-gcc-run:
    #!/usr/bin/env bash
    set -euo pipefail
    timeout=600
    eval "$({{ python }} contrib/infra/dynamic_test_opts.py | grep -E '^TEST_OPTS=|^LDFLAGS_EXE=')"
    echo "Running unit tests with: $TEST_OPTS"
    contrib/test/run_unit_tests.sh --tests {{ OBJDIR }}/unit-test/automatic.txt $(TEST_OPTS)
```

To:
```justfile
test-unit-fd-linux-x86-gcc-run:
    #!/usr/bin/env bash
    set -euo pipefail
    timeout=600
    export TEST_OPTS := `{{ python }} contrib/infra/dynamic_test_opts.py | grep '^TEST_OPTS=' | cut -d= -f2- | tr -d '"'`
    test_jobs := $(shell expr $(cpu_count) - 1)
    @echo "Running unit tests with: $TEST_OPTS (using $(cpu_count) cores → $test_jobs jobs)"
    contrib/test/run_unit_tests.sh --tests {{ OBJDIR }}/unit-test/automatic.txt $TEST_OPTS
```

Note: `export` in justfile makes `TEST_OPTS` available as an env var to subprocesses (same pattern as `os`/`arch`). The `@echo` line prints the resolved values before execution. `$(cpu_count)` references the exported justfile variable.
