# Story 8.3.2 — Eliminate bash scripts for llm-server, use pure orchestrator.py strategies

## Context

Story 8.3.1 moved the llama.cpp / model bash scripts from `contrib/test/` to `contrib/setup/`, and updated the justfile to call `orchestrator.py llm-server` before tests. However, the bash scripts are still the actual implementation — `llama_cpp.py` strategy just wraps them via `subprocess.run(['bash', script_path])`.

This creates 8 redundant scripts that duplicate logic already expressible as Python install strategies:

```
contrib/setup/ensure_llama_cpp.sh          106 lines  # clone + cmake (Linux/macOS)
contrib/setup/ensure_llama_cpp_win.sh       88 lines  # clone + cmake preset (Windows)
contrib/setup/ensure_hf_model.sh           144 lines  # install hf CLI + download GGUF
contrib/setup/llama_cpp_env.sh              56 lines  # tk_resolve_llama_cpp_dir, tk_expand_home
contrib/setup/run_llm_server.sh            121 lines  # start llama-server (CPU/GPU config)
contrib/setup/run_llm_server_win.sh        115 lines  # start llama-server.exe
contrib/setup/run_system_model_tests.sh     99 lines  # orchestrate: ensure + start + test
contrib/setup/run_system_model_tests_win.sh 90 lines  # same for Windows
────────────────────────────────────────────────────────────────────
Total: ~819 lines of shell scattered across 8 files
```

All of these should be replaced by Python install strategies (and a lean just recipe for the test runner). GPU support is intentionally excluded — CPU + OpenBLAS only.

## What each script does and what replaces it

| Script | What it does | Replacement |
|--------|-------------|-------------|
| `ensure_llama_cpp.sh` | Clone llama.cpp, cmake with OpenBLAS, build server | **New Python strategy** — unified clone+cmake (CPU, OpenBLAS, no CUDA) |
| `ensure_llama_cpp_win.sh` | Same but Windows-specific (cmake preset, cygpath) | **Unified into above** — use `uname` + `cygpath` conditional, single code path |
| `ensure_hf_model.sh` | Install huggingface-cli via pip, download GGUF model | **New Python strategy** — pip install + `hf download` |
| `llama_cpp_env.sh` | `tk_resolve_llama_cpp_dir`, `tk_expand_home` helpers | **Built into the strategy** — Python path resolution |
| `run_llm_server.sh` | Start llama-server with CPU/GPU config | **New Python strategy** — start server, wait for health, return PID |
| `run_llm_server_win.sh` | Same for Windows | **Unified into above** |
| `run_system_model_tests.sh` | Orchestrate: start server + run Zig system-test | **Moved to `contrib/test/run_system_model_tests.sh`** — keep test logic in contrib/test, use orchestrator for setup, run llama-server via setup strategy, then run Zig test |
| `run_system_model_tests_win.sh` | Same for Windows | **Same move** |

Key separation:
- `contrib/setup/` — build llama.cpp, download model, start/stop server
- `contrib/test/` — orchestrate setup → start server → run Zig system-test → kill server

## Plan

### 1. Create `install/strategies/llama_cpp_build.py`

Unified cross-platform strategy for cloning + building llama.cpp (CPU + OpenBLAS only).

```python
@register('llama_cpp_build')
class LlamaCppBuildStrategy(InstallStrategy):
    def execute(self, tool, config, platform_str, dry_run):
        # 1. Resolve clone dir (~/work/models/llama.cpp or ~/work/git/llama.cpp)
        # 2. Check if llama-server binary already exists → skip if present
        # 3. Verify git + cmake are available
        # 4. git clone https://github.com/ggml-org/llama.cpp
        # 5. cmake -B build -S llama.cpp -DGGML_BLAS=ON -DGGML_BLAS_VENDOR=OpenBLAS
        #    -DGGML_NATIVE=OFF -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_TOOLS=ON
        #    -DLLAMA_BUILD_SERVER=ON -DLLAMA_BUILD_APP=OFF -DLLAMA_BUILD_EXAMPLES=OFF
        # 6. cmake --build build --config Release -j NPROC
        # 7. Copy binaries from build/bin/ to llama.cpp root
        # 8. Verify llama-server binary exists
```

Platform differences handled in one code path:
- Windows: use `cygpath -m` for native paths when needed
- Linux/macOS: standard paths
- Windows cmake: uses cmake presets (`x64-windows-llvm-release`)
- Linux/macOS cmake: direct `-B build -S llama.cpp`

        # 2. Check if model file exists in model_dir → skip if present

        # 4. hf download repo_id model_file --local-dir model_dir
        # 5. Verify model file exists

### 6. Move test runners to `contrib/test/` and rewrite

Move the test runners back to `contrib/test/` (they were moved to `contrib/setup/` in 8.3.1) and rewrite them to use orchestrator.py for setup:

```bash
# contrib/test/run_system_model_tests.sh (Linux/macOS)
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# Phase 1: Setup via orchestrator (idempotent)
python3 "$(dirname "$SCRIPT_DIR")/setup/orchestrator.py" llm-server

# Phase 2: Resolve paths (now available from setup helpers)
llama_dir="$HOME/work/models/llama.cpp"
model_dir="${TK_HF_MODEL_DIR:-$HOME/work/models/gemma/gemma-4-E2B-it-qat-GGUF}"
model_file="${TK_HF_MODEL_FILE:-gemma-4-E2B-it-qat-UD-Q4_K_XL.gguf}"
model_path="${model_dir}/${model_file}"
server_bin="${llama_dir}/llama-server"

# Phase 3: Start server, wait for health
"$server_bin" -m "$model_path" --port 9931 --no-mmproj \
  --reasoning-format none --ctx-size 4096 --cache-type-k q4_0 \
  --cache-type-v q4_0 --threads 4 --batch-size 64 --ubatch-size 32 \
  --metrics --slots &
SERVER_PID=$!

# Wait for health endpoint (max 120s)
for i in $(seq 1 60); do
    if curl -sf "http://127.0.0.1:9931/health" >/dev/null 2>&1; then
        break
    fi
    sleep 2
done

# Phase 4: Run Zig system test
ZIG_GLOBAL_CACHE_DIR=.zig-global-cache zig build -Dtest=true -Dfd-lib-dir=build/fd-tickoni-fd/lib system-test --summary all </dev/null | sed '/^failed command:/d'

# Phase 5: Cleanup
kill "$SERVER_PID" 2>/dev/null || true
wait "$SERVER_PID" 2>/dev/null || true
```

Same pattern for Windows (`llama-server.exe`, `cygpath` for model paths).

### 7. Simplify justfile test recipes

The justfile `test-system-tk` recipe calls `orchestrator.py llm-server` then the test runner. Since the test runner now calls orchestrator internally, the justfile can be simplified to just call the test runner:
