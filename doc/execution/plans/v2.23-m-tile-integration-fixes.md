# Plan: Fix Critical Issues in Firedancer Metric Tile Integration

> **Context:** The current `tkmetr` integration into Tickoni works but has structural weaknesses. This plan addresses them in order of dependency.

**Goal:** Replace fragile `#include .c` coupling, eliminate the custom stem-loop bypass, consolidate extern declarations, and add integration tests.

**Affected files:**
- `src/tickoni/c_abi/shim/tk_metric_tile.c`
- `src/tickoni/c_abi/shim/tile_run.c`
- `src/tickoni/c_abi/shim/topob.c`
- `src/tickoni/c_abi/topo_run/tk_metric_tile.h` (new)
- `src/tickoni/c_abi/topo_run/topo_run.h` (new)
- `src/tickoni/c_abi/topo_run/shim.h` (new)
- `build-lib/lib/topo_run.zig`
- `src/tickoni/c_abi/topob.zig`
- `src/tickoni/test/integration/test_metric_tile_integration.zig` (new)

## Task 0: Create shared header for TK_METRIC_RUN extern

**Problem:** `TK_METRIC_RUN` is extern-declared in two independent C files (`tile_run.c` line 49, `topob.c` line 362) with no shared header. This is fragile linkage.

**Steps:**
1. Create `src/tickoni/c_abi/topo_run/tk_metric_tile.h`:
   - Declare `extern fd_topo_run_tile_t TK_METRIC_RUN;`
   - Declare `extern fd_topo_run_tile_t* tk_get_metric_run_tile(void);` (wrapper that returns &TK_METRIC_RUN)
2. Update `tile_run.c`: `#include "tk_metric_tile.h"` instead of the raw `extern fd_topo_run_tile_t TK_METRIC_RUN;`
3. Update `topob.c`: `#include "tk_metric_tile.h"` instead of the raw `extern fd_topo_run_tile_t TK_METRIC_RUN;`

**Verification:** Both files compile and link successfully. No duplicate extern symbols.

**Status: ✅ DONE — `tk_metric_tile.h` created, `tile_run.c` and `topob.c` updated to use it.

## Task 1: Replace `#include "....../fd_metric_tile.c"` with proper FFI

**Problem:** Including Firedancer's `.c` source file instead of a header+library creates tight coupling. Build breaks silently until link time if Firedancer refactors internal symbols.

**Steps:**
1. Analyze what symbols `tk_metric_tile.c` actually needs from `fd_metric_tile.c`:
   - `stem_run` — Firedancer's stem-based polling loop
   - `METRICS_PARAMS` — configuration struct for the metrics HTTP server
   - `fd_metric_ctx_t` — context struct
   - `scratch_footprint(tile)` — scratch size calculator
   - `scratch_align()` — scratch alignment
   - `populate_allowed_seccomp()` — seccomp filter setup
   - `populate_allowed_fds()` — allowed FDs setup
   - `metrics_http_request()` — HTTP request handler
   - `before_credit(ctx, ...)` — per-credit callback
   - `fd_prometheus_render_all()` — output rendering
2. Check if Firedancer already exports these via `fd_metrics.h` or if a header already exists. Look for existing headers in `src/disco/metrics/`.
3. If no header exists, create `src/disco/metrics/fd_metric_tile.h` (or extend existing headers) that declares all needed symbols.
4. In `tk_metric_tile.c`, replace the `#include` with a proper header include.
5. Verify that all symbols are linked from Firedancer's libraries (libfd_disco, libfd_ballet, etc.) rather than included inline.

**Verification:** Build succeeds. The `fd_metric_tile.c` source file is no longer listed in the C source compilation.

**Status:** ✅ DONE — `fd_metric_tile.h` created, `fd_metric_tile.c` and `fd_prometheus.c` added to build, `tk_metric_tile.c` uses proper header, build passes cleanly.

## Task 2: Fix the root cause of the stem_run SIGSEGV and use stem directly

**Problem:** The comment says "tkmetr has 0 in/out links. Firedancer's stem_run loop dereferences out_seq[0] even when out_cnt==0, causing SIGSEGV." The custom `tk_metric_run` loop duplicates the before_credit semantics and can rot independently.

**Steps:**
1. Investigate Firedancer's `stem_run` implementation in `src/disco/stem/fd_stem.c` (or wherever it lives) to understand the out_seq[0] dereference when out_cnt==0.
2. Determine if this is a known bug that can be fixed upstream (in Firedancer) or if Tickoni can work around it safely (e.g., passing a dummy out_seq array).
3. If the bug can be fixed: submit the fix to Firedancer (or apply it in the Tickoni fork's copy of the Firedancer source).
4. If it must be worked around locally: create a small helper that allocates a dummy array and passes it to stem_run only when out_cnt==0.
5. Once the workaround is solid, replace `tk_metric_run`'s custom loop with a call to `stem_run`, removing the custom before_credit polling logic.
6. Simplify `tk_metric_privileged_init` to match Firedancer's `unprivileged_init` pattern so `stem_run` can call it directly.
7. Remove `unprivileged_init = NULL` and set it to a proper initializer if stem_run expects one.

**Verification:** `tkmetr` boots and shuts down via stem_run (not the custom loop). The custom `tk_metric_run` polling loop is removed or replaced with `stem_run`. No SIGSEGV.

## Task 3: Eliminate runtime CNC string-scan, use structured lookup

**Problem:** `tk_metric_run` scans `tile->uses_obj_id[]` with `strcmp(topo->objs[obj_id].name, "cnc")` at runtime. If Firedancer changes the CNC object naming, this silently fails.

**Steps:**
1. In `topob.c`, the cnc object is already created with a fixed name "cnc" in `cnc_new()`. The name is hardcoded there.
2. Replace the string scan in `tk_metric_run` with a direct object lookup by type. Since "cnc" is the only cnc-type object, use `fd_topo_find_obj(topo, "cnc", ...)` or similar.
3. If no such helper exists, add a thin helper `tk_topo_find_cnc_obj_id(topo, tile_id)` in `topob.c` that:
   - Iterates `topo->objs[]` looking for an object of type "cnc" that is listed in the tile's `uses_obj_id[]`
   - Returns the object id, or ULONG_MAX if not found
4. Use this helper in `tk_metric_run` instead of the raw string scan.
5. Add a compile-time check that the "cnc" name is consistent between `topob.c` (where it's created) and `tk_metric_tile.c` (where it's looked up).

**Verification:** `tkmetr` finds its CNC correctly. No `strcmp` on object names in the tile run path.

## Task 4: Consolidate all TK_METRIC_RUN access into a single C source file

**Problem:** `TK_METRIC_RUN.scratch_footprint(NULL)` is called directly from `topob.c` (line 367), which means topob.c depends on the full definition of `TK_METRIC_RUN`, not just the extern. This is a violation of the FFI boundary — the topology builder should not know about individual tile implementations.

**Steps:**
1. In `tk_metric_tile.h`, add a helper function:
   ```c
   extern ulong tk_metric_scratch_footprint(void);
   ```
   that simply returns `TK_METRIC_RUN.scratch_footprint(NULL)`.
2. In `topob.c`, replace `TK_METRIC_RUN.scratch_footprint(NULL)` with `tk_metric_scratch_footprint()`.
3. Ensure `topob.c` only sees `TK_METRIC_RUN` as an extern (for the footprint query), never as a full definition.
4. Update `tickoniTileScratchFootprint` in `topob.c` to use the helper:
   ```c
   if (strcmp(tile_name, "tkmetr") == 0)
       return tk_metric_scratch_footprint();
   return 1UL;
   ```

**Verification:** `topob.c` no longer includes `tk_metric_tile.c` or depends on the full `fd_topo_run_tile_t` definition for TK_METRIC_RUN. The footprint query goes through a thin wrapper.

## Execution order

Tasks must be done in order: 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7.

- Task 0 (header consolidation) has no dependencies.
- Task 1 (replace #include) depends on Task 0 (header already exists).
- Task 2 (fix stem_run bug) is the highest-risk task and should be done early to unblock the rest.
- Tasks 3, 4 are small cleanup tasks that can be done after Task 2.
- Task 5 (tests) depends on Tasks 0-4 being complete so tests cover the final state.
- Tasks 6-7 are documentation and verification, done last.
