## Verdict

**Telemetry contract: PASS. Observability contract: PASS.**

V2.10.S2 is a build-system refactor only. It moves the ~2,600-line monolithic `build.zig` into a ~56-line entrypoint that imports modular helpers from `build-lib/`. No Tickoni runtime source files, telemetry endpoints, metric definitions, diagnostic snapshots, operator signals, alert rules, or Firedancer metrics are added, removed, or modified. The existing Phase 0 snapshot and local-first operator surface are completely unchanged.

## Findings

### TEL-01 — New metric or diagnostic fields

**Status: PASS / N/A for S2.**

No S2 change adds or modifies a metric or diagnostic signal. The existing Phase 0 snapshot boundary is intact and untouched:

- `MetricSnapshot` (the ten documented fields: `produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`, `audited`, `backpressure_waits`, `max_queue_depth`, `max_latency_hops`) is in `src/tickoni/tiles/payment_pipeline/runtime.zig:61-72`.
- `DiagSnapshot` (the five documented fields: `crashed_tile`, `sandbox_failures`, `audit_records`, `replay_checked`, `replay_match`) is in `src/tickoni/tiles/payment_pipeline/runtime.zig:74-80`.
- The CLI obtains both values through `snapshotMetrics()` and `snapshotDiag()` and prints the established `metrics:` and `diag:` lines in `src/app/tickoni/main.zig:206-239`.
- The supervisor CLI output path is unchanged.

The `build-lib/lanes/cov.zig` file references `test-cnc-counters` (source: `src/tickoni/runtime/cnc_counters.zig`) — this is a **pre-existing** test that was already registered in the old monolithic `build.zig`. S2 merely extracted it into a new lane module; it did not introduce new metric counters. The `demo_diagnostic` module references (`build-lib/mod/modules.zig:22`, `build-lib/lanes/unit.zig:222-230`) are **build-system test registrations** for `src/tickoni/demo/diagnostic.zig` — not Tickoni runtime diagnostic snapshots. They are Zig `@import` module declarations and test-step names in `build.zig`, not runtime telemetry signals.

No new diagnostic signal bypasses the Phase 0 snapshot pattern.

### TEL-02 — Low-cardinality label policy

**Status: PASS.**

S2 introduces no metric labels, telemetry attributes, or operator dimensions. The `build-lib/` module registry uses bounded, compile-time string constants for module names and import paths (e.g., `"demo_diagnostic"`, `"cnc_counters"`, `"firedancer"`). These are Zig `@import` identifiers, not metric labels. They are not emitted as telemetry, do not appear in any `MetricSnapshot`, `DiagSnapshot`, or Firedancer metric definition, and are not high-cardinality runtime identifiers.

No S2-scoped path adds source event IDs, payment IDs, account IDs, case IDs, wallet or processor addresses, prompt text, raw model output, raw error messages, or stack traces to any telemetry surface. The low-cardinality label policy in `doc/execution/telemetry.md:131-158` is therefore preserved.

### TEL-03 — Alerting policy and generated metrics

**Status: PASS / N/A for S2.**

S2 adds no alert rules. The documented `critical`/`warning`/`info` taxonomy and future alert sources remain unchanged.

S2 does not modify `src/disco/metrics/metrics.xml` or any generated metrics outputs. No `make -C src/disco/metrics metrics` regeneration is required.

### OBS-01 — Per-tile visibility

**Status: PASS — preserved.**

S2 does not change tile ownership, tile IDs, tile run loops, supervisor monitor state, `PaymentPipelineState`, or the `tkmetr`/`tkdiag` snapshot paths. The existing per-tile visibility remains available through the established local snapshot and supervisor output:

- `tkings` / ingest: produced events, ingress backpressure, sandbox failure.
- `tknorm` / normalize: valid framing, invalid drops, stable event hashes.
- `tkdedu` / dedupe: duplicate detection.
- `tkpoly` / policy: allow, deny, duplicate-drop decisions.
- `tkaudt` / audit: append-only ordering and hash-chain records.
- `tkrepl` / replay: deterministic comparison and divergence.
- `tkmetr` / metric: metric snapshots.
- `tkdiag` / diag: crash, sandbox, audit, replay diagnostics.

The build-system refactor does not create a second observability surface or hide these signals behind build artifacts.

### OBS-02 — Smoke-check coverage

**Status: PASS — preserved.**

S2 does not modify the smoke-check command surface (`just test-unit-tk`, `zig build run -- start`, `just test-unit-fd`, `just test-all`). The walk-based test discovery in `build-lib/lanes/` replaces the manual per-file registration in the old monolithic `build.zig`, but the test binaries themselves are the same and the output format is unchanged. The existing smoke checks remain available and unchanged.

### OBS-03 — Failure visibility

**Status: PASS — preserved.**

Failure visibility is unchanged:

- Existing Phase 0 crash-only behavior and `snapshotDiag()` failure reporting are untouched.
- The sandbox failure test continues to assert `crashed_tile`, `sandbox_failures`, and the stop signal in `src/tickoni/tiles/payment_pipeline/ingest.zig:43-50`.
- No S2 change suppresses tile crashes, sandbox failures, audit failures, replay mismatches, queue saturation, invalid-event rejection, or policy-deny signals.

The build.zig refactor improves **build-time** failure visibility (errors are now localized to specific `build-lib/` modules rather than buried in a 2,600-line monolith), but this is a build-system concern, not an operator-visibility concern.
