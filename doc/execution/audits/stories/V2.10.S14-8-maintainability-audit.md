## ISO/IEC 25010 Maintainability Characteristics

### 1. Modularity

**Assessment: PASS (with observations)**

The branch achieves strong modularity for the stem migration:
- Each tile has its own stem file (`tk_*_stem.c`), cleanly separated
- Shared infrastructure lives in `stem_helpers.h` (publish, sequence counters, fragment handling) and `stem_diag.h` (diagnostic records, health counters)
- All 11 stem tiles include `stem_helpers.h`, demonstrating shared helper usage
- No raw `fd_dcache_send` or `fd_dcache_compact` calls in stem tiles — all use `stk_publish` or `fd_stem_publish` from shared helpers
- Build system properly decomposed into `build-lib/` submodules (modules, test_modules, factory, lanes, helpers, shims)

**Finding 1.1 (LOW) — stem_helpers.h at 466 lines with no section comments** — DONE
- **Path:** `src/tickoni/c_abi/shim/stem_helpers.h` (466 lines)
- **Issue:** Large shared header with no section comments. Developers cannot quickly navigate to specific helper groups. The threshold for analysis is 300 lines for build integration — this is a shared header but still large enough to need organization.
- **Remediation:** Add section comments dividing helpers into groups: "DCache publishing", "Fragment handling", "Sequence counters", "Diagnostics publishing".
- **Status:** DONE — added 6 navigational section headers (`// ── Context, Workspace, and CNC ──`, `// ── Sequence Counters ──`, `// ── Diagnostics Publishing ──`, `// ── Fragment Handling ──`, `// ── DCache Publishing ──`, `// ── Run-tile ABI Accessors ──`). Build verified clean.

**Finding 1.2 (LOW) — tile_ids.zig uses "tkgate0" for the tkgate tile** — RESOLVED
- **Path:** `src/tickoni/runtime/tile_ids.zig:50`, `audit_schema.h:52`, `tkgate.zig:38`, `tile_registry_test.zig:34`, fixture files
- **Issue:** The `tkgate` tile ID was `"tkgate0"` (6 bytes) rather than `"tkgate"` (5 bytes). This was the only tile with a numbered suffix; all other 16 tiles use their natural name. The doc comment said `"tkgate"` needs no truncation but the constant was `"tkgate0"` — a contradiction.
- **Remediation:** Changed `"tkgate0"` to `"tkgate"` across all code and docs: `tile_ids.zig`, `audit_schema.h`, `tkgate.zig`, `tile_registry_test.zig`, fixture JSONL, plan docs, and all use case docs.
- **Status:** DONE — `tkgate` now uses `"tkgate"` consistently across all 17 tiles.

### 3. Analysability

**Assessment: MEDIUM (with findings)**

The stem tiles are generally well-structured, but several analysability concerns exist:

**Finding 3.1 (HIGH) — supervisor.zig at 1689 lines with ZERO section comments** — DONE
- **Path:** `src/app/tickoni/supervisor.zig` (1689 lines)
- **Issue:** The largest file in the codebase has no section comments. Without navigational aids, a developer cannot quickly find specific concerns. The threshold for long Zig control plane files is 700 lines — this is 2.4x above. The code has 17 public functions averaging ~99 lines each (well above the 70-line recommended maximum).
- **Remediation:** Add section comments dividing the file into logical blocks: "Lifecycle management", "Process spawning", "Health monitoring", "Metrics snapshotting", "Shutdown coordination", "Configuration loading", "Test harness integration".
- **Status:** DONE — added 11 navigational section headers (`/// ── Imports ──`, `/// ── Helper Functions ──`, `/// ── Supervisor Struct ──`, `/// ── Lifecycle Management ──`, `/// ── Process Spawning ──`, `/// ── Child Lifecycle ──`, `/// ── Health Monitoring ──`, `/// ── Metrics Snapshotting ──`, `/// ── Shutdown Coordination ──`, `/// ── Test Harness Integration ──`, `// ── Tests ──`). All 87 supervisor.zig tests pass.

**Finding 3.2 (MEDIUM) — No FD_LOG_DEBUG in any stem tile** — RESOLVED
- **Path:** All 11 `tk_*_stem.c` files
- **Issue:** Zero `FD_LOG_DEBUG` calls across all stem tiles. Only `FD_LOG_INFO`, `FD_LOG_WARNING`, and `FD_LOG_ERR` are used. This makes runtime debugging extremely difficult — operators cannot enable debug logging to trace callback invocations, fragment processing, or credit management.
- **Remediation:** Add `FD_LOG_DEBUG` at key entry/exit points: tile run entry, before_credit entry, during_frag entry/exit, after_credit entry, should_shutdown check, publish operations, and error paths.
- **Status:** DONE — 30 `FD_LOG_DEBUG` calls added across all 11 stem tiles (run entry/exit, before_credit report cycle, after_credit queue status, after_frag publish trace). No `FD_LOG_DEBUG` in DURING_FRAG hot paths. Build verified clean.

**Finding 3.3 (MEDIUM) — topob.c at 907 lines, 54 functions, ZERO section comments**
- **Path:** `src/tickoni/c_abi/shim/topob.c` (907 lines)
- **Issue:** Topology builder is the second-largest file, with 54 functions and no section comments. The C file also uses 16 `strcmp` calls for tile name matching, which is less type-safe than enum-based dispatch.
- **Remediation:** Add section comments. Consider replacing string-based tile lookup with `tile_ids.lookup()` or TileId enum matching.
- **Status:** ACCEPTED — string matching in topob.c is acceptable for Firedancer C integration; owner: story author

**Finding 3.4 (LOW) — Missing module docstrings in 3 new files** — DONE
- **Path:** `src/tickoni/c_abi/trace_id.zig`, `src/tickoni/codec/audit/hash.zig`, `src/tickoni/codec/audit/jsonl.zig`
- **Issue:** These new files lack module-level documentation.
- **Remediation:** Add `///` module doc comments explaining purpose, usage, and any non-obvious behavior.
- **Status:** DONE — added `//!` module docs to hash.zig (Siphash record hashing and event equality) and jsonl.zig (JSONL serialization of audit events). trace_id.zig already had a module doc. Build verified clean.
