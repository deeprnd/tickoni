## Manual Security Audit Findings

### 1. Tile Process-Mode — PASS

Production tile runtime uses process-mode (`tile_process.zig`'s `tk_tile_run`). Each tile runs as a separate OS process with its own sandbox. The `TileHandle.thread` field is set only in test mock servers (`mock_openai_server.zig`, `mock_broker_market_server.zig`), not in any production tile code. Thread-mode is confined to the payment-pipeline spike/test path and the test harness. No thread-mode was introduced as a production path.

### 2. Input Validation at Trust Boundaries — PASS (with noted findings)

| Boundary | Validation | Status |
|----------|-----------|--------|
| LaunchSpec (file input) | magic/version checks, truncated rejection, shmem_path_len bounds check | Pass |
| ProcessConfig (file input) | magic/version checks, truncated rejection | Pass |
| RawPayment framing (ingest) | Rejects malformed=true, non-USD currency, non-positive amounts | Pass |
| TileId (string input) | Rejects >6 characters | Pass |
| ToolName (string input) | Rejects unknown names via `UnknownTool` error | Pass |
| Policy amount check | Strict `amount_cents > policy_limit_cents` comparison | Pass |
| Dedupe state | Preserves tknorm's `malformed_drop` — no bypass | Pass |
| Channel count | `max_links_per_tile` enforced, returns `TooManyInLinks`/`TooManyOutLinks` | Pass |

### 3. Output/Error Checking — PASS (with noted findings)

- Every `publish`/`push` call in pipeline stages checks `.catch break` — backpressure stops the loop rather than silently dropping.
- `tk_tile_run` in `tile_process.zig` catches work errors, logs with identifiers, and calls `std.process.exit(1)`.
- `readProcessConfig` and `LaunchSpec.readFromFile` validate length, magic, and version before returning.

**Finding S7-01 (low severity):** `model/backend.zig:264` — `connectWithTimeout` uses `catch unreachable` on `std.Io.net.IpAddress.parse(host, port)` where `host` is from external configuration (potentially env-var driven). If the host string is malformed, the tile crashes rather than returning a bounded error.

```zig
// src/tickoni/tiles/model/backend.zig:264
var address = std.Io.net.IpAddress.parse(host, port) catch unreachable;
```

**Finding S7-02 (low severity):** `model/run.zig:46` — `buildProviderRequest` is called with `catch unreachable` after the validator returned `.allow_live`. This is provably safe by construction (the validator guarantees the request shape), but if the validator logic changes without updating this path, it becomes an unwarranted assumption.

### 4. Fail-Closed Behavior — PASS

- `LaunchSpec.readFromFile` rejects truncated files with `error.LaunchSpecTruncated` and bad magic with `error.LaunchSpecBadMagic` — tile boot returns exit code 1.
- `ProcessConfig.readProcessConfig` rejects truncated and bad-magic configs — same fail-closed.
- Policy decision defaults: amount over limit → `deny`. Malformed → `malformed_drop`.
- `ToolName.fromString` returns `UnknownTool` for unrecognized names.
- `validFraming` checks all three fields: malformed flag, currency, and amount sign.
- `tile_process.zig` boot failures return 1 before any tile work starts.
- `tk_tile_privileged_init` checks `signal_halt` before writing RUN — prevents race-induced hang.

### 5. Static/Preallocated Memory Discipline — PASS

- Pipeline stages use fixed-size buffers: `buf: [msg_size]u8 = undefined` — no per-event allocation.
- `PaymentPipelineState.init` allocates dedup tables and queue memory once at init time (bounded by `config.event_count` and `config.queue_depth`).
- AuditLog uses allocator-backed but pre-allocated arrays — capacity set at init, not during the run loop.
- No `ArrayList`, `HashMap`, `malloc`, or `realloc` in any hot-path tile code (confirmed via grep across `payment_pipeline/` and `agent/`).
- Process-mode config files use fixed-size struct serialization.

### 6. C/Zig Memory and Stack Safety — PASS (with noted findings)

**Finding S7-03 (medium severity):** `catalog.zig:68-72` — Production helper functions `sectorRef()` and `industryRef()` use `catch unreachable` on `ClassificationRef.init()` which internally does `try refs.append(...)`. The `append` on a `std.ArrayList` can fail with `error.OutOfMemory` when allocating. These are production helpers (not in test blocks) and `catch unreachable` masks an OOM as a crash rather than a graceful error.

```zig
// src/tickoni/schema/consumer_money/catalog.zig:68
pub fn sectorRef(sector_taxonomy_version: u16, code: []const u8) ThesisRef {
    return thesis.ClassificationRef.init("gics_sector", sector_taxonomy_version, code) catch unreachable;
}
```

Similarly at lines 72, 78, 86, 94, 350, 362-368, 465, 466, 519.

**Finding S7-04 (informational):** `util.zig:80` — `nextWorkspaceName()` uses `catch unreachable` on `bufPrint` with a fixed-format string containing only a `u32`. This is provably safe — no external input is involved, and the buffer is caller-provided at 16+ bytes.

**`@ptrCast`/`@intCast` usage:** All casts are in the C ABI layer (`c_abi/*`) or codec/model code where values are comptime constants or already-validated sizes. No unsanitized external input is cast to a smaller type. The C ABI structs are size-checked in tests.

### 7. Agent Capability Boundaries — PASS

- Agent code routes through `tkmodl` for all model access (enforced by `runInvestmentAgent` — `model_backend` is the sole path).
- Tool calls go through `tktool.normalize*()` functions which validate the tool name first.
- Adapter calls go through `tkadpt` — the `adapter_backend.call()` is the only path to external effects.
- `runRestrictedInstrumentDenialAgent` has no `adapter.Backend` or `model.Backend` parameter — compile-time guarantee that model/adapter boundaries are never crossed for restricted instruments.
- Paper execution only occurs when `ticket.policy_outcome == .allow` (line 153 of `agent/mod.zig`).
- Capability envelope is explicit: actor role, workflow, capability, envelope ID, policy version, and budget ID are all set.

### 8. Deny-By-Default Policy — PASS

- `PolicyDecision` enum has four explicit outcomes: `allow`, `deny`, `malformed_drop`, `duplicate_drop`.
- `runPolicy` in both process-mode (`process.zig`) and thread-mode (`policy.zig`) uses explicit `if/else` chains — no implicit allow.
- Missing or over-limit amounts → `deny`.
- Unknown tool names → `error.UnknownTool`.
- Unknown capability names are not routable (no stringly-typed registry).

### 9. No Elevated Permissions — PASS

- `sandbox_defaults.zig` sets: `nobody_uid`/`nobody_gid` for sandbox identity, `rlimit_file_cnt: 64`, `rlimit_address_space: 1 GiB`, `rlimit_data: 256 MiB`.
- No code paths that drop privileges, disable seccomp, or widen syscall allowlists.
- Tile processes run with minimal capabilities as per Firedancer's `privileged_init` → capability drop → seccomp install pattern.

### 10. Audit Records — PASS

- AuditLog uses append-only, hash-chained records (`prev_hash` → `record_hash` chain).
- `append()` returns `error.AuditFull` when capacity is exceeded — no silent overwrite.
- Malformed events are NOT silently dropped: tknorm stamps `malformed_drop` and forwards to audit; tkpoly preserves the decision.
- Every decision records `decided_by` tile ID and `event_hash`.

### Remediation for S7-03 (Medium)

The `sectorRef()` and `industryRef()` helpers in `catalog.zig` should propagate errors rather than using `catch unreachable`:

```diff
- pub fn sectorRef(sector_taxonomy_version: u16, code: []const u8) ThesisRef {
-     return thesis.ClassificationRef.init("gics_sector", sector_taxonomy_version, code) catch unreachable;
+ pub fn sectorRef(sector_taxonomy_version: u16, code: []const u8) ThesisRef!ThesisRef {
+     return thesis.ClassificationRef.init("gics_sector", sector_taxonomy_version, code);
```

This affects callers at `catalog.zig:78, 86, 350, 362-368`. Callers would need to propagate or handle the error. Given these helpers are used primarily in schema construction paths (not hot-path event processing), the risk is limited to startup/initialization time.

## Conclusion

**Overall: PASS with 1 flagged finding (S7-03, medium).**

The codebase follows Tickoni security model well: process-mode tiles, bounded memory, fail-closed config parsing, explicit deny-by-default policy, append-only hash-chained audit, and agent capability boundaries through `tkmodl`/`tktool`/`tkadpt`. The scanner suite passed all checks.

The medium finding (S7-03) is a code quality/correctness concern — OOM in catalog helpers should be propagated rather than crashing — but it does not affect the hot event path, does not bypass any security boundary, and only impacts schema construction (startup/initialization time). Remediation is a straightforward signature change to propagate errors.
