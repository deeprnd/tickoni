## Stories in Scope

### V2.10.S13 — Metric Tile (tkmetr)

A Firedancer-backed metric tile that reuses `fd_metric_tile.c` (Prometheus HTTP endpoint, `fd_prometheus_render_all`, stem-based polling loop) through a thin C shim (`tk_metric_tile.c`) with a custom `tk_metric_run` polling loop. The tile exposes all Firedancer tile and link metrics over a Prometheus-format HTTP endpoint on configurable address/port, shuts down cleanly via CNC HALT signal, and integrates into the Tickoni topology with correct scratch layout, seccomp policy, and allowed file descriptors.

## ISO/IEC 25010 Maintainability Characteristics

### 1. Modularity

**Assessment: PASS**

The story achieves excellent modularity. Each file owns a single, well-scoped responsibility:

- `tk_metric_tile.c` owns the metric tile shim — scratch footprint wrapper, init delegation, tk_metric_run, TK_METRIC_RUN struct. No logic bleeds into other files.
- `tk_metric_tile.h` owns the shared extern declarations — prevents duplicate symbol definitions in tile_run.c and topob.c.
- `tile_run.c` owns the dispatch gate — tile_is_metric() is a single strcmp that routes "metric" → TK_METRIC_RUN, everything else → TK_TILE_RUN.
- `topo_run.c` owns the topology launcher — seccomp, FDs, sandbox, uid/gid, init → run orchestration. The story adds no new code here; it merely receives the TK_METRIC_RUN struct through the existing dispatch path.
- `topo_build.zig` owns topology construction — metric tile detection, workspace creation, scratch footprint injection.
- `test_metric_tile_integration.zig` owns integration tests — 5 focused tests covering topology, HTTP, 404, timestamp, shutdown, CNC join.

**Finding 1.1 (PASS)** — No modularity issues found. Each file has a single responsibility and clear ownership boundary.

### 2. Reusability

**Assessment: PASS**

All metric definitions come from Firedancer's existing `metrics.xml` — no hardcoded version strings, no duplicated metric definitions. The scratch footprint is computed at runtime via `TK_METRIC_RUN.scratch_footprint()`, not hardcoded. The shared header (`tk_metric_tile.h`) prevents duplicate extern declarations across consumers.

**Finding 2.1 (PASS)** — All data driven from Firedancer infrastructure. No hardcoded values in Tickoni code.

**Finding 2.2 (PASS)** — `tk_get_metric_run_tile()` provides a named accessor so callers never need to know the `TK_METRIC_RUN` symbol name. Consolidated into a single header prevents duplicate extern declarations.

### 3. Analysability

**Assessment: PASS**

The story achieves strong analysability:

- **Documentation:** 890+ lines of comments across 3 C files explain the design rationale, Firedancer integration, and shutdown mechanics. The header file `tk_metric_tile.h` has module-level comments explaining each symbol's purpose.
- **Naming:** Consistent with Firedancer patterns — `TK_METRIC_RUN` mirrors `fd_tile_metric`, `tk_metric_run` mirrors the Firedancer run loop name, `tk_metric_scratch_footprint` follows the `tk_*` naming convention for Tickoni-owned wrappers.
- **Traceability:** The `tile_is_metric()` function in `tile_run.c` provides a single, auditable gate for dispatching to TK_METRIC_RUN. A developer can trace a failure from HTTP request → `metrics_http_request` (Firedancer) → `before_credit` (Firedancer) → `tk_metric_run` (shim) → `stem_run` (Firedancer).
- **CNC join path:** `tk_metric_run` scans `topo->objs[]` for the "cnc" object using `tk_topo_find_tile_obj()` (not raw strcmp), making the shutdown path traceable.

**Finding 3.1 (PASS)** — Documentation is thorough. Comments explain why (not just what), referencing Firedancer source files and design decisions.

### 4. Modifiability

**Assessment: PASS**

Low complexity throughout:

- **Function length:** Maximum function is ~130 lines (tk_metric_run in tk_metric_tile.c). All other functions are 30–50 lines. Well within the 70-line review limit from `tickoni.md`.
- **Nesting depth:** Minimal nesting. The deepest nesting is in `tile_run.c`'s `tk_topo_run_tile_simple()` (3 levels: function → if/else → platform-specific block).
- **Dynamic dispatch:** Only one dispatch point (`tile_is_metric()` in tile_run.c). No hidden global registries, no stringly-typed lookups outside the single strcmp gate.
- **Config-driven:** The metric port is configurable via topology spec (`metric_port: u16`). All other values (max connections, request length, out buffer size) come from Firedancer's `fd_metric_tile.c` constants.

**Finding 4.1 (PASS)** — Complexity is minimal. No unnecessary abstractions, no dead code, no commented-out branches.

**Finding 4.2 (PASS)** — No magic numbers. `FD_HTTP_SERVER_METRICS_MAX_CONNS` (4), `FD_HTTP_SERVER_METRICS_MAX_REQUEST_LEN` (2048), and out buffer size (256 KiB) are all defined in `fd_metric_tile.c` and referenced via the header, not duplicated.

### 5. Testability

**Assessment: PASS**

The story achieves strong testability:

- **5 integration tests** cover all critical paths:
  - Topology build verifies metric tile references are laid out (offsets, validation)
  - Pipeline start/stop verifies tile lifecycle (build, start, run, stop, no crashes)
  - HTTP /metrics returns 200 with valid Prometheus output (HELP, TYPE, metric names, values)
  - HTTP 404 for unknown paths verifies routing isolation
  - Boot timestamp validation verifies metric tile is running (value > 1e18 nanoseconds)
  - CNC shutdown verifies clean shutdown (not crash, allow_shutdown set)
  - CNC join verifies tile finds CNC object (8 tiles total, metric tile index verified)

- **Test isolation:** Each test creates its own tmp directory, supervisor instance, and workspace. No shared mutable state between tests.
- **HTTP client:** Uses Python subprocess (`metric_http_get.py`) for cross-platform HTTP requests. Test-only concern, no security impact.
- **Prometheus parser:** `parsePrometheusMetric()` is a pure function — easily unit-testable, handles _total suffix stripping for consistent comparison.

**Finding 5.1 (PASS)** — All 5 integration tests are focused, isolated, and cover both happy paths and error paths (404, missing CNC).

**Finding 5.2 (INFO)** — No dedicated unit tests for `tk_metric_scratch_footprint()` or `tk_topo_find_tile_obj()`. Not adding a separate unit test: `tk_topo_find_tile_obj()` is a 6-line linear scan with no branching logic, no edge cases, and no overflow risk — its behavior is already exercised by the CNC join integration test. A separate test would duplicate coverage without reducing risk. `tk_metric_scratch_footprint()` is a thin delegate to Firedancer, tested end-to-end via the integration test's HTTP and lifecycle assertions.

## Coupling Analysis

**Assessment: PASS**

Cross-component coupling is minimal:

- **C shim → Firedancer:** Only through `#include "disco/metrics/fd_metric_tile.h"` (header-only declarations, no .c source inclusion). This is the correct pattern — avoids pulling in `stem_run`'s static helpers.
- **Topo_run.c → tile_run.c:** `tile_run.c` includes `tk_metric_tile.h` for the extern declaration. `topo_run.c` does not include it — it receives `TK_METRIC_RUN` through the `tile_run` parameter passed by `tk_topo_run_tile_simple()`.
- **Topo_build.zig → topob.zig:** `topo_build.zig` calls `c_abi.topob.tickoniTileScratchFootprint()` via the Zig FFI layer. No direct Firedancer type exposure.
- **Tests → production code:** Integration tests import `topologies.paymentPipelineProcess()`, `supervisor.Supervisor`, and `c_abi.topob` — all existing production modules. No test-specific production code changes.

Internal coupling within source units is low:
- `tk_metric_tile.c` has 4 static helper functions that all delegate to Firedancer symbols. No internal cross-calls.
- `tile_run.c` has `tile_is_metric()` (static helper) that is called once by `tk_topo_run_tile_simple()`. Single call site.

## API and Ownership Boundaries

**Assessment: PASS**

The story respects architectural boundaries:

- **Tickoni → Firedancer directionality:** Tickoni Zig calls down into Firedancer C through the shim layer. No Tickoni code embeds or includes Firedancer source files directly.
- **C ABI membrane:** `tk_metric_tile.c` is a narrow C shim — it delegates to Firedancer's `fd_metric_tile.c` functions without modifying them. The header provides extern declarations only.

- **Topology builder:** `topo_build.zig` creates the metric tile's scratch and CNC objects. `topob.zig` provides the scratch footprint accessor. Clear ownership separation.
