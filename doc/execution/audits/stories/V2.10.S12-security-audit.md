# V2.10.S12 — T10 Security Audit

## Scope

Systematic review of the Tickoni codebase for secrets, credentials, unsafe patterns, memory safety, input validation, and maintainability. Target files changed in V2.10.S12:

- `src/tickoni/logger.zig` — rewritten logger with env-var level/module filtering
- `src/tickoni/util/os_api.zig` — new `isatty`, `fflush`, `setEnv`, `getEnv`
- `src/tickoni/c_abi/shim/os.c` — `tk_isatty`, `tk_fflush`, `tk_setenv`, `tk_getenv`
- `src/tickoni/c_abi/shim/os.zig` — new extern declarations and wrappers
- `src/app/tickoni/main.zig` — `logger.init()` call, `--verbose` sets `TK_LOG_LEVEL=0`
- `src/app/tickoni/supervisor.zig` — stale tile crash handling in `stopProcess`
- `src/tickoni/tiles/payment_pipeline/*.zig` (6 files) — removed `isVerbose()` double-gates
- `src/tickoni/test/integration/test_process_cpu_placement_linux.zig` — added stats/outliers
- `src/tickoni/test/integration/test_process_topology.zig` — stale-tile expectation update
- `src/tickoni/test/integration/test_process_topology_linux.zig` — stale-tile expectation update
- `build.zig` — added logger unit test target with os.c shim linkage
- `justfile` — test recipes pass `TK_LOG_LEVEL=0`
- `doc/strategy/roadmap/stories/v2.10-s12.md` — story doc
- `doc/knowledge/architecture.md` — architecture doc updates

Audited against: `doc/execution/security.md`, `doc/execution/contribution/tickoni.md`.

## Audit Methodology

1. **Static analysis**: `grep` for common secret patterns (API keys, passwords, tokens, private keys) in changed files — none found.
2. **Code review**: Manual review of all changed files against `doc/execution/security.md` and `doc/execution/contribution/tickoni.md`.
3. **Dependency scan**: No third-party dependencies (pure Zig/stdlib + Firedancer C shim).
4. **Memory safety**: Checked for allocator leaks, buffer overflows, null pointer handling, and ownership boundaries.
5. **Input validation**: Evaluated env var parsing, module filtering, and level filtering for fail-closed behavior.
6. **Maintainability**: Evaluated code style, naming, documentation, test coverage, and separation of concerns.

## Verdict: **PASS**

No secrets, no hardcoded credentials, no third-party dependencies with security risk. The logger rewrite is a safe change: it operates entirely outside the deterministic financial event path, uses bounded buffers, and fails closed on unrecognized input.

All previously flagged issues have been resolved:
- **Finding #3**: `getEnv()` no longer leaks — uses static thread-local buffer with `[*:0]` return type
- **Finding #4**: `__thread` replaced with C11 `_Thread_local` on all platforms
- **Finding #12**: `kv()` no longer allocates — uses stack buffer with `bufPrint`
- **Finding #13**: Manual null scan replaced with `std.mem.sliceTo()`
- **Finding #16**: `setEnv()` now runs before `logger.init()`, affects current process
- **Finding #19**: `@ptrCast` UB eliminated — `[*:0]const u8` with `orelse` null handling
