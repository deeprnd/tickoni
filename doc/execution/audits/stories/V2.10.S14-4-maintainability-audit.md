## ISO/IEC 25010 Assessment

### 1. Modularity — PASS

**Strengths:**
- Clean layering: C shim files (`tk_audit_stem.c`, `tk_dedu_stem.c`, `tk_normalize_stem.c`) own the Firedancer stem bridge; Zig modules (`c_abi/audit.zig`, `c_abi/tkdedu.zig`, `c_abi/tknorm.zig`) wrap them; topology builder (`topo_build.zig`) wires them; supervisor (`supervisor.zig`) orchestrates them.
- `stem_helpers.h` consolidates the shared field accessor pattern across all three stem files — no duplicated accessor definitions.
- `test_build.zig` (new) provides a single compile-time gate (`rt.test_build.enabled`) that replaces scattered `@import("builtin").is_test` checks across `ingest.zig`, `runtime.zig`, and `process.zig`. This is a genuine improvement in modularity.
- `topo_run/` headers (`tk_audit_stem.h`, `tk_dedu_stem.h`, `tk_norm_stem.h`) provide a clean extern declaration boundary — callers never see the full `fd_topo_run_tile_t` definition.
- `process.zig` removed `runDedupeProcess` (154→218 net lines after adding policy process refactor). The dedupe process logic was moved to the stem tile — a correct ownership change.

**Minor issues:**
- `supervisor.zig` changed `inject_duplicate: bool = true` → `duplicate: ?tiles_mod.DuplicateConfig = null`. The comment in `launch_spec.zig` was correctly updated to `duplicate`. No stale references remain.

### 2. Reusability — PASS

**Strengths:**
- The `stem_helpers.h` pattern (field accessors + scratch footprint/align callbacks + event_count setter) is identical across all three stem files. This is a reusable template for future stem tiles.
- The `topob.c` wrapper functions (`tk_topob_tickoni_tile_scratch_footprint`) are generic — they dispatch by tile name without hardcoding.
- `DuplicateConfig` in `runtime.zig` is a reusable struct that decouples duplicate injection from the boolean flag.

**Minor issues:**
- None significant. The pattern is well established.

### 3. Analysability — PASS

**Strengths:**

- The FFI boundary in Zig (`audit.zig`, `tkdedu.zig`, `tknorm.zig`) is thin and explicit — extern declarations map 1:1 to C symbols.
- `test_build.zig` is self-documenting with a detailed comment explaining the two-shape test problem (thread mode vs process mode).

### 4. Modifiability — PASS

**Strengths:**
- Tile ownership is explicit: each stem tile owns its own scratch footprint and align values. No central registry needs updating when a new tile is added (except the build.zig lane registration).
- `tile_registry.zig` removed `tkdeduProcess` (the old process-mode dedupe runner) — the dedupe process now runs entirely through the stem tile, and the supervisor no longer needs to dispatch it. This is a genuine reduction in coupling.
- The `DuplicateConfig` struct makes it trivial to add more duplicate injection parameters (e.g., probability, distribution) without changing the function signature of `syntheticPayment`.
- `process.zig` removed `runDedupeProcess` and the `seenOrRemember` helper — the dedupe logic moved to the C stem tile, which is the correct home for Firedancer-internal loop logic.

**Minor issues:**
- `topob.c` has 96 lines changed with several reorganized blocks. The `tk_topob_tickoni_tile_scratch_footprint` switch statement (tile_name dispatch) could benefit from a comptime table lookup instead of a runtime string comparison, but this is a performance optimization, not a modifiability issue.

### 5. Testability — PASS

**Strengths:**

- `audit.zig` integration tests verify scratch layout, record count, seq/prev_hash/hash fields, and schema version — comprehensive coverage of the audit stem tile's exposed state.

**Minor issues:**
- None. Coverage is thorough.

## Cohesion and Coupling

### Cohesion — GOOD
- Each C shim file has a single responsibility: bridge one tile's logic through `fd_stem` callbacks.
- `stem_helpers.h` is cohesive: it contains ONLY the shared accessor/footprint/align pattern.
- `test_build.zig` is a single-purpose compile-time gate with a clear justification.

### Coupling — GOOD
- C shim files depend on Firedancer infrastructure (`fd_stem.h`, `fd_topo.h`, `fd_log.h`) but not on Tickoni application logic.
- Zig wrapper modules depend on C shim externs but not on each other.
- The supervisor depends on `c_abi` modules for topology wiring but does not call stem tile functions directly.
- `tile_registry.zig` no longer depends on the dedupe process runner — coupling reduced.

### Separation of Concerns — GOOD
- Ingestion, normalization, deduplication, auditing: each has its own C shim, Zig wrapper, and header.
- The Firedancer stem bridge is in C; the Tickoni application logic is in Zig. The boundary is clean.
- Test-only code is gated by `rt.test_build.enabled`, not scattered `@import("builtin").is_test` calls.

### API and Ownership Boundaries — GOOD
- Each stem tile's `fd_topo_run_tile_t` is owned by its C shim file. The header provides extern declarations.
- Field accessors are the only public API — callers never access scratch memory or context structs directly.
- `topob.c` is the single point where tile scratch footprints are queried by name.

## Naming and Documentation — GOOD
- C shim symbols follow the `tk_<tile>_` prefix consistently.
- Zig wrapper functions use PascalCase (`getNormRunName`, `normScratchFootprint`) matching the Zig convention.
- Doxygen comments are comprehensive on C functions.
- Zig module comments are adequate for thin wrapper modules.

## Duplication — RESOLVED

**Original Finding:** The three stem files (`tk_audit_stem.c`, `tk_dedu_stem.c`, `tk_normalize_stem.c`) share a near-identical pattern for field accessors, scratch footprint/align callbacks, event count setters, and other boilerplate.

**Resolution:** Extracted into `src/tickoni/c_abi/shim/stem_helpers.h` with the `STK_DEFINE_RUN_TILE_ACCESSORS` macro that generates all seven field accessors (`_run_name`, `_run_tile`, `_run_run`, `_run_scratch_align`, `_run_scratch_footprint`, `_run_privileged_init`, `_run_unprivileged_init`) via a single macro invocation per tile. Each tile calls it with four parameters: API prefix, `fd_topo_run_tile_t` descriptor, scratch align function name, and scratch footprint function name.

`stem_helpers.h` also consolidates eight additional reusable helpers: `STK_GET_CTX`, `stk_derive_wksp`, `STK_UNPRIV_INIT`, `STK_EVENT_EXHAUSTED`, `stk_publish_counter`, `stk_validate_frag`, `stk_chunk_to_gaddr`, and `stk_find_cnc`. These are used by all three stem files with zero duplication.

**Status:** RESOLVED — all three stem files include `stem_helpers.h` and call `STK_DEFINE_RUN_TILE_ACCESSORS`. Tile-specific logic (ctx struct, scratch layout, callbacks, domain logic) remains in the owning translation unit.

**Verification:** Verified in `tk_audit_stem.c` (line 474), `tk_dedu_stem.c` (line 420), `tk_normalize_stem.c` (line 384) — each calls `STK_DEFINE_RUN_TILE_ACCESSORS` with the correct parameters. All 77 integration tests pass, including stem tile identity tests.
