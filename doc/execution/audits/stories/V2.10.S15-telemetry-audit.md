# V2.10.S15 — Telemetry and Observability Audit

## Scope

Audit story V2.10.S15 ("Port shared memory (fd_shmem) to macOS and Windows") against:

- `doc/execution/telemetry.md` — metric/diagnostic field definitions, label policy, alerting policy, generated metrics
- `doc/execution/observability.md` — per-tile visibility, smoke checks, failure visibility

## Story Summary

V2.10.S15 ports Firedancer's `fd_shmem` workspace infrastructure to macOS and Windows. The implementation extends the existing C shim layer (`wksp.c`, `topo_run_platform_*.c`) rather than creating separate `cross_shmem.zig` modules as originally planned in the spec. The telemetry/observability-relevant changes landed in:

| File | Change |
|------|--------|
| `src/disco/metrics/fd_metric_tile.c` | Added FD_LOG_NOTICE debug logging at every major path; CNC app-region index 0 increment in `before_credit` (heartbeat mechanism for supervisor); error handling for `fd_http_server_new` and `fd_http_server_listen` failures |
| `src/disco/metrics/fd_prometheus.c` | Fixed integer formatting to use `PRIu64` casts for cross-platform compatibility (Windows LLP64 vs Linux LP64); added `#include <inttypes.h>` |
| `src/tickoni/c_abi/shim/tile_run.c` | Added FD_LOG_NOTICE logging to `tile_is_metric()` and `tk_topo_run_tile_simple()`; extended metric tile dispatch to macOS and Windows; updated comments |
| `src/app/tickoni/supervisor.zig` | Refactored process state management (`ChildRecord`, `ChildOwnership`, `ProcessOperations`); changed `heartbeat_stale_after_ns` to `heartbeat_stale_after_ms`; added explicit `workspace_name` override; per-tile delta polling preserved |

## Audit Against `doc/execution/telemetry.md`

### 1. New metrics using low-cardinality labels only — PASS

**Zero new metrics defined.** S15 does not modify `metrics.xml` or any metric definitions. The metric tile exposes the same four pre-existing Firedancer metrics:

| Metric | Type | Description |
|--------|------|-------------|
| `metric_boot_timestamp_nanos` | gauge | Timestamp when validator started (nanoseconds since epoch) |
| `metric_conn_active` | gauge | Active HTTP connections to the Prometheus endpoint |
| `metric_bytes_written` | counter | Bytes written to all responses on the Prometheus endpoint |
| `metric_bytes_read` | counter | Bytes read from all requests to the Prometheus endpoint |

The CNC app-region index 0 increment added in `fd_metric_tile.c:94-97` (`before_credit`) is **not a new metric** — it writes to the CNC's app-defined region as a heartbeat counter for the supervisor's per-tile delta polling (`main.zig` lines 218-256). This counter is read by the supervisor process and printed as delta output; it is not exposed via the Prometheus `/metrics` endpoint and does not appear in `metrics.xml` or the generated `fd_metrics_metric.h`. It is an internal inter-process signal, not a telemetry metric.

**PASS.** No new metrics introduced. The four exposed metrics carry no labels beyond the implicit `tile="metric"` prefix.

### 2. New diagnostic signals follow Phase 0 snapshot pattern — PASS

**No new diagnostic signals added.** The Phase 0 diagnostics (`snapshotDiag()` fields: `crashed_tile`, `sandbox_failures`, `audit_records`, `replay_checked`, `replay_match`) and Phase 0 metrics (`snapshotMetrics()` fields: `produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`, `audited`, `backpressure_waits`, `max_queue_depth`, `max_latency_hops`) are untouched.

The CNC app-region heartbeat mechanism (`app[0]++` in `before_credit`) is an **observer-side signal** — the metric tile writes a monotonically increasing counter that the supervisor reads and displays as per-tile delta output. It follows the existing Phase 0 metrics pattern of delta-computed per-tile counters. It does not modify `snapshotMetrics()` or `snapshotDiag()`.

**PASS.** No diagnostic surface changes.

### 3. Alerting policy — PASS

telemetry.md lists alert-worthy signals: tile crash, sandbox failure, replay mismatch, audit append failure, sustained backpressure, sustained invalid-event rate, unexpected policy deny rate, queue depth saturation. S15 does not add alert rules (consistent with "No Tickoni alert rules are committed yet"). The CNC heartbeat counter could theoretically be used for a "tile stalled" alert if the counter stops advancing, but no such alert rule is introduced by this story.

**PASS.** No new alert rules.

### 4. Label policy compliance — PASS

telemetry.md's label policy restricts labels to: `tile`, `link`, `decision`, `failure_kind`, `stage`, `capability`, `environment`. Forbidden: source event IDs, payment IDs, account IDs, case IDs, wallet/processor addresses, prompt text, raw model output, raw error messages, stack traces.

The Prometheus formatting fix in `fd_prometheus.c` changes integer output from `%lu` to `%" PRIu64 "` for `kind_id`, `link_kind_id`, and `value` fields. This is a **portability fix**, not a label change — the labels remain `kind`, `kind_id`, `link_kind`, `link_kind_id`, and `le` (histograms). No new labels added. No high-cardinality identifiers introduced.

**PASS.**

### 5. Generated metrics — PASS

telemetry.md describes `make -C src/disco/metrics metrics` for regenerating metrics from `metrics.xml`. S15 does NOT modify `metrics.xml` or `gen_metrics.py`. No changes to `src/disco/metrics/generated/` directory. The metric tile's 4 metrics were already declared before S15.

**PASS.**

### 6. Retail runtime privacy defaults — PASS

telemetry.md states: telemetry disabled by default, no outbound telemetry, evidence generation local/offline, no network-side collection, no hosted analytics dependencies. The metric tile's HTTP endpoint is bound to `127.0.0.1` (local loopback) by default. No changes to the binding behavior. The metric tile now also serves on macOS and Windows (via expanded `#if FD_HAS_LINUX || FD_HAS_MACOS || FD_HAS_WINDOWS` in `tile_run.c`), but the binding remains local.

**PASS.**

## Audit Against `doc/execution/observability.md`

### 1. Per-tile visibility — PASS

observability.md defines per-tile signal focus for Phase 0 tiles and lists `tkmetr / metric_tile` as a tile in the per-tile visibility table. S15 preserves the metric tile's role as an observer tile with zero in/out links. The changes extend metric tile dispatch to macOS and Windows, ensuring per-tile Prometheus visibility is available on all platforms.

The CNC heartbeat counter (`app[0]++`) provides an additional liveness signal that the supervisor reads for per-tile delta computation. This complements (not replaces) the existing Phase 0 metrics. The metric tile's four Prometheus metrics (boot timestamp, connection count, bytes read, bytes written) remain unchanged and are still exposed on all platforms.

**PASS.** Per-tile visibility preserved and extended to macOS/Windows.

### 2. Failure visibility — PASS

observability.md states: "Failures are not silent. The target model is crash-only." S15 preserves and slightly enhances failure visibility:

- **CNC heartbeat as stall detection:** The app-region counter (`app[0]++`) in `before_credit` provides a per-tile liveness signal. If this counter stops advancing while other tiles are progressing, the supervisor can detect a stalled metric tile. The supervisor's per-tile delta polling (`main.zig` lines 218-256) already computes deltas and prints non-zero deltas to stdout, making stalls visible.
- **Error handling added:** `fd_metric_tile.c` now checks `fd_http_server_new` and `fd_http_server_listen` failures with `FD_LOG_ERR`, which will abort the tile process and trigger crash detection via the supervisor monitor. This is consistent with the crash-only model.
- **Debug logging:** S15 adds `FD_LOG_NOTICE` calls at every major path in the metric tile, `tile_run.c`, and `tk_metric_tile.c`. This increases diagnostic visibility during boot and per-iteration operation. Note: `FD_LOG_NOTICE` level is typically visible in production (not debug-only), and the `before_credit` path fires every stem_run iteration. This is a **high-frequency logging concern** (see Findings).
- **Observer isolation:** The metric tile remains an observer with zero pipeline links. It cannot introduce backpressure, overrun, or dependency on the financial event critical path. A metric tile failure cannot cascade to other tiles.

**PASS.** Failure visibility preserved. Stall detection via CNC heartbeat is a new capability that improves failure observability.

### 3. Smoke checks — PASS

observability.md recommends `just test-unit-tk` for Zig runtime, topology, supervisor, queue, sandbox, payment pipeline behavior. The integration test suite (`test_metric_tile_integration.zig`) validates topology build, HTTP /metrics (200 + valid Prometheus output), 404 for unknown paths, boot timestamp validity, and clean CNC shutdown. S15 does not modify these tests but the metric tile changes are exercised by the existing integration tests.

The per-tile delta polling in `main.zig` (`cmdStartProcess`) serves as an implicit smoke check: if all per-tile deltas are zero after the initial snapshot, the pipeline is healthy. This pattern is unchanged.

**PASS.**

### 4. Principle: No Black Boxes — PASS

observability.md states: "Every tile ... should expose runtime state. Observability is not log text added after the fact; it is part of the tile ownership model." S15 enhances this principle:

- The metric tile exposes all Firedancer tile and link metrics over a Prometheus endpoint (unchanged from S13).
- The CNC heartbeat counter (`app[0]++`) provides an additional observable signal for the supervisor's monitoring loop.
- The supervisor's per-tile delta polling (`main.zig`) prints per-tile counter deltas every second, making every tile's activity visible as structured text output.

**PASS.**

### 5. Runtime commands — PASS

observability.md documents `just build-tk`, `zig build run -- status`, and `zig build run -- start` as runtime commands. S15 does not modify these commands. The metric tile starts as part of the topology and serves `/metrics` on a configurable port (default 7999, configurable via `ProcessPipelineConfig.metric_port`). The supervisor's monitor output includes per-tile state transitions.

**PASS.**

## Findings

| # | Severity | Location | Issue | Status |
|---|----------|----------|-------|--------|
|| 1 | **WARN** | `src/disco/metrics/fd_metric_tile.c` (multiple functions) + `src/tickoni/c_abi/shim/tile_run.c` | S15 adds `FD_LOG_NOTICE` logging to high-frequency code paths. Specifically, `before_credit()` fires every stem_run iteration (1ms polling interval per `fd_http_server_poll(ctx, 1)`), and S15 adds two `FD_LOG_NOTICE` calls per iteration (ENTER and EXIT at lines 87 and 98). Combined with logging in `scratch_align`, `scratch_footprint`, `metrics_http_request`, `metrics_write`, `privileged_init`, `unprivileged_init`, `tile_is_metric`, and `tk_topo_run_tile_simple`, this significantly increases log volume. `FD_LOG_NOTICE` is typically visible in production (not debug-only), so this logging will fire continuously during normal operation. | **RESOLVED** — Downgraded `before_credit` ENTER/EXIT and `metrics_write` ENTER/EXIT from `FD_LOG_NOTICE` to `FD_LOG_DEBUG` (level 0). Firedancer's default `--log-level-stderr` is 2 (NOTICE), so DEBUG messages are silently dropped in production. Boot-time logging (scratch, priv/unpriv init) and per-request HTTP logging remain at NOTICE. Debug visibility is available via `--log-level-stderr 0` or `FD_LOG_LEVEL_STDERR=0`. |
| 2 | **INFO** | `src/disco/metrics/fd_prometheus.c` | `PRIu64` formatting fix for cross-platform compatibility. The original `%lu` format specifier was incorrect on Windows (LLP64: `ulong` is 32-bit) and could cause truncated or garbled Prometheus output for `kind_id`, `link_kind_id`, and histogram values. This is a correctness fix that ensures metric labels render correctly on all platforms. | **INFO** — No action needed. This is a necessary portability fix that improves metric accuracy on Windows. |
| 3 | **INFO** | `src/disco/metrics/fd_metric_tile.c:94-97` | CNC app-region index 0 heartbeat counter increments every stem_run iteration. This is a raw `ulong` write to shared memory without atomicity guarantees. On architectures with weak memory ordering (ARM), a concurrent read might see a torn value if the counter crosses a 64-bit boundary (unlikely but possible over very long uptimes). | **INFO** — No action needed for V2.10. The counter is read by the supervisor for delta computation, which tolerates occasional stale reads. Atomic semantics would be appropriate if this counter were exposed to external monitoring or used for precise timing. Consider `atomicStore`/`atomicLoad` if the heartbeat becomes a production alert source. |

## Verdict: PASS

V2.10.S15 is fully compliant with both `doc/execution/telemetry.md` and `doc/execution/observability.md`. Key observations:

1. **Zero new metrics defined** — S15 does not modify `metrics.xml` or add any new metric definitions. The metric tile exposes the same four pre-existing Firedancer metrics on all platforms.

2. **CNC heartbeat counter is internal signaling, not a metric** — The `app[0]++` increment in `before_credit` writes to the CNC app-defined region as a liveness signal for the supervisor's per-tile delta polling. It is not exposed via Prometheus, not declared in `metrics.xml`, and not a new diagnostic surface. It is an inter-process shared-memory signal that complements existing Phase 0 metrics.

3. **Low-cardinality only** — The 4 metric tile metrics carry no labels beyond the implicit `tile="metric"` prefix. The Prometheus formatter fix (`PRIu64`) improves cross-platform correctness without changing label structure.

4. **Failure visibility preserved and slightly enhanced** — The CNC heartbeat counter adds a new stall-detection signal. The metric tile's error handling (`FD_LOG_ERR` for HTTP server failures) ensures crash-only behavior is preserved. Observer isolation means metric tile failures cannot cascade.

5. **Cross-platform visibility** — The metric tile now dispatches on macOS and Windows (not just Linux), ensuring Prometheus visibility on all supported platforms.

6. **Generated metrics untouched** — No changes to `metrics.xml` or generated outputs.

7. **Logging volume resolved** — `before_credit` ENTER/EXIT and `metrics_write` ENTER/EXIT downgraded from `FD_LOG_NOTICE` to `FD_LOG_DEBUG`, eliminating high-frequency log noise in production. Boot-time logging (scratch, priv/unpriv init) and per-request HTTP logging remain at NOTICE. Debug visibility available via `--log-level-stderr 0` or `FD_LOG_LEVEL_STDERR=0`.

**No compliance blockers. No changes required to align code with telemetry/observability docs.**
