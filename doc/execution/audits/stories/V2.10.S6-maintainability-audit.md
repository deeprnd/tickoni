# V2.10.S6 Maintainability Audit

**Story:** V2.10.S6 — CI cutover to fully-qualified recipes
**Audit date:** 2026-08-29
**Auditor:** Repository maintainability review
**Scope:** Story-owned CI command routing and its supporting recipe/checker/documentation surface: `.github/workflows/{build-fd,build-tk,coverage,quality,security,tests-long,tests-short,tests-xlong}.yml`, `.github/actions/setup-public-gh-runner/action.yml`, `.github/actions/build-fd-tk-libs/action.yml`, `justfile`, `contrib/test/check_ci_command_surface.py`, `contrib/test/check-just-recipe-grid.sh`, and the S6 execution documentation. Earlier S2/S4 implementation and unrelated repository reorganization are treated as pre-existing/out of scope except where they are a dependency of this surface.

## Verdict

**Acceptable with explicitly recorded follow-up debt; no unresolved high-severity
maintainability defect was introduced by the S6 cutover.** The qualified recipe
grid and the retained workflow entrypoints are present, the repository-local
checkers pass, and the available quality gate was attempted. Native full CI
validation and the full quality gate are environment-limited on this Linux host
because `zig` is not installed.

The story remains `Backlog`; this audit does not update roadmap status or
acceptance checkboxes.

## ISO/IEC 25010 assessment

### Modularity

**Pass with accepted boundary-coverage debt.** CI lane selection is separated
from implementation: workflows select qualified recipes, while `justfile` owns
setup/build/test behavior. Aggregate recipes retain the required bare-dispatcher
boundary. The checker itself does not yet cover every local composite action,
which weakens the enforcement module but does not merge runtime concerns.

### Reusability

**Pass with bounded duplication.** The shared `justfile` recipe bodies and
`contrib/build`/`contrib/setup` helpers are reused by qualified aliases. The
remaining repeated workflow calls are lane declarations, not copied shell
implementations. The thin composite actions centralize GitHub-specific
orchestration without duplicating build logic.

### Analysability

**Pass with documentation/checker debt.** Qualified names expose platform and
compiler intent directly. `check-just-recipe-grid.sh` checks the expected grid,
aggregate boundaries, Linux-only CET placement, and FD/Tickoni test separation.
However, its fixed action inventory and the stale “seven workflows” wording can
mislead maintainers about the complete command surface (MAINT-01 and MAINT-02).

### Modifiability

**Pass with accepted follow-up.** A lane-specific command can normally be
changed at one qualified recipe or workflow call site. Compatibility aliases
remain thin delegates. Extending the checker requires keeping its hard-coded
workflow/action inventory synchronized with the tree; that is the main
cross-cutting maintenance risk and is assigned to the CI owner.

### Testability

**Partial, environment-limited.** The S6-specific checker self-test, live
command-surface scan, recipe-grid check, recipe listing, and dry-runs passed.
The required `just quality-check-all` and native Zig regression lane could not
complete because `zig` is not installed on this host. macOS, Windows, and GitHub
runner behavior require CI/native-host evidence and are not claimed here.

## Findings and remediation decisions

### MAINT-01 — Command-surface checker does not cover the full composite-action surface

- **Severity:** Medium
- **Characteristics:** Modularity, analysability, modifiability, testability
- **Affected paths:** `contrib/test/check_ci_command_surface.py:12-26,72-106`; `.github/actions/` (particularly actions outside the two listed in `ACTIONS`); `.github/workflows/tests-xlong.yml:80-87`; `.github/workflows/tests-long.yml:48-50`
- **Objective observation:** The checker hard-codes eight workflows but only two
  composite actions. A repository search found additional local actions and
  command-bearing action/workflow content not represented by the checker. The
  checker therefore passes without proving that every local action is a thin
  `just` wrapper. The same limitation makes future action additions easy to
  miss.
- **Decision:** **Accepted debt for this audit; no CI behavior change made.**
  The current covered workflow surface and S6 checker pass, but enforcement is
  incomplete relative to the plan's exclusive-command-surface goal.
- **Owner:** S8 CI/platform lane owner
- **Follow-up task:** Replace the fixed action allowlist with a deterministic
  inventory of all `.github/actions/*/action.yml` files, or explicitly classify
  each excluded GitHub-native action. Add a regression fixture containing a
  forbidden command in an additional action and require the checker to fail.
  Update the expected count and run the checker in the canonical quality/test
  lane.

### MAINT-02 — Workflow-count and command-surface documentation drift

- **Severity:** Low
- **Characteristics:** Analysability, modifiability, testability
- **Affected paths:** `doc/strategy/roadmap/stories/v2.10-s6.md:8,27,46`;
  `doc/execution/ci.md:38`; `doc/execution/plans/v2.10-s6.md:53-68`;
  `contrib/test/check_ci_command_surface.py:12-26`
- **Objective observation:** The story and CI overview use “7” while the
  execution plan and live workflow inventory contain eight retained workflows:
  `build-fd`, `build-tk`, `coverage`, `quality`, `security`, `tests-long`,
  `tests-short`, and `tests-xlong`. The checker reports `retained workflows: 8`.
- **Decision:** **Accepted documentation debt, not silently normalized during
  an audit.** The execution plan and live checker are the current objective
  sources; changing roadmap language is a documentation-owner decision.
- **Owner:** S8 roadmap/documentation owner
- **Follow-up task:** Reconcile the story and `doc/execution/ci.md` to the
  eight-workflow inventory, add a single source-of-truth inventory or generated
  count, and verify all references with the documentation link checker.

### MAINT-03 — Native and full quality regression coverage is unavailable on this host

- **Severity:** Low, environment-limited
- **Characteristics:** Testability, analysability
- **Affected paths:** `justfile:623-700`; `contrib/quality/quality.sh:16`;
  all platform-qualified recipes in `justfile`; CI workflows
- **Objective observation:** `just quality-check-all` reached the Tickoni format
  check and failed with exit code 127 because `zig` was not found. The Linux
  host cannot provide native macOS/Windows runner evidence. Dry-runs validate
  command rendering only and do not validate build/link behavior.
- **Decision:** **Accepted environment debt; no code defect claimed.** The
  failure is recorded exactly below; no fabricated quality or cross-platform
  pass is asserted.
- **Owner:** S8 CI/platform lane owner
- **Follow-up task:** Run `just quality-check-all` and the qualified Linux unit
  and integration lanes on a toolchain-provisioned host, then attach successful
  native macOS/Windows CI results for the retained matrix.
