## Trust-boundary review

### Input validation

- CI workflows use fixed recipe names (`just security-sanitize-check-all`, `just security-seccomp-check-all`, `just security-proof-check-all`, `just security-engine-check-all`); no external input reaches these commands.
- Matrix entries in sub-workflows use hardcoded `runner` and `platform` values; no user-controlled input flows into build or test commands.
- `plan-ci/action.yml` uses a fail-open policy for unknown files — any unlisted path triggers `core=true`, preventing silent CI skips. This is a correct default: if a new workflow file is added, the pipeline runs rather than silently dropping a gate.

### Output and error checking

- The `ci-required` aggregation job iterates all 11 job results via a `case` statement and fails the pipeline if any dependency fails. No gate can be silently bypassed.
- Each sub-workflow uses explicit `needs:` to enforce the cascading gate — GitHub Actions auto-skips downstream jobs on upstream failure. No `if: success()` or `if: always()` workarounds.
- Security-deep stage runs after integration/system/demo stages, so it executes even if earlier stages have partial failures (the aggregation job catches this).

### Fail-closed and no-bypass behavior

- Quality + security-secrets (Stage 1) gates builds (Stage 2). If quality or gitleaks fail, no build runs. This is the fast-fail behavior the story requires.
- No stage rebuilds what an upstream already built — artifact download prevents re-execution of failed stages.
- The `@true` entries for CodeQL/Seccomp-tk/Proof-tk are documented gaps, not bypasses. They are explicitly recorded in `doc/execution/security.md` as unavailable harnesses. The security aggregate includes these names, so future implementations can replace `@true` with real commands without changing the aggregate structure.
- No new network access, shell command construction from user input, filesystem privilege, or agent authority was introduced by S8.

### Agent capability boundaries and deny-by-default policy

- N/A. S8 is CI orchestration only. No agent, model, tool, adapter, execution, capability envelope, or policy boundary is changed.

### No elevated permissions

- S8 does not change any recipe's permission scope. Existing `mem-*` recipes and Windows setup recipes are unchanged. CI jobs run as the invoking user on GitHub-hosted runners.

### Static and preallocated memory discipline

- N/A. S8 changes no C/Zig source, no tile run loop, no buffer allocation, no queue capacity, and no stack discipline.

### C/Zig memory and stack safety

- N/A. No C/Zig source, C ABI wrapper, or runtime buffer changed.
