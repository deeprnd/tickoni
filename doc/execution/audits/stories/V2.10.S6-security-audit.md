## Security requirements assessment

### Input validation at every trust boundary

- Workflow lane commands are explicit qualified recipes in the retained
  workflows; the command-surface checker verifies recipe existence and rejects
  bare recipes where a qualified variant exists.
- Composite action recipe selectors are now environment-mediated and
  allowlisted. Unknown setup, dependency, and Firedancer-library recipes are
  rejected before dispatch.
- Python tool input is allowlisted rather than interpolated as arbitrary package
  text.
- `contrib/platform.sh` rejects invalid Windows architecture overrides and
  unrecognized host platforms instead of selecting a default platform.
- The checker reads fixed repository paths and fails when a covered file is
  missing; it does not infer success from an absent workflow.

### Output and error checking

- The two remediated action shell blocks use `set -euo pipefail`; rejected
  values exit non-zero and `just` failures propagate to the action.
- `check_ci_command_surface.py` returns non-zero for direct commands, missing
  recipes, bare recipes, deleted-workflow references, and unsafe input
  interpolation.
- `check-just-recipe-grid.sh` uses `set -euo pipefail` and checks `just --list`
  and all expected qualified recipes.
- `security-check-all` is chained with `&&`; it does not continue after a
  failed constituent. The aggregate result below records the completed run.

### Fail-closed behavior and no-bypass paths

- Unknown action inputs fail closed.
- The security aggregate completed successfully with the installed Zig
  toolchain.
- No S6 workflow command uses `|| true` to suppress a security gate result.
- The command-surface checker self-test includes both a forbidden `zig build`
  command and unsafe action-input interpolation.
- The deleted benchmark and book workflows are checked for both absence and
  active references.

### Static and preallocated memory discipline

S6 changes CI orchestration only. No event, policy, audit, replay, or tile
steady-state allocation was introduced. The Firedancer sanitizer and Tickoni
ReleaseSafe sanitizer both executed through the aggregate. Static workflow
inspection cannot prove runtime allocation discipline; no such claim is made
here.

### C/Zig memory and stack safety

No C or Zig source boundary was changed by S6. Firedancer ASan/UBSan build and
unit-test compilation, plus the Tickoni ReleaseSafe sanitizer, completed within
`security-check-all`. This is evidence for the executed Linux lanes only; it is
not native macOS/Windows evidence.

### Agent capability boundaries and deny-by-default policy

No agent, model, tool, adapter, capability envelope, policy outcome, audit, or
execution path is reachable from the changed CI routing. The action allowlists
are deny-by-default dispatch controls for the CI command boundary; they do not
grant financial authority or alter Tickoni capability policy.

### No elevated permissions

The workflows retain `permissions: contents: read` and S6 adds no GitHub token
permissions, credentials, network authority, or runtime privileges. The
allowlisted recipes may invoke existing setup behavior, including platform
setup requirements, but the changed actions do not add a new elevated command
path. Privileged hugepage actions noted above are pre-existing and remain
outside this S6 remediation.
