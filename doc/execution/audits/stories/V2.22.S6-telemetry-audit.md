### Finding 3 — runSystemSuite uses std.debug.print but no structured logger

**Level:** LOW — ACCEPTED AS-IS

runSystemSuite (mod.zig:850–904) uses std.debug.print for output dumps ("=== Live tkmodl ===", "=== Allowed USD 2,000 ===", etc.). These are ad-hoc print statements, not structured logger calls. The project has logger.zig with enter/exit support, but test code does not use it. This is consistent with other test files in the repo (e.g. test_portfolio_cash_demo.zig:97 uses std.debug.print), so it is an established pattern. Not a bug, but it means test output cannot be filtered by log level via --verbose. Finding 4 (live/fixture branch logging) partially addresses this by adding path selection logging.

**Status:** ACCEPTED AS-IS — consistent with existing test code patterns across the repo.

### Finding 5 — TK_LIVE_TEST env var parsing uses raw string comparison

**Level:** LOW

test_investment_demo_live.zig now uses std.mem.span (consistent with envOrDefault at line 197) and warns on unexpected values:

```zig
if (std.c.getenv("TK_LIVE_TEST")) |v| {
    const val = std.mem.span(v);
    if (!std.mem.eql(u8, val, "1")) {
        if (val.len > 0) {
            std.debug.print("=== WARNING: TK_LIVE_TEST has unexpected value '{s}', staying in fixture mode ===\n", .{val});
        }
    } else {
        live_config.use_fixture = false;
    }
}
```

**Status:** FIXED — uses std.mem.span consistently and warns on unexpected env values.

### Finding 6 — Correct log type: std.debug.print is appropriate for test code

**Level:** OBSERVATION — ACCEPTED

The project's structured logger (logger.zig) is designed for runtime tile/supervisor code. Test code uses std.debug.print throughout, which is consistent across the codebase. The fd_log macros are for C shim and tile infrastructure. This branch's use of std.debug.print is the correct type for test output. No violation of log-type conventions.

**Status:** ACCEPTED — no change needed.

### Finding 7 — Verbosity adherence: no --verbose gating on test output

**Level:** LOW — ACCEPTED AS-IS

None of the std.debug.print calls in mod.zig are gated behind a verbosity check. They always emit. In runtime tile code, debug logs are gated via logger.zig's verbose toggle. Test code does not import or use the logger, so there is no --verbose mechanism available. This is by design for test code (test output should always be visible), but worth noting that this branch's changes do not introduce any verbose-gated logging either.

**Status:** ACCEPTED AS-IS — test code intentionally emits unconditionally; --verbose gating is a runtime concern only.

### Finding 8 — New fixture path is replay-safe

**Level:** POSITIVE — VERIFIED

runFixtureModel sets replay_mode = .live in the TkModlRequest (line 402), same as runLiveModel (line 339). The model backend is FixtureBackend (not ReplayBackend), so the request goes through the normal allow_live path in runTkModlRequest, gets a canned response, and proceeds to replay verification downstream. The fixture backend does not bypass policy checks — it goes through the same runTkModlRequest validator. Replay verification in runAllowedTradeScenario (mod.zig:481–495) uses a separate FixtureBackend instance and calls replay.verifyAllowedTrade, which substitutes fixture responses. The replay chain is intact.

**Status:** VERIFIED — replay chain confirmed intact; FixtureBackend flows through the same validator as HttpBackend.
