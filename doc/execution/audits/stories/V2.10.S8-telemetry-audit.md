## Verdict

**Telemetry contract: PASS / N/A. Observability contract: PASS.**

V2.10.S8 is CI/build orchestration work. It consolidates 10 scattered GitHub
Actions workflow files into a single `ci.yml` with a 6-stage cascading gate,
replaces shell-based contrib scripts with Python orchestrators, and restructures
the `justfile` with fully-qualified recipe names. It introduces **no** Tickoni
runtime metrics, diagnostic fields, metric labels, alert rules, exporters, or
generated Firedancer metric definitions. The existing Phase 0 snapshot and
local-first operator surface are preserved.

All S8-scoped findings pass. The previously deferred OBS-03 (composite-action
allowlist mismatch) is resolved: the `setup-public-gh-runner` action and its
`build-fd.yml` matrix are deleted; sub-workflows call `just` directly via
matrix variables. OBS-02 smoke checks now execute locally on Linux with
69/69 unit tests passing.

The branch diff touches 382 files (+17,385 / -18,750), but the only Tickoni
source change is a CLI argument-parsing fix in `src/app/tickoni_cli/cli.zig`
that is unrelated to telemetry. No `src/tickoni/` or `src/app/tickoni/` files
were modified. `doc/execution/telemetry.md` and `doc/execution/observability.md`
are both unchanged.

Failure visibility is preserved and, in CI, improved: all new composite-action
shell blocks use `set -euo pipefail`, the `fail-fast: false` strategy prevents
a single platform failure from hiding another platform's failure signal, and
the `ci-required` aggregation job makes pipeline status machine-readable.

The roadmap story status is unchanged; this audit does not update story status
or acceptance checkboxes.

### OBS-01 — Per-tile visibility

**Status: PASS / preserved.**

S8 does not change tile ownership, tile IDs, tile run loops, supervisor
monitoring, `PaymentPipelineState`, or the `tkmetr`/`tkdiag` snapshot paths.
The documented per-tile visibility remains available through the existing local

orchestration layers with no knowledge of Tickoni metrics or diagnostics.

### OBS-02 — Smoke-check coverage

**Status: PASS — 69/69 unit tests pass on Linux.**

`just test-unit-tk-linux-x86` executes successfully, compiling and running 69
test binaries. The command-surface checker and recipe-grid checker remain in
place and pass. Dry-runs confirm that representative setup, unit-test, and
test-preparation recipes render. The new `tests-dev-setup.yml` workflow runs `just build-all test-unit-tk
test-integration-all test-system-all` as a full-lifecycle smoke check on each

### OBS-03 — Composite-action recipe allowlist omits retained matrix values

**Status: RESOLVED.**

The original S4 finding (`setup-public-gh-runner/action.yml:61-68,95-102` failing closed for recipe values outside its explicit allowlists) is resolved by S8's
architecture change:

- `setup-public-gh-runner/action.yml` is deleted entirely.
- `build-fd.yml` (which passed values outside the allowlist) is deleted.
- The new `_ci-build.yml` sub-workflow calls `just ${{ matrix.setup-recipe }}` and `just ${{ matrix.build-recipe }}` directly, bypassing the composite action wrapper.
- No workflow in `.github/workflows/` references `setup-public-gh-runner` (grep confirms zero matches).

The previous recipe values (`setup-fd-deps-linux-arm-gcc`, `setup-fd-deps-macos-x86`, `setup-fd-deps-macos-arm`) that were outside the allowlist are now routed through the direct `just` matrix dispatch in `_ci-build.yml`. This is a correct, visible routing — invalid recipes fail at the `just` dispatch layer, not inside a hidden composite action allowlist.

**Owner:** CI/platform lane owner.

**Follow-up:** None — the structural root cause is eliminated. Retain native CI results as verification evidence.

### OBS-04 — Failure propagation and visibility

**Status: PASS — improved.**

S8 improves failure visibility across the board:

- `set -euo pipefail` is present in all new composite-action shell blocks and
  justfile recipes. Rejected recipe values return non-zero instead of being
  ignored.
- The command-surface checker and recipe-grid checker return non-zero on invalid
  command routing; their self-test and live scan pass.
- No new workflow adds `continue-on-error`.
- All sub-workflows use `strategy.fail-fast: false`, so a single platform
  failure does not hide failures on other platforms. This is an improvement
  over the previous per-lane `build-fd.yml`/`build-tk.yml` pattern where
  `fail-fast: false` was per-lane.
- The `ci-required` aggregation job explicitly checks all 11 job results and
  reports `FAIL: <job>=<status>` for any failure, making pipeline status
  machine-readable and human-readable.
- Existing `if: always()` artifact-upload behavior remains in `coverage.yml`
  (unchanged).
- Existing Phase 0 crash-only behavior and `snapshotDiag()` reporting are
  outside the changed S8 runtime surface and remain unchanged.
- The new `tests-dev-setup.yml` workflow validates the full lifecycle
  (`build-all` → `test-unit-tk` → `test-integration-all` → `test-system-all`)
  on each platform, providing an additional failure visibility layer.

OBS-03 is resolved — the composite action and its allowlist are eliminated entirely, and sub-workflows dispatch `just` directly. Failure propagation and visibility are maintained through the same mechanisms (set -euo pipefail, fail-fast: false, ci-required aggregation job).
