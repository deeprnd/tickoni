# V2.10.S13 — T11 Telemetry and Observability Audit

## Scope

## Audit Against `doc/execution/telemetry.md`

### 1. New metrics using low-cardinality labels only — PASS

**tkmetr does NOT define new metrics.** It exposes Firedancer's existing metric tile metrics over HTTP. The metrics exposed are already declared in `src/disco/metrics/metrics.xml` under `<tile name="metric">` (lines 1654–1660):

| Metric | Type | Description |
|--------|------|-------------|
| `metric_boot_timestamp_nanos` | gauge | Timestamp when validator started (nanoseconds since epoch) |
| `metric_conn_active` | gauge | Active HTTP connections to the Prometheus endpoint |
| `metric_bytes_written` | counter | Bytes written to all responses on the Prometheus endpoint |
| `metric_bytes_read` | counter | Bytes read from all requests to the Prometheus endpoint |

None of these metrics carry labels beyond the implicit `tile="metric"` prefix. No source event IDs, payment IDs, account IDs, case IDs, wallet/processor addresses, prompt text, raw error messages, or stack traces appear in metric output. The Prometheus endpoint is bound to `127.0.0.1` (local only) by default. **PASS.**

### 2. New diagnostic signals follow Phase 0 snapshot pattern — PASS

**tkmetr does NOT add or modify diagnostic signals.** The Phase 0 diagnostics (`snapshotDiag()` fields: `crashed_tile`, `sandbox_failures`, `audit_records`, `replay_checked`, `replay_match`) are untouched. The `PaymentPipelineState.snapshotMetrics()` function (Phase 0 metrics: `produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`, `audited`, `backpressure_waits`, `max_queue_depth`, `max_latency_hops`) is also untouched. tkmetr is a pure observer — it reads Firedancer's metrics substrate and exposes it over HTTP, but does not mutate or add to the Tickoni diagnostic surface. **PASS.**

### 3. Alerting policy — PASS

telemetry.md lists alert-worthy signals: tile crash, sandbox failure, replay mismatch, audit append failure, sustained backpressure, sustained invalid-event rate, unexpected policy deny rate, queue depth saturation. tkmetr does not add alert rules (consistent with "No Tickoni alert rules are committed yet"). The metrics it exposes (`metric_boot_timestamp_nanos`, `metric_bytes_read`, `metric_bytes_written`, `metric_conn_active`) are suitable for alerting but do not introduce new alert targets or severity levels. **PASS.**

### 4. Label policy compliance — PASS

telemetry.md's label policy restricts labels to: `tile`, `link`, `decision`, `failure_kind`, `stage`, `capability`, `environment`. Forbidden: source event IDs, payment IDs, account IDs, case IDs, wallet/processor addresses, prompt text, raw model output, raw error messages, stack traces. The 4 metric tile metrics carry zero labels beyond the implicit tile name prefix. No high-cardinality data enters the Prometheus output. **PASS.**

### 5. Generated metrics — PASS

telemetry.md describes `make -C src/disco/metrics metrics` for regenerating metrics from `metrics.xml`. V2.10.S13 does NOT modify `metrics.xml` or `gen_metrics.py`. The metric tile's 4 metrics were already defined in `metrics.xml` before S13. `src/disco/metrics/generated/fd_metrics_metric.h` (generated output) was not touched. **PASS.**

### 6. Retail runtime privacy defaults — PASS

telemetry.md states: telemetry disabled by default, no outbound telemetry, evidence generation local/offline, no network-side collection, no hosted analytics dependencies. tkmetr's HTTP endpoint is bound to `127.0.0.1` (local loopback only) by default. It does not send outbound telemetry, does not connect to hosted analytics, and does not use background exporters. It is a passive read-out of in-process metrics. **PASS.**

## Audit Against `doc/execution/observability.md`

### 1. Per-tile visibility — PASS

observability.md defines per-tile signal focus for Phase 0 tiles and lists `tkmetr / metric_tile` as a tile in the per-tile visibility table. S13 adds tkmetr as an observer tile with zero in/out links. The integration tests verify:

- tkmetr tile exists in topology with `in_cnt == 0`
- tkmetr reaches `.running` state
- HTTP `/metrics` returns 200 with valid Prometheus output (`# HELP`, `# TYPE`, metric names)
- HTTP 404 for unknown paths
- Boot timestamp is a large positive value (> 1e18 nanoseconds)
- CNC HALT signal stops tile cleanly (`.stopped`, not `.crashed`, `crashed_because == .none`)

The metric tile exposes 4 metrics (boot timestamp, active connections, bytes read, bytes written). These are low-cardinality runtime signals suitable for Prometheus. No high-cardinality identifiers. **PASS.**

### 2. Failure visibility — PASS

observability.md states: "Failures are not silent. The target model is crash-only." tkmetr preserves failure visibility:

- **Crash detection:** Integration tests verify that non-ingress tiles do not crash during normal operation (`expectNoCrashes()`). The supervisor's monitor reports `state == .crashed` for any crashed tile.
- **Clean shutdown:** CNC HALT signal causes `allow_shutdown = 1` and `.stopped` transition (not `.crashed`). This confirms the tile respects the crash-only teardown model.
- **Missing CNC handling:** `tk_metric_run` gracefully handles missing CNC object (logs warning, continues polling) — no crash on misconfiguration.
- **Observer isolation:** tkmetr has zero in/out links and zero fseq objects. It cannot introduce backpressure, overrun, or dependency on the financial event critical path. A tkmetr failure cannot cascade to other tiles.

**PASS.** Failure visibility is preserved. tkmetr's observer nature means it cannot hide failures from other tiles.

### 3. Smoke checks — PASS

observability.md recommends: `just test-unit-tk` for Zig runtime, topology, supervisor, queue, sandbox, payment pipeline behavior. S13 adds integration tests via `test_metric_tile_integration.zig`, registered in `build-lib/lanes/integration.zig` and wired to `just test-integration-tk-linux-x86`. The integration test suite validates topology build, HTTP endpoint, HALT shutdown, CNC discovery, and scratch footprint. **PASS.**

### 4. Principle: No Black Boxes — PASS

observability.md states: "Every tile ... should expose runtime state. Observability is not log text added after the fact; it is part of the tile ownership model." tkmetr exposes all Firedancer tile and link metrics over a Prometheus endpoint. Every Firedancer tile (net, quic, pack, replay, repair, etc.) and every link (linkin) is visible through tkmetr's `/metrics`. tkmetr is an observer tile with zero pipeline links — it never blocks or depends on the financial event critical path. **PASS.**

### 5. Runtime commands — PASS

observability.md documents `just build-tk`, `zig build run -- status`, and `zig build run -- start` as runtime commands. S13 does not modify these commands. The metric tile starts as part of the topology and serves `/metrics` on a configurable port (default 9500). The supervisor's monitor output includes tkmetr's state transitions. **PASS.**

7. **Integration test coverage** — 5 tests verify topology build, HTTP /metrics (200 + valid Prometheus output), 404 for unknown paths, boot timestamp validity, and clean CNC shutdown.
