## Checklist

### No elevated permissions on Windows retail
**Status:** PASS

The retail runtime guide documents only user-scoped paths (`%LOCALAPPDATA%\tickoni\`,
`~\.tickoni\`) and explicit no-admin install/update/uninstall flows for Windows.

Evidence:
- `doc/execution/retail-runtime-support.md`
- `doc/knowledge/platform-tiers.md`

### Paper/sandbox default on Windows retail
**Status:** PASS

Windows retail defaults to paper/sandbox/mock/sandbox-substitute behavior:
- No seccomp namespace (Linux-only) — sandboxed by design via no-live-effect defaults
- No shared-memory topology — retail tier uses process-local execution only
- Live execution disabled — all financial operations fail-closed

Evidence:
- `doc/execution/retail-runtime-support.md`
- `doc/execution/development.md` (Windows Build Notes)

### No privileged execution paths on Windows
**Status:** PASS

Windows retail does not require:
- Administrator privileges
- Token manipulation (SeDebugPrivilege, SeImpersonatePrivilege)
- Driver installation or kernel-mode code
- UAC bypass or service account creation

Evidence:
- `doc/execution/retail-runtime-support.md`

### Manual verification route is explicit
**Status:** PASS

The retail guide documents SHA256-based manual verification for release artifacts,
built binaries, and the manifest used to generate deterministic evidence.

Evidence:
- `doc/execution/retail-runtime-support.md`

### Unsupported/deferred work is not hidden on Windows
**Status:** PASS

The docs explicitly state that V2.22 does not claim:
- Windows throughput parity with Linux full runtime
- shared-memory topology parity on Windows
- CaseOps UI tier/degraded-guarantee display in this epic
- signed release assets unless they are actually published
- live trading, live payments, or live crypto transfers on Windows

Evidence:
- `doc/execution/retail-runtime-support.md`
- `doc/knowledge/platform-tiers.md`

### Secrets are not required for Windows install/demo
**Status:** PASS

The Windows retail path is documented to avoid broker/payment/crypto/live-provider
credentials during install and deterministic demo flows.

Evidence:
- `doc/execution/retail-runtime-support.md`

### Fail-closed blocked flow exists on Windows
**Status:** PASS

The evidence packet includes a captured stale-manifest failure proving the deterministic
demo path blocks unsupported or stale inputs instead of silently degrading on Windows.

Evidence:
- `doc/execution/V2.22.S7/` evidence artifacts

## Conclusion

V2.22.S7 satisfies the story-level security closure requirements for the Windows retail
runtime trust surface:
- user-scoped / no-admin documented path
- explicit no-live-effect defaults
- manual verification route
- fail-closed blocked-flow evidence
- no hidden claim of UI/platform/support work that does not exist
- focused secret scan and Zig ReleaseSafe lane both passed
