## Trust-boundary review

### Input validation

- `justfile` dispatchers select only from fixed `os-arch` case arms and reject unsupported combinations with a non-zero exit.
- `contrib/platform.sh` normalizes architecture values to the closed set `x86|arm`; invalid explicit overrides now fail closed.
- CPU counts are validated as positive decimal integers before being passed to parallel build/test commands.
- Recipe names and platform values are repository-controlled literals, not interpolated user paths or shell fragments.
- Shell variables in the reviewed scripts are quoted at command boundaries. No S4 path interpolates an external identifier into a query, file path, or log format string.
- The recipe-grid checker uses a fixed expected-name list and fails on missing recipes, direct qualified calls from aggregates, Linux-only CET leakage, or FD-to-TK fallback.

### Output and error checking

- Dispatcher recipes use `set -euo pipefail` and `exec just ...`; unsupported routes return 1.
- The platform detector propagates OS/architecture errors and now validates command output before returning it.
- Security aggregate execution is chained with `&&`; the first failed gate stops the aggregate and returns failure.
- The security command was executed and returned exit code 0. The `zig releasesafe` run and security badge updates completed successfully.

### Fail-closed and no-bypass behavior

- **Fixed:** `tests-all` no longer contains the security `@true` bypass.
- Unsupported platform/architecture routes fail rather than selecting a default recipe.
- Missing proof tooling fails the security aggregate rather than being treated as success; the corrected security command now passes.
- The remaining `@true` entries are test-family placeholders or documented unavailable constituents; they are not newly introduced by S4 and are explicitly recorded above.

### Static and preallocated memory discipline

N/A to the S4 implementation. The change is build orchestration and shell dispatch; it does not allocate event-path buffers, modify queue capacity, add runtime growth, or change tile run loops. The audit found no S4-induced dynamic allocation, unbounded loop, recursion, or buffer-copy path.

### C/Zig memory and stack safety

N/A to the S4 implementation. No C/Zig source, C ABI wrapper, extern layout, pointer arithmetic, codec, parser, or stack-resident runtime buffer changed in this story. The security gate passed without a reported memory-safety finding.

### Agent capability boundaries and deny-by-default policy

N/A to the S4 implementation and preserved. No agent, model, tool, adapter, execution, capability envelope, policy outcome, or audit/replay contract is changed. The recipe surface does not expose a financial action or runtime capability; unknown platform routes are rejected.

### No elevated permissions

No new elevated-permission path was introduced by S4. Existing `mem-*` recipes use explicit `sudo` for hugepage administration and existing Windows setup recipes use their established `ExecutionPolicy Bypass` invocation; these are outside the S4 recipe-grid change and were not widened. S4 build/test/security dispatchers run as the invoking user.
