## 17. Findings and Remediation

### Finding 1 (RESOLVED): Tile ID `tkbrokr` Exceeds 6-Byte Buffer

**Severity:** Critical (compile blocker)
**Path:** `src/tickoni/runtime/tile_ids.zig:38,49`
**Description:** Tile ID `tkbrokr` used `"tkbrokr0"` (8 bytes) against the `[6]u8` field in `tile.TileId.bytes`. This caused a compile error: `error: string is too long for '[6]u8'`.
**Remediation:** Renamed tile ID to `tkbrok` with bytes `"tkbrok"` (6 bytes). Updated line 38 (const declaration) and line 49 (the `all` array reference). All documentation references also updated to `tkbrok`.
**Verified:** `just build-tk-linux-x86` succeeds; all unit tests pass; `just quality-check-all` passes.

### Finding 2 (RESOLVED): Zig Format Violation

**Severity:** Low (quality check failure)
**Path:** `src/tickoni/runtime/tile_ids.zig`
**Description:** After the tile ID rename, `zig fmt` flagged formatting differences (extra spaces in the `all` array).
**Remediation:** Ran `zig fmt src/tickoni/runtime/tile_ids.zig` to auto-format.

### Finding 3 (RESOLVED): Documentation Spelling Errors

**Severity:** Low (quality check warning, not code issue)
**Paths:** `doc/strategy/roadmap/usecases/*.md`,
`doc/strategy/roadmap/usecases/architecture/broker-bridge.md`
**Description:** Spelling errors in documentation files. These are domain acronyms (`tkport`, `tktkr`, `Agnt`, `Modl`) not in the cspell dictionary. All `tkbrokr` references have been renamed to `tkbrok` to match code.
**Remediation:** Renamed all documentation references from `tkbrokr` to `tkbrok` across all use case files (02, 04, 08, 09) and broker-bridge architecture doc. Added 6-byte naming convention comments to `tile_ids.zig`. Remaining spelling errors are only for intentional domain abbreviations (`tkport`, `tktkr`, `Agnt`, `Modl`) — to be added to `.cspell.json`.

### Finding 4 (ACCEPTED): Long C Shim Files — Cohesion

**Severity:** Medium
**Paths:**
- `tk_agent_stem.c`: 53,632 chars (~1,200 lines)
- `tk_dedu_stem.c`: 20,232 chars (~500 lines)
- `tk_normalize_stem.c`: 17,955 chars (~450 lines)
- `tk_policy_stem.c`: 17,704 chars (~450 lines)
- `tk_ingest_stem.c`: 12,053 chars (~320 lines)
**Analysis:** All follow the same structural template:
`privileged_init()`, `unprivileged_init()`, `work()`, `footprint()` with
shared helpers from `stem_helpers.h` and `stem_diag.h`. The
`tk_agent_stem.c` file is notably long due to agent-specific state tracking
(correlation IDs, result parsing, policy enforcement, budget checks), but is
internally well-structured with clear section boundaries.
**Decision:** ACCEPTED — each file has a single clear responsibility. The
template pattern (documented in contribution guide) makes long files
analyzable: find the pattern once, apply it to any file.
**Owner:** Story lead (review at next code review)
