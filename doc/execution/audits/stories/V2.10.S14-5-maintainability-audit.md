# V2.10.S14-5 Maintainability Audit

**Date:** 2026-11-19  
**Scope:** V2.10.S14 fd_stem migration, with emphasis on the current `tkpoly` stem tile and the supervisor, registry, topology builder, and policy integration tests that launch it.  
**Baseline:** `doc/execution/contribution/tickoni.md`, especially the fd_stem callback, scratch, FFI, and test contracts; ISO/IEC 25010 maintainability characteristics.

## Assessment

| Characteristic | Finding |
| --- | --- |
| Modularity | Tile-owned `tk_policy_stem.c` stages in `DURING_FRAG` and commits in `AFTER_FRAG`; policy decisions remain in the policy tile. The C shim and Zig FFI are separate. The supervisor's launch choice was coupled to a list of tile names; resolved below. |
| Reusability | `stem_helpers.h` supplies shared fragment validation, publication, and accessor patterns. The registry now supplies one launch-mode decision for each configured tile. |
| Analysability | Named C accessors and explicit signed policy-limit handoff make the policy path traceable. The story and older migration plan still describe a shared stem registry and `AFTER_CREDIT` publication, contrary to the current per-tile implementation and the contribution contract. |
| Modifiability | Registry validation and launch selection now use tile identity, not registry position or a supervisor-owned tile list. A configured topology can omit or reorder registered observer tiles if its links remain valid. |
| Testability | Policy helper boundary tests, fragment staging tests, policy process integration tests, and a metric-only topology regression test cover relevant behavior. Native macOS and Windows execution was not run in this Linux audit. |

## Findings And Remediation Decisions

| ID | Severity | Affected paths | Objective finding and decision |
| --- | --- | --- | --- |
| M1 | Medium, resolved | `src/app/tickoni/supervisor.zig`, `src/app/tickoni/tile_registry.zig` | The supervisor selected `__stem-run` by testing four tile names. The registry already owns tile identity. Added `LaunchMode` to each registry entry and made the supervisor select the child command from the entry. No numeric tile index decides the launch path. |
| M2 | Medium, resolved | `src/app/tickoni/tile_registry.zig`, `doc/knowledge/tile-orchestration.md`, `doc/knowledge/tile-topology.md` | Registry validation required all eight entries in one order and read `entries[t.id]`. This rejected a valid topology after a tile was removed or reordered. Validation now checks each configured identity, rejects duplicates, and checks its actual link counts against that entry. Tests cover a removed and reordered observer. Updated the architecture text and corrected the registry path. |
| M3 | Medium, resolved | `src/app/tickoni/supervisor.zig`, `src/tickoni/runtime/topo_build.zig` | Zero-channel topologies could index `channels[0]`, underflow `channels.len - 1`, or create an empty `metric_in` workspace rejected by Firedancer. The supervisor now requires an explicit workspace name when there is no channel, passes that name to each launch spec, and the topology builder omits the unused metric input workspace. A metric-only build test covers the empty-channel case. |
| M4 | Low, resolved | `src/tickoni/test/integration/test_tile_tkpoly.zig` | The tests assumed `tkpoly` was at index 3, contained silent `catch {}` cleanup, a swallowed failed assertion, and constant-false skip branches. They now resolve the tile index from the configured topology, surface cleanup errors, return a timeout error, and have no inert skip branches. No empty `catch {}` remains in the audited paths. |
| M5 | High, open story blocker | `src/app/tickoni/tile_registry.zig`, `src/tickoni/tiles/payment_pipeline/process.zig`, `src/app/tickoni/tile_main.zig`, `doc/strategy/roadmap/stories/v2.10-s14.md` | The full eight-tile migration is not implemented: `tkings` still uses the Zig `runIngestProcess` loop; `tkrepl` and `tkdiag` have no `process_fn`, and `runPipelineStage` returns without work for them. The statement that every story feature is active is therefore unverified and false for these process roles. **Owner:** Tickoni runtime owner. **Follow-up:** complete S14 T5/T6 and the corresponding replay/diagnostics integration tests before closing the story. This audit executed on Linux only; it cannot establish native macOS/Windows runtime behavior. **Owner:** platform CI owner. **Follow-up:** attach native integration run results for both operating systems and architectures claimed by the story. |
| M7 | Low, resolved by documented test fixture | `src/tickoni/test/unit/test_tile_dispatcher_stub.c`, `build-lib/lanes/unit.zig`, `doc/strategy/roadmap/stories/v2.10-s14.md` | The descriptor identity test uses a dedicated test-only linker fixture for `tk_topo_find_tile_obj`; production uses the real implementation in `topob.c`. The fixture now aborts if called, its comment names the actual call site, and the story documents the exception. Claims that no stub exists anywhere in code must exclude this test fixture. |

The `tkpoly` path has cohesive tile-local policy state and one publish point. Its FFI exposes accessors rather than a duplicate Zig context layout. No new dependency or production stub was introduced by this audit. C dispatch still maps tile names to their dedicated run descriptors; that mapping is required at the C ABI boundary and uses identity rather than position. The registry owns the supervisor's launch-mode choice.

The older V2.10.S14 story and migration plan are prospective and conflict with the current callback contract. The current contract in `doc/execution/contribution/tickoni.md` requires `DURING_FRAG` staging and `AFTER_FRAG` commit. Product documentation needs reconciliation when M5 is implemented; this audit does not rewrite intended financial or replay behavior to match the incomplete code.

## Evidence To Attach

Commands were run from the repository root on Linux x86. `XDG_RUNTIME_DIR=/tmp`, `TMPDIR=/tmp`, `ZIG_LOCAL_CACHE_DIR=build/.zig-cache`, and `ZIG_GLOBAL_CACHE_DIR=build/.zig-global-cache` were set for the final runs. The unit and integration suites required localhost socket access for the metric tile.

| Command | Result |
| --- | --- |
| `just quality-check-all` with the workspace cache and runtime directory variables above | PASS: format, Zig build check, proto, YAML, and CSpell; 327 files checked by CSpell, zero issues. |
| `just test-unit-tk` with the same variables and localhost socket access | PASS: registry, metric-only topology, policy helper, fragment staging, process lifecycle, and remaining Tickoni unit tests. |
| `just test-integration-tk` with the same variables and localhost socket access | PASS: includes all 17 `test_tile_tkpoly` process integration tests and the model HTTP tests. |
| `rg -n 'catch\\s*\\{\\s*\\}'` over the audited code paths | No matches after remediation. |
| `git diff --check` | PASS. |

The initial sandboxed unit and integration runs failed because socket creation was denied; the metric tile logged `prometheus listen failed`. A direct Python localhost socket probe returned `PermissionError: Operation not permitted`. The suites passed with localhost socket permission, so the sandbox failures are not counted as product regressions.

One later integration retry stopped before tests because the checked-in local `build/zig-out` symlink pointed to a missing `zig-out` directory. Creating `zig-out/bin` restored the build output path; the final integration run passed. No source change was needed for that local artifact state.

**Closure decision:** maintainability fixes M1–M4 and M7 are complete; the story remains open because M5 is a feature blocker and M6 needs platform evidence. No open finding is silently accepted.
