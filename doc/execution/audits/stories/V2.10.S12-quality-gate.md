## 3. Quality And Security Checks

### Fail-closed validation
- [x] `TK_LOG_LEVEL` unrecognized values → default `.err` (level 4). Fail-closed.
- [x] `TK_LOG_MODULES` unrecognized values → logs everything (no silent drop). Fail-open is acceptable for module filtering (it's a visibility control, not a security boundary).
- [x] Missing env vars → `.err` default (backwards-compatible with original behavior).
- [x] `--verbose` CLI flag → `TK_LOG_LEVEL=0` set before `logger.init()`. Fail-closed.

### Forbidden-direct-access
- [x] Logger does not reach `tkmodl`, `tktool`, `tkadpt`, `tkexec`, the approved execution ledger, or TigerBeetle. The logger is purely a stderr diagnostic tool. It accesses `util.os_api` (os_api.zig) which wraps C shim functions (`os.c`). This is the correct, approved boundary.
- [x] The C shim (`os.c`) functions (`tk_isatty`, `tk_fflush`, `tk_setenv`, `tk_getenv`) are declared in `os.zig` with proper `extern` signatures and exposed via `os_api.zig`. No module reaches them directly.

### Malformed envelope/config/manifest handling
- [x] `TK_LOG_LEVEL` out-of-range values → default `.err`. Not silently accepted.
- [x] `TK_LOG_MODULES` with commas, trailing spaces, empty strings → handled correctly (trimmed, wildcard `*` supported, empty = no filter).
- [x] `syncFiredancerLevels()` → sets `FD_LOG_LEVEL_*` env vars via `setEnv()`, which overwrites (overwrite=1). No silent truncation.

### `just quality-check-all`
- [ ] **FAIL — environment issue, not story issue.** Sub-checks that work pass:
  - `just quality-format-check-tk` PASS (`zig fmt check` — no formatting issues)
  - `just quality-lint-check-tk` PASS (`zig build check` — no lint errors)
  - `just quality-proto-check-all` FAIL (`buf` not installed, exit 127)
  - `just quality-proto-check-fd` FAIL (same, `buf` not installed)
  - Root cause: `buf` protobuf linter not in the development environment. Not a story defect.

### `just security-check-all`
- [ ] **FAIL — environment issue, not story issue.** Sub-checks that work pass:
  - `just security-engine-check-all` PASS (13 harness files in sync, linter clean)
  - `just security-codeql-check-all` PASS (no CodeQL issues)
  - `just security-seccomp-check-all` PASS (seccomp policy generation runs)
  - `just security-gitleaks-check-all` FAIL (`gitleaks` not installed, exit 127)
  - `just security-proof-check-all` FAIL (`cbmc` not installed, exit 2)
  - `just security-sanitize-check-all` FAIL (build toolchain issue, missing `clang-asan-ubsan`)
  - Root cause: `gitleaks`, `cbmc`, and `clang-asan-ubsan` build toolchain not in the development environment. Not story defects.

### No new allocation on hot/event path
- [x] Logger uses fixed-size stack buffers: 512-byte log buf, 1024-byte panic buf, 1024-byte KV buf. C shim uses 4096-byte static `_Thread_local` buffer for `tk_getenv()`. No heap allocation in the log-write path. `kv()` uses stack buffer with `std.fmt.bufPrint` (zero-allocation, per security audit Finding #12).
