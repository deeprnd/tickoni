# V2.10.S6 Telemetry and Observability Audit

**Story:** V2.10.S6 — CI cutover to fully-qualified recipes
**Audit date:** 2026-08-29
**Auditor:** Hermes Agent
**Basis:** `doc/execution/telemetry.md` and `doc/execution/observability.md`

## Verdict

**Telemetry contract: PASS / N/A. Observability contract: PASS with one open
operational routing finding.**

V2.10.S6 is CI/build orchestration work. It introduces no Tickoni runtime
metrics, diagnostic fields, metric labels, alert rules, exporters, or generated
Firedancer metric definitions. The existing Phase 0 snapshot and local-first
operator surface are preserved.

Failure visibility is preserved: the retained workflows do not add
`continue-on-error`, continue to use fail-fast command execution, and retain
`if: always()` artifact-upload behavior where it already existed. However,
one newly allowlisted composite-action boundary does not include recipe values
used by the retained build matrix. Those values fail visibly and non-zero, but
would prevent affected CI lanes from reaching their build step. This is an open
operational finding, not a telemetry-schema violation.

The roadmap story remains `Backlog`; this audit does not update story status or
acceptance checkboxes.

## Findings

**Status: PASS / N/A.**

No S6-scoped change adds or changes a metric or diagnostic signal. The existing
Phase 0 snapshot boundary remains intact:

- `MetricSnapshot` contains the documented counters/gauges
  (`produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`,
  `audited`, `backpressure_waits`, `max_queue_depth`, and `max_latency_hops`)
  in `src/tickoni/tiles/payment_pipeline/runtime.zig:61-72`.
- `DiagSnapshot` contains the documented fields (`crashed_tile`,
  `sandbox_failures`, `audit_records`, `replay_checked`, and `replay_match`) in

- The CLI continues to obtain both values through `snapshotMetrics()` and
  `snapshotDiag()` and prints the established `metrics:` and `diag:` lines in
  `src/app/tickoni/main.zig:206-239`.

No new diagnostic signal bypasses the Phase 0 snapshot pattern.

**Status: PASS / N/A.**

### OBS-02 — Smoke-check coverage

**Status: PASS for available static/dry-run checks; runtime smoke environment-limited.**

The command-surface checker and recipe-grid checker are appropriate narrow
checks for this story. Qualified dry-runs confirm that representative setup,
unit-test, and test-preparation recipes render. The documented runtime command
`zig build run -- start` and `just test-unit-tk` could not execute because this
host has no `zig` executable. No runtime telemetry output is claimed.

### OBS-03 — Composite-action recipe allowlist omits retained matrix values

**Status: DEFERRED TO S8 — Medium operational severity.**

`setup-public-gh-runner/action.yml:61-68,95-102` fails closed for recipe values
outside its explicit allowlists. The retained `build-fd.yml` matrix passes
values that are not in those lists:

- `build-fd.yml:91` passes `setup-fd-deps-linux-arm-gcc`, while the action only
  accepts the two x86 dependency recipes.
- `build-fd.yml:110` passes `setup-fd-deps-macos-x86`, while the action accepts no
  macOS dependency recipe.
- `build-fd.yml:129` passes `setup-fd-deps-macos-arm`, while the action accepts no
  macOS dependency recipe.

The corresponding recipes are present in `justfile` (also visible in the
successful `just --list` output), so this is an action allowlist mismatch rather
than a missing recipe. The failure is visible and fail-closed, but affected
lanes terminate during setup instead of producing build telemetry or completing
CI.

**Owner:** CI/platform lane owner.

**Follow-up:** Defer to S8. Align the explicit action allowlist with the
supported workflow matrix, or change the workflow inputs to the intended
supported recipes. Add a checker test that extracts action call-site values and
rejects allowlist drift. Re-run the affected native Linux/macOS lanes as part
of S8 validation.

### OBS-04 — Failure propagation and visibility

**Status: PASS; OBS-03 deferred to S8.**

The S6 routing changes preserve failure visibility:

- `set -euo pipefail` is present in both retained composite-action shell blocks;
  rejected recipe values return non-zero instead of being ignored.
- The command-surface checker and recipe-grid checker return non-zero on invalid
  command routing; their self-test and live scan pass.
- No S6 workflow adds `continue-on-error`.
- Existing `if: always()` artifact-upload behavior remains in `coverage.yml`.
- The retained workflows continue to use PR-triggered lanes except the
  pre-existing scheduled-only `coverage.yml`; S6 did not add a schedule.
- Existing Phase 0 crash-only behavior and `snapshotDiag()` reporting are
  outside the changed S6 runtime surface and remain unchanged.

OBS-03 is therefore a visible hard failure, not a silent degradation. It needs
correction in S8 because a visible setup failure is not successful lane
operation, but it is not an S6 closure blocker after this explicit deferral.
