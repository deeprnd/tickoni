**PASS with aggregate build evidence.**

V2.10.S4 is build/test orchestration work. It does not add or modify Tickoni

## Findings

### TEL-01 — New metrics or diagnostic fields

**Status: PASS / N/A for S4.**

No S4 change adds a metric or diagnostic signal. The existing Phase 0 snapshot
contract remains the source of truth:

- `MetricSnapshot` retains the ten documented fields: `produced`, `normalized`,
  `invalid`, `duplicates`, `allowed`, `denied`, `audited`,
  `backpressure_waits`, `max_queue_depth`, and `max_latency_hops` in
  `src/tickoni/tiles/payment_pipeline/runtime.zig:61-72`.
- `DiagSnapshot` retains the five documented fields: `crashed_tile`,
  `sandbox_failures`, `audit_records`, `replay_checked`, and `replay_match` in
  `src/tickoni/tiles/payment_pipeline/runtime.zig:74-80`.
- `snapshotMetrics()` and `snapshotDiag()` remain the snapshot boundary; S4
  does not alter their shape or semantics.
- The supervisor CLI output remains the existing Phase 0 snapshot presentation
  in `src/app/tickoni/main.zig:206-239`.

No new diagnostic signal bypasses the Phase 0 snapshot pattern.

### TEL-02 — Low-cardinality label policy

**Status: PASS.**

S4 introduces no metric labels and no telemetry attributes. The values added or
used by the recipe grid are bounded platform/compiler categories (`linux`,
`macos`, `windows`, `x86`, `arm`, `gcc`, and `clang`) and fixed recipe names.
They are not emitted as metric labels.

The reviewed S4 paths do not add source event IDs, payment IDs, account IDs,
case IDs, wallet/processor addresses, prompt text, raw model output, raw error
messages, or stack traces to telemetry. The forbidden high-cardinality label
policy in `telemetry.md` is therefore preserved.

### TEL-03 — Alerting policy and generated metrics

**Status: PASS / N/A for S4.**

S4 adds no alert rules. The documented `critical`/`warning`/`info` taxonomy
and future alert sources remain unchanged.

S4 does not modify `src/disco/metrics/metrics.xml` or any generated metrics
outputs. No `make -C src/disco/metrics metrics` regeneration is required.

### OBS-01 — Per-tile visibility

**Status: PASS / preserved.**

S4 does not change tile ownership, tile IDs, tile run loops, supervisor monitor
state, or Phase 0 metric/diagnostic polling. The existing per-tile visibility
remains available through the established local snapshot and supervisor paths:

- `tkings` / ingest: produced events, backpressure, and sandbox-failure path.
- `tknorm` / normalize: normalized and invalid-event counters.
- `tkdedu` / dedupe: duplicate counter.
- `tkpoly` / policy: allow/deny counters.
- `tkaudt` / audit: audited records.
- `tkrepl` / replay: replay status and match result.
- `tkmetr` / metric: metric snapshots and backpressure polling.
- `tkdiag` / diag: crash, sandbox, audit, and replay diagnostics.

The S4 dispatcher changes do not create a second observability surface or hide
these signals behind a platform-specific recipe.

### OBS-02 — Smoke-check coverage

**Status: PASS for available checks.**

The new checker is an appropriate narrow smoke check for the changed surface.
It verifies all 50 qualified recipes, aggregate bare-dispatcher calls, the
`tests-all` security gate, Linux-only CET placement, and the absence of FD-to-TK
fallbacks.

Qualified dry-runs also render successfully for build, unit, integration,
aggregate, and dispatcher recipes. The aggregate `just build-all` recipe also
completed successfully.

### OBS-03 — Failure visibility

**Status: PASS.**

Failure visibility is preserved and one orchestration bypass is removed:

- `tests-all` now invokes `just security-check-all` instead of `@true`
  (`justfile:177-184`). A failed security gate is therefore visible to the
  all-in validation path rather than being silently skipped.
- Bare dispatchers use `set -euo pipefail`, explicit fixed-case routing, and a
  non-zero error for unsupported platform combinations (`justfile:201-213`,
  `justfile:232-244`, `justfile:325-335`, `justfile:350-360`, and
  `justfile:394-405`).
- The recipe-grid checker fails on missing qualified recipes, aggregate contract
  violations, CET leakage, and FD-to-TK fallback.
- Existing Phase 0 crash-only behavior and `snapshotDiag()` failure reporting
  are untouched. The existing sandbox failure test continues to assert
  `crashed_tile`, `sandbox_failures`, and the stop signal in
  `src/tickoni/tiles/payment_pipeline/ingest.zig:43-50`.

No S4 change suppresses tile crashes, sandbox failures, audit failures, replay
mismatches, queue saturation, invalid-event rejection, or policy-deny signals.
