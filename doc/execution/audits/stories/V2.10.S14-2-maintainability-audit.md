## ISO/IEC 25010 Maintainability Characteristics

### 1. Modularity

**Finding M1 — HIGH: Audit logic fragmented across three directories for the same concern.**

Audit schema lives in `schema/audit/`, audit codec in `codec/audit/`, and C ABI shim in `c_abi/shim/`. While these represent different layers (schema → codec → interop), there is no single index module that ties them together. A developer landing on "audit" has to visit three different top-level paths to understand the full picture.

**Affected paths:** `schema/audit/mod.zig`, `codec/audit/mod.zig`, `c_abi/shim/tk_audit_stem.c`

**Recommendation:** Add a `src/tickoni/audit.zig` umbrella module (similar to `@import("runtime")`) that re-exports schema, codec, and shim types so external consumers have one entry point.

**Finding M2 — MEDIUM: `payment_pipeline/` now owns audit pipeline logic but is named for payments.**

The `audit_sink.zig`, `replay.zig`, `audit_stage.zig` files under `payment_pipeline/` handle generic audit events, not payment-specific ones. This is a naming/coupling concern: future audit consumers (investment, treasury) will look in `payment_pipeline/` for audit functionality.

**Affected paths:** `tiles/payment_pipeline/audit_sink.zig`, `tiles/payment_pipeline/replay.zig`, `tiles/payment_pipeline/audit_stage.zig`

**Recommendation:** Either rename the directory to `pipeline/` or add a `tiles/audit_pipeline/` directory. The current naming conflates "pipeline" with "payment pipeline" — the audit stage is not payment-specific.

**Finding M3 — PASS: Deleted files are clean removals with clear rationale.**

`tiles/audit/` was consolidated into `payment_pipeline/`. `audit_shared.zig` was extracted into `audit_consts.h`/`audit_consts.zig`. Deletions are all accounted for in git diff with no orphaned imports.

### 2. Reusability

**Finding R1 — RESOLVED: `audit_consts.h` is the single source of truth; Zig derives constants via translate-c.**

The C header `src/tickoni/c_abi/shim/audit_consts.h` defines audit hash constants as `static const uint64_t`. Translate-c extracts these as compile-time constants in the Zig `audit_mod` module. `src/tickoni/codec/audit/audit_consts.zig` re-exports them from `audit_mod`. No duplication: changing a value in the C header automatically updates the Zig constants at compile time.

**Finding R2 — GOOD: Hash codec functions are reusable across audit and replay.**

`audit_trace.zig` reuses `replay.hashBytes`, `replay.hashQuoteSnapshot`, `replay.hashAffordability`, `replay.hashTicket`, `replay.hashPaperResult` (line 65-69) instead of reimplementing field-by-field mixing. This prevents silent divergence between fixture audit traces and replay checks.

**Finding R3 — RESOLVED: Zig wrapper exists at `c_abi/audit.zig`.**

The finding referenced non-existent C symbols (`tk_audit_stem_audit_append`, `tk_audit_stem_record_hash`). The C shim only exposes two public symbols (`tk_get_audit_run_tile`, `tk_audit_scratch_footprint`), both already wrapped in `src/tickoni/c_abi/audit.zig` with Zig-typed `pub fn` wrappers. Consumers access them via `@import("audit").getAuditRunTile` / `@import("audit").auditScratchFootprint`. The recommendation path (`codec/audit/interop.zig`) does not match the project convention — `c_abi/` is the correct location for C interop, and `codec/` is reserved for serialization.

### 3. Analysability

**Finding A1 — PASS: All audit event types use a tagged union (`AuditEvent`).**

`src/tickoni/schema/audit/audit.zig` defines `AuditEvent` as a tagged union with explicit variants (`source_event`, `normalization`, `deduplication`, `case_creation`, `policy_decision`, `model_call`, `financial_adapter_call`, `proposal`, `limit_check`, `denial`, `approval_required`, `replay_result`). Each variant is self-describing. A developer can trace any event type to its schema definition in one file.

**Finding A2 — PASS: Hash chaining is explicit and traceable.**

`audit_trace.zig` builds events in strict sequence, updating `prev_hash` after each event (lines 133, 142, 150, 160, 174, 189, 199, 209, 218, 228, 242, 251, 260, 269, 278). The chain integrity is visible in the code flow.

**Finding A3 — MEDIUM: `audit_trace.zig` is a large fixture file (528 lines).**

`audit_trace.zig` contains three build functions (`buildAllowedTradeChain`, `buildOversizedTradeBlockedChain`, `buildRestrictedInstrumentBlockedChain`) each building 7-15 events. The `buildAllowedTradeChain` function alone is 182 lines and handles thesis→normalization→dedup→case→policy→model→adapter→proposal→paper_fill→policy→proposal→approval→proposal→replay.

**Affected path:** `test/fixtures/investment/audit_trace.zig`

**Recommendation:** Split into three smaller files (`allowed_trade_trace.zig`, `blocked_limits_trace.zig`, `blocked_restricted_trace.zig`) or extract the shared `header()` function to a common fixture module.

### 4. Modifiability

**Finding MD2 — PASS: `audit_schema_version` is a single constant.**

`audit.audit_schema_version` is defined once in `schema/audit/audit.zig` and referenced everywhere. Schema version bumping touches one location.

**Finding MD3 — RESOLVED: `parseFixedAsciiBytes` and `header()` moved to `test/fixtures/shared.zig`.**

`parseFixedAsciiBytes(N: usize, value: []const u8) [N]u8` was extracted from `audit_trace.zig` into `src/tickoni/test/fixtures/shared.zig` (49 lines). `header()` was moved alongside it since it is the only caller and tightly coupled. All 34 call sites in `audit_trace.zig` now reference `fixtures_shared.parseFixedAsciiBytes` / `fixtures_shared.header`. Audit_trace.zig went from 528 to 496 lines (net −32). Build clean.

**Remediation applied:** `src/tickoni/test/fixtures/shared.zig` created; `src/tickoni/test/fixtures/investment/audit_trace.zig` updated to import and use `fixtures_shared.` prefix.

## Additional Maintainability Reviews

### Cohesion and Coupling

**Finding C1 — PASS: High functional cohesion in audit modules.**

- `audit_consts.zig`: single responsibility (seed, schema version)
- `hash.zig`: single responsibility (Wyhash computation)
- `audit_sink.zig`: single responsibility (AuditLog builder)
- `replay.zig`: single responsibility (replay capsule management)
- `audit_stage.zig`: single responsibility (audit stage lifecycle)

**Finding C2 — PASS: Fixture tile IDs are wired, not hardcoded.**

`audit_trace.zig` imports tile IDs from the canonical source: `const tile_ids = runtime.tile_ids;` and references them via `tile_ids.<name>.slice()` throughout. The fixture does **not** hardcode tile name strings — it depends on the single source of truth in `runtime/tile_ids.zig`.

If a tile ID is renamed or removed, the fixture fails at **compile time** (not silent drift), forcing the fixture to be updated alongside the tile rename. This is the correct behavior: fixtures document expected values and serve as living documentation of the tile topology. The "tight coupling" concern is by design — coupling to `runtime.tile_ids` ensures fixtures always reflect the actual tile registry.

**Affected path:** `src/tickoni/test/fixtures/investment/audit_trace.zig` → `src/tickoni/runtime/tile_ids.zig`

**Finding C3 — RESOLVED: `AuditState` extracted from `PaymentPipelineState`.**

`audit_state.zig` owns a slim 10-field struct (`stop`, `audit_done`, `crashed_tile`, `audited`, `max_latency_hops`, `audit`, `replay_divergences`, `replay_match`, `replay_checked`, `external_effects_disabled`). `runAudit(*AuditState, *std.atomic.Value(bool), *MessageQueue)` and `runReplay(*AuditState, PaymentPipelineConfig)` depend only on `AuditState`, not `PaymentPipelineState`. Payment-specific metric counters (`produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`, `sandbox_failures`, `diag_snapshots`) remain on `PaymentPipelineState` for pipeline tiles that need them. The audit pipeline no longer depends on payment-specific state.

**Affected path:** `src/tickoni/tiles/payment_pipeline/runtime.zig` → `src/tickoni/tiles/payment_pipeline/audit_state.zig`

**Remediation applied:** Created `audit_state.zig`; embedded `AuditState` in `PaymentPipelineState`; updated `runAudit` and `runReplay` signatures; migrated all pipeline tiles (`ingest`, `normalize`, `dedupe`, `policy`, `diag`) to `state.audit.stop` for queue operations. 11 files changed. All tests pass.

### Separation of Concerns

**Finding S1 — PASS: Clear separation between schema, codec, shim, and pipeline.**

- `schema/audit/` — data definitions (structs, enums)
- `codec/audit/` — serialization/deserialization (hash, binary)
- `c_abi/shim/` — C interop layer
- `tiles/payment_pipeline/` — runtime pipeline logic

No layer violates its boundary. Schema modules don't import codec. Codec doesn't import pipeline. Pipeline imports schema and codec.

**Finding S2 — PASS: Agents are not in the audit critical path.**

Audit events are recorded by the pipeline (`audit_sink.zig`) before any agent execution. This follows the invariant: "AI is not in the deterministic financial event critical path."

**Finding S3 — RESOLVED: `VersionInfo` reads schema version via build option, not `audit_schema` import.**

`version.zig:79` no longer imports `audit_schema`. The build system (`build-lib/mod/modules.zig:187-191`) injects `AUDIT_SCHEMA_VERSION` via `build_opts`, matching the `BUILD_VERSION` pattern. `version.zig` accesses it as `build_opts.AUDIT_SCHEMA_VERSION` (lines 87–88). The `audit_schema` import was removed from the version module's import list (`modules.zig:197-200`). Single source of truth remains `audit_schema.h:19` (`#define AUDIT_SCHEMA_VERSION 2`).

**Affected path:** `version.zig:78-88` → `build-lib/mod/modules.zig:187-200`

**Remediation applied:** Removed `@import("audit_schema")` from `version.zig`; added `AUDIT_SCHEMA_VERSION` to `version_opts` in `modules.zig`; version module imports now only `tier` and `build_options` — no audit dependency.

### Empty `catch {}` Blocks

**Finding E1 — RESOLVED: 4 instances of `std.Thread.yield() catch {};` in pipeline code.**

| File | Line | Context | Justification | Status |
|------|------|---------|---------------|--------|
| `tiles/payment_pipeline/diag.zig` | 23 | Diag polling loop yield | ACCEPTABLE — `std.Thread.yield()` on failure is a best-effort backoff. Thread yield returning an error is extremely rare (OS scheduling failure) and retrying or aborting would not improve behavior. | Resolved — justification comment added |
| `tiles/payment_pipeline/queue.zig` | 44 | Queue poll push | ACCEPTABLE — Same reasoning as diag.zig. | Resolved — justification comment added |
| `tiles/payment_pipeline/queue.zig` | 62 | Queue poll pop | ACCEPTABLE — Same reasoning as above. | Resolved — justification comment added |
| `tiles/payment_pipeline/replay.zig` | 31 | Replay polling yield | ACCEPTABLE — Same reasoning as above. | Resolved — justification comment added |

**Remediation applied:** Added justification comment above each `catch {};` block explaining that `std.Thread.yield()` error is an OS scheduling failure where retrying or aborting provides no benefit — the loop naturally slows and recovers. Logging the error was considered but rejected: a transient scheduling failure would spam logs with recoverable noise.

```zig

```

**Finding E2 — PASS: No `catch {}` in codec, schema, or C shim files.**

The critical audit logic (hash computation, binary parsing, C interop) has no silent error handling. Errors propagate up.

**Finding E3 — PASS: Test file `catch {}` blocks are in test teardown.**

`test_investment_replay.zig:335` (`defer w.interface.flush() catch {};`) and `test_tkaudt_integration.zig:207,232` (`stopProcess catch {};`) are in defer blocks — test cleanup. Silently failing cleanup in a test is correct because: (1) test results are already captured, (2) the test process exits immediately, (3) no production state is at risk.
