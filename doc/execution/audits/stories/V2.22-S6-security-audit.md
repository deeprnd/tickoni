## What's on this branch

The branch is a **clean separation of concerns** between two distinct workstreams:

1. **Windows build infra / CI** — ~90% of the diff: CI workflows, shell scripts, justfile additions, CMake patches for llama.cpp on Windows. All changes are in `.github/`, `contrib/`, `justfile`, and `config/`.
2. **Fixture-backed system test** — 2 Zig files: `src/tickoni/test/demo/investment/mod.zig` and `src/tickoni/test/system/test_investment_demo_live.zig`. This is the runtime test change.

## Source code (Zig/C) — Clean

**No OS branches exposed in source code.** Zero `_WIN32`, `WIN32`, `windows`, or `std.os.windows` references in any `.zig`, `.c`, or `.h` file changed on this branch. The only OS-specific code in `src/` that uses OS checks is in Firedancer infrastructure files (e.g., `fd_bundle_windows_stub.c`, `fd_topo_platform.h`) which are the designated shim/stub layer. `supervisor.zig` still uses `@import("builtin").os.tag == .linux` for CPU affinity — but this is **pre-existing on main**, not introduced by this branch.

The test change is clean: `use_fixture` is a test-only struct field, not a compile-time constant. The runtime decision at test time is `if (live_config.use_fixture) runFixtureModel(...) else runLiveModel(...)`. No OS awareness. This is correct.

## Architectural coherence

**Fixture-backed system tests are aligned with the roadmap.** The roadmap was updated (v2.22.md, v2.22-s6.md) to explicitly defer live LLM tests to V2.10, and this branch implements that deferral by defaulting to fixtures. The `TK_LIVE_TEST=1` env var gives manual override — appropriate for CI debugging, not a production escape hatch.

**Demo conformance cross-platform comparison is coherent.** The CI now runs demo conformance on Windows x86 and ARM, exports bundles, and compares JSON against Linux/macOS. This is the right abstraction: deterministic outputs, OS-agnostic comparison.

**E2E deferral documented in roadmap stories.** v2.22-s6.md adds T15 documenting the deferral. Consistent with v2.22.md changes.

## Test substance

**The system test (`test_investment_demo_live.zig`) is substantive.** It runs the full investment demo scenario suite:

- Allowed trade (USD 2,000 ETF)
- Blocked trade (USD 25,000 oversized)
- Restricted instrument
- Policy enforcement
- Replay match verification
- Decision payload capture

With `use_fixture=true` (the default), it exercises `runFixtureModel` which provides deterministic output. Without the fixture, it hits a live llama.cpp server — controlled by `TK_LIVE_TEST=1`. This is a proper split between CI-passing deterministic tests and manual live validation.

**Demo conformance bundles provide cross-platform test coverage.** Each platform (Linux, macOS, Windows x86/ARM) exports a `conformance.json`, and the CI pipeline compares them. This is the right level of test for this scope.

> **FINDING 1 (Operational):** `quality.yml` and `security.yml` are now cron-scheduled (weekly Monday 09:00 UTC) instead of PR-gated. This means PRs can merge without quality/security checks passing. This needs a separate justification or follow-up if PR gating is expected to remain.

**Coverage workflow is new.** Adds a weekly coverage lane. Reasonable addition.

**tests-short.yml has been restructured.** The Windows lane was already partially working; this branch makes it production-grade with proper CI detection, build profiles, conformance exports, and cross-platform comparison. The restructuring is coherent.

**New Windows system test scripts are substantial.** `ensure_llama_cpp_win.sh` (521 lines), `run_llm_server_win.sh` (113 lines), `run_system_model_tests_win.sh` (100 lines). These mirror Linux/macOS infrastructure test flows. The shell scripts are well-structured with proper error handling, cleanup traps, and platform-specific logic (MSVC detection, SDK path resolution, CRT redist staging).

## Findings

### FINDING 1 (Operational — medium)

`quality.yml` and `security.yml` moved from PR-gated to cron-only. PRs no longer get quality/security gates. If the intent is to gate PRs only with `tests-short.yml`, quality/security should remain PR-triggered or have a PR lane added to the scheduled runs.

### FINDING 2 (Pre-existing, not introduced)

`supervisor.zig:411` has `@import("builtin").os.tag == .linux` for CPU affinity. This is pre-existing on main. If Windows process-mode CPU pinning is needed, that's a V2.22 follow-up task, not a blocker for this branch.

### FINDING 3 (Minor — cosmetic)

The `ZIG_TARGET_OVERRIDE` change from `aarch64-windows-gnu` to `aarch64-windows` in both `action.yml` and `zigw.sh` is correct (Zig 0.16 uses `aarch64-windows` as the GNU-ABI Windows target name; `-gnu` was incorrect). This aligns with the comment cleanup. No issue here, just confirming the fix is correct.

### FINDING 4 (Minor — edge case)

`run_system_model_tests_win.sh` uses `ZIG_GLOBAL_CACHE_DIR=.zig-global-cache` which is a relative path. On Windows, if the CWD changes between justfile steps (e.g., via `workdir` in future justfile updates), this could break. The `mkdir -p build` additions in justfile show the authors are aware of CWD fragility, so this is low-risk.

### FINDING 5 (Not a bug)

The large deletion of Firedancer contrib files (`agave-cluster`, `bundle-test-server`, `ledger-gen`, `containers`, `offline-replay`) and book content — these are pre-existing cleanup unrelated to this branch's scope, likely co-merged. They reduce surface area, which is positive.

## Verdict: Ship-ready (with caveat)

The source code changes are minimal, clean, and free of OS branches. The test coverage is substantial and deterministic by default. The CI changes are well-structured and mirror existing Linux/macOS patterns.

**One blocking consideration:** Finding 1 (quality/security no longer PR-gated) needs a decision. If this is intentional, document it. If oversight, revert those two workflow triggers before merging.

**No code smell in the new code.** The shell scripts follow proper patterns (set -euo pipefail, trap cleanup, explicit error messages, platform diagnostics). The Zig changes are minimal and use the existing `LiveConfig` pattern correctly. No drive-by refactors. No hidden OS switches. No drive-by refactors. No hidden OS switches.
