# V2.10.S11 — Telemetry and Observability Audit

## Scope

Audit story V2.10.S11 ("Reduce Test Memory Footprint") against:

- `doc/execution/telemetry.md` — metric/diagnostic field definitions, label policy, alerting policy, generated metrics
- `doc/execution/observability.md` — per-tile visibility, smoke checks, failure visibility

## Story Summary

V2.10.S11 has three sub-tasks:

1. **Fix 5 failing Firedancer unit tests** — Add `--page-cnt` overrides in `run_unit_tests.sh` so tests that default to `--page-sz gigantic --page-cnt 1` work correctly with the runner's `--page-sz normal` flag.
2. **Remove CI memory freeing** — Strip `prlimit --memlock=unlimited` and `echo 3 > /proc/sys/vm/drop_caches` from `.github/workflows/tests-long.yml`.
3. **Consolidate llama.cpp to CPU-only** — Replace build-from-source strategy with pre-built binary download (`llama_cpp_download`), strip GPU code paths, reduce model size from ~16 GB to ~1 GB.

## Audit Results

### 1. New metrics using low-cardinality labels only — PASS

No new metrics were introduced by this story. The changes are entirely in build/test infrastructure (unit test runner, CI workflows, llama.cpp setup, install strategies). Zero changes to `supervisor.zig`, `payment_pipeline.zig`, or any metrics code that would produce new metric labels.

### 2. New diagnostic signals follow Phase 0 snapshot pattern — PASS

No new diagnostic signals were added. `snapshotDiag()` and `snapshotMetrics()` are untouched. The story's test fixes (`--page-cnt` overrides in `run_unit_tests_dynamic.sh` and `test_wksp.c`) change how tests request memory — they do not introduce diagnostic output.

### 3. Failure visibility preserved — PASS

This is actually an improvement:

- **Before:** `prlimit --memlock=unlimited` hid real memory budget failures from the test runner. `echo 3 > /proc/sys/vm/drop_caches` with `|| true` masked failures silently.
- **After:** Tests that OOM will produce real, visible ENOMEM errors. The `--page-cnt` overrides ensure tests get the memory they actually need without the CI hacks masking misconfigurations.
- **Crash-only model:** The Firedancer crash-only teardown behavior, `snapshotDiag()` crash reporting, and sandbox failure recording are all in `supervisor.zig` and `payment_pipeline.zig` — untouched.
- **Smoke checks:** `just test-unit-fd` and `zig build run -- start` remain the canonical verification commands. No changes to these.

### 4. Label policy compliance — PASS

No new metrics, no new labels. No high-cardinality identifiers introduced.

### 5. Alerting policy — PASS

No new alert rules added (consistent with telemetry.md's note that "No Tickoni alert rules are committed yet"). No changes to existing alert-relevant signals.

### 6. Generated metrics — PASS

No changes to `src/disco/metrics/metrics.xml` or generated outputs. `make -C src/disco/metrics metrics` was not run and was not needed.

### 7. Per-tile visibility — PASS

No new tiles or agents were added. No changes to per-tile signal exposure. The llama.cpp consolidation affects build-time tooling only, not runtime tile observability.

### 8. Retail runtime privacy defaults — PASS

The story does not add any outbound telemetry, hosted analytics, or background exporters. The pre-built llama.cpp download strategy uses curl to GitHub releases (no telemetry endpoint). The model swap (Gemma 4 → Qwen2.5-1.5B) has no telemetry implications.

## Evidence

- **Telemetry substrate untouched:** `supervisor.zig`, `payment_pipeline.zig`, `main.zig`, and `src/disco/metrics/` are absent from the diff.
- **Test runner changes:** `run_unit_tests_dynamic.sh` adds `--page-cnt` override logic for memory budget fixes. This is test harness code, not runtime telemetry.
- **CI cleanup:** Removal of `prlimit` and `drop_caches` improves failure visibility (real errors surface instead of being masked).
- **Llama.cpp consolidation:** Build-time tooling changes only. No runtime telemetry impact.

## Conclusion

**PASS.** V2.10.S11 has zero impact on Tickoni telemetry or observability. The story touches build/test infrastructure, CI workflows, and llama.cpp setup — none of which interact with the telemetry substrate (`supervisor.zig`, `payment_pipeline.zig`, Firedancer metrics). The CI cleanup (removing `prlimit` and `drop_caches`) actually improves failure visibility by stopping the masking of real test failures.

No telemetry or observability policy violations.
