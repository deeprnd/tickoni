### 1.2 Full build error messages — ACTIONABLE ✓

This shows the full dependency graph of the failure — the developer can trace that the install step failed because compile failed because the link step couldn't find `libfd_util`.

### 2.4 Structured logger (`src/tickoni/logger.zig`) — DESIGN SOUND ✓

The logger uses a timestamp + severity + module + function + message format:

```
{ts} {LEVEL} [{module}] {func}: {message}
```

Key design properties:
- **Compile-time disabled by default** (level = `err`): zero overhead for production builds that don't need debug tracing
- **`--verbose` flag** at runtime enables DEBUG level — no rebuild needed
- **Panic and err levels always enabled** for critical failure tracing
- **Monotonic nanosecond timestamps** via OS shim — deterministic ordering
- **Single-threaded, lock-free**: safe for tile context without mutex contention
- **stderr output only**: never pollutes stdout/stdin pipes, always visible to terminal

### 2.5 Metric and diagnostic polling (`tkmetr` / `tkdiag`) — CLEAN ✓

`src/tickoni/tiles/payment_pipeline/metric.zig` and `diag.zig` implement bounded polling loops that:
- Terminate cleanly when `replay_checked` is set or `stop` is signaled
- Yield the thread between polls (`std.Thread.yield()`) to avoid busy-waiting
- Print debug-level messages only when `--verbose` is enabled
- Take a final snapshot after the loop exits

No spurious output, no unbounded growth, no resource leaks.

### 3.1 No new Zig 0.17 compile-time errors introduced ✓

### 3.2 Previous migration errors were clear and actionable ✓

The Zig 0.17 migration previously encountered two types of errors:

1. **`EnvInfo`/`getEnvVarOwned` removal** (commit `37a119644`): The Zig compiler gave a clear "no field named 'get' in struct 'EnvInfo'" error at `mod.zig:190`, making it immediately obvious what needed to change.

2. **`writeAll` API break** (commit `c39b3e066`): The compiler gave "no member named 'writeAll' in 'std.Io.File'" at `fixture_events.zig:407`. Clear and actionable.

Both were fixed by applying the same patterns used elsewhere in the codebase (the `std.Io.File.Writer.init()` pattern from `test_investment_demo_live.zig`).

### 3.3 Compile-time validation errors remain descriptive ✓

The codebase uses `@compileError` extensively for compile-time validation (schema constraints, buffer sizing, type consistency). These produce clear Zig compiler error messages with file:line context:

```

src/tickoni/codec/audit/wire.zig:420: error: schema.AuditEvent.Payload and wire.Payload have a different number of record-type variants
```

These are **actionable**: they tell the developer exactly which constraint was violated and where.

### 3.4 Runtime diagnostic prints remain useful ✓

A few `std.debug.print` statements remain in the codebase (not production-critical, mainly for debugging):

## 7. Findings

### 7.1 No issues found

The Zig 0.17 migration did not affect diagnostic output, build log format, or error message quality in any negative way. All output formats are consistent with pre-migration behavior, and all Zig compiler error messages are clear and actionable. ✅ DONE — all 3 minor observations addressed in code and committed.

### 7.2 Minor observations (non-blocking)

1. **`std.debug.print` in topo_build.zig** — prints allocation size and pointer for every topology build. Useful during development but could be gated behind a build-time option if this output becomes noisy in CI. Not a blocker. ✅ DONE — gated behind `pub const topo_build_debug: bool = false`; enableable via `-Dtopo_build_debug` build option.

2. **`std.debug.print` in tile_process.zig** — prints connection failure messages at runtime. These are appropriate for a diagnostic tool but would benefit from going through the structured logger (`logger.zig`) for consistency. Not a blocker. ✅ DONE — replaced all `std.debug.print` error paths with structured logger (`logger.get().err(...)`) in `tk_tile_privileged_init`, `tk_tile_run` callbacks, and `run()` setup failures.

3. **No `--verbose` flag in process-mode** — `cmdStartProcess` doesn't currently pass `--verbose` to child tiles. If debug-level tile logging is needed for process-mode troubleshooting, this would need to be wired up. Not a blocker for T9. ✅ DONE — added `verbose` field to `ProcessPipelineConfig`, wired `--verbose` from parent CLI into child tile argv.
