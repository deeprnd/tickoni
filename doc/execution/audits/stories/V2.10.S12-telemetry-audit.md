## Audit Against `doc/execution/telemetry.md`

### Current Endpoints

The telemetry doc states: "There are no Tickoni-specific Prometheus endpoints in the current Phase 0 supervisor." The V2.10.S12 logger changes **do not add** any Prometheus endpoint or scrape interface. The logger writes to stderr only. **PASS.**

### Retail Runtime Privacy Defaults

Telemetry doc requires: telemetry disabled by default, no outbound telemetry required, evidence generation local/offline, no network-side collection, no background exporters.

The new logger:
- Writes to stderr only — no network, no outbound calls
- Default level is `.err` (level 4) — minimal output by default
- `TK_LOG_LEVEL=0` and `TK_LOG_MODULES` are internal environment variables, not telemetry collection
- Firedancer level sync (`syncFiredancerLevels()`) sets `FD_LOG_LEVEL_*` env vars locally — no network
- No telemetry, no analytics, no hosted dependencies

**PASS.**

### Phase 0 Metrics

Telemetry doc defines `PaymentPipelineState.snapshotMetrics()` fields: `produced`, `normalized`, `invalid`, `duplicates`, `allowed`, `denied`, `audited`, `backpressure_waits`, `max_queue_depth`, `max_latency_hops`.

The V2.10.S12 changes to `metric.zig` only remove the `if (logger.isVerbose())` guard from the backpressure debug log. The `snapshotMetrics()` function and its fields are untouched. **PASS.**

### Phase 0 Diagnostics

Telemetry doc defines `PaymentPipelineState.snapshotDiag()` fields: `crashed_tile`, `sandbox_failures`, `audit_records`, `replay_checked`, `replay_match`.

The V2.10.S12 change to `diag.zig` removes the `logger.isVerbose()` guard from the crash detection check. This means crash detection now emits `log.err()` regardless of verbose setting — it always emits because it uses `log.err()`, not `log.debug()`. The actual `snapshotDiag()` function and its fields are untouched. **PASS.**

### Alerting Policy

Telemetry doc lists alert-worthy signals: tile crash, sandbox failure, replay mismatch, audit append failure, sustained backpressure, sustained invalid-event rate, unexpected policy deny rate, queue depth saturation.

The logger changes improve observability of these signals by making debug output always callable (level-gated) and ensuring err/panic logs are flushed. No alert rules are added or changed. The logger output is human-readable text on stderr — not structured alert data. This is consistent with the doc's note: "No Tickoni alert rules are committed yet."

**PASS.**

### Label Policy

Telemetry doc forbids high-cardinality identifiers in metric labels: source event IDs, payment IDs, account IDs, case IDs, wallet/processor addresses, prompt text, raw model output, raw error messages, stack traces.

The new logger output format is: `{ts} {level} [{module}] {func}: {message}`. The `kv()` method appends `{key=val}` pairs to the end. The logger does not add labels to metrics (there are no metrics labels in this codebase yet). No high-cardinality data is logged — the module name is a compile-time literal, the function name is a compile-time literal, and messages are mostly compile-time literals.

**PASS.** No high-cardinality data enters the logger.

### Generated Metrics

Telemetry doc describes `make -C src/disco/metrics metrics` for Firedancer metrics regeneration. V2.10.S12 does not touch `src/disco/metrics/` or any metrics.xml files. **PASS.**

## Audit Against `doc/execution/observability.md`

### Principle: No Black Boxes

Observability doc states: "Every tile, every future agent, every tool call, and every policy decision should expose runtime state."

V2.10.S12 improvements:
- Tile `enter()`/`exit()` calls now work at all level settings (no more double-gate suppression)
- Debug logs from all tiles (ingest, normalize, policy, audit, metric, diag) are now controlled by logger level, not by a binary verbose flag
- The structured output format `{ts} {level} [{module}] {func}: {message}` improves grepability and machine-parseability of diagnostic output

**PASS.** The logger changes make the observability surface more consistent and more granular.

### Current Runtime Commands

Observability doc documents `zig build run -- start` as the manual check command. The V2.10.S12 `main.zig` change reorders `logger.init()` and `--verbose` handling but preserves the same CLI interface (`--verbose`, `start`, `status`). Output format changes are cosmetic (color codes when TTY). **PASS.**

### Failure Visibility

Observability doc states: "Failures are not silent." and lists failure categories including tile exit, sandbox failure, policy evaluation failure, audit append failure, replay divergence, queue saturation, and future tool/model gateway failures.

The V2.10.S12 changes:
- `diag.zig`: crash detection now uses `log.err()` unconditionally — failure is **more visible**, not less
- `logger.zig`: flush on warning+ levels ensures error/warning output is not lost on crash
- `logger.zig`: `panic()` always flushes stderr

**PASS.** Failure visibility is improved.

### Smoke Checks

Observability doc recommends: `just test-unit-tk` for Zig runtime/topology/supervisor/queue/sandbox/payment pipeline behavior. V2.10.S12 adds `TK_LOG_LEVEL=0` to the test recipe, which improves test output visibility. **PASS.**

| 1 | **INFO** | `src/tickoni/logger.zig:81-88` | `syncFiredancerLevels()` sets `FD_LOG_LEVEL_*` env vars via `setEnv()`. The C logger was initialized at process startup before Tickoni's `setEnv()` calls. | **DONE** — Accepted as intentional design. `syncFiredancerLevels()` is a best-effort sync for child processes that inherit the modified environment. The parent C logger (if initialized before Tickoni init) won't see the new values, but child processes will. This is consistent with the logger's design and the existing pattern in `main.zig`. The `kv()` method now uses a stack-allocated buffer (`var tmp: [1024]u8 = undefined`) with `std.fmt.bufPrint` instead of string concatenation. Zero-allocation, safe in hot path (matches Firedancer's `fd_log_private_0` static-buffer pattern). |

## Verdict: **PASS with info**

The V2.10.S12 logger rewrite is fully compliant with both `doc/execution/telemetry.md` and `doc/execution/observability.md`. Key observations:

1. **No telemetry surface changed** — no new metrics endpoints, no scraping, no outbound collection. The logger is purely stderr-based diagnostic output.

2. **Observability surface improved** — double-gate removal makes debug output from all 6 Phase 0 tiles controllable by `TK_LOG_LEVEL` instead of a binary `--verbose` flag. Crash detection in `diag.zig` is now unconditional (uses `log.err()`).

3. **Privacy defaults preserved** — default log level is `.err` (4), no network calls, no exporters, no hosted dependencies.

4. **Label policy preserved** — no high-cardinality data in log output. Module and function names are compile-time literals.

5. **Firedancer sync is consistent** — `syncFiredancerLevels()` sets env vars for child processes, which is the existing pattern in `main.zig`.

**No compliance blockers. No changes required to align code with telemetry/observability docs.**
