# V2.21.S4: macOS retail runtime support

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.21: Cross-Platform Retail Runtime Support
**Labels:** `story`, `platform`, `enhancement`

Select the first macOS support path and define the macOS-specific build,
install, and runtime scope so consumer Mac users can run deterministic paper
demos without needing Linux.

## Product Outcome

A Mac user can build or install Tickoni, run preflight, execute a deterministic
paper demo, and see platform-tier evidence on a normal MacBook or Mac desktop.

## User Story

As a consumer-money user on macOS, I want to install Tickoni without sudo, run
a demo, and see my platform tier and isolation limits, so that I can inspect
policy-gated proposals on my own hardware.

## Scope

- In scope: macOS path decision (native, container/Colima, VM, or hybrid),
  macOS-specific Firedancer adaptation plan from S2, macOS build prerequisites,
  installer/uninstaller design for macOS, macOS preflight checks.
- Out of scope: Windows path (S5), Linux implementation (no change), demo
  execution (S6), trust closure (S7).

## Preconditions And Assumptions

- S1 defines tier language (macOS retail runtime tier).
- S2 defines the build-scope filter and Firedancer reuse inventory.
- Consumer macOS must not require sudo or elevated privileges.
- S3 defines version/doctor/manifest preflight that macOS must implement.

## Acceptance Criteria

- [ ] Given a supported macOS version, when the user builds or installs Tickoni,
      then the install is user-scoped by default and does not request admin
      credentials.
- [ ] Given a macOS host, when `tickoni doctor` runs, then it identifies the
      macOS support path (native, container/Colima, VM), reports tier status,
      and lists any missing prerequisites.
- [ ] Given a macOS retail build, when the build system runs, then only the
      Firedancer modules included in S2's reuse inventory are compiled.
- [ ] Given the macOS installer, when a user verifies it, then checksums,
      signatures, or attestations are available for manual verification.
      (Deferred to V2.23 — no installer shipped in this epic; runtime only.)
