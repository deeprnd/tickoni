# V2.10.S3: Qt Hello-World Build Validation

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.10: Build System Consolidation And Qt Build Validation
**Labels:** `type/story`, `area/platform`

Create the smallest possible Qt 6 CMake build that compiles and launches a
hello-world window, so we confirm the Qt build path works before investing in
QML pages, API clients, or styling.

## Product Outcome

A single Qt 6 CMake build produces a binary that opens a window saying
"tickoni" and exits cleanly. The build is invoked via `just build-qt` on
Linux x86.

## User Story

As a developer, I want to run `just build-qt` and get a compiled Qt binary
that opens a hello-world window, so that I can verify the Qt build path works
before V3.19 invests effort in QML pages, API clients, and terminal styling.

## Scope

- In scope: create `src/tickoni/terminal/CMakeLists.txt` that finds Qt 6
  components (Quick) and compiles the project.
- In scope: create `src/tickoni/terminal/app/main.cpp` — a minimal Qt
  application that creates a `QQuickWindow` or `QQmlApplicationEngine`, loads
  a single `Main.qml`, and returns from `main()`.
- In scope: create `src/tickoni/terminal/qml/Tickoni/Main.qml` — a plain QML
  file with a single Text element showing "tickoni" centred on a white or
  grey background. No style, no palette, no colours beyond basic contrast.
- In scope: add `just build-qt` recipe that invokes CMake to build the Qt
  terminal.
- In scope: confirm the binary launches on Linux x86 (shows a window, no
  crash).
- In scope: add `just build-qt` entry to the justfile alongside existing
  `build-tk` / `test-unit-tk` etc.
- Out of scope: full QML page implementation (V3.19 story).
- Out of scope: real tkapi HTTP/WebSocket client (V3.19 story).
- Out of scope: actual investment flow logic (V3.19 story).
- Out of scope: application controller, API types, or command registry.
- Out of scope: color schemes, styles, palettes, or visual identity.
- Out of scope: macOS and Windows Qt build validation (deferred to V3.19).
- Out of scope: Qt packaging (deferred to V3.23).

## Preconditions And Assumptions

- Qt 6 is available on the developer's Linux x86 environment (or can be
  installed via `just setup-linux-x86` once S5 is done, but this story does
  not depend on S5 — the developer installs Qt manually).
- `build.zig` is not involved — Qt is a separate CMake build tree under
  `src/tickoni/terminal/`.

## Acceptance Criteria

- [ ] Given a Linux x86 environment with Qt 6 installed, when `just build-qt`
      is run, then CMake configures successfully, compiles all C++ sources,
      and links a Qt 6 binary at `build/tickoni-terminal` (or a documented
      output path).
- [ ] Given the compiled binary, when it is launched, then it opens a window
      with the text "tickoni" displayed and does not crash.
- [ ] `CMakeLists.txt` finds Qt 6 via `find_package(Qt6 COMPONENTS Quick REQUIRED)`.
- [ ] `main.cpp` creates a `QQmlApplicationEngine`, loads `Main.qml`, and
      returns from `main()`.
- [ ] `Main.qml` contains a single Text element showing "tickoni" centred on
      a plain background. No style, palette, or color constants.
- [ ] The build is documented in `justfile` as `build-qt` following existing
      `just` recipe conventions.
- [ ] No `build.zig` changes are required for the Qt build.

## Notes And Open Questions

- Should Qt be built alongside the main Tickoni build or as a separate
  `just build-qt`? Story chooses separate — `build-qt` stays focused on Qt,
  `build-all` stays focused on Tickoni runtime.
- The CMakeLists.txt lives under `src/tickoni/terminal/` to keep the root
  build.zig untouched.
- Qt 6 version minimum: use whatever is available on the dev environment;
  document the minimum version in `doc/execution/build.md` when known.
