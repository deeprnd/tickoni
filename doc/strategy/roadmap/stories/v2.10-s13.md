# V2.10.S13: Metric Tile — tkmetr Observer Tile Wrapped from Firedancer fd_metric_tile

**Labels:** `type/story`, `area/operations`, `type/feature`

**GitHub Issue:** TBD

A Tickoni-owned metric tile (`tkmetr`) that reuses Firedancer's `fd_metric_tile.c`
(Prometheus HTTP endpoint, `fd_prometheus_render_all`, stem-based polling loop)
through a thin C shim (`tk_metric_tile.c`) with a custom `tk_metric_run` polling
loop — because the metric tile has zero in/out links and Firedancer's
`stem_run` crashes when `out_cnt == 0` (dereferences `out_seq[0]`). The tile
exposes all Firedancer tile and link metrics over a Prometheus-format HTTP
endpoint on configurable address/port, shuts down cleanly via CNC HALT signal,
and integrates into the Tickoni topology with correct scratch layout, seccomp
policy, and allowed file descriptors.

## Product Outcome

Operators can inspect the runtime health of every Firedancer tile and link
through a single Prometheus endpoint served by `tkmetr`. The metrics surface
includes per-tile counters, gauges, and link-level throughput — all in
Prometheus exposition format. `tkmetr` runs as an independent observer tile
with zero pipeline links, meaning it never blocks or depends on the financial
event critical path. Shutdown is signal-driven and deterministic.

## User Story

As a developer-operator, I want `tkmetr` to expose all tile metrics over HTTP,
so that I can observe runtime health without attaching a debugger or reading
log files.

As a test author, I want `tkmetr` to start, serve `/metrics`, and shut down
cleanly via HALT signal, so that integration tests can validate the metric tile
lifecycle alongside other tiles.

As a runtime owner, I want `tkmetr` to have zero in/out links so it never
introduces backpressure, overrun, or dependency on the financial pipeline.

## Scope

- In scope:
  - `src/tickoni/c_abi/shim/tk_metric_tile.c`: C shim wrapping Firedancer's
    `fd_metric_tile.c` with custom `tk_metric_run` for the 0-I/O observer
    pattern. Reuses `fd_metric_tile.h` declarations (not the .c source) to
    avoid pulling in `stem_run`'s static helpers.
  - Custom `tk_metric_run` loop: calls `before_credit` for HTTP polling only
    (no stem input/output processing), checks CNC signal for HALT, sets
    `tile->allow_shutdown = 1`.
  - CNC join path: `tk_metric_run` scans `topo->objs[]` for the "cnc" object
    whose index matches the tile's `uses_obj_id`, joins it via `fd_cnc_join`,
    and queries `fd_cnc_signal_query` for shutdown.
  - `src/tickoni/c_abi/topo_run/tk_metric_tile.h`: header declaring
    `TK_METRIC_RUN` (`fd_topo_run_tile_t`) for dispatch.
  - `src/tickoni/c_abi/shim/topo_run.c`: dispatch to `TK_METRIC_RUN` when
    tile name matches "tkmetr".
  - `src/tickoni/c_abi/shim/tile_run.c`: `tile_run_main` dispatch for
    "tkmetr" — calls `TK_METRIC_RUN.privileged_init`, `TK_METRIC_RUN.run`,
    and handles CNC join for the metric tile's special path.
  - `src/tickoni/c_abi/topob.zig`: `topobTickoniScratchFootprint("tkmetr")`
    returns the correct footprint from `TK_METRIC_RUN.scratch_footprint`.
  - `src/tickoni/runtime/topo_build.zig`: creates scratch and CNC objects for
    "tkmetr" tile during topology construction.
  - Integration tests in `src/tickoni/test/integration/test_metric_tile_integration.zig`:
    topology build + start, HTTP /metrics endpoint, CNC HALT shutdown, CNC
    object discovery, scratch footprint consistency.

- Out of scope:
  - Modifying Firedancer's `fd_metric_tile.c` or `fd_metric_tile.h`.
  - Adding custom metric definitions beyond what Firedancer generates.
  - Changing the Firedancer metrics XML or `gen_metrics.py` generator.
  - Adding a separate Tickoni metrics aggregation or alerting layer.
  - Changes to Firedancer's `stem_run` or stem infrastructure.
  - gRPC, OpenTelemetry, or other metric export backends beyond Prometheus.

## Preconditions And Assumptions

- Firedancer's `fd_metric_tile.c` exports the following symbols as external:
  `METRICS_PARAMS`, `scratch_align`, `scratch_footprint`, `before_credit`,
  `metrics_http_request`, `populate_allowed_seccomp`, `populate_allowed_fds`.
- Firedancer's `fd_metric_tile.h` provides declarations for all exported symbols
  plus `fd_metric_ctx_t` and `fd_tile_metric`.
- `fd_metric_tile.c` uses `stem_run` internally, but `stem_run` calls
  `before_credit` on every iteration — which is all tkmetr needs.
- Firedancer's `stem_run` dereferences `out_seq[0]` even when `out_cnt == 0`,
  so tkmetr cannot use `stem_run` directly. A custom loop is required.
- The metric tile is an observer: it has zero mcache/dcache links and zero
  fseq objects. Its `.in_cnt` is 0.
- `topo_build.zig` creates a CNC object per tile via `topobTileUses`.
- The tile name used by dispatch is the null-terminated string "tkmetr"
  (6 chars + null = 7 bytes total).

## Acceptance Criteria

- [ ] Given the topology is built with `paymentPipelineProcess()`, when the
  tile list is scanned, then "tkmetr" appears as a tile with `in_cnt == 0`.
- [ ] Given the supervisor starts the pipeline with `tkmetr` present, when
  all tiles reach running state, then `tkmetr`'s monitor state is `.running`.
- [ ] Given `tkmetr` is running, when a GET request is sent to
  `http://127.0.0.1:<prometheus_listen_port>/metrics`, then the response
  status is 200 and the body contains Prometheus-format metric output
  (starts with `fd_`, `#`, or `help`).
- [ ] Given `tkmetr` is running, when a GET request is sent to any path other
  than `/metrics`, then the response status is 404.
- [ ] Given `tkmetr` is running, when `FD_CNC_SIGNAL_HALT` is sent via CNC,
  then `tkmetr` sets `tile->allow_shutdown = 1` and its monitor state
  transitions to `.stopped` (not `.crashed`).
- [ ] Given `tkmetr` receives HALT, when the monitor is checked, then
  `crashed_because` is `.none`.
- [ ] Given `TK_METRIC_RUN` is queried for scratch footprint via
  `topobTickoniScratchFootprint("tkmetr")`, when the value is compared against
  `TK_METRIC_RUN.scratch_footprint(&tile)`, then the values are equal.
- [ ] Given the metric tile's seccomp policy, when the tile starts in a sandbox,
  then `populate_allowed_seccomp` returns the correct filter count for the
  metrics HTTP socket, stderr, and logfile.
- [ ] Given the metric tile's allowed file descriptors, when `populate_allowed_fds`
  is called, then stderr, logfile (if present), and the metrics listen socket
  are included in the fd array.
- [ ] Given `tk_metric_run` cannot find a CNC object, when the tile starts,
  then it logs a warning and continues polling (does not crash).
- [ ] Given integration tests for `test_metric_tile_integration.zig` run,
  then all five tests pass: topology build, HTTP endpoint, HALT shutdown,
  CNC discovery, scratch footprint consistency.

## Notes And Open Questions

- Firedancer's `fd_metric_tile.c` promotes `before_credit`,
  `metrics_http_request`, `populate_allowed_seccomp`, and
  `populate_allowed_fds` to external linkage. The static
  `privileged_init` and `unprivileged_init` are duplicated in
  `tk_metric_tile.c` because they are not exported.
- `stem_run` is generated via `#include "../stem/fd_stem.c"` with
  `STEM_CALLBACK_BEFORE_CREDIT before_credit`. The Tickoni shim avoids
  `stem_run` entirely because `stem_run` requires at least one output link.
- CNC join path: `tk_metric_run` scans `topo->objs[]` by name ("cnc") for
  each tile's `uses_obj_id`. This is a linear scan but runs once at init.
- The HTTP endpoint port is configurable per tile via
  `tile->metric.prometheus_listen_port` in the topology. Default is 9500.
