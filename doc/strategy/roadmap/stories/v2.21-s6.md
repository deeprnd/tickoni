# V2.21.S6: Cross-platform deterministic demo and conformance suite

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.21: Cross-Platform Retail Runtime Support
**Labels:** `story`, `trust`, `enhancement`

Define the deterministic demo and conformance gates that prove retail modes
preserve Tickoni's policy, audit, replay, and no-live-effect behavior across
supported platforms.

## Product Outcome

A Mac or Windows user can run a money-decision proof that matches Linux for
deterministic fixture flows, while unsupported or privileged requests fail
closed.

## User Story

As a partner reviewer, I want cross-platform demo evidence to match for
deterministic fixtures, so that I can trust the proof even when the runtime
tier is not the full Linux high-throughput engine.

## Scope

- In scope: select the first retail demo manifest, define cross-platform
  conformance outputs, compare Linux full-runtime with macOS/Windows retail
  paths, add blocked-flow cases, require all model/tool/adapter effects to be
  mocked or fixture-backed, define focused CI matrix.
- Out of scope: tier definitions (S1), build scope (S2), preflight (S3),
  installer design (S4/S5), trust/docs closure (S7).

## Preconditions And Assumptions

- S1 defines tiers; S3 defines version/doctor/manifest schema.
- S4/S5 select macOS and Windows support paths.
- V2.14.S8.T5 documented that real sandbox entry (`tk_sandbox_enter`) requires
  `unshare(CLONE_NEWUSER)`, which failed closed with `EPERM` in session-
  sandboxed environments even though the kernel supports it. Process isolation
  (per-tile OS-process isolation via supervisor-managed child processes)
  holds with `sandbox=0` throughout. This is a product-architecture finding,
  not a workaround. The full sandbox-wiring detail is in V2.14; S6 references
  it rather than copying it verbatim.
- See V2.14.S8.T5 for the full sandbox entry analysis, including the
  `generate_filters.py` topology-independence finding.

## Acceptance Criteria

- [ ] Given a supported retail platform, when the selected demo manifest runs,
      then the demo produces deterministic conformance outputs matching the
      fixture set: normalized event hash, policy outcome, proposal hash, audit
      JSONL, replay capsule, replay result, and blocked-flow diagnostic.
- [ ] Given a comparison between Linux full-runtime and a supported macOS
      retail path, when deterministic outputs are checked, then they match for
      the scope dimensions the tier claims equivalence on.
- [ ] Given an unsupported runtime tier, missing fixture, stale demo manifest,
      attempted live execution, or tampered replay/proposal artifact, when a
      demo is invoked, then the flow fails closed with an explicit diagnostic
      and no live side effects.
- [ ] Given the demo, when model, tool, adapter, or execution effects are
      triggered, then they are mocked, fixture-backed, or replay-substituted
      — no live provider, broker, payment, trading, crypto, approved execution ledger, or
      `tkexec` calls.

### Conditional Acceptance

**Financial capability and policy**

- [ ] Given a retail demo, when `tkpoly` evaluates capability envelopes, then
      policy outcomes (allow, deny, require_approval, require_more_evidence,
      escalate) match the Linux full-runtime fixture results.

**Audit and replay**

- [ ] Given a successful demo on Linux and a supported retail path, when audit
      JSONL and replay capsules are compared, then the material fields (event
      hash, policy decision, proposal hash, approval state, replay result)
      are equivalent where the tier claims equivalence.

**Runtime topology and tile ownership**

- [ ] N/A - story validates runtime behavior, does not change tile ownership.

**Model, tool, adapter, or execution boundary**

- [ ] Given a demo, when model, tool, adapter, or execution calls occur, then
      they are substituted via `tkmodl`, `tktool`, `tkadpt`, or replay
      substitution — no direct provider or financial API access.

**CaseOps API or UI**

- [ ] N/A - demo evidence is CLI/fixture-facing; CaseOps display is in S7.

## Evidence Plan

- Demo or command: retail demo manifest on Linux, macOS, and Windows.
- Tests: conformance comparison tests, blocked-flow tests.
- Fixtures or samples: Demo manifest, fixture set, conformance output samples.
- Audit/replay evidence: Audit JSONL and replay capsule samples from each
  platform.
- Blocked-flow evidence: Blocked-flow diagnostic output from at least one
  unsupported scenario.

## Quality Gate

- [ ] Deterministic demo produces equivalent fixture outputs on Linux and each
      supported macOS/Windows path where equivalence is claimed.
- [ ] Attempted live execution, direct adapter bypass, direct model-provider
      use, missing prerequisites, and tampered artifacts fail closed.
- [ ] Replay runs without external side effects.
- [ ] Documentation and roadmap status are updated when demo or conformance
      behavior changes.
