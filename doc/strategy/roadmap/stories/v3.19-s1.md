# V3.19.S1: Terminal Shell, Navigation, And Command Bar

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V3.19: Tickoni Native Investment Terminal
**Labels:** `type/story`, `area/platform`

Deliver the terminal shell, Midnight Oni visual system, keyboard navigation,
command bar, and panel layout that all V3.19 screens share.

## Product Outcome

Operators can move through Tickoni's investment workspace with a dense,
stable, keyboard-first UI that feels like a financial terminal while centering
policy, consequence, audit, and replay. The shell provides the persistent frame
that every V3.19 function builds on.

## User Story

As a CaseOps operator, I want a compact terminal workspace with command-driven
navigation, so that I can inspect investment cases quickly without losing the
policy and proof context.

## Scope

- In scope: terminal frame (QML shell with C++ application services), status
  status strip showing TKNI label, current function, case id, policy version, data
  freshness, BUS OK, and replay status; navigation bar with five top-level
  functions — CASE, POLICY, IMPACT, PROOF, SYSTEM; command bar accepting
  `/show`, `/explain`, and `/save` commands with deterministic results;
  Midnight Oni color palette (Carbon black `#070A0E`, Midnight navy `#0B1119`,
  Steel navy `#101923`, Dark slate `#192431`, Blue-gray `#263445`, Cool white
  `#E7EDF4`, Muted steel `#8D9AAA`, Disabled gray `#566270`, Oni blue
  `#3478D4`, Active blue `#4A9EFF`, Terminal amber `#E8A83E`, Pass green
  `#47A66A`, Signal red `#E0525E`, Warning amber `#D69A32`); compact sans-serif
  for labels, monospace/tabular numbers for values; thin gray-blue dividers;
  sharp rectangles with minimal radius; keyboard focus model; loading/error/empty
  panel states; responsive panel grid; status color semantics (green=allowed/pass,
  red=denied/failed, amber=approval/evidence/stale, blue=selected/focus,
  gray=unavailable/disabled).
- Out of scope: financial policy logic, live adapter calls, execution actions,
  domain-specific panels (investment workbench, policy detail, impact view,
  proof black box, system availability), and any direct runtime mutation.

## Preconditions And Assumptions

- The terminal is a presentation and operator-control surface over `tk_api`;
  financial correctness, policy decisions, proposal identity, audit records,
  and replay results remain owned by the Tickoni runtime.
- CaseOps remains an attached UI over `tk_api`.
- UI state is presentation state only; runtime truth remains in Tickoni tiles
  and artifacts.
- The terminal uses the Midnight Oni visual identity from the epic — cold
  machine surfaces, blue Tickoni intelligence, restrained amber interaction,
  rare vermilion brand seal, strict semantic state colors.
- Motion is limited to focus transition, command completion, connection state,
  replay progress, and critical state change. No celebratory animation.

## Acceptance Criteria

- [ ] Given deterministic fixture data, when the terminal loads, then the
      status strip, navigation bar, command bar, and empty CASE/POLICY/IMPACT/
      PROOF/SYSTEM panels render without overlapping text at supported desktop
      and narrow widths.
- [ ] Given a known command such as `/show policy`, when the operator submits
      it, then focus moves to the POLICY function panel or shows a deterministic
      command result.
- [ ] Given an unknown command, when the operator submits it, then the terminal
      fails closed with a non-mutating error message and no runtime action.
- [ ] Given keyboard navigation, when the operator tabs or uses function keys
      between the five CASE, POLICY, IMPACT, PROOF, SYSTEM panels, then focus
      highlight is visible and keyboard shortcuts are documented.
- [ ] Given the Midnight Oni color palette, when the terminal renders, then the
      proportion of colors follows the discipline target: approximately 80%
      black/navy/gray surfaces, 15% white/muted text, 4% Oni blue focus, 1%
      combined amber/vermilion/semantic accents.
- [ ] Given a backend disconnect or stale payload, when the terminal detects
      it, then action state transitions to disabled or unavailable rather than
      showing stale data.

### Conditional Acceptance

**Financial capability and policy**

- [ ] N/A - shell story displays no policy decisions beyond shared status badge
      containers and the policy version shown in the status strip.

**Audit and replay**

- [ ] N/A - shell story reserves panel slots for CASE, POLICY, IMPACT, PROOF,
      SYSTEM functions but does not define audit or replay data contracts.

**Runtime topology and tile ownership**

- [ ] N/A - no tile ownership, queue, workspace, or link changes.

**Model, tool, adapter, or execution boundary**

- [ ] Unknown commands cannot call model, tool, adapter, execution, shell, or
      network paths directly.

**CaseOps API or UI**

- [ ] UI routes and commands are documented as CaseOps presentation commands,
      not financial capability names.

**Storage role: Memory, Analytics, Ledger**

- [ ] N/A - shell story does not touch storage roles.

**Metrics, diagnostics, and operations**

- [ ] N/A - shell story does not introduce metrics or diagnostic signals.

**Security and fail-closed behavior**

- [ ] Given an unknown command, when submitted, then the terminal fails closed
      with a non-mutating error — no runtime mutation, no network call, no
      credential exposure.
