# V2.10.S11: Improved Zig Logging System

**Labels:** `type/story`, `area/operations`

**GitHub Issue:** #82

A Zig-native logger in `src/tickoni/logger.zig` that supports environment variables for level and module filtering, structured key-value output, ANSI color when stdout is a TTY, flush on err/panic, and no double-gate pattern — with all tile code updated to use it and unit tests covering the new functionality.

## Product Outcome

Operators can control log visibility and diagnostic detail at runtime using `ZIG_LOG_LEVEL` and `ZIG_LOG_MODULES` environment variables instead of relying on the `--verbose` CLI flag alone. Debug logs from tile pipelines, the supervisor, and tile main entry points become visible in test output by default. Logs are structured with key-value fields for greppability and colorized for terminal readability. Crash output is flushed so no diagnostic data is lost.

## User Story

As a developer-operator, I want to control Tickoni's logging detail through environment variables and see structured, colorized debug output, so that I can diagnose runtime issues without modifying CLI flags or source code.

As a test author, I want test binaries to emit debug logs by default through `ZIG_LOG_LEVEL=debug`, so that test output captures the full diagnostic trail without requiring special setup.

As an operator, I want to filter logs to specific modules (e.g. `ZIG_LOG_MODULES=ingest,normalize`) so I can focus on the relevant pipeline stage during troubleshooting.

## Scope

- In scope:
  - Rewrite `src/tickoni/logger.zig` to support `ZIG_LOG_LEVEL` and `ZIG_LOG_MODULES` env vars.
  - Add structured key-value output format: `{ts} {level} [{module}] {func}: {message} {key1=val1 key2=val2}`.
  - Add ANSI color support detected via `isatty(2)`.
  - Add flush on err/panic via `fflush(stderr)`.
  - Remove double-gate pattern: `log.debug()` is always callable; level check is internal.
  - Add `isatty` and `fflush` to `src/tickoni/util/os_api.zig` and `src/tickoni/c_abi/shim/os.c`.
  - Update `src/app/tickoni/main.zig` to set `ZIG_LOG_LEVEL=debug` after `--verbose` detection.
  - Update `tickoni-build/test/helpers.zig` to pass `ZIG_LOG_LEVEL=debug` in test env.
  - Remove redundant `if (logger.isVerbose())` guards from payment pipeline tile code.
  - Unit tests for env var parsing, module filtering, colorize detection, and structured KV output.

- Out of scope:
  - Changing the Firedancer C logger.
  - Async logging or separate log threads.
  - Log rotation or file output.
  - Performance counters or metrics in the logger.
  - Changes to the global logger singleton pattern (`logger.get()`).
  - Support for `TK_LOG_LEVEL` / `TK_LOG_MODULES` (reserved for future, not implemented here).

## Preconditions And Assumptions

- The existing logger in `src/tickoni/logger.zig` uses `level: .err` as default and `log.debug()` is guarded by `if (logger.isVerbose())` checks at call sites.
- `ZIG_LOG_LEVEL` and `ZIG_LOG_MODULES` are the chosen env var names (not `TK_LOG_*`).
- `--verbose` CLI flag continues to work as an alias for `ZIG_LOG_LEVEL=debug`.
- `util.os_api.zig` does not currently expose `isatty` or `fflush`; these require additions to `os.c` shim.
- Tile code under `src/tickoni/tiles/payment_pipeline/` contains the redundant `isVerbose()` guards to remove.

## Acceptance Criteria

- [x] Given `ZIG_LOG_LEVEL=debug` is set, when a tile calls `log.debug(...)`, then the message is written to stderr.
- [x] Given `ZIG_LOG_LEVEL=off` is set, when any tile calls `log.debug(...)` or `log.err(...)`, then debug messages are suppressed and error messages are written.
- [x] Given `ZIG_LOG_MODULES=ingest` is set, when ingest calls `log.debug(...)` and normalize calls `log.debug(...)`, then only ingest messages are emitted.
- [x] Given `ZIG_LOG_MODULES=*` is set, when any tile calls `log.debug(...)`, then all debug messages are emitted.
- [x] Given no env vars are set and `--verbose` is not passed, when a tile calls `log.debug(...)`, then the message is suppressed (backwards-compatible default).
- [x] Given `--verbose` is passed on the CLI, when the process runs, then `ZIG_LOG_LEVEL=debug` is effectively set (including inherited by child tile processes).
- [x] Given stdout is a TTY, when log output is written, then debug messages are blue, err messages are red, and panic messages are red+bold.
- [x] Given stdout is not a TTY, when log output is written, then no ANSI color codes are present.
- [x] Given a panic or err-level log, when the process writes the message, then `fflush(stderr)` is called so the output is not lost on crash.
- [x] Given structured KV output is used (e.g. `log.kv(...)`), then key-value pairs appear at the end of the log line in `{key=val}` format.
- [x] Given no `if (logger.isVerbose())` guards remain in payment pipeline tile code, when `ZIG_LOG_LEVEL=debug` is set, then all tile debug calls emit.
- [x] Given test binaries run via `tickoni-build/test/helpers.zig`, when tests execute, then `ZIG_LOG_LEVEL=debug` is in the test environment.
- [x] Given unit tests for the logger run, then all tests pass.
