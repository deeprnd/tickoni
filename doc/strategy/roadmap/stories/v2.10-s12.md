# V2.10.S12: Improved Zig Logging System

**Labels:** `type/story`, `area/operations`

**GitHub Issue:** #82

A Zig-native logger in `src/tickoni/logger.zig` that supports environment variables for level and module filtering, structured key-value output, ANSI color when stdout is a TTY, flush on err/panic, and no double-gate pattern — with all tile code updated to use it and unit tests covering the new functionality.

## Product Outcome

Operators can control log visibility and diagnostic detail at runtime using `TK_LOG_LEVEL` and `TK_LOG_MODULES` environment variables instead of relying on the `--verbose` CLI flag alone. `TK_LOG_LEVEL` accepts numeric values 0-7 (0=DEBUG, 1=INFO, 2=NOTICE, 3=WARNING, 4=ERR, 5=CRIT, 6=ALERT, 7=EMERG) that map 1:1 to Firedancer's syslog-style log levels. It also accepts string names ("debug", "info", "notice", "warning", "err", "crit", "alert", "emerg") as convenience aliases. The level is synced to Firedancer's `FD_LOG_LEVEL_*` env vars. Debug logs from tile pipelines, the supervisor, and tile main entry points become visible in test output by default. Logs are structured with key-value fields for greppability and colorized for terminal readability. Crash output is flushed so no diagnostic data is lost.

## User Story

As a developer-operator, I want to control Tickoni's logging detail through environment variables and see structured, colorized debug output, so that I can diagnose runtime issues without modifying CLI flags or source code.

As a test author, I want test binaries to emit debug logs by default through `TK_LOG_LEVEL=0`, so that test output captures the full diagnostic trail without requiring special setup.

As an operator, I want to filter logs to specific modules (e.g. `TK_LOG_MODULES=ingest,normalize`) so I can focus on the relevant pipeline stage during troubleshooting.

I want `TK_LOG_LEVEL` to accept both numeric values (0-7) and string names ("debug", "info", etc.) as convenience aliases.

## Scope

- In scope:
  - Rewrite `src/tickoni/logger.zig` to support `TK_LOG_LEVEL` (numeric 0-7 + string aliases) and `TK_LOG_MODULES` env vars.
  - Add structured key-value output format: `{ts} {level} [{module}] {func}: {message} {key1=val1 key2=val2}`.
  - Add ANSI color support detected via `isatty(2)`.
  - Add flush on err/panic via `fflush(stderr)`, plus flush on warning+ level.
  - Remove double-gate pattern: `log.debug()` is always callable; level check is internal.
  - Add `isatty` and `fflush` to `src/tickoni/util/os_api.zig` and `src/tickoni/c_abi/shim/os.c`.
  - Update `src/app/tickoni/main.zig` to set `TK_LOG_LEVEL=0` (max verbosity) after `--verbose` detection.
  - Update `justfile` test recipes to pass `TK_LOG_LEVEL=0` in test environment.
  - Remove redundant `if (logger.isVerbose())` guards from payment pipeline tile code.
  - Add `syncFiredancerLevels()` to sync `TK_LOG_LEVEL` numeric value to Firedancer's `FD_LOG_LEVEL_*` env vars.
  - Unit tests for env var parsing (numeric + string), module filtering, colorize detection, structured KV output, level ordering, and Firedancer sync.

- Out of scope:
  - Changing the Firedancer C logger.
  - Async logging or separate log threads.
  - Log rotation or file output.
  - Performance counters or metrics in the logger.
  - Changes to the global logger singleton pattern (`logger.get()`).
  - Support for `TK_LOG_LEVEL` / `TK_LOG_MODULES` (reserved for future, not implemented here).

## Preconditions And Assumptions

- The existing logger in `src/tickoni/logger.zig` uses `level: .err` as default and `log.debug()` is guarded by `if (logger.isVerbose())` checks at call sites.
- `TK_LOG_LEVEL` and `TK_LOG_MODULES` are the env var names.
- `TK_LOG_LEVEL` accepts both numeric values (0-7) and string names ("debug", "info", etc.).
- `--verbose` CLI flag continues to work as an alias for `TK_LOG_LEVEL=0`.
- `util.os_api.zig` does not currently expose `isatty` or `fflush`; these require additions to `os.c` shim.
- Tile code under `src/tickoni/tiles/payment_pipeline/` contains the redundant `isVerbose()` guards to remove.

## Acceptance Criteria

- [x] Given `TK_LOG_LEVEL=0` is set, when a tile calls `log.debug(...)`, then the message is written to stderr.
- [x] Given `TK_LOG_LEVEL=4` is set, when any tile calls `log.debug(...)`, then debug messages are suppressed and error messages are written.
- [x] Given `TK_LOG_MODULES=ingest` is set, when ingest calls `log.debug(...)` and normalize calls `log.debug(...)`, then only ingest messages are emitted.
- [x] Given `TK_LOG_MODULES=*` is set, when any tile calls `log.debug(...)`, then all debug messages are emitted.
- [x] Given no env vars are set and `--verbose` is not passed, when a tile calls `log.debug(...)`, then the message is suppressed (backwards-compatible default, level=4=ERR).
- [x] Given `--verbose` is passed on the CLI, when the process runs, then `TK_LOG_LEVEL=0` is effectively set (including inherited by child tile processes).
- [x] Given stdout is a TTY, when log output is written, then debug messages are blue, err messages are red, and panic messages are red+bold.
- [x] Given stdout is not a TTY, when log output is written, then no ANSI color codes are present.
- [x] Given a panic or err-level log, when the process writes the message, then `fflush(stderr)` is called so the output is not lost on crash.
- [x] Given structured KV output is used (e.g. `log.kv(...)`), then key-value pairs appear at the end of the log line in `{key=val}` format.
- [x] Given no `if (logger.isVerbose())` guards remain in payment pipeline tile code, when `TK_LOG_LEVEL=0` is set, then all tile debug calls emit.
- [x] Given test binaries run via `just test-unit-tk`, when tests execute, then `TK_LOG_LEVEL=0` is in the test environment.
- [x] Given `TK_LOG_LEVEL` is set to a numeric value (e.g. `TK_LOG_LEVEL=0`), when Firedancer's `FD_LOG_LEVEL_*` env vars are queried, then they all reflect the same numeric level.
- [x] Given unit tests for the logger run, then all tests pass.
