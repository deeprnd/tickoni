# V2.21.S7: Retail runtime trust, security, docs, and evidence gate

**Status:** Done
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.21: Cross-Platform Retail Runtime Support
**Labels:** `story`, `security`, `enhancement`

Close the epic by updating docs, evidence requirements, operator-visible trust
surfaces, security defaults, and release gates for cross-platform retail
support.

## Product Outcome

The retail runtime can be promoted only when users, operators, and reviewers
can inspect platform support, degraded guarantees, audit/replay evidence, and
no-bypass behavior from product docs and runtime outputs.

## User Story

As a security reviewer, I want cross-platform support to publish explicit
evidence and non-goals, so that portability does not hide weaker controls or
ambiguous financial authority.

## Scope

- In scope: update product/developer/security docs with support matrix,
  runtime tiers, install paths, demo commands, storage locations, manual
  verification, update/uninstall behavior, unsupported features; expose platform
  tier and degraded guarantees in CLI, CaseOps, audit, replay, metrics,
  diagnostics; document paper/sandbox default and no-live-effect for Mac/Win;
  document privacy/telemetry defaults; link evidence artifacts.
- Out of scope: tier definitions (S1), build scope (S2), preflight (S3),
  macOS implementation (S4), Windows implementation (S5), demo execution
  (S6).

## Preconditions And Assumptions

- S1 defines tiers; S3 defines preflight; S4/S5 define platform paths;
  S6 defines demo/conformance.
- S7 is the closure story — it does not introduce new behavior but
  documents and gates everything that came before.

## Acceptance Criteria

- [x] Given a retail runtime promotion, when reviewers inspect docs, then they
      find the support matrix, runtime tiers, install paths, demo commands,
      storage locations, manual verification, update/uninstall behavior, and
      unsupported features for each supported OS.
- [x] Given the CLI, audit, replay, metrics, or diagnostics, when platform tier
      is active, then tier and degraded-guarantee information is visible where
      it affects trust, and the deferred CaseOps UI surface is stated
      explicitly instead of being implied.
- [x] Given consumer Mac/Windows modes, when docs describe execution defaults,
      then they state that paper, fixture, mock, or sandbox-substitute behavior
      is default and live execution is disabled.
- [x] Given consumer Mac/Windows modes, when docs describe privacy defaults,
      then they state that installer telemetry is disabled unless a later
      explicit privacy decision approves opt-in diagnostics.
- [x] Given a retail demo completion, when evidence is linked from this epic,
      then support matrix, version samples, doctor samples, installer
      verification samples, demo output, audit JSONL, replay capsule,
      blocked-flow output, and conformance result are all linked.
