# V2.22.S7: Retail runtime trust, security, docs, and evidence gate

**Status:** Done
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.22: Windows Retail Runtime Support
**Labels:** `story`, `security`, `enhancement`

Close the epic by updating docs, evidence requirements, operator-visible trust
surfaces, security defaults, and release gates for Windows retail support.

## Product Outcome

The Windows retail runtime can be promoted only when users, operators, and
reviewers can inspect platform support, degraded guarantees, audit/replay
evidence, and no-bypass behavior from product docs and runtime outputs.

## User Story

As a security reviewer, I want Windows retail support to publish explicit
evidence and non-goals, so that portability does not hide weaker controls or
ambiguous financial authority.

## Scope

- In scope: update product/developer/security docs with support matrix,
  runtime tiers, install paths, demo commands, storage locations, manual
  verification, update/uninstall behavior, unsupported features; expose platform
  tier and degraded guarantees in CLI, CaseOps, audit, replay, metrics,
  diagnostics; document paper/sandbox default and no-live-effect for Windows;
  document privacy/telemetry defaults; link evidence artifacts.
- Out of scope: tier definitions (S1), build scope (V2.21.S2), preflight
  (S3), Windows implementation (S4), demo execution (S6).

## Preconditions And Assumptions

- S1 defines tiers; S3 defines preflight; S4 selected the Windows support path:
  **native portable Tickoni on Windows** (documented in v2.22-s4.md under
  "Windows Support Path Decision (T5)"); S6 defines demo/conformance.
- S7 is the closure story — it does not introduce new behavior but
  documents and gates everything that came before.
- V2.21.S7 (macOS) establishes the trust/documentation pattern that V2.22
  adapts for Windows.

## Acceptance Criteria

- [x] Given a Windows retail runtime promotion, when reviewers inspect docs,
      then they find the support matrix, runtime tiers, install paths, demo
      commands, storage locations, manual verification, update/uninstall
      behavior, and unsupported features for Windows.
