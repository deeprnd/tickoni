# V2.10.S9: Zig 0.17 Migration

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.10: Build System Consolidation And Qt Build Validation
**Labels:** `type/story`, `area/platform`

Upgrade the project from Zig 0.16.0-dev to Zig 0.17.0, resolve all breaking
changes across the Tickoni source trees and build system, update the Zig
installer, CI tooling, and documentation, and verify every build and test lane
passes on the new version.

## Product Outcome

Developers and CI run on Zig 0.17, gaining the latest language features,
stdlib improvements, and compiler optimizations without accumulated migration
debt. The build tooling (`zigw.sh`, `install-zig.py`, `zig-build-patterns`,
`zig-016-compat` → `zig-017-compat`), all docs referencing 0.16, and the
`build.zig.zon` minimum version are updated to 0.17. No code logic changes are
introduced — only breaking-change fixes and tooling updates.

## User Story

As a developer or CI runner, I want the repository locked to Zig 0.17 so that
I get the latest compiler fixes and stdlib improvements without encountering
outdated 0.16-specific patterns, and so that `just build-all` and `just
test-unit-all` succeed on a fresh checkout without any manual Zig version
overrides.

## Scope

- In scope: audit all Zig source for 0.16→0.17 breaking changes (stdlib API
  removals/renames, comptime behavior changes, error union changes, struct
  layout changes, builtin changes).
- In scope: apply fixes to all `.zig` files under `src/app/tickoni/`,
  `src/tickoni/`, `build.zig`, and any other Zig source in the repo.
- In scope: update `build.zig.zon` `.minimum_zig_version` to the target 0.17
  release version.
- In scope: update `zigw.sh` and `contrib/setup/helpers/install-zig.py` (or the relevant
  installer) to download and verify Zig 0.17.
- In scope: update `justfile` build/test recipes to reference the 0.17 tool
  path where they pin a specific version.
- In scope: update `doc/execution/development.md` Prerequisites section to
  reflect Zig 0.17.
- In scope: rename `zig-016-compat` skill to `zig-017-compat` and update its
  content with 0.17-specific patterns (or mark 0.16 skill as deprecated if
  patterns carry through).
- In scope: update any embedded dependency (`clap-0.12.0`, etc.) that may
  have a 0.17-compatible fork or version requirement.
- In scope: verify all `just build-*`, `just test-*`, `just quality-*` lanes
  pass on at least Linux x86_64.
- In scope: if a Zig 0.17 release candidate is not final, target the latest
  release candidate with a documented upgrade path from RC to GA.
- Out of scope: runtime behavior changes, new features, policy changes, tile
  logic changes, or Firedancer C code changes.

## Preconditions And Assumptions

- The project currently uses Zig 0.16.0-dev.3132+fd2718f82 (internal dev build
  from the Firedancer tree, see `doc/knowledge/zig/language-reference.md:13548`).
- The `zig-016-compat` skill documents 0.16-specific pitfalls that are likely
  resolved or changed in 0.17.
- Zig 0.17 is assumed to be the next stable release; if only an RC exists, the
  story targets the RC with a path to GA noted.
- The clap dependency (`zig-clap 0.12.0`) bundles its own `build.zig.zon` with
  `.minimum_zig_version = "0.16.0-dev.2261"`. This must be checked for a
  0.17-compatible fork or update.
- Breaking changes are limited to compiler/stdlib/API surface — no intentional
  changes to Tickoni financial logic, tile behavior, or policy.
