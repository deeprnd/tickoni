## Scope

After the fd-stem migration is complete (all tiles running through `__stem-run`), every inter-tile channel must be explicitly backed by Firedancer Tango shared memory (`.backing = .tango_shm`). Currently, two channel arrays default to heap-backed rings, and the topology spec serialization loses the `.backing` field on round-trip.

### In Scope

- `payment_channels` (used by `paymentPipeline()`): set explicit `.backing = .tango_shm`, `.reliability = .reliable`, `.workspace_name = "tkpay0"`.
- `investment_channels` (used by `investmentWorkflow()`): set explicit `.backing = .tango_shm`, `.reliability = .reliable`, `.workspace_name = "tkinv0"`.
- `topology_spec.zig` version bump to 3 (serialization format change).
- `topology_spec.zig`: add `.channel_backing` field to `TopologySpec`, serialize it in `fromTopology()`, deserialize it in `toTopology()`.
- Update all topology spec tests to verify the new field round-trips correctly.
- Verify all existing tests pass with the updated channel definitions.

### Out Of Scope

- Adding new tiles or topology variants
- Changing channel depth, MTU, or topology graph shape
- Modifying supervisor spawn logic or stem tile wiring
- Changes to Firedancer infrastructure, workspaces, or link properties beyond `.backing`/`.reliability`
- Workspace name changes for existing topologies that already have them

## Security

- `.backing` defaults to `.tango_shm` on deserialization of v2 specs — fail-safe for the all-stem migration. If a v3 spec says `.heap_dev`, it will be respected (correct behavior for any future in-process testing).
