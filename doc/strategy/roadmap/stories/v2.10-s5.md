# V2.10.S5: `setup-*` installation recipes

**Status:** Done
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.10: Build System Consolidation And Qt Build Validation
**Labels:** `type/story`, `area/platform`

Add `setup-{os}-{arch}[-{compiler}]` `just` recipes that install everything a
platform lane needs — Zig, compiler, make, shellcheck, gitleaks, buf, llvm tools,
kcov, pre-commit — so a new contributor or CI runner needs exactly one command
before any other `just` recipe works.

## Product Outcome

A fresh checkout goes from zero to green using only `just setup && just build-all
&& just test-unit-all` (plus the one documented manual prerequisite: install `just`
itself). CI's `setup-public-gh-runner` composite action becomes a thin wrapper
around `just setup-{os}-{arch}[-{compiler}]`.

## User Story

As a new contributor, I want to run `just setup` once after cloning the repo so
that I don't need to read three separate install guides before building.

As a CI workflow author, I want the composite action to call `just setup-*`
instead of containing 100+ lines of inline `if: runner.os ==` branching, so
that developer and CI installs are provably identical.

## Scope

- In scope: add `setup-linux-x86-gcc`, `setup-linux-x86-clang`, `setup-linux-arm-gcc`,
  `setup-macos-x86`, `setup-macos-arm`, `setup-windows-x86`, `setup-windows-arm`
  recipes to `justfile`.
- In scope: each `setup-*` recipe installs, idempotently, everything its lane
  needs:
  - Zig: reads version from `contrib/setup/tool-versions.json`, calls `helpers/install-zig.py`.
  - GNU make (macOS): `brew install make`.
  - Firedancer system deps: calls `deps.sh` (repo root) the same way
    `deps/action.yml` does today.
  - gitleaks: installs via the package manager.
  - kcov: installs via package manager for lanes that run coverage.
  - shellcheck, pre-commit, buf, llvm-18 tools: installs for lanes that need them.
  - Windows bootstrap tools: calls Scoop for LLVM, gitleaks, gmake.
- In scope: add a bare `setup-env` dispatcher that auto-detects platform via
  `uname` and routes to `setup-{os}-{arch}[-{compiler}]`.
- In scope: `just` itself is the sole exception to "one way in" — developers
  install it manually. Document this in `doc/execution/build.md` as a one-line
  prerequisite.
- In scope: convert `setup-public-gh-runner/action.yml` into a thin wrapper that
  calls `just setup-{os}-{arch}[-{compiler}]`.
- In scope: create `contrib/setup/` folder structure with lane scripts and helpers.
- Out of scope: CI workflow file changes (covered in S6).
- Out of scope: installer/distribution for end users (deferred to V3.23).
- Out of scope: Qt prerequisites — not needed for the Qt build POC (S3 does
  the POC without relying on S5).

## Implementation

### Folder Structure (committed)

Actual layout on disk:

```
contrib/setup/
  tool-versions.json              # Single source of truth for tool versions
  linux-x86-essential.sh          # Linux x86_64 — essential system packages (sudo)
  linux-x86-ops.sh                # Linux x86_64 — ops tools (gitleaks, kcov, etc.)
  linux-arm-essential.sh          # Linux aarch64 — essential system packages (sudo)
  linux-arm-ops.sh                # Linux aarch64 — ops tools
  macos-x86-essential.sh          # macOS x86_64 — Xcode CLT
  macos-x86-ops.sh                # macOS x86_64 — brew tools
  macos-arm-essential.sh          # macOS ARM64 — Xcode CLT
  macos-arm-ops.sh                # macOS ARM64 — brew tools
  windows-x86.ps1                 # Windows x86_64 — LLVM, Zig, Scoop/MSYS2 setup
  windows-arm.ps1                 # Windows ARM64 — LLVM, Zig, Scoop/MSYS2 setup
  README.md                       # Folder documentation
  helpers/
    common.sh                     # Shared POSIX helper functions (log, tool_exists, ensure_*)
    common.ps1                    # Shared Windows PowerShell functions
    install-zig.py                # Zig binary installer wrapper
    install-openssl.sh            # OpenSSL build helper
```

The implementation uses a two-script pattern for Linux and macOS (`*-essential.sh` + `*-ops.sh`) to separate privileged system-level installs (apt/brew/Xcode CLT) from per-lane tool installs. Windows uses single scripts since it handles both via PowerShell+Scoop.

### justfile Recipes (committed)

```
setup-env              # Auto-detects platform and routes to correct lane
setup-linux-x86-gcc    # Linux x86_64 — GCC 12
setup-linux-x86-clang  # Linux x86_64 — Clang 18
setup-linux-arm-gcc    # Linux aarch64 — GCC 14
setup-macos-x86        # macOS x86_64
setup-macos-arm        # macOS ARM64
setup-windows-x86      # Windows x86_64
setup-windows-arm      # Windows ARM64
```

### CI Conversion (committed)

`.github/actions/setup-public-gh-runner/action.yml` now calls `just setup-*`
instead of containing inline platform branching. Developer and CI installs are
provably identical.

## Notes And Open Questions

- Setup scripts use `sudo` where needed (apt-get, Homebrew system installs).
  The V1.21 no-sudo constraint applies to daily operations only.
- `contrib/setup/tool-versions.json` is the single source of truth for all tool versions. Update it once and all lanes + CI pick it up automatically.
- When V2.10.S1 (`contrib/platform.sh`) lands, the `setup-env` recipe in justfile
  will switch to call it instead of the current `uname` + `detect-windows-arch.sh`
  routing.
