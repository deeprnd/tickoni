# V2.10.S5: `setup-*` installation recipes

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.10: Build System Consolidation And Qt Build Validation
**Labels:** `type/story`, `area/platform`

Add `setup-{os}-{arch}[-{compiler}]` `just` recipes that install everything a
platform lane needs — Zig, compiler, make, shellcheck, gitleaks, buf, llvm tools,
kcov, pre-commit — so a new contributor or CI runner needs exactly one command
before any other `just` recipe works.

## Product Outcome

A fresh checkout goes from zero to green using only `just setup && just build-all
&& just test-unit-all` (plus the one documented manual prerequisite: install `just`
itself). CI's `setup-public-gh-runner` composite action becomes a thin wrapper
around `just setup-{os}-{arch}[-{compiler}]`.

## User Story

As a new contributor, I want to run `just setup` once after cloning the repo so
that I don't need to read three separate install guides before building.

As a CI workflow author, I want the composite action to call `just setup-*`
instead of containing 100+ lines of inline `if: runner.os ==` branching, so
that developer and CI installs are provably identical.

## Scope

- In scope: add `setup-linux-x86-gcc`, `setup-linux-x86-clang`, `setup-linux-arm-gcc`,
  `setup-macos-x86`, `setup-macos-arm`, `setup-windows-x86`, `setup-windows-arm`
  recipes to `justfile`.
- In scope: each `setup-*` recipe installs, idempotently, everything its lane
  needs:
  - Zig: calls `contrib/install-zig.py` (the single Zig install path).
  - GNU make (macOS): `brew install make`.
  - Firedancer system deps: calls `.github/actions/deps/deps.sh` the same way
    `deps/action.yml` does today.
  - gitleaks: installs via the package manager or `contrib/install-gitleaks.sh`.
  - kcov: installs via package manager for lanes that run coverage.
  - shellcheck, pre-commit, buf, llvm-18 tools: installs for lanes that need them.
  - Windows bootstrap tools: calls `contrib/setup-windows.ps1` for LLVM,
    gitleaks, gmake.
- In scope: add a bare `setup` dispatcher that auto-detects platform via
  `platform.sh` and routes to `setup-{os}-{arch}[-{compiler}]`.
- In scope: `just` itself is the sole exception to "one way in" — developers
  install it manually. Document this in `doc/execution/build.md` as a one-line
  prerequisite.
- In scope: convert `setup-public-gh-runner/action.yml` into a thin wrapper that
  calls `just setup-{os}-{arch}[-{compiler}]`.
- Out of scope: CI workflow file changes (covered in S6).
- Out of scope: installer/distribution for end users (deferred to V3.23).
- Out of scope: Qt prerequisites — not needed for the Qt build POC (S3 does
  the POC without relying on S5).

## Preconditions And Assumptions

- S1 (`platform.sh` + cleanup) has shipped.
- `install-zig.py` is the single Zig install path (D1 from build-tooling-consolidation.md).
- `deps.sh` exists in `.github/actions/deps/` and handles Firedancer system deps.
- `setup-windows.ps1` exists for Windows bootstrap tools.
- `just` is a documented manual prerequisite — no bootstrapping script for it.

## Acceptance Criteria

- [ ] Given a fresh Linux x86 environment, when `just setup-linux-x86-gcc` is
      run, then Zig, gcc, make, gitleaks, kcov, shellcheck, pre-commit, and
      buf are installed idempotently.
- [ ] Given a fresh macOS ARM environment, when `just setup-macos-arm` is run,
      then Zig, clang, make (via brew), gitleaks, kcov, shellcheck, pre-commit,
      and buf are installed idempotently.
- [ ] Given a fresh Windows x86 environment, when `just setup-windows-x86` is
      run, then LLVM, Zig, gitleaks, gmake, and bootstrap tools are installed
      idempotently.
- [ ] Given a bare `setup` dispatcher, when it runs on any supported platform,
      then it routes to the correct `setup-{os}-{arch}[-{compiler}]` recipe.
- [ ] `just setup && just build-all && just test-unit-all` succeeds on at least
      one platform after the setup completes.
- [ ] `install-zig.py` is called exactly once per setup, for all platforms.
- [ ] `setup-public-gh-runner/action.yml` is converted to call `just setup-*`
      instead of containing inline platform branching.
- [ ] `doc/execution/build.md` documents "install `just`" as the sole manual
      prerequisite.
- [ ] Re-running `just setup-*` is idempotent — no errors or duplicate installs
      on subsequent runs.

## Notes And Open Questions

- Should `setup-*` recipes use `sudo` or not? Per the product constraint (memory),
  V1.21 consumer hardware tiers must not require sudo. If any tool requires
  elevated privileges to install, the setup recipe should document the requirement
  and suggest a user-level alternative (e.g., `pip install --user`, `cargo install`).
- Should `install-zig.py` handle both CI and local installs, or should setup
  recipes call a different Zig installer for local vs CI? D1 says one path for
  everyone.
