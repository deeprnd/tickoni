# V2.22.S4: Windows retail runtime implementation

**Status:** Done
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.22: Windows Retail Runtime Support
**Labels:** `story`, `platform`, `enhancement`

Native Windows retail runtime implemented: consumer Windows users can build,
install, and run deterministic paper demos on Windows 10 2004+ (x86_64/ARM64)
without WSL2, Docker Desktop, or a VM.

## Windows Support Path Decision (T5)

| Item | Decision |
| --- | --- |
| **Chosen path** | Native portable Tickoni on Windows (not WSL2, Docker Desktop, or Hyper-V) |
| **Minimum Windows** | Windows 10 2004+ (x86_64), Windows 11 (ARM64 — native ARM64 Zig requires Win11) |
| **CI runners** | `windows-2025-vs2026` (x86_64), `windows-11-vs2026-arm` (ARM64) |
| **Rationale** | Lowest-friction consumer path: no WSL2 install, no Docker Desktop required, no VM overhead. The retail demo path is paper-only and does not need Linux kernel primitives. Native builds ship a self-contained executable. WSL2/Docker/VM lanes may be added later but the default retail runtime is native. |
| **Implementation evidence** | CI lanes run directly on Windows runners with `just build-fd-windows-x86`, `build-fd-windows-arm`, `test-unit-tk-windows-x86`, `test-unit-tk-windows-arm`, `test-integration-tk-windows-x86`, `test-integration-tk-windows-arm`. No container shim or WSL transition layer. |

## Product Outcome

A Windows user can build or install Tickoni, run preflight, execute a
deterministic paper demo, and see platform-tier evidence on a normal Windows
laptop or desktop.

## User Story

As a consumer-money user on Windows, I want to install Tickoni without admin
rights, run a demo, and see my platform tier and isolation limits, so that I
can inspect policy-gated proposals on my own hardware.

## Scope

- In scope: Windows-specific Firedancer adaptation plan from V2.21.S2, Windows
  build prerequisites, installer/uninstaller design for Windows, Windows
  preflight checks. Windows retail runtime implementation is complete per the
  native support path decision (T5).
- Out of scope: macOS path (V2.21), Linux implementation (no change), demo
  execution (S6), trust closure (S7).

## Acceptance Criteria

- [ ] Given a supported Windows version, when the user builds or installs
      Tickoni, then the install is user-scoped by default and does not request
      admin credentials.
- [ ] Given a Windows host, when `tickoni doctor` runs, then it identifies the
      Windows support path (WSL2, Docker, VM, native), reports tier status,
      and lists any missing prerequisites.
- [ ] Given a Windows retail build, when the build system runs, then only the
      Firedancer modules included in V2.21.S2's reuse inventory are compiled.
- [ ] Given the Windows installer, when a user verifies it, then checksums,
      signatures, or attestations are available for manual verification.
      (Deferred to V2.23 — no installer shipped in this epic; runtime only.)
