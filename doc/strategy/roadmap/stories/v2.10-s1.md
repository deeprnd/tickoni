# V2.10.S1: Platform detection script and script cleanup

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.10: Build System Consolidation And Qt Build Validation
**Labels:** `type/story`, `area/platform`

Create `contrib/platform.sh` as the single cross-platform OS/arch detection
script and consolidate `zigw.sh`, `fd-build-windows.sh`, and all inline
`uname -s`/`uname -m` parsing in `justfile` to use it. Delete redundant scripts.

## Product Outcome

Platform detection lives in one sourceable bash script instead of at least 4
scattered inline implementations. New contributors and CI have one place to
understand the OS/arch taxonomy, eliminating the repeat failure mode where
adding a new platform lane requires updating N separate `case` blocks.

## User Story

As a developer or CI workflow author, I want `just` recipes to determine my
OS/arch through one shared script, so that I never encounter inconsistent
platform classification between recipes and the platform taxonomy is obvious
to update when a new platform lane is needed.

## Scope

- In scope: create `contrib/platform.sh` with `tk_os()`, `tk_arch()`,
  `tk_platform()` functions covering Linux/Darwin/Windows and x86/arm.
- In scope: update `zigw.sh` to call `platform.sh` instead of its own Windows
  ARM detection.
- In scope: update `fd-build-windows.sh` to call `platform.sh` instead of
  `detect-windows-arch.sh`.
- In scope: update `justfile` to compute `os` and `arch` via `platform.sh`
  at top-level `just` variables and use them in dispatcher recipes.
- In scope: delete `detect-windows-arch.sh` (absorbed into `platform.sh`).
- In scope: delete `fd-build-linux.sh` (9-line wrapper; inline its one call
  into `justfile`'s Linux dispatch).
- In scope: confirm `fd-build-windows.ps1` is unused and delete it.
- In scope: delete `install-zig-bootstrap.py` (one Zig install path per D1).
- In scope: update `doc/execution/ci.md` to remove references to
  `install-zig-bootstrap.py` as a local install path.
- Out of scope: renaming `justfile` recipes (covered in S4).
- Out of scope: `setup-*` recipes (covered in S5).

## Preconditions And Assumptions

- V2.21/S2 and V2.22 established Linux/macOS/Windows as supported platforms
  with x86/arm arch variants.
- `zigw.sh` and `fd-build-windows.sh` are the only in-repo scripts currently
  doing Windows/ARM detection independently.
- The platform taxonomy is: `linux`, `macos`, `windows` × `x86`, `arm`.

## Acceptance Criteria

- [ ] Given any supported host, when `bash contrib/platform.sh os` is run,
      then the output is one of `linux`, `macos`, `windows` with no platform
      ambiguity.
- [ ] Given any supported host, when `bash contrib/platform.sh arch` is run,
      then the output is one of `x86`, `arm`, correctly detecting Windows
      ARM via `MSYSTEM_CARCH`/`PROCESSOR_ARCHITEW6432`/`PROCESSOR_ARCHITECTURE`
      when `uname -m` is unreliable.
- [ ] Given a host, when `bash contrib/platform.sh platform` is run, then the
      output is the concatenation of `$(tk_os)-$(tk_arch)`.
- [ ] Given `zigw.sh`, when it runs, then it calls `platform.sh` for OS/arch
      instead of implementing its own Windows/ARM detection.
- [ ] Given `fd-build-windows.sh`, when it runs, then it calls `platform.sh`
      instead of `detect-windows-arch.sh`.
- [ ] Given `justfile`, when it runs a dispatcher recipe like `build-fd`, then
      the OS/arch are computed once from `platform.sh` at top-level variables.
- [ ] `detect-windows-arch.sh` is deleted.
- [ ] `fd-build-linux.sh` is deleted and its one call is inlined into `justfile`.
- [ ] `fd-build-windows.ps1` is deleted.
- [ ] `install-zig-bootstrap.py` is deleted.
- [ ] `ci.md` no longer references `install-zig-bootstrap.py` as a local install
      path.
- [ ] `just build-all`, `just test-unit-all`, `just test-integration-tk` pass
      on at least one platform after the changes.
