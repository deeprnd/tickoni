# V2.10.S15: Port shared memory (fd_shmem) to macOS and Windows

**Labels:** `type/story`, `area/platform`
**GitHub Issue:** TBD

<!-- One sentence: the independently verifiable deliverable. -->
Port Firedancer's `fd_shmem` shared memory infrastructure to macOS and Windows using cross-platform POSIX `shm_open`/`mmap` and Win32 `CreateFileMapping`/`MapViewOfFile` backends, so Tickoni's multi-process tile architecture works identically on all three platforms.

## Product Outcome

Tickoni's multi-process runtime (tiles communicating over shared memory workspaces) runs on macOS and Windows with the same topology and behavior as Linux. Operators can develop, test, and run TileOni locally on any supported platform without hitting stub errors. The "No black boxes" telemetry audit is resolved on all platforms.

## User Story

As a developer-operator, I want to run Tickoni's process-mode tiles on macOS or Windows without encountering stubbed shared memory errors, so that I can develop and iterate locally on any platform instead of being locked to Linux.

## Scope

- In scope:
  - Cross-platform `fd_shmem` abstraction: a new Zig module (`cross_shmem`) with POSIX (`shm_open`/`mmap`) and Windows (`CreateFileMapping`/`MapViewOfFile`) backends.
  - C ABI wrappers in `wksp.c`, `fd_shmem_posix.c`, and replacement of `fd_shmem_windows_stub.c`.
  - Workspace shim (`wksp.c`) updates to route through the cross-platform backend.
  - Supervisor tile spawning (CPU placement: Windows `SetThreadAffinityMask` vs Linux cpuset).
  - Platform shim updates in `topo_run_platform_macos.c` and `topo_run_platform_windows.c`.
  - Unit/integration tests for cross-platform shmem.
  - Telemetry audit doc update ("No black boxes" PASS).
- Out of scope:
  - Firedancer's native hugetlbfs path on Linux (unchanged).
  - Tile financial logic (shmem is infrastructure, not business state).
  - Firedancer's `fd_topo` and `fd_stem` topology/lifecycle (unchanged).
  - Thread-mode (dev/test) heap-backed rings (unchanged).
  - NUMA binding on macOS/Windows (expected no-op).
  - Huge page support on macOS/Windows (expected fallback to 4KB normal pages).

## Preconditions And Assumptions

- Firedancer's `fd_shmem` C API (`fd_shmem_create`, `fd_shmem_join`, `fd_shmem_leave`, `fd_shmem_unlink`) is the surface contract that must be preserved.
- `FD_HAS_WINDOWS` and `FD_HAS_LINUX` compile-time conditionals control platform paths in existing Firedancer code.
- NUMA binding is already a no-op stub on macOS/Windows.
- Huge pages are a Linux optimization; normal 4KB pages are the cross-platform baseline.
- Tickoni build uses `zig build`; target triples for macOS are `aarch64-apple-darwin` and `x86_64-apple-darwin`.
- macOS 10.7+ has `shm_open` (POSIX.1-2008). Older versions may need a `tmpfs` fallback.
- Windows `CreateFileMapping` for the small regions Tickoni uses (kilobytes to megabytes) does not require admin privileges.

## Acceptance Criteria

- [ ] Given a macOS or Windows target, when `zig build` is run, then the cross-platform shmem module compiles and links successfully without stub errors.
- [ ] Given a `fd_shmem_create` call, when a named shared memory region is created, then the region is backed by POSIX `shm_open`/`mmap` on macOS or Win32 `CreateFileMapping`/`MapViewOfFile` on Windows, and returns a valid address.
- [ ] Given two TileOni processes running on the same machine, when one calls `fd_shmem_create` and the other calls `fd_shmem_join` with the same region name, then the second process sees the same shared memory and can read/write data written by the first.
- [ ] Given a `fd_shmem_unlink` call, when a region is unlinked after all joiners leave, then the region is removed and a subsequent `fd_shmem_join` with the same name fails to find it.
- [ ] Given a `page_sz` of `huge` or `gigantic`, when the region is created on macOS or Windows, then it falls back to 4KB normal pages without error.
- [ ] Given a TileOni supervisor spawning a tile on Windows, when `cpu_placement` is set to `.exclusive` or `.shared`, then the tile process gets CPU affinity via `SetThreadAffinityMask` instead of a Linux cpuset.
- [ ] Given the telemetry audit, when reviewed after this story lands, then "No black boxes" is marked PASS for macOS and Windows, with `/metrics` served via the metrics tile on all platforms.
- [ ] Given `zig build test`, when all existing tests run on macOS or Windows, then they pass (no regressions from the stubbed paths).
