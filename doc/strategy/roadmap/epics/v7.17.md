# V7.17: Tkmodl Budget And Call-Limit Governance

**Status: Planned · Milestone: M7**

**Epic:** #TBD · **Issue:** #TBD
**Labels:** `epic`, `area/agents`, `area/security`

Add per-run, per-role, and per-case model-call limits to `TkModlConfig` and
define call-limit-exceeded and budget-exhaustion as auditable terminal states.
V1.11 establishes the governed `tkmodl` dispatch boundary and fail-closed
validation; this increment adds the enforcement layer for budget and
call-frequency governance.

Extracted from V1.11.S2 (T6–T8).

---

## Product Intent

V1.11 `tkmodl` validates every model request, fails closed on unknown or
disabled providers, and substitutes captured output during replay. What it does
not enforce is how many times a given role or case may call a model, or what
happens when a token budget runs out mid-run. V7.17 adds these limits as
auditable policy-relevant events: call-limit-exceeded and budget-exhausted are
expected terminal states with explicit audit records, not panics or silent
truncations. A per-role limit halts only that role's model access, not the
entire run.

## User Story

As a compliance operator, I can configure per-role and per-case model-call
limits and token budgets, so that every call-limit or budget-exhaustion event
produces an auditable record with the limit type, consumed count, and budget id
before the run halts.

## What The Operator Sees

- call-limit-exceeded audit record with budget id, limit type (run, role, or
  case), consumed call count, configured limit, run id, and policy version
- budget-exhausted audit record with budget id, consumed tokens, token limit,
  run id, and policy version
- `TkModlConfig` fields for per-run, per-role, and per-case call limits
- role-scoped enforcement: a per-role limit halts that role's model access
  without affecting other roles or the overall run state

## Success Demo

- [ ] A per-role model-call limit produces a call-limit-exceeded audit record
  and halts that role's model access.
- [ ] Other roles in the same run continue after one role hits its call limit.
- [ ] Token budget exhaustion produces a budget-exhausted audit record before
  the run halts.
- [ ] A run that stays within all limits completes normally with no limit audit
  records.

## Release Gate

- `just test-unit-tk` passes with no unexpected skips
- `just test-integration-tk` passes offline against local mocks
- per-role call limit produces call-limit-exceeded record and stops that role
  without affecting other roles
- budget exhaustion produces audit record; run cannot issue further model
  requests afterward

## Non-Goals

- no changes to `tkmodl` request validation or provider dispatch logic
- no changes to model allowlist, endpoint mapping, or replay substitution
- no changes to agent run envelope or tool broker
