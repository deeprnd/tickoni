# V8.6: Guarded Broker, Payment, And Crypto Sandbox

**Labels:** `type/epic`, `area/payments`, `area/crypto`, `area/security`, `area/operations`, `area/platform`
**GitHub Issue:** [37](https://github.com/deeprnd/tickoni/issues/37)

Connect sandbox broker, payment, bank, or crypto accounts and submit approved
small actions through a signed-action envelope with read-back reconciliation
and kill switch. Paper mode remains the default.

## One-Paragraph Summary

People don't trust money-moving systems because they've never seen one shut
itself down voluntarily. V8.6 is where Tickoni proves that the most important
feature of a financial execution system isn't what it can do — it's the
guaranteed ability to stop doing it. Sandbox adapters turn approved proposals
into real actions through a signed-action envelope, but the kill switch ensures
those actions can be revoked at any layer. Every ingested event returns one of
four explicit responses, every action carries a deterministic idempotency key,
and every downstream read-back is reconciled against the local proposal. Paper
mode remains the default for all sandbox execution.

## Product Intent

V8.6 adds signed action envelopes, sandbox adapters, read-back reconciliation,
and a kill switch. It also adds an authenticated financial event ingestion
endpoint (`POST /v1/events`) via `tkapi` so external sources can submit
authenticated financial events into the Tickoni runtime. Paper mode remains the
default for all sandbox execution.

The sandbox isn't a limitation — it's a trust signal. By constraining execution
to broker, payment, bank, and crypto sandbox environments, we prove that
Tickoni's policy gates, signed envelopes, and reconciliation loop work with
real-side-effect connectors before any production path opens. The kill switch
isn't paranoia; it's the mechanism that proves Tickoni governs execution rather
than being governed by it.

## Users And Jobs

- [Product evaluator]: Connect sandbox broker, payment, bank, or crypto accounts
  and submit approved small actions through a safe-action flow.
- [External event source]: Submit authenticated financial events into Tickoni
  via a documented API endpoint with source identity, idempotency, and signature
  verification.
- [CaseOps operator]: View sandbox action status, read-back reconciliation
  results, and kill switch state.

## Success Metrics

- Sandbox adapter behavior is substitutable by replay capsules with no external
  side effects.
- A read-back mismatch is detectable and produces a reconciliation artifact.
- Every ingested external event returns one of four explicit responses:
  accepted, duplicate, malformed, or rejected.
- The kill switch blocks all sensitive execution capabilities immediately.

## Demo Moment

- Command or flow: `just tkapi-event-ingest` (or exact CaseOps flow)
- Expected result: An external event with a known source identity and valid
  signature is accepted with a stable event id; a duplicate returns the original
  event id; a malformed payload or invalid signature is rejected with no state
  change; sandbox actions submit only after policy, evidence, approval, signed
  envelope, and action-id checks pass.

## Scope

### In Scope

- Sandbox adapter manifests for broker, payment processor, bank transfer, and
  crypto custody or wallet connectors.
- Paper/sandbox/live mode switch with safe default to paper or draft-only mode.
- Signed action envelope for approved sandbox orders, payment retries, transfers,
  and crypto withdrawals.
- Deterministic action id and idempotency key.
- Sandbox action submission gated on capability, evidence, limit, and approval
  checks.
- Read-back downstream status and reconciliation with the local proposal.
- Mismatch note or reconciliation case when read-back differs.
- Kill switch that blocks all sensitive execution capabilities.
- Authenticated financial event ingestion endpoint via `tkapi`: `POST /v1/events`
  accepts external events with source identity, idempotency key, event type,
  payload, timestamp, and source signature.
- Source identity registration: source id, allowed event types, allowed rate
  limits, and public key or token for signature verification.
- Idempotency key uniqueness per source identity and time window.

### Out Of Scope

- Production live execution by default.
- Margin trading.
- Derivatives.
- Autonomous execution.
- Story-level implementation tasks — these are scoped at story creation time.
