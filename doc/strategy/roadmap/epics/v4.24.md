# V4.24: Monte Carlo and Scenario Analysis

**Status:** Backlog
**Milestone:** M4
**Labels:** `epic`, `area/investing`, `area/platform`

A single DCF number is not a decision. Investors need to understand the range of
outcomes given assumption uncertainty. V4.24 brings native Monte Carlo simulation
to the Tickoni runtime — no Python, no R dependency. Perturb beta, ERP, growth
rate, and terminal value inputs through 100,000 iterations, producing
base/bull/bear cases with uncertainty bands. Cross-checks (reverse DCF, peer
multiples, sum-of-the-parts) flag divergence. Sensitivity tables show which
assumptions drive the widest range. This is where Tickoni stops pretending
uncertainty doesn't exist.

This epic does not ingest data (V4.34) or produce investment conclusions
(V4.25) — it adds statistical rigor to the computation.

## Product Intent

A single DCF number is not a decision. Investors need to understand the range
of outcomes given assumption uncertainty. V4.24 brings native Monte Carlo
simulation — no Python or R dependency — to the Tickoni runtime. Perturb
beta, ERP, growth rate, and terminal value inputs through thousands of
iterations, producing base/bull/bear cases with uncertainty bands. Add
cross-checks (reverse DCF, peer multiples, sum-of-the-parts) and sensitivity
analysis to make every assumption's impact visible.

## Users And Jobs

- Portfolio analyst: run Monte Carlo on a DCF, get base/bull/bear
  cases with uncertainty bands, and see which assumptions drive the widest
  range.
- Risk reviewer: audit which assumption perturbations caused the most
  valuation divergence.
- CaseOps operator: review a valuation analysis card showing Monte Carlo
  distribution, scenario probabilities, sensitivity tables, and cross-check
  divergences.
- Quant researcher: run deterministic sensitivity experiments (beta, ERP,
  growth perturbations) and compare results byte-identically on replay.

## Success Metrics

- Native Monte Carlo simulation (no Python/R dependency) runs at least
  100,000 iterations in under 30 seconds on a single core for a standard
  5-year DCF parameter set.
- Monte Carlo produces base/bull/bear cases with uncertainty bands (percentiles).
- Cross-check suite (reverse DCF, peer multiples, sum-of-the-parts) runs
  alongside primary DCF and reports divergences.
- Two-dimensional sensitivity tables show valuation impact of paired
  assumption perturbations.
- Methodology self-audit reports transparency metrics: assumption count,
  data quality score, model limitations.
- All statistical outputs are traceable to input perturbations and seed;
  deterministic under replay.

## Demo Moment

- Command or flow: `just val-mc-demo` runs Monte Carlo with 10,000 iterations
  on an AAPL FY2023 fixture, prints base/bull/bear cases with uncertainty
  bands, runs cross-checks, generates sensitivity tables, and reports
  methodology transparency score.
- Expected result: reproducible Monte Carlo output with distribution statistics,
  cross-check divergences, sensitivity tables, and transparency report.

## Scope

### In Scope

- Native Monte Carlo simulation engine using Varanus library.
- Scenario analysis: base, bull, and bear case definitions with scenario
  probabilities.
- Cross-check suite: reverse DCF, peer multiples, sum-of-the-parts.
- Two-dimensional sensitivity tables: paired assumption perturbations.
- Methodology self-audit and transparency reporting.
- Deterministic, seed-stable Monte Carlo computation.
- Perturbation distribution configuration (normal, uniform, triangular).
- Audit trail for Monte Carlo parameters, results, and cross-checks.

- Model provider integration (LLMs) for scenario generation.
- Options-based valuation (Black-Scholes, Binomial).

## Story Breakdown

### How Many Stories

Mid-range epic — 4 stories covering Monte Carlo engine, cross-checks,
sensitivity analysis, and methodology audit/closure.

### Decomposition Rules

1. Independent delivery: each story produces a testable analysis slice.
2. One capability per story: Monte Carlo, cross-checks, sensitivity, audit.
3. Split by domain: each analysis method is its own story.
4. Closure via T10 child tasks in the final story.
5. Domain boundaries: Monte Carlo and cross-checks are separate stories.

### Bad Splits (Avoid)

- "Monte Carlo engine" and "Monte Carlo scenarios" as two stories — scenarios
  are part of the Monte Carlo capability, same story.
- "Reverse DCF" and "peer multiples" as two stories — both are cross-checks,
  same story.
- "Sensitivity table" and "sensitivity visualization" as two stories — output
  format does not define a separate capability.

## Dependencies And Decisions

- Varanus library must be integrated and tested before Monte Carlo stories
  begin (depends on V4.32).
- Decision: Monte Carlo random number generation — Mersenne Twister vs PCG
  vs Xoshiro family. Determinism vs speed trade-off. PCG recommended for
  deterministic replay with good statistical properties.
- Decision: perturbation distribution shapes — normal, uniform, triangular,
  or custom. Normal distribution is the default for financial parameters.
- Decision: number of iterations for default demo (10,000 vs 100,000).
  10,000 for demo speed; 100,000 available via flag.
- Depends on V4.32 (core DCF engine) for base computation input.
- Depends on V4.34 (data layer) for canonical fact input availability.
