# V2.10: The First Impression — A Build System That Welcomes Trust

**Status:** Backlog
**Milestone:** M2
**Labels:** `epic`, `area/platform`, `area/operations`, `type/enhancement`, `type/documentation`

<!-- One paragraph: what complete feature this epic delivers and why now. -->

V2.10 recognizes the first truth of open-source trust: **the build system is not plumbing — it is the handshake.** It is the moment a contributor decides whether to invest or walk away. The largest single file in the codebase — a 1,766-line monolithic build script — becomes a declarative under-500-line system. A new developer clones the repo, runs two commands, and gets green tests. They add a test file — the build system discovers it. No reading boilerplate required.

The logical answer is "optimize the build script for maintainability." That's what every competitor does, and it's expensive because the damage has already been done — the contributor already closed the tab. The psycho-logic answer is to make the *first impression* so frictionless that the contributor never reaches for the tab-closing reflex. Make the build feel like a welcome, not an obstacle course. The material gain is a shorter `build.zig`; the psychological gain is a community that stays.

This epic also consolidates build, test, quality, and security tooling into a single `just`-driven surface, and validates the Qt 6 CMake-based build path that V3.19's native terminal depends on. One epic, two transformations: **trust through accessibility for the community, and proven foundation for the terminal.**

## The Why

We are in the infinite game. Our competitors are not other build systems — they are the five hundred other open-source financial infrastructure projects competing for the same engineers, the same auditors, the same attention. Every new contributor who hits the build wall is a vote of no-confidence in the entire project. This epic is not about build scripts. It is about **making it easy for people to say yes to Tickoni.**

We believe that a codebase should lower the cost of trust. That means the path from "I'm interested" to "I built it" should be shorter than the path to "I give up."

## Product Intent

A single entry point for every build, test, quality, and security action. No contributor, CI workflow, or script should invoke `gcc`, `zig`, `gmake`, or a `contrib/*.sh` directly. Platform detection lives in one script. The Zig build script is refactorable without touching CI, Firedancer C build, or Tickoni runtime behavior. And Qt must be demonstrably buildable through the repo before terminal development starts.

The perceptual outcome is what matters: **the build system should feel like an invitation, not an exam.** A contributor shouldn't need to learn the project's secret handshake before they can contribute. The uniform recipe names, the auto-discovery, the platform detection — they all serve the same purpose. They make the first impression one of competence and care.

## Users And Jobs

- **New contributor** — runs `just setup` once and proceeds without consulting multiple scattered install guides. Their job: "Is this project worth my time?" The build system answers: "Yes."
- **Developer-operator** — runs `just build-all` and `just test-unit-all` locally on any supported platform without memorizing OS-specific flags. Their job: "I need to iterate quickly." The build system answers: "Go."
- **CI workflow author** — calls fully-qualified recipes with zero ambiguity about which OS/arch/compiler triple is in effect. Their job: "I need predictability at scale." The build system answers: "Here."
- **Terminal developer** — builds the Qt investment terminal scaffolding through a validated CMake integration before V3.19 UI work begins. Their job: "I need the foundation to be real, not aspirational." The build system answers: "It is."
- **Security reviewer** — runs `just security-check-all` and `just quality-lint-check-fd` with deterministic output. Their job: "I need to trust what I'm auditing." The build system answers: "You can."

## Success Metrics

- `contrib/platform.sh` replaces all inline `uname -s`/`uname -m` parsing in `justfile`, `zigw.sh`, `fd-build-windows.sh`, and `detect-windows-arch.sh`.
- `detect-windows-arch.sh`, `fd-build-linux.sh`, `fd-build-windows.ps1`, and `install-zig-bootstrap.py` are deleted (or confirmed orphaned and deleted).
- `build.zig` refactored to <500 lines with walk-based discovery for unit, integration, and cov lanes passing all existing tests.
- `just setup-{os}-{arch}[-{compiler}]` recipes install everything a build/test lane needs; a fresh checkout goes from zero to green via `just setup && just build-all && just test-unit-all` plus the one documented manual prerequisite (install `just`).
- CI workflows call fully-qualified recipe names for all scheduled jobs.
- Qt 6 CMake build path builds the terminal scaffolding (`main.cpp`, `ApplicationController`, `ApiTypes`, QML stub) on at least Linux x86.
- **Psychological metric:** A new contributor can go from clone to green build with fewer steps and less documentation than the top three comparable open-source financial infrastructure projects.

## Demo Moment

- **Command or flow:** on a clean checkout, run `just setup`, `just build-all`, `just test-unit-tk`, `just test-integration-tk`, then `just build-tkni` (Qt build) and confirm the terminal binary launches with the QML shell rendering.
- **Expected result:** all lanes pass; `tickoni-terminal` launches, shows the dark shell, and connects to a local fixture mode without requiring any manual platform-specific flags.
- **The feeling:** The contributor didn't fight the system. They rode it. That feeling is the product.

## Scope

### In Scope

- `contrib/platform.sh`: single cross-platform OS/arch detection script.
- `justfile` cleanup: consolidate inline OS detection, introduce fully-qualified recipe names, keep bare dispatchers as auto-routing conveniences.
- Delete orphaned/redundant scripts: `detect-windows-arch.sh`, `fd-build-linux.sh`, `fd-build-windows.ps1`, `install-zig-bootstrap.py`.
- `build.zig` refactor: module registry + walk-based test discovery (<500 lines).
- Qt build POC: CMakeLists.txt, minimal Qt 6 scaffolding (C++ app, API types, command registry stub, QML shell), buildable on Linux x86 at minimum.
- CI workflow cutover: update all 7 workflow files to use fully-qualified recipe names; no new scheduled lanes.
- `setup-*` recipes: one per platform lane, install everything needed.
- Documentation updates: `doc/execution/build.md`, `development.md`, `ci.md`, `testing-tickoni.md`, `contribution/tickoni.md`.

### Out Of Scope

- New CI lanes or CI schedule changes beyond wiring existing recipes to fully-qualified names (D5).
- Full Firedancer unit-test coverage on macOS/Windows (spike in S3).
- Qt terminal beyond the build POC — no QML pages, no real API client, no investment flow implementation (V3.19 owns that).
- Changes to Firedancer C build, upstream Makefiles, or Firedancer tile semantics.
- Changes to Tickoni runtime tile behavior, capability envelopes, audit schema, or replay logic.

But more importantly: the first time someone opens this repository, it *works*.

- **What changed from the previous roadmap increment?**
  Consolidated build surface, reduced `build.zig` complexity, validated Qt build foundation. The perceptual change: building Tickoni no longer feels like solving a puzzle. It feels like starting work.

- **What is this epic's wow-effect?**
  A new developer clones the repo, runs two commands, gets green tests on their platform, and can add a new Zig test file with zero changes to `build.zig`. They look at the screen and think: "Someone actually cares about this."

- **How does this epic progress Tickoni's unique value proposition?**
  Removes a structural contribution barrier, making the codebase safer for community extension without weakening financial boundaries. In the infinite game, the team that makes it easiest for strangers to join is the team that wins trust. Trust compounds.

- **Which demo command or CaseOps flow closes the epic?**
  `just setup && just build-all && just test-unit-all && just test-integration-tk && just build-tkni`.

- **Is execution paper-only, draft-only, sandbox, live, or disabled?**
