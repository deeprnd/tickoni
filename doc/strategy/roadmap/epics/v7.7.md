# V7.7: The Trust Layer

**Status: Later · Milestone: M7**
**Labels:** `epic`, `area/trust`, `area/audit`, `area/security`

People don't trust what a system says. They trust what it can prove. Every time a recommendation becomes a proposal, a proposal becomes an approval, and an approval becomes an action — someone needs to see the full chain of accountability, replay it from scratch, and export the evidence to a partner without exposing internal system details.

**V7.7 is where Tickoni stops being a system that claims to be trustworthy and becomes a system that can prove it.** Not through marketing, not through access controls — through a complete, verifiable, exportable record of every material decision.

---

## Users And Jobs

- Regulated fintech partner: "I need to export the full decision trail for audit, and I need it to show *why* a decision was made or blocked — not just what happened."
- Compliance/risk reviewer: "I need to verify replay reproduces the exact same evidence, and I need blocked/resized/escalated decisions to be visible in plain language."
- CaseOps operator: "I need to understand a money decision without reading raw JSONL or tile logs."
- Engineering team: "I need hash-chain-verified audit records that survive replay."

## Success Metrics

- A partner can retrieve a complete money-decision record via authenticated API and understand every step of a decision without reading raw JSONL.
- Hash-chain verification on exported audit JSONL reports no broken links.
- Replay from an exported JSONL capsule reproduces the same event hashes in order; tampered records produce a mismatch report.
- An incomplete run is distinguishable from a complete run by the `incomplete_run` flag.
- Partner-facing language at every endpoint — no internal error codes, tile names, or log references in API responses.

## Demo Moment

```bash
# 1. Run a case that goes through policy check, model analysis, and proposal
# 2. Export the money-decision record
POST /v1/cases/{id}/export  →  self-contained record with audit timeline, replay capsule, policy version, approval state, divergence report

# 3. Verify replay reproduces the same hashes
POST /v1/cases/{id}/replay  →  "matched" or "diverged" with exact event_id and field of first difference

# 4. Verify hash chain
tk-diag verify-audit /path/to/audit.jsonl  →  "chain intact, N records" or "broken link at event_id X, seq N"
```

## Scope

### In Scope

- Append-only, hash-chained audit JSONL record format and hash-chain verification
- Signed audit records with stable event IDs and cryptographic signatures
- Replay capsules that substitute external effects (model output, adapter calls, execution)
- Divergence detection on replay (policy version, evidence, market fixture, model output, adapter output)
- Incomplete-run marker for non-clean shutdowns
- Partner-facing API endpoints for case list, case detail, evidence, audit timeline, replay status, and money-decision export
- Capability-based access control on partner endpoints
- Backpressure, queue-depth, and crash diagnostics included in trust evidence exports
- Partner-facing language on all API responses (blocked, resized, approval-required, evidence-required, escalated)

### Out Of Scope

- TigerBeetle ledger execution or approval execution (future `tkexec`)
- Direct model/provider calls (governed through `tkmodl`)
- Direct financial API access (governed through `tkadpt`/`tktool`)
- Operator UI changes (separate epic)

### How Many Stories

17 stories. This epic spans three distinct concerns: the audit record format (T1–T4, T8), the replay and verification machinery (T2, T9–T13), and the partner-facing API surface (T5–7, T14–17). Each concern has enough surface area that smaller stories would fragment the work without enabling independent delivery.

### Decomposition Rules

- One capability per story: audit record, replay capsule, hash-chain verification, incomplete-run marker, divergence detection, case endpoints, export endpoint, access control, partner-facing language.
- Lifecycle split: record format → replay → API → access control → language.
- Closure story last: T17 (partner-facing language) ties all API work together.

### Bad Splits (Avoid)

- Splitting the JSONL record format into "write the schema" and "implement the hash chain" — these are interdependent and must ship together.
- Splitting T14 and T15 into separate per-endpoint stories — the access control and evidence model is shared.
- Creating a story for "write docs" — documentation is part of the closure evidence, not a standalone story.

## Release / Evidence Gate

- Trust export shows audit timeline, replay status, policy version, model/tool/adapter attribution, approval state, and signed records without requiring raw log review.
- Hash-chain verification passes for exported audit JSONL with no broken links.
- An incomplete-run flag is present on the final record of a non-clean shutdown and absent on a clean shutdown.
- Partner API endpoints return case, evidence, audit, replay, and export data without disclosing internal codes or tile names.
- A replay verification run from exported JSONL reproduces the same event hashes in order; a tampered record produces a mismatch report with the first differing event_id and field.
- Divergence reports correctly identify changed policy version, evidence hash, market fixture hash, model output hash, and adapter output hash.
- Backpressure, queue-depth, and crash diagnostics are included in the trust evidence export.
- Capability-based access control rejects unauthenticated and unauthorized requests on all partner endpoints.
- All partner-facing language returns blocked, resized, approval-required, evidence-required, and escalated outcomes in plain language.
- Signed audit records contain stable event IDs, nanosecond-precision timestamps, previous hashes, input/output hashes, results, and signatures.
- Replay runs substitute model, adapter, and execution results — no external system calls are made.
- The money-decision export is self-contained: audit timeline, replay capsule, policy version, attribution, approval state, and divergence report are all present.

## Dependencies And Decisions

- Depends on: `tkaudt` hash-chained audit record format (core tile), `tkrepl` replay capability, `tkmodl` model attribution, `tkadpt`/`tktool` adapter attribution, `tkcase` deterministic case state.
- Decision: audit JSONL is append-only and hash-chained. No mutable audit state.
- Decision: replay substitutes all external effects (model, adapter, execution). No LLM server or API calls during replay.
- Decision: capability envelopes govern both financial events and partner API access using the same model.
