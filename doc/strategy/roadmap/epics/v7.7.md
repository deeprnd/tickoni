# V7.7: Trust Layer

**Status: Later · Milestone: M7**
**Labels:** `epic`, `area/trust`, `area/audit`, `area/security`

Let partners inspect the proof behind each recommendation, payment proposal,
transfer proposal, trade ticket, approval, denial, and downstream result.

---

## Product Intent

Every consequential recommendation, proposal, approval, denial, and downstream
result is attributable, policy-checked, and replayable. Audit, replay,
attribution, and exportable money-decision records form the trust layer.

## User Story

As a regulated fintech, brokerage, payments, or crypto partner, I can inspect
the proof behind each recommendation, payment proposal, transfer proposal,
trade ticket, approval, denial, and downstream result.

## Tasks

- V7.7.T1: Add money-decision audit timeline for thesis, basket, ticket,
  payment proposal, transfer proposal, crypto proposal, guardrail checks,
  approval, sandbox execution, read-back, mismatch, and impact.
- V7.7.T2: Add replay capsule for investing, payment, transfer, and crypto
  flows.
- V7.7.T3: Include policy version, policy hash, capability envelope id,
  model/tool/adapter attribution, actor id, agent identity, tool name, and
  invocation protocol.
- V7.7.T4: Include signed audit records with stable event id, timestamp,
  previous hash, input hash, output hash, result, and signature.
- V7.7.T5: Export a money-decision record for partner review.
- V7.7.T6: Show blocked, resized, approval-required, evidence-required, and
  escalated reasons in partner-facing language.
- V7.7.T7: Show model usage, adapter behavior, approval state, replay status,
  and downstream result without requiring raw-log review.
- V7.7.T8: Define the audit JSONL record format: one JSON object per line with
  fields event_id (stable, nanosecond-precision uuid), type, timestamp_ns, case_id,
  actor_type, actor_id, agent_identity, model_id, action, tool_name,
  invocation_protocol, input_hash, output_hash, policy_version, policy_decision,
  capability, result, prev_hash, and signature. The event_id is stable across
  replay runs for the same logical event.
- V7.7.T9: Add a hash-chain verification command or test recipe that reads an
  audit JSONL file, recomputes each prev_hash from the preceding record, and
  reports the first broken link with event_id and sequence number.
- V7.7.T10: Add an incomplete-run marker: the final audit record of a run that
  terminates without a clean shutdown carries an incomplete_run flag and the last
  valid sequence number. A run without the flag is a complete run.
- V7.7.T11: Include backpressure, queue-depth, and crash diagnostics in the
  trust evidence export: tile queue depths at the last checkpoint, backpressure
  event count by tile, and crash signal and cause when present.
- V7.7.T12: Add replay verification from exported audit records: a verification
  run driven from an exported audit JSONL file must reproduce the same event
  hashes in the same order as the original run. A mismatch is reported with the
  first differing event_id and field name.
- V7.7.T13: Add a divergence report to the money-decision export: when a replay
  diverges due to a changed policy version, changed evidence hash, changed market
  fixture hash, changed model output hash, or changed adapter output hash, the
  export includes the divergence reason, the original hash, the replay hash, and
  the first divergent event sequence number.
- V7.7.T14: Add authenticated partner read endpoints via `tkapi`:
  - `GET /v1/cases` — list cases or synthetic runs with id, status, created_at,
    thesis or event summary, and policy decision summary
  - `GET /v1/cases/{id}` — case detail with policy decision, model usage
    summary, adapter behavior summary, approval state, and replay status
  - `GET /v1/cases/{id}/evidence` — evidence item list with item id, type,
    content hash, source identity, and sequence number
  - `GET /v1/cases/{id}/audit` — structured audit timeline in partner-facing
    language; not raw JSONL
  - `GET /v1/cases/{id}/replay` — replay capsule summary with status, capsule
    id, expected outcome, and divergence report when present
- V7.7.T15: Add an authenticated money-decision export endpoint:
  `POST /v1/cases/{id}/export` returns a self-contained money-decision record
  including audit timeline, replay capsule summary, policy version, model usage
  attribution, adapter behavior, approval state, divergence report when present,
  and signed audit records.
- V7.7.T16: Apply capability-based access control to all partner read and export
  endpoints using the same capability envelope model that governs financial
  events. Unauthenticated or unauthorized requests are rejected with no data
  disclosed.
- V7.7.T17: Return partner-facing language at every endpoint for blocked,
  resized, approval-required, evidence-required, and escalated outcomes.
  Internal error codes, tile names, and raw log references must not appear in
  partner API responses.

Acceptance:

- A partner can inspect how intent became a recommendation or proposal, why it
  was allowed or blocked, and how replay reproduces the decision.
- A reviewer can understand the money decision without reading raw audit JSONL
  or tile logs.
- Audit JSONL records follow the defined format and pass hash-chain verification.
- An incomplete run is distinguishable from a complete run by the incomplete_run
  flag on the final record.
- A partner can retrieve case list, case detail, evidence items, structured
  audit timeline, replay capsule summary, and money-decision export via
  authenticated API endpoints.
- Partner API responses use partner-facing language; internal codes and tile
  names are not disclosed.

## Evidence Gate

- Trust export shows audit timeline, replay status, policy version,
  model/tool/adapter attribution, approval state, and signed records without
  requiring raw log review.
- Hash-chain verification passes for exported audit JSONL with no broken links.
- An incomplete-run flag is present on the final record of a non-clean shutdown
  and absent on a clean shutdown.
- Partner API endpoints return case, evidence, audit, replay, and export data
  without disclosing internal codes or tile names.
- A replay verification run from exported JSONL reproduces the same event hashes
  in order; a tampered record produces a mismatch report with the first differing
  event_id and field.
