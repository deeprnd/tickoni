# V7.15: Bounded Agent Run Governance

**Status: Planned · Milestone: M7**

**Epic:** #TBD · **Issue:** #TBD
**Labels:** `epic`, `area/agents`

Define the agent run envelope, run-state machine, step and retry counters,
budget-exhaustion terminal state, and identity propagation rules. V1.11 routes
agents through governed tile boundaries; this increment adds the enforcement
layer that makes budget exhaustion and step-limit termination auditable
policy-relevant events rather than runtime errors.

Extracted from V1.11.S7.

---

## Product Intent

V1.11 agents run inside governed tile boundaries with capability envelopes, but
the agent run itself has no formal lifecycle or enforcement layer. An agent
could loop indefinitely, exhaust its token budget silently, or present a
different identity on downstream requests. V7.15 closes these gaps: a run
envelope bounds every agent run with explicit step, retry, and token limits;
exhaustion is an auditable terminal state, not a panic; and identity context
propagates from the envelope exclusively.

## User Story

As a governed agent runner, I can bound every agent run with explicit step,
retry, and token limits, so that budget exhaustion and step-limit termination
are auditable policy events with explicit audit records rather than runtime
errors or silent truncations.

## What The Operator Sees

- run envelope fields in audit output: run id, role, step limit, retry limit,
  token budget id, run state
- step-limit-exceeded audit record with step count and limit before the run
  halts
- retry-limit-exceeded audit record with retry count and limit
- budget-exhausted audit record with budget id, consumed tokens, and token limit
- run state transition sequence in the audit timeline per case or synthetic run

## Success Demo

- [ ] A run that reaches its step limit emits a step-limit-exceeded audit record
  and halts without a runtime error.
- [ ] A run that exhausts its token budget emits a budget-exhausted audit record
  and cannot issue further model requests.
- [ ] A run that completes within all limits emits a completed run state.
- [ ] An agent cannot substitute a different identity or role on a downstream
  model, tool, or adapter request.

## Release Gate

- `just test-unit-tk` passes with no unexpected skips
- `just test-integration-tk` passes offline against local mocks
- step-limit-exceeded halt produces audit record and no unhandled panic
- budget-exhaustion halt produces audit record; run cannot continue afterward
- agent identity substitution attempt is denied

## Non-Goals

- no new agent capabilities or tools
- no changes to `tkmodl` dispatch, `tktool` dispatch, or replay substitution
- no changes to capability envelopes, policy rules, or audit record schema

## WBS

### V7.15.S1: Agent run envelope and terminal states

**Issue:** #TBD

**Description:** Define agent run envelope with step, retry, and token budget limits, define run state enum including terminal states, add step and retry counters, audit budget exhaustion as a policy event, enforce identity propagation from envelope.

Tasks:

- V7.15.S1.T1: Define an agent run envelope with run id, agent identity, role,
  workflow, case or synthetic run id, policy version, capability envelope id,
  step limit, retry limit, token budget id, start time, and run state.
- V7.15.S1.T2: Define run state as a tagged union or enum: running, completed,
  step-limit-exceeded, retry-limit-exceeded, budget-exhausted, policy-denied,
  and error. Budget-exhausted and step-limit-exceeded are expected terminal
  states, not runtime errors.
- V7.15.S1.T3: Add a loop step counter: each iteration of an agent reasoning
  loop increments the step counter. When the step limit is reached the run
  transitions to step-limit-exceeded and emits an audit record before halting.
- V7.15.S1.T4: Add a retry counter: each agent-level retry increments the
  counter independently of any model-level retry. When the retry limit is
  reached the run transitions to retry-limit-exceeded.
- V7.15.S1.T5: Audit budget-exhaustion as a policy-relevant event: emit an
  audit record with budget type, budget id, consumed tokens, token limit, run
  id, and policy version before halting.
- V7.15.S1.T6: Require agents to carry explicit role and identity context on
  every model request, tool request, and adapter request they generate. The run
  envelope is the sole authority for this context; an agent may not substitute
  a different identity or role on any downstream request.
- V7.15.S1.T7: Add tests for step-limit-exceeded halt with audit record,
  retry-limit-exceeded halt, budget-exhaustion audit record, and a run that
  completes within all limits.

Acceptance:

- A step-limit-exceeded run emits an audit record and halts without a runtime
  error or unhandled panic.
- Budget exhaustion produces an audit record with budget id, consumed tokens,
  and token limit before the run halts.
- An agent run that exhausts its budget cannot continue even if the model would
  respond to further requests.

## Evidence Gate

- What can the operator do now that they could not before? Inspect the audit
  record for every agent run terminal state — including step-limit-exceeded and
  budget-exhausted — with explicit counts and limits.
- What changed from V1.11? Agent runs now have a formal envelope, state machine,
  and terminal-state audit records. Budget exhaustion and step limits are
  enforced rather than advisory.
- What is the demo moment? Integration test drives a run to each terminal state
  and shows the audit record for each.
- Which checks are enforced? Step limit, retry limit, token budget, and identity
  propagation from envelope.
- What happens when a run exceeds its step limit? Run transitions to
  step-limit-exceeded, emits an audit record, and halts without a panic.
- Is execution paper-only, draft-only, sandbox, live, or disabled? Unchanged
  from V1.11 — paper-only.
- Which artifacts are needed for partner trust? Audit JSONL samples for each
  terminal state, run-envelope fixture set.
- Which command closes the increment? `just test-integration-tk` with
  run-envelope suite passing.
- Which fixtures are used? Run envelope fixtures for step-limit-exceeded,
  retry-limit-exceeded, budget-exhausted, and completed states.
- Are policy and limit decisions visible in audit output? Yes — each terminal
  state produces an audit record with the relevant limit and consumed count.
- Can replay run without side effects? Yes; run envelope fields are captured and
  restored during replay.
- What intentional failure proves failure behavior? Budget-exhausted run that
  cannot issue a further model request even when the fixture would respond.
