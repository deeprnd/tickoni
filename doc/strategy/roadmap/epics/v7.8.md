# V7.8: Capability Control Surface

**Status: Later · Milestone: M7**
**Labels:** `epic`, `area/security`, `area/trust`

Let fintech, brokerage, payments, crypto, treasury, risk, and compliance
partners see and manage the financial action classes and policy outcomes that
govern every agent recommendation, proposal, approval, denial, escalation, and
execution path.

---

## Product Intent

Partners can inspect the capability catalog by action class, policy outcome,
scope dimension, evidence prerequisite, aggregate limit, approval path, and
denied-by-default execution or override path.

## User Story

As a fintech, brokerage, payments, crypto, treasury, risk, or compliance
partner, I can see and manage the financial action classes and policy outcomes
that govern every agent recommendation, proposal, approval, denial, escalation,
and execution path.

## Tasks

- V7.8.T1: Surface a capability catalog in finance-native language.
- V7.8.T2: Add action-class view: observe, analyze, draft, recommend, propose,
  prepare, execute, override, and administer.
- V7.8.T3: Add policy outcome view: `allow`, `deny`, `require_approval`,
  `require_more_evidence`, and `escalate`.
- V7.8.T4: Add scope viewer for account, customer, merchant, legal entity,
  beneficiary, IBAN, wallet, custody account, rail, currency, country, market,
  venue, sector, instrument, order type, amount, exposure, frequency, holding
  period, risk tier, jurisdiction, and environment.
- V7.8.T5: Add later-lane templates for ledger corrections, accounting
  adjustments, reconciliation breaks, fraud/risk triage, compliance case
  preparation, treasury alerts, chargebacks, merchant risk review, bank
  transfers, crypto transfers, and trading execution.
- V7.8.T6: Add evidence prerequisite display for proposal capabilities.
- V7.8.T7: Add aggregate limit display by case, customer, account,
  beneficiary, wallet, instrument, and time window.
- V7.8.T8: Add approval-path display with approver roles, expiry, revocation,
  and maker-checker requirements.
- V7.8.T9: Add explicit denied-by-default execution and override list for
  money movement, ledger posting, payout approval, account freezing, risk-rule
  override, policy modification, and unsupported trading or crypto actions.
- V7.8.T10: Add tests proving agents cannot edit policy, expand capabilities,
  administer allowlists, or execute outside signed adapter and privileged
  executor paths.
- V7.8.T11: Add a programmatic capability catalog endpoint via `tkapi`:
  `GET /v1/capabilities` returns the full catalog in finance-native language
  structured by action class, policy outcome, scope dimension, evidence
  prerequisite, aggregate limit, and approval path. The response mirrors the UI
  surface defined in T1–T4 and is programmatically queryable by partners.
- V7.8.T12: Integrate the operator review surface with the partner read endpoints
  from V1.7: capability catalog, case evidence, policy decision, model usage,
  adapter behavior, approval state, and replay status are accessible through the
  same authenticated API surface without raw-log review. Access is scoped to the
  authenticated actor's capability envelope; data from one partner must not be
  disclosed to another.

Acceptance:

- A partner can inspect the capability catalog by action class, policy outcome,
  scope dimension, evidence prerequisite, aggregate limit, approval path, and
  denied-by-default execution or override path.
- The capability catalog is programmatically accessible via `GET /v1/capabilities`
  and returns the same content as the UI surface.
- The operator review surface presents evidence, policy decision, model usage,
  adapter behavior, approval state, and replay status without raw-log access,
  and access is scoped to the authenticated actor.

## Evidence Gate

- Capability catalog is inspectable by action class, policy outcome, scope,
  evidence prerequisite, aggregate limits, approval path, and denied-by-default.
- `GET /v1/capabilities` returns a programmatically queryable catalog consistent
  with the UI surface.
- Operator review surface presents case evidence, policy decision, model usage,
  adapter behavior, approval state, and replay status without raw-log access.
