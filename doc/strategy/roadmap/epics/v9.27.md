# V9.27: YouTube Research Monitor

**Status:** Backlog
**Milestone:** M9
**Labels:** `epic`, `area/audit`, `area/investing`, `area/platform`, `area/security`, `type/documentation`

## Description

V9.27 introduces Tickoni's first external-source ingestion capability: a governed
YouTube monitoring and summarization system that reads only the authenticated
user's subscribed channels, detects new videos, fetches metadata and captions,
generates source-grounded summaries through `tkmodl`, and surfaces those
summaries as audit-chained evidence in CaseOps. No transcript storage, no model
training, no trade recommendations, no auto-execution.

## Product Intent

The investment workflow begins with information gathering. YouTube financial
commentary — earnings recaps, macro analysis, technical deep-dives — is a real
source of market narrative. Currently Tickoni has no ingestion path for external
research data. V9.27 closes that gap by establishing a governed adapter path
for YouTube that feeds research evidence into the proposal pipeline without
introducing financial risk.

## Users And Jobs

- **Investment analyst / operator:** Monitor specific YouTube channels, detect new
  videos, receive structured summaries with source links and timestamps, and view
  those summaries as evidence alongside trading proposals in CaseOps.
- **Compliance / risk operator:** Verify which external research sources informed
  each proposal. Trace each claim back to a timestamped video segment. Confirm
  no unauthorized claims were made and no full transcripts were stored.
- **Consumer user:** Stay informed about financial markets through YouTube channels
  they follow, with clear boundaries on monitoring scope, content handling, and
  output framing.

## Success Metrics

- A user can authenticate a YouTube account, select subscribed channels, and
  trigger a full ingest cycle from video detection to CaseOps evidence without
  any hardcoded credentials or bulk-scraping paths.
- Every ingest event produces a hash-chained audit record with video URL, summary
  hash, timestamp references, and source attribution.
- Replay of any ingest event produces the identical summary and audit record
  without calling the YouTube API.
- All model calls for summary generation route through `tkmodl` with token budgets
  and context limits enforced.
- All YouTube Data API calls route through `tkadpt` as a governed adapter path.

## Demo Moment

- Command or flow: authenticate YouTube account → select 3 subscribed channels
  → trigger manual poll → wait for new-video detection → view summary in CaseOps
  → replay the ingest event from fixture → verify identical summary and audit record.
- Expected result: a source-grounded summary with video URL, timestamp references,
  and "not investment advice" framing appears in CaseOps; replay produces the
  identical output without external API calls.

## Scope

### In Scope

- OAuth authentication via Google/YouTube account (OAuth-scoped only)
- Reading user's subscribed channels via YouTube Data API
- User selection of which subscribed channels to monitor
- Periodic detection of new videos on monitored channels
- Fetching video metadata: title, URL, thumbnail, publish date, description
- Caption/subtitle download (only when available via official API)
- Summary generation via `tkmodl` with metadata-only fallback and disclaimer
- Capability envelope definition: `research_signal.youtube_ingest` in `tkpoly`
- Audit recording of ingestion events in `tkaudt`
- Evidence attachment in `tkevid` when available
- CaseOps surface for viewing YouTube-sourced research evidence
- Timestamp references alongside summaries
- Source-linking back to the original video
- Replay support with summary substitution capsules

### Out Of Scope

- Bulk scraping of arbitrary channels
- Full transcript storage or export
- Model training or fine-tuning on video content
- Real-time live-stream monitoring
- Audio-only podcast ingestion
- Sentiment analysis or alpha scoring
- Automated trade signal generation
- Portfolio impact scoring based on YouTube sentiment
- Social media monitoring beyond YouTube
- Video content moderation or fact-checking
- Subscription management beyond user channel selection
- Video recommendation beyond subscribed-channel context
- Per-channel poll frequency (default: global configurable interval)
- Semantic video analysis (image/audio processing)

## Release / Evidence Gate

- What can the user or operator do now that they could not before this epic?
  Browse and inspect audited YouTube research evidence alongside trading proposals.
  Trace any claim in a proposal back to a specific video and timestamp.

- What changed from the previous roadmap increment?
  M8 established the approved execution sandbox for financial actions. V9.27 adds
  the first external-source research ingestion capability, closing the research
  → analysis → proposal → approval loop end to end.

- What is this epic's wow-effect?
  An operator reviews a trade proposal and can click through to the exact YouTube
  video, see the creator's timestamped commentary, and verify the summary is accurate
  and bounded — all within the same governed harness that enforces policy, audit,
  and replay.

- How does this epic progress Tickoni's unique value proposition?
  Demonstrates that Tickoni's governance (capability envelopes, audit chains, replay
  substitution, model gateway) applies uniformly to external research sources, not
  just internal event streams. Every YouTube evidence source is traceable, replayable,
  and policy-gated — a generic scraper cannot provide this.

- Which demo command or CaseOps flow closes the epic?
  Authenticate → select channels → poll → ingest → view in CaseOps → replay.

- Which account, beneficiary, IBAN, wallet, rail, currency, market, venue,
  asset class, instrument, notional, amount, exposure, and frequency checks are
  enforced, if any?
  Account: user's OAuth-scoped YouTube subscription scope. Market/instrument/sector
  tags extracted from video content for context. No money-impacting dimensions.

- What happens when the requested action exceeds policy, scope, or evidence?
  Capability check returns `deny` for non-subscribed channels or transcript-storage
  requests. Metadata-only fallback with disclaimer when captions are unavailable.
  API failure skips polling and logs — no fallback to unofficial scraping.

- Is execution paper-only, draft-only, sandbox, live, or disabled?
  Disabled. YouTube ingest never executes financial actions.

- Which fixtures, samples, audit records, replay capsules, screenshots, or API
  examples prove the behavior?
  Deterministic fixtures with mocked YouTube Data API responses. Replay capsules
  containing summary text and metadata. Audit records with hash chains.

- Can replay run without external side effects when replay applies?
  Yes. Summary substitution capsules eliminate all YouTube API calls during replay.

- What intentional blocked-flow or divergence example proves fail-closed behavior?
  Non-subscribed channel monitoring request → policy `deny`. YouTube API failure →
  poll skipped, logged. Captions unavailable → metadata-only summary with disclaimer.

## Dependencies And Decisions

Prerequisites:
- M8 (approved execution sandbox) establishes the same governance patterns that V9.27
  replicates for external research ingestion.
- Existing tiles: `tkmodl` (model gateway), `tkpoly` (policy), `tkaudt` (audit),
  `tkadpt` (adapter dispatch), `tkevid` (evidence — when available), `tkapi` (CaseOps).

Open decisions from YouTube proposal:
- Capability name: `research_signal.youtube_ingest` (recommended) vs alternatives
- Caption availability: metadata-only fallback with disclaimer (recommended)
- Poll frequency: global configurable interval (recommended default)
- Replay caption strategy: snapshot at ingest time for deterministic replay (recommended)
- OAuth scope boundary: YouTube API scope only (recommended)
- Integration with `tkmodl`: use existing model gateway path (recommended)
